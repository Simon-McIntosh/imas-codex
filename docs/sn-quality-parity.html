Current scope: make documentation quality measurable, then improve it on evidence

This plan owns the documentation half of the project goal — names whose docs carry the definition, governing equation, variable definitions, semantic scope and exclusions, essential relationships, sign convention where COCOS applies, and the working cross-references a physicist actually needs. Typical values and general measurement recipes are deliberately excluded: ungrounded ranges are worse than none, and the live faithfulness policy admits measurement content only where it is constitutive or discriminating (docs-content-gates, locked 2026-08-23).

Every change proves itself against the holdout; nothing regenerates sound content wholesale. Most of the original programme had already shipped by the time this plan was executed — the 2026-08-23 currency audit reclassified 43 claims and left five open, all of them about evidence rather than capability. The 2026-08-10 evidence-recovery overlay was removed in the 2026-08-11 portfolio review: advisory triage and rescores live in sn-benchmark-evolution, and the backlog drain already ran under sn-pipeline-recovery §4.

§4 — Constraints, dependencies, and documentation fallout

  • Library-first context. The source explicitly rejects using the MCP server formatting layer for DD context enrichment; the implementation should call the shared library/query layer directly.
  • Link resolution needs a terminal failure state. The plan is explicit that unresolved links cannot silently loop forever; failed is part of the intended lifecycle.
  • Publish/export safety matters as much as generation quality. Unresolved links must not appear in published output.
  • The benchmark relationship runs the other way. This plan informs only sn-west-review-rehearsal; sn-benchmark-evolution informs this plan. No state-of-the-nation resource exists in the live tree, so nothing is owed to one.
  • Documentation fallout is already discharged. Repo guidance already documents the seven-pool docs generation, review and refine loop, COCOS injection, link hygiene and family harmonization; the link lifecycle and unit authority are already in the LinkML source; the schema reference is generated output, not a hand-maintained target; and the transport module's docstring already states its current two-step boundary.
