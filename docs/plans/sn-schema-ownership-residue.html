§1 — Measured, not suspected

The static property audit built for the identity convention checked 13,517 property occurrences across the repository and adjudicated every one. Three of its permanent allowances are not really allowances: they are places where the schema and the live graph name different owners for the same data, and the audit recorded them as such rather than blessing or breaking either side.

§2 — Why the identity plan refused to settle it

Repairing a working query into a zero-coverage one is the exact harm that audit exists to prevent, so a reader pointed at a populated undeclared property must not be mechanically moved onto a declared empty one. Every candidate substitution measured zero. The alternative — declaring the runtime property in LinkML — expands durable schema authority to cover operational state, which is a different decision with different consequences.

Both real fixes require a graph migration plus ingestion and query changes together. That is a scope this plan owns and the identity plan did not.

§3 — What done looks like

Each of the three gets an owner, and the code, data and schema agree on it. The measure is the same in every case and it is not “the tests pass”: after the change, the property the code queries must have non-zero live coverage, and the property it stopped querying must be gone rather than merely unused. A migration that leaves both readable is a rename that did not happen.

patterns_found is the cheap one and may need no migration at all. It needs path discovery to run and populate it, after which the repaired query stops being a schema correction awaiting data and starts being a fix.
