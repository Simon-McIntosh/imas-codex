§1 — Map, triage, attach, map again

The conventions stage (signal-cocos-conventions) and the map's slot decisions (mapping-decision-chain §5) both stop short of guessing: a judgment below its acceptance threshold, or a COCOS class factor the surviving conventions disagree on, is left open. Today an open result is a status on the source and nothing more. Nobody is asked the question, and when someone does find the missing fact, there is nowhere to put it where the next run will read it.

This plan makes the open result a SignalFollowup in the graph: the source, the stage that raised it, the open question in plain words, and Jev's distribution. A person, or an agent in an interactive session, triages it with the evidence the pipeline already gathered in view, searches the facility's wiki, code and documents for more, and may read a shot. What they find is attached to the source as evidence, and the source is re-queued. The next judgment reads that evidence first. Mapping therefore improves in rounds: map, triage and attach, map again.

Attached evidence reuses MappingEvidence, which a SignalSource already links through HAS_EVIDENCE, and whose EvidenceType already holds sign_convention, data_validation, expert_knowledge and escalation. One type is added: declared, a value a person states with a reference, such as "positive Ip is clockwise seen from above, from the JT-60SA operations handbook".

§2 — A followup is a graph record

A SignalFollowup carries an id, the facility, the stage that raised it (conventions, candidates or mapping), the open slot or question kind, the question text, Jev's distribution as JSON, a status (open, attached, resolved, dismissed), and when and by whom it was raised and resolved. It links HAS_FOLLOWUP from its source. raise_followup is idempotent on the source, stage and open slot, so a re-run that reaches the same open question updates the record rather than adding a second.

§4 — The next judgment reads the evidence first

The conventions stage and the map's slot judgment raise followups through raise_followup instead of only setting a status, and their state builders put a source's attached evidence first, labelled by type and author. A declared value settles its slot with a new SlotResolution.HUMAN authority and keeps its reference as evidence. A probe that later reads data contradicting a declared value raises a new followup and leaves the declaration in place; it never overwrites one.

§5 — First triage round on JT-60SA

Once the conventions proof has run, the lead triages the JT-60SA followups in an interactive session with an agent, through the §3 tools, then re-runs the conventions stage on the attached sources. This round is human work, so it is not dispatched to a worker. It measures whether the loop closes questions.
