§1 — Map, triage, attach, map again

The conventions stage (signal-cocos-conventions) and the map's slot decisions (mapping-decision-chain §5) both stop short of guessing: a judgment below its acceptance threshold, or a COCOS class factor the surviving conventions disagree on, is left open. Two records of an open result exist today. The map's insufficient_context disposition marks the source, and write_mapping_result in imas_codex/ids/models.py writes each escalation as a MappingEvidence of type escalation, confidence 0, linked HAS_EVIDENCE from the source. Neither names the question, the stage or the open slot, neither has a status a person can move, and the conventions stage writes neither. So nobody is asked the question, and a fact someone finds has nowhere to go that the next run reads.

This plan extends that escalation evidence into the followup rather than adding a second record of an open result: an escalation MappingEvidence gains the stage that raised it, the open slot, the question in plain words, Jev's distribution and a followup status. The disposition stays the source-level summary. A person, or an agent in an interactive session, triages it with the evidence the pipeline already gathered in view, searches the facility's wiki, code and documents for more, and may read a shot. What they find is attached to the source as evidence, and the source is re-queued. The next judgment reads that evidence first. Mapping therefore improves in rounds: map, triage and attach, map again.

Attached evidence reuses MappingEvidence, which a SignalSource already links through HAS_EVIDENCE, and whose EvidenceType already holds sign_convention, data_validation, expert_knowledge and escalation. One type is added: declared, a value a person states with a reference, such as "positive Ip is clockwise seen from above, from the JT-60SA operations handbook".

§2 — A followup is an escalation record

MappingEvidence gains the properties an open question needs, used on escalation records: the stage that raised it (conventions, candidates or mapping), the open slot or question kind, the question text, Jev's distribution as JSON, a followup status (open, attached, resolved, dismissed), and when and by whom it was resolved. raise_followup in imas_codex/discovery/signals/followups.py writes one escalation idempotently on the source, stage and open slot, so a re-run that reaches the same open question updates the record rather than adding a second. write_mapping_result's escalation writer becomes a caller of it, so one function owns escalation records. The same module owns listing, showing and attaching, which §3's terminal and MCP front ends call.

What this adds and merges. No new node class: the open result and its answer are both MappingEvidence, and one value joins EvidenceType, declared. The escalation writer is merged into raise_followup.

§3 — Triage from the terminal and from an agent session

imas-codex discover followups FACILITY lists open followups grouped by stage and question kind, with counts. --show ID prints everything a person needs to answer one: the source's description, members, unit and accessor, the question, Jev's distribution, the source's geometry, its candidate DD fields, and its top reranked code, wiki and document hits. --attach ID with one of --note, --ref (a WikiChunk, CodeChunk or Document id), --declare (a value with its reference) or --probe-shot writes the evidence, marks the followup attached, and re-queues the source for the stage that raised it. The command is a thin adapter over the §2 module.

What this adds. One subcommand, not two: attaching is an option of the same command. Nothing existing lists or answers an escalation, so nothing is retired.

§4 — The next judgment reads the evidence first

The conventions stage and the map's slot judgment raise followups through raise_followup instead of only setting a status, and their state builders put a source's attached evidence first, labelled by type and author. A declared value settles its slot with a new SlotResolution.HUMAN authority and keeps its reference as evidence. A probe that later reads data contradicting a declared value raises a new followup and leaves the declaration in place; it never overwrites one.

§5 — First triage round on JT-60SA

Once the conventions proof has run, the lead triages the JT-60SA followups in an interactive session with an agent, through the §3 tools, then re-runs the conventions stage on the attached sources. This round is human work, so it is not dispatched to a worker. It measures whether the loop closes questions.
