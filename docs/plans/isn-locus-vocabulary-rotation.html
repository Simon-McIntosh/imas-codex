§1 — The one row that leaves this repository

Of everything the graph-wide integrity programme could not close, exactly one item is blocked by a vocabulary that this repository does not own. The source dd:b_field_non_axisymmetric/time_slice/field_map/grid/phi still targets toroidal_angle_of_measurement_position, which does not describe it. The identity it should carry is a toroidal coordinate of the field-map grid, and that name cannot be written: toroidal_coordinate_of_field_map_grid is absent from the graph AND fails strict parsing under ISN 0.8.0rc67, because field_map_grid is not a locus token the closed grammar admits.

This is a real gap rather than a naming preference. The rule that all grammar segments are closed is exactly what makes the composer trustworthy, and the correct response to a genuine missing token is to rotate the vocabulary on the ISN side, never to invent a spelling locally or substitute a nearest-fitting locus that would assert semantics the Data Dictionary does not carry.

§2 — Establish that the token is warranted before adding it

A closed vocabulary stays useful only if additions are justified rather than convenient, and this project has recorded the opposite error too — valid candidates wrongly dismissed on a quick read. So the first work is adjudication, not implementation:

  • Is the locus real? A field map grid is a computational sampling structure. Establish from the DD whether it is a physical locus at all, or whether the correct identity names something else entirely and the locus framing is the mistake.
  • How many identities need it? One row motivates this plan. Measure whether other DD paths under field-map or similar grid structures need the same token, because a token added for a single row is a weaker case than one that resolves a family.
  • Does an existing token already cover it? Derive the candidate set from get_grammar_context() rather than memory, and state why each near-miss fails. A token that duplicates an existing one damages the vocabulary more than the gap does.

If adjudication concludes the token is not warranted, that is a valid outcome and the owner/geometry row stays a recorded refusal permanently, with its reason upgraded from “awaiting vocabulary” to a settled semantic judgement.

§3 — The rotation, and the two places the pin lives

If warranted, the mechanical path is known and documented: add the token on the ISN fork, cut a release candidate, and bump the dependency in this repository — where the pin appears twice in pyproject.toml and both occurrences must move together. A partial bump produces a grammar snapshot that disagrees with the installed package, which is a failure mode this programme has already met: an ISN pin bump does not by itself resync the graph's grammar snapshot, and scoped runs skip that sync.

So the rotation is not complete when the dependency resolves. It is complete when the graph's grammar snapshot carries the new token, the previously unspellable identity parses strictly, and the owner/geometry source can be migrated onto it through the ordinary sanctioned path rather than a bespoke repair.

One caution recorded from this programme's own history: never order ISN versions as strings. rc9 sorts above rc65 lexically, and a comparison that gets this wrong silently serves stale vocabulary while reporting success.
