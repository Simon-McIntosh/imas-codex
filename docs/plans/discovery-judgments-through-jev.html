§1 — Why every discovery judgment moves

Each discovery pipeline makes the same kind of decision. A language model scores an item on several purpose dimensions from 0 to 1 against a written rubric, and code compares those numbers with fixed thresholds to decide what to keep, expand or ingest. The code pipeline showed that this is the wrong instrument.

  • The rubric places core facility code at 0.65–0.85, while the gates sat at 0.75 and 0.90.
  • The scale drifts by facility: ingested TCV files have a median of 0.85, while the JT-60SA Grad-Shafranov solver tops out at 0.75.
  • Against 128 hand-labelled files from JT-60SA, TCV and JET, the old composite separates the code a mapper needs at AUC 0.56.
  • Jev's typed judgments separate the same files at AUC 0.962.

§25 of JT-60SA Discovery Completion deployed that change for code. This plan carries it to every other pipeline.

Jev, TypeSafe's decisions model reached through OpenRouter's /api/alpha/decisions endpoint, answers three typed primitives:

  • Noul: the probability that a condition holds.
  • Choice: one option from a set, with its distribution.
  • Score: a probability-weighted position on ordered, concretely described levels.

Three rules select among them. Two are measured; the third follows from what each primitive returns.

  • Gate on Nouls. For an in-or-out decision, the maximum of the scope Nouls separated in-scope code at AUC 0.962. A five-level relevance Score reached 0.894, and the maximum of four facet Scores reached 0.913.
  • Use one Noul per label wherever several labels can hold. A Choice is single-answer. Measured by the mapping-candidate-selection plan: a JET plasma-current source received 1.0 on magnetics and 0 on equilibrium and summary, although it belongs in all three.
  • Use Choice for an exclusive classification, and Score for a graded facet that is stored and tracked. Facets are read only for items that pass the gate: outside it, MINPACK's least-squares routines scored 2.5 of 3 on signal processing.
  • Store every distribution beside its value. The lead decided this on 2026-10-07. Every Jev judgment a pipeline persists keeps the model's own uncertainty, as typed fields that Cypher can query:
    • A Score field X is stored with X_probs, ordered by level index, and X_confidence.
    • A Choice is stored with X_probs, aligned to the schema enum's fixed order, and X_confidence.
    • A Noul's value is its probability.
    Confidence near 0 marks a judgment whose mass is split between levels. Such a judgment is worth a second look, and the expected value alone hides it.

Text generation stays with the language model: descriptions, keywords, signal names, cluster labels, and the DD, IDS and identifier enrichment text.

§6 — Signal enrichment and DD domain classifications through Jev

Signal enrichment keeps the language model for the generated name and description, and moves its classifications to Jev:

  • physics domain as Nouls per label;
  • diagnostic and context quality as Choices;
  • a Noul asking whether the generated description is supported by the source context the enrichment read. A low value sends the signal back for enrichment rather than accepting the description.

The DD domain classifier becomes the same physics-domain judgment over DD paths.

Done when both deploy behind a prototype that measures agreement with a labelled sample, with the change against the current assignments reported.

Interface account: signal enrichment supplies §3's three functions for its classifications and retires those classification fields from its language-model response model. The DD domain classifier's language-model call retires for the same physics-domain judgment.

§7 — Re-judge the stored rows

After §3–§6 land, each pipeline's own run re-judges its stored rows once per facility through §3's stale-judgment claim:

  • JT-60SA first, then TCV, JET and ITER;

A row whose decision changes from skip to admit enters its pipeline's normal fetch. A row whose decision changes from admit to skip keeps what it already ingested, and is only reported.

§17 — Correct the goldens, find the variation, and give every judge its graph neighbourhood

Why. The lead asked on 2026-10-08 what limits the judges and whether the goldens are wrong. The lead also asked whether the knowledge graph is exploited: a resource's links to and from other resources, and the types of the resources it links to. §15's paired run gave AUC 0.850 without facility matches and 0.851 with them, at the 0.30 scan gate on the 158 labelled JT-60SA paths. Reading its 32 misses and 6 false alarms (coordinator, 2026-10-08) gives four findings.

  • The measure scores a decision the pipeline does not make. 16 of the 32 misses are containers the judge already marks worth expanding, with children-worth-listing at 0.5 or more (edas2/v2.1.14 0.87, esurf_plugins 0.88, topics/common 0.83). Scored on the decision the pipeline makes, scan or expand, the same judgments give AUC 0.890. Scan at 0.30 or expand at 0.6 reaches 101 of 118 positives with 6 of 40 false alarms. The children-worth-listing values come from the deploy run, not the fresh one.
  • The goldens are skewed and inconsistent. 50 of 158 labels are working copies of TOPICS under /home/a048717/src/pjtopics_*, 36 of them positive. atdisp is negative in three copies while sibling TOPICS directories are positive, and client_eqdbms…/eqtrace, equilibrium tracing in the EQDB client, is negative. The labels were made from paths and stored descriptions, which is the same text the judge reads, not from the source.
  • Variation exceeds the effects being measured. Repeat calls changed the score on 117 of 137 paths whose state did not change. The fresh describe step writes a new description on every pass, and the description is in the state, so the input may not be stable.
  • The graph context is unused. The path state carries the directory alone. The schema holds its parent and children (IN_DIRECTORY), aliases (ALIAS_OF) and repository copies (INSTANCE_OF), the CodeFiles under it with their chunks' DataReference and IDS links, and the Documents under it. 20 of the 32 misses have no children or files in the graph, because they were never scanned. The containers do have judged children the state does not show: edas2/v2.1.14 has a child scoring 0.50 for analysis code, and the FLEDD eqdbms has a child scoring 0.67 for data access. None of the 32 carries INSTANCE_OF or ALIAS_OF, so the working copies look independent. Wiki pages naming a tool or path (eSurf, eqdbms, getseldata) are not linked to the FacilityPath. Code files carry no include or import links.

Node 1: goldens and noise. Relabel the set from source inspection on the facility, with two labels per path: worth scanning for code, and worth expanding. Mark each working copy with the canonical path it copies; a copy is judged once, by its canonical path. Add enough non-TOPICS paths that no single tree supplies more than a quarter of the set. Find the variation source by judging each path three times with a frozen state and three times with a fresh description. Report AUC on the scan-or-expand decision, with confidence intervals, under the old and new labels. Committed beside the fragment: labelled-paths-v2.json, which does not replace the earlier files.

Node 2: graph context, after node 1 and §15 land. Add the graph neighbourhood to each judge's state, read through the graph client. For a path: its parent's and children's judgments, its canonical copy and that copy's judgment, and the CodeFiles and Documents under it with their facets and data references. For a code file: its directory's judgment and the DataReferences and IDS its chunks link. For a wiki page: the types of its link targets and documents, and its inbound link count. Measure AUC with and without that context on node 1's labels.

Done when node 1's fragment gives the relabelled set's composition, the variation source with repeat-call evidence, and the scan-or-expand AUC under both labellings. Lead, 2026-10-08: the knowledge front. When a facility is scanned for the first time, forward information is not yet in the graph: child paths, files under a directory, their judgments, copies and wiki links appear only as the scan advances. Every method this section adds must work for a new facility's first discovery, not only for a facility the graph already knows. Concretely:

  • Unknown is not empty. Each neighbourhood field in a judge's state records whether that neighbourhood has been observed. For example, children not yet listed is distinct from no children, and files not yet scanned is distinct from no code files. The question text tells the judge that an unobserved field is no evidence either way. A missing property reads as nothing in Cypher, so an unset field must never reach the state as zero or as an empty list.
  • The category gate stands without the graph. The path-stage decision (category plus children-worth-listing) uses only what the scanner sees at that directory. Graph context may raise confidence once it exists, but no gate depends on it.
  • Measure a cold-start arm. Node 2 reports AUC on node 1's labels with the graph context stripped to what a first scan holds at each path, beside the full-context arm. It also runs one bounded first-discovery pass, on a facility subtree with no FacilityPaths yet or a scratch facility id, to show the gates admit and expand from an empty graph.
  • Roll-ups name their evidence. A path facet value rolled up from files records how many judged files it rests on, and is absent rather than zero before any file under it is judged.
