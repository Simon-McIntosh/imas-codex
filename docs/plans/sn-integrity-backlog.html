Plan · standard names · S18, ahead of the WEST release

The integrity backlog, fixed before the release

From August to late September the standard-name work was mostly about the machinery that manages names: lifecycle axes, provenance, scalar mirrors, deletion guards and repair receipts. Sixteen plans carried that work, and between them they held 53 open followups while the WEST batch waited. The guards that mattered most landed. What remains is gathered here, one row per item. The lead ruled on 2026-10-12 that it is worked before the WEST release, not after it.

§1 — Why it comes before the release

The portfolio review of 2026-10-12 first parked this residue behind the WEST release, to keep a one-week release in reach. The lead reversed that the same day. Several rows sit on the path the release itself takes. WEST's name repairs and the grouping plan's synonym rulings go through sn edit and sn supersede. The fold guard reads history where it means the present, and when this plan was written four sanctioned paths refused an orphaned identity's state (§4, §2); three remain (§7). The restore command's refusal of a re-armed origin is now pinned (§9), and 412 live names (334 when recorded) are labelled scaffolding while carrying reviewed documentation (§2). A catalog built on machinery with those holes would be released on trust rather than on evidence.

Every row below was read against its source plan and kept only if it described a defect or decision that still existed. Each row names the plan and followup it came from, so the full measurement is one click away in that plan's frozen text. The measurements are weeks old, and adjacent work has fixed recorded defects before, so no row is dispatched as written: §6 re-confirms every row on the live graph first.

A row needed by the WEST release has already moved to sn-west-prototype-release and is not repeated here: the export gate chain, the two recovered names, the two vocabulary admissions, the half-width base, rehearsal accounting and roster identity.

§35 — Where the lost DD sources went

On 2026-10-18, 264 of 2,971 live standard names had no PRODUCED_NAME edge from any DD source. This section is the census; §36 to §38 are the writers, the audit and the repair.

Not every sourceless name is a dropped edge. When a refine or a fold moves a name's sources to its successor, the exhausted predecessor is left sourceless by design. But §31's orphan lifecycle (supersede_exhausted_orphan in graph_ops.py) retires on name_stage = exhausted, non-derived and no incoming PRODUCED_NAME, with no successor clause. So an exhausted name whose sources were dropped rather than moved is retired too, and its quantity leaves the catalog unbound. The census must separate five populations. They are tested in this order, and a name takes the first that applies, so every sourceless live name falls in exactly one. A name's recorded sources are the ones it recorded itself (its own path, source_id or resolution id), compared by source identity.

  1. Derived parents: origin = derived with children. They legitimately have no source.
  2. Never bound: the name recorded no source, so no writer ever gave it one.
  3. Dropped edges: at least one recorded source is held by no live name, whatever its other sources. A partial transfer lands here, naming which sources moved and which did not. Exhausted names here must be repaired before §31's lifecycle may retire them.
  4. Held by an unchained name: every recorded source is held by a live name, and at least one holder is not in the name's own REFINED_FROM, supersede or fold chain. The source is still in the catalog. Whether the holder carries the same quantity is a semantic question §38 settles before the name is retired or restored, and until then §31's lifecycle does not retire it.
  5. Held in chain: every recorded source is held by a live name in the name's own chain, in either direction. An exhausted, non-derived name here is an orphan awaiting retirement. The usual case is a successor that took the sources, and an abandoned refine attempt whose live ancestor kept them is the same case. A name here that is not exhausted is a refine that never took its sources, and §38 repairs it like a dropped edge.

For each dropped or never-bound name, trace which writer dropped or never wrote the edge: REFINED_FROM chains, supersede and fold chains, renames, harmonize revisions. Read each identity-changing writer for whether it moves or copies PRODUCED_NAME.
