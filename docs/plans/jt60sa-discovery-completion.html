§25 — Code triage decides by diagnostic relevance through Jev

Scope rule (lead, 2026-10-06): the code pipeline exists to ingest code that loads data from diagnostics or processes diagnostic signals, together with the machine and diagnostic description and the IMAS mapping that this work needs. The lead widened it the same day. In scope are sensor and probe positions, lines of sight, coil, vessel and limiter geometry, channel maps, calibration constants and signal conventions, and code that maps facility data to or from IMAS. Simulation codes are out of scope. The rule is global: every facility uses it.

Why the current gates fail, measured 2026-10-06. Code discovery is gated three times against absolute LLM scores: path scan at --min-score (default 0.90), file triage at 0.75, and ingest at the same --min-score. Triage sees only file names, and the content scorer's rubric puts core facility code at 0.65–0.85, so the gates sit above the scale the scorer produces. At JT-60SA, 1,523 of 1,657 files were skipped, including 7 of the 8 files the SELENE sensor-order receipt is built on. The scale also differs by facility: ingested TCV files have a median of 0.85, while the SELENE Grad-Shafranov solver tops JT-60SA at 0.75. Against 111 hand-labelled files from JT-60SA, TCV and JET, the old content score separates in-scope code at AUC 0.63, and at 0.90 it finds 14% of it. Jev's typed judgments reach AUC 0.96 when given the file's content, and 0.87 from names alone.
