The naming rules live in one versioned file that the pipeline loads

Lead ruling, 2026-11-24: seven naming rules are adopted as the standard. They extend the 2026-11-18/19 ruling that a name identifies and its definition specifies. They were written after a re-reading of the 33 held-out incumbents counted as failures (docs/evidence/fragments/sn-case-file-generation/incumbent-failures-under-codified-rules.json). That re-reading found the two earlier readings disagreeing on 21 of the 33 names, because the rules left the call open.

  1. Identity. A word that changes the number a quantity takes belongs in the name. Examples are energy versus number, ions versus neutrals, equivalent electrons versus particles, apparent versus thermodynamic temperature, and the quantity a rate or time belongs to.
  2. Specification. Where and how a quantity is evaluated belongs in the definition. Examples are a location such as the midplane, a reconstruction context, a component sub-unit and the species pair of a collisionality. The exception is when two catalog names would otherwise read the same; then the name carries the least that separates them.
  3. Owner. A centre, centroid, axis or similar locus names its owner unless the term is unique in the catalog.
  4. Parent. A generic parent name is right when it names the general quantity its children specialise.
  5. Settled terms. A term with a settled meaning is used only with that meaning. Neutron flux counts neutrons; parity is not a sign; a coil's radius is not an arc's curvature radius.
  6. Transfer. A transfer between two populations names both donor and recipient. The grammar has no form for this today, so such names go to the grammar work rather than to repair.
  7. One name. One quantity has one name. A repair that collides with an existing name marks a duplicate. Which name is retired is put to the lead.

The lead also ruled that the rules are updated as edge cases arise. Each case is put to the lead and recorded with its ruling.

Done when:

  • One versioned file in the repository states the seven rules. Each rule carries at least one worked example drawn from the 33 incumbents, and the file has a log of edge-case rulings with date and example.
  • The name-generation and name-review prompts render the rules from that file.
  • A test fails when a rule is removed from the file and a prompt still renders. Removing a rule in a copy makes it fail, and that run's log is committed at docs/evidence/fragments/names-follow-the-rules/rules-negative-control.log.
  • The version of the rules file is recorded with every name the pipeline writes or reviews from then on.
  • The whole tests/standard_names directory adds no failure at head against base, run as one job on all_debug.

Every live name is read against the rules

Lead ruling, 2026-11-24: names are measured against the rules and only those that break one are repaired; the catalog is not regenerated. Regeneration did not beat the incumbent in the second benchmark round (60 against 54 of 87, inside the interval), and rewriting sound names broke some.

Done when:

  • Every live standard name is read against the rules file at one recorded version, and each result records that version. A ruling made during the read raises the version. Every name whose result rests on the changed rule is then read again at the new version before §3 starts. Each name gets one of three results:
    • it conforms;
    • it breaks a named rule, with the words that break it and the source or definition words that show it;
    • it is an edge case the rules do not settle.
  • The counts by result and by rule are committed at docs/evidence/fragments/names-follow-the-rules/catalog-reading.html and .json.
  • Two controls are drawn from the re-reading of the 33 incumbents. The reader flags at least 15 of the 17 names read there as real defects. It flags at most 2 of the 13 read there as not defects.
  • The coordinating session reads by hand a sample of 100 names drawn by a recorded seed, before seeing the reader's result for them. The agreement is reported with a 95 % interval.
  • Edge cases are listed for the lead. Each ruling the lead gives is added to the rules file's log.
  • Spend is stated beside a ceiling of USD 10.
  • No graph write.

Names that break a rule are repaired, and the rest are left alone

Repairs go through the pipeline's own edit path. A rename carries its documentation links with it.

Done when:

  • Each name §2 reads as breaking a rule is repaired once, changing only what its rule names. Edge cases are not repaired until the lead has ruled and §2 has re-read them. A name that breaks the transfer rule is listed for the grammar section of sn-case-file-generation rather than repaired.
  • A repair whose new name collides with an existing name is not applied. It is listed as a duplicate, with the name proposed to keep, for the lead to rule on which is retired.
  • After the repairs:
    • every documentation link to a renamed name resolves to its new name;
    • a renamed name's own documentation is regenerated only where its text depends on the old name.
  • The coordinating session adjudicates a seeded sample of the repaired names blind, beside their incumbents, before the key is opened.
  • The repairs are accepted only if both hold:
    • no name the sample reads as sound before is read as wrong after;
    • at least half of the sampled names that break a rule are right after.
  • A name §2 found conforming is unchanged, compared by digest before and after.
  • A verified graph checkpoint is taken before the first write, and no other graph writer runs at the same time.
  • Spend is stated beside a ceiling of USD 90.
  • The evidence is committed at docs/evidence/fragments/names-follow-the-rules/repairs.html and .json.
