§1 — One misplaced directory disables read_plan for the whole project

Every read_plan call in this project currently fails, whatever plan it asks for, with: 

research/standard-names/01-current-state-standard-names.html: typed resource path
must be <root>/<slug>.html or <root>/archive/<slug>.html

The named file is not the caller's plan and has nothing to do with it. Resource resolution walks the whole documentation tree and raises on the first path that violates the contract, so a layout fault in one research directory presents as a total read outage. Discovered 2026-08-25 during sprint S8 execution, independently hit by a second concurrent session the same morning.

The blast radius is narrower than the symptom suggests, and that matters for how this is fixed. edit_plan and roadmap are unaffected — only the typed-resource read path raises. Both sessions worked around it by taking expected_version from each plan's own plan-version meta tag, which is why S8 continued to land work throughout. This is a real defect with a real workaround, not an emergency.

§2 — What the contract actually is

Authority is reckon/resources.py: TYPE_ROOTS declares six typed roots — plans, research, evidence, sprints, milestones, blockers — and _path_context raises ResourceCollision when a path whose first segment is one of those roots is not exactly <root>/<slug>.html or <root>/archive/<slug>.html.

A guessed version of this rule over-counts by 2.5×, so measure with the real one. An initial sweep against an invented root list reported 87 violations across six directories. The true figure is 34, all in one directory. The difference is that archive is not a typed root, so docs/archive/** is never checked at all — and sprints/*.html is two segments deep, which is legal. Neither was a defect.

§3 — The repair, and the one thing that must not be lost

Move all 34 to docs/research/<slug>.html with git mv, then rewrite the 106 references. 31 of the 34 carry plan-informs edges, so the graph relationships those files feed are the asset at risk: a move that silently drops an edge trades a read outage for missing provenance, which is strictly worse because it is invisible. The edge count before and after is therefore the gate, not the fact that the files moved.

Archived referrers under docs/archive/ are rewritten too. They are historical documents, but a dead link in a historical document is still a dead link, and the same pass fixes them at no extra cost.

§4 — The guard, without which this returns

A layout rule that only fails at read time, deep inside an unrelated call, is a rule with no check — which is how 34 files accumulated in one directory without anyone noticing. Add a test that walks the documentation tree, applies reckon's own TYPE_ROOTS rather than a local copy of it, and fails closed listing every offending path. Importing the authority instead of restating it is the point: a second transcription of the root list is exactly the drift that produced the 87-versus-34 discrepancy above.

§ Decisions

How should the 34 nested research documents be brought back under the contract?

Flatten. The basenames are already collision-free against docs/research/, so flattening preserves every slug identity and every plan-informs edge while needing no renaming scheme. Stripping reckon-type would silence the error by deleting 31 documents' graph identity, trading a visible outage for invisible loss. Widening the contract is a change to shared tooling to accommodate one repository's layout, and the contract is doing useful work everywhere else.

§ Followups
