§1 — How this was found, and why it is not a permissions problem

A schema migration on 2026-08-25 unified the foreign-key and axis spellings and migrated 60,230 nodes. Afterwards, 21 long-lived stdio MCP servers were still running, every one started between 19 and 24 August, each holding the pre-rename schema against a post-rename graph. None had any way to know.

The first fix proposed was to make those servers read-only. That was wrong twice over. This repository's own guidance makes the write tools the primary interface — update_facility_config() is mandated over direct file editing, add_to_graph() is the documented persistence path, repl() is the documented route for raw Cypher — and its serve-mode table lists a bare serve as the development configuration. More importantly, read-only would have removed the write half of the drift and left the read half untouched: a stale server returning a clean empty result is not a lesser problem, it is exactly the silent-zero defect sn-graph-identity-convention was written to eliminate.

§2 — The gap is in an existing pattern, not a missing feature

This graph already records the version of every external authority it was built against. There are 35 DDVersion nodes and 110 ISNGrammarVersion nodes, and code consults them rather than trusting that whoever is connected loaded the right thing.

The LinkML schema is the one authority with no such node and no digest anywhere. imas_codex/graph/schema_context_data.py is 2,303 lines generated deterministically from the schema sources and carries neither a version nor a hash. So the thing most likely to drift underneath a running process is the only thing the graph cannot state a version for.

That reframes the work. It is not new machinery justified on its own; it is the missing third member of a set of two that already exist and already work.

§3 — Digest the source, never the contents

This is the design decision the rest depends on, and getting it backwards produces something worse than nothing. The digest must cover the LinkML source the server loaded against the LinkML source the graph was built from.

A digest over graph contents fails in both directions at once: it churns on every ordinary write, so it would be ignored within a day, and it would not have caught this break at all, because what drifted was slot and enum spellings in the schema while the data underneath was migrated to match. A content hash would have reported agreement throughout.

§4 — Fail closed, because the alternatives rely on memory

Three shapes were considered. A migration that announces that attached servers must reconnect is a rule someone has to carry, and the incident that produced this plan is what happens when a rule is carried by 21 processes and no one. A session-start check is better but advisory. A server that refuses to serve when its loaded schema digest differs from the one the graph records needs nobody to remember anything.

That is the same shape as every repair that held during the migration itself: the property detector, the shrink-tolerant adjudication inventory, and the guidance test that reads retired spellings from LinkML at runtime. Each replaced a rule a person carries with an authority the code consults. This applies that pattern to process lifetime.

§5 — What done looks like

A schema digest is written as a node when the schema is applied, in the same shape as DDVersion, so nothing novel needs justifying. A server compares its loaded digest against that node on connect and refuses rather than serving a mismatch. Done is demonstrated the way the rest of this family is: a deliberately mismatched digest must produce a refusal in a test, and a matching one must serve — a check that only ever passes proves nothing.
