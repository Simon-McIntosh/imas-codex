§1 — Under-specified, not false: where the threshold actually lives

This section was twice wrong before it was right, and both corrections are kept because the second one matters more than the first.

First reading, relayed and unverified: “Gate A, description-embedding coverage, failed at export and was downgraded to advisory.” Second reading, over-corrected: that the premise was false, because GATE_A = "graph_tests" and _run_gate_a() merely shells out to pytest -m "graph or corpus_health" with no threshold of its own, and no 0.95 exists in imas_codex/standard_names/.

Both of those findings are true and together they locate the threshold. Gate A owns no threshold precisely because it is a suite runner — so every bar it enforces lives in the tests it selects, and both of these carry pytestmark = pytest.mark.graph:

  • tests/graph/test_sn_graph.py:159 — assert coverage >= 0.95, counting descriptions on accepted names. This is the 0.95; it is not an embedding bar and must never be substituted for one.
  • tests/graph/test_data_quality.py:210 — assert corrupted == 0 for nodes carrying embedded_at with no embedding vector. This is the assertion that actually failed, reproduced at 26, and it is an exact zero rather than a percentage.

So the sentence that reached this session compressed a real chain rather than inventing one. The lesson is not that it was fabricated but that a grep over production source cannot find a bar enforced by a test suite — the instrument was pointed at the wrong tree.

A gate that fails on work-in-flight will be downgraded every time it runs, which is how a real assertion becomes a permanent advisory.

§2 — Establish the number before arguing about the threshold

The downgrade is recorded; the shortfall is not. Before any decision:

  • How many accepted identities lack a description embedding, over the release set and over the whole accepted corpus, with the schema sanity count that proves the figure is real rather than a property-name miss.
  • Do they lack the embedding, or the description? A missing embedding on a real description is a pipeline gap fixable by re-embedding at no provider cost. A missing description is a content gap needing generation and review. These have different costs and different owners and must not be counted together.
  • What did Gate A actually assert, and what threshold did it fail against? A gate whose measure is not written down cannot be honestly relaxed or honestly enforced.
  • Are any of them in the WEST release set? A coverage shortfall entirely outside the shipped identities is a different problem from one inside it.

Related and worth measuring in the same pass: the 296 dangling links pruned at export. Pruning at export means the shipped artifact is clean while the graph is not, so those links are still wrong wherever they came from.

§3 — The three honest outcomes

Only three endings are legitimate, and all of them are better than an unexamined advisory:

  • Fix the coverage and restore the gate to enforcing. Correct if the shortfall is mostly missing embeddings on real descriptions, since re-embedding is deterministic and free.
  • Relax the gate deliberately, with the new threshold written down and the reason recorded, so a future reader knows the release shipped under a chosen bar rather than an abandoned one.
  • Withhold the affected identities from the release set with named reasons, which is the policy bar this programme already applies to 45 other withheld rows.

§ Decisions

Should the coverage assertion be scoped to accepted identities rather than all StandardName nodes?

Scope it to accepted identities and keep the exact zero, locked by the lead on the measured shortfall. The gate's assertion was never the problem: exact zero is the right bar for a shipped catalog, and a percentage would trade a crisp claim for a number someone has to defend. The cohort was the problem. Measured, every one of Gate A's 26 failures is a description gap on a NON-accepted row, so the gate was failing a release on work still in flight, and it will keep failing continuously as new drafts arrive - which is what made it expedient to downgrade rather than a bar anyone chose. Meanwhile the shipped population is already clean: WEST export survivors 363/363 and the current WEST cohort 385/385 with zero gaps of either kind, and zero affected identities inside the 369-name survivor set. The one real accepted embedding gap was closed for nothing, deterministically and at USD 0.000000, taking the accepted corpus to 2302/2302. So scoping to accepted makes the gate pass honestly rather than by relaxation, and restores it to enforcing against the population a release actually ships. Clearing all 26 was rejected because it pays generation and review cost so that drafted work can satisfy a release gate, and the next draft re-fails it. Withholding was rejected as close to a no-op: the measurement shows nothing affected is in the survivor set already.

§ Followups

Measure the coverage shortfall, split embedding gaps from description gaps, then decide the gate

FIRST establish what actually failed and under which name, because Gate A is graph_tests and asserts nothing about embeddings. Then measure the coverage shortfall over the release set and the whole accepted corpus with sanity counts proving each figure, separate missing embeddings on real descriptions (deterministic and free to fix) from missing descriptions (generation plus review), and count how many affected identities are inside the WEST set. Use radial_coordinate_of_reflector as the entry case. Invent no threshold: if none was ever set, say so and propose one explicitly.

The signed-repair collateral snapshot costs more than the repairs it protects

Pointer to a shared-module performance defect, surfaced while applying an unrelated repair and deliberately NOT fixed inside that repair's fence. signed_manifest._collateral_snapshot matches every node carrying any tracked label and every relationship of any tracked type, returns full properties() maps for each, ships them over bolt, and SHA-256s them client-side — then repeats for the after-snapshot. Against the current graph that is tens of thousands of rows with full property payloads, twice per apply, and it drove a twelve-row repair past a five-minute boundary twice before completing.

Two shapes of fix are visible and both need measuring rather than assuming: digest server-side in Cypher so full property maps never cross the wire, or narrow the snapshot to the dimensions an operation actually owns. The second has precedent worth reading — the relocation-retirement apply proved collateral on external non-cohort HAS_PARENT alone, 1,411 rows, and its plan argued that a digest covering an axis another session is writing measures their work rather than the repair. A graph-wide snapshot is therefore not just slow but arguably measuring the wrong thing.

This is shared repair-authority machinery every future signed repair depends on, so it wants its own scope, a before/after timing measurement, and its guard tests intact. Owner is a lead decision: extend this plan, or open one for the repair-authority operator.

The gate's premise was wrong in a way worth recording, because it inverts what the plan set out to do. The plan opened on a failing coverage gate and asked whether to fix the coverage, relax the bar, or withhold identities. All three assumed the gate was measuring what it claimed. It was not.

GATE_A = "graph_tests" shells out to the graph suite, and the assertion that failed reads "Embeddings were written then lost — possible data corruption". But all 26 failing rows carry embedded_at with neither a description nor an embedding, which is not written-then-lost — nothing ever attempted to embed them. The cause is run_embedding_preflight stamping every candidate it considered rather than every vector it wrote. So the gate was never detecting corruption; it was detecting a producer bug, and every one of its failures was a name still in flight (14 superseded, 8 drafted, 4 pending, 0 accepted).

That is why the disposition is a rescope rather than a repair or a relaxation, and why the producer fix matters more than the rescope: without it the stamping would keep minting rows that look embedded and are not, now below a gate that no longer looks at them.
