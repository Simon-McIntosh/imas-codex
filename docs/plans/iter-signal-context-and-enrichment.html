Plan · ITER plant data

ITER plant signals carry context and are enriched by group

The archive lists about a million plant variables and describes almost none of them. This plan gives each signal context from ITER's own records, enriches signals a component and a field pattern at a time, and ends with an agent finding a plant signal by description and reading it.

§1 — Where this starts

The scanner, loader, plotting and name parser landed under the plan codac-uda-signals. Its full-archive census counted 988,145 variables on the slow archive and 6,861 on the fast one, with none in common. The archive's type metadata gives the same description, "Signal value", for every variable measured, and refuses metadata altogether for about one variable in eight. A second archive interface returns a label for 70 of a 200-variable sample and a unit for some of them. The first 200 signals catalogued are five controllers that each expose the same forty fields.

A test question to the ITER document assistant about three of those names matched one component conditionally, one probably and one not at all, and pointed to the documents that hold the meaning: a per-system signal list, a per-system data file from which control-system variables are generated, a control functional specification, and the plant breakdown structure. A build worker cannot reach any of them: the document system redirects an unauthenticated request to a login page.

The lead has decided four things. ICP and IDM content may be curated into the graph as metadata and links. Every node and link so created references the ITER facility and is covered by the facility-scoped protected backup, and none of it enters the repository. Work that reads that content runs on the locally served model inside ITER, once a benchmark shows that lane is capable. Signals are enriched by component and by field pattern, not one at a time.

The existing signals discovery pipeline already enriches a source once and fills a template for each member, and already exports and pushes graph archives per facility. This plan uses both.

§2 — Every configured model seat names its model's latest version

Delivers. Each model seat the project configuration declares names the latest available version of the model it intends, or the landing record states why a seat stays on an earlier one. Seats that route to the locally served model name the model that lane serves today.

Done when. The landing record lists every declared seat with the model it named before, the latest version found and where that was established, and the model it names after; the configuration tests pass with no added failure against the base revision; and each changed seat answers one live request. Negative control: a seat naming a model its route does not serve fails its live request and is reported, not silently left.

§3 — The local lane is shown capable of this plan's build work

Delivers. A measured comparison of the locally served build lane against the external lane that built the catalogue plan, on work that contains no ICP or IDM content, so the lead can decide whether the local lane builds the sections that read such content.

Done when. The landing record gives, for the local lane, the independent review scores of at least two build nodes of this project completed since the model-seat section landed, one of them section 2 of this plan, beside the mean and range of the review scores of the external lane's nodes on the catalogue plan; the number of resumes each needed; and whether each passed its gate. The lead's acceptance or refusal of the local lane for ICP-reading sections is recorded in this plan before section 4 is dispatched. Negative control: a local-lane node that fails its gate is counted in the comparison, not dropped from it.

§4 — One plant system's signals carry context from ICP and IDM

Delivers. For one pilot plant system, the magnet cold test bench, the graph holds its plant breakdown structure nodes, the rows of its signal list and data file, and references to its functional specification, each as an ITER-facility node, and each catalogued signal of that system is linked to the rows and component it corresponds to. A link is marked as exact when the source names the archive variable, as derived when it was joined through a component number, and as absent when no source row was found. The content reaches the graph from ICP and IDM without entering the repository or a prompt to an external provider.

Done when. The landing record gives the number of source rows imported per source, the number of the pilot system's signals with an exact link, a derived link and no link, and twenty links of each present kind checked by hand against the source; every imported node and link reaches the ITER facility node; a second import adds none; and a search of the tracked tree for the imported identifiers and a sample of imported titles finds none. Graph-marked statements pass. Negative control: a signal whose component number appears in no source row receives no link, and a row that names a different system links to no pilot signal.

§5 — Catalogued signals are grouped by component and by field pattern

Delivers. Every catalogued archive signal belongs to a component group, and components that expose the same set of fields share a field pattern. The grouping is derived from the parsed variable names and the archive metadata, stored in the graph under the ITER facility, and recomputed without duplicates when the catalogue grows.

Done when. The landing record gives the number of signals, component groups and field patterns; the distribution of group size; the share of signals whose group has a single member; and the twenty largest patterns with their field counts, using invented names in tracked files. The number of group descriptions and pattern descriptions that enrichment would need is stated beside the number of signals. A second run adds no groups. Negative control: a signal whose name does not parse is placed in an explicit ungrouped state and is counted, never attached to another component's group.

§6 — The pilot system's signals are enriched by group and the result is measured

Delivers. Each component of the pilot system has one description written from its linked context, each field pattern has one description of what its fields mean, and every member signal carries a description composed from the two, with its unit and its physics or engineering classification. The language model that writes them is the locally served one. A signal with no linked context is described from its name and metadata alone and is marked as such.

Done when. The landing record gives the number of component descriptions, pattern descriptions and member descriptions written and the number of language-model calls and their cost; for forty member signals chosen before the run, a hand comparison against the functional specification with the count that are right, partly right and wrong; the same count for the subset with no linked context; and the projected call count and cost for the whole catalogue from the grouping in section 5. The projection is in this plan and accepted by the lead before section 7 is dispatched. Negative control: a member of a group whose component description failed is reported in a failed state and carries no composed description.

§7 — Every catalogued signal is enriched, checked and embedded

Delivers. The whole catalogue has passed group enrichment and the discovery pipeline's check and embedding stages, so the existing signal search returns ITER plant signals beside other facilities' signals. Signals of systems with no imported context are enriched from name and metadata and marked as such, ready to be re-enriched when their context arrives.

Done when. The landing record gives the number of signals in each pipeline state with the reason for every failure class, the actual call count and cost beside the accepted projection, and, for twenty described quantities written to a private file before the run with its digest recorded, the rank at which search returns the expected signal. A search for a quantity of another facility still returns that facility's signal. The run executed on rigel. Negative control: a signal whose enrichment failed is reported in a failed state and is not counted as enriched.

§8 — An agent finds an ITER plant signal and reads it through the server

Delivers. Through the project's server, a search for a described quantity returns an ITER plant signal with its component and context links, and a facility read loads it by identity over a bounded window. The read returns metadata, basic statistics and a reference to an internal file holding the arrays, with arrays inlined only under a strict byte limit. It accepts no host or endpoint from the caller, and is absent in the data-dictionary-only mode. The server gains at most one tool.

Done when. Through a running server, a search for a described quantity returns a pilot-system signal and the read returns its statistics for a two-second window, both in the landing record; the tool list in data-dictionary-only mode does not contain the read; a response never exceeds the transport's bounded size; and the landing record gives the server's tool count before and after. Negative control: a call supplying an endpoint, and a call with an unbounded window, are each refused.

§9 — ITER graph content is in a protected facility backup and nowhere public

Delivers. Every node and link this work and the catalogue plan created for ITER reaches the ITER facility node, a facility-scoped archive of them is stored as a private registry package, and no public archive or repository file carries them.

Done when. The landing record gives the number of ITER-derived nodes by label, the number that do not reach the ITER facility node, which is zero, and the registry package's name, visibility and digest; an archive built without the facility filter is shown to contain none of the ITER-derived labels' ITER rows; and the search of the tracked tree from section 4 still finds nothing. No graph writer is running when the archive is taken. Negative control: a node created for ITER without a facility link is found by the count and reported.
