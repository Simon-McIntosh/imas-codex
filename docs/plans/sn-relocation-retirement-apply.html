§1 — Built, proved, and not yet applied

This is the only item in the graph-wide residual with no external dependency. Everything needed already exists in main:

  • The diagnosis — the parser is lossless and never proposes the relocated tip. _rewire_has_parent_off_superseded walks each edge through a six-hop REFINED_FROM chain onto a tip the current derivation does not authorize.
  • The prevention — commit b926b8dd guards the rewire; an unauthorized successor tip gets 0 rewires while a legitimate unary_prefix tip still rewires once. Migration 6 proved the guard survives the structural-edge operator moving onto the shared envelope.
  • The retirement program — commit a495fb07, retire_unauthorized_has_parent_relocations, a closed program under build_repair_authority and apply_signed_manifest.

What remains is one production apply. The measured class is 78 non-self MERGE pairs with 0 of 78 tips authorized by current derive_edges output, alongside a live census of 52 stale qualifier pairs.

§2 — It is a release barrier, not only a hygiene item

Two of the 78 are the pair that aborts the WEST catalog export on a hierarchy cycle: spectral_signal_to_noise_ratio_of_spectrometer_channel → logarithm_of_spectral_signal_to_noise_ratio_of_spectrometer_channel carrying operator_kind: qualifier. The export was made to complete by isolating strongly-connected components and withholding their members, so the release is no longer blocked outright — but those identities are withheld rather than repaired, and the underlying edge is still wrong.

A governed reversibility receipt records that exact edge as already removed once, and it is live again. That is what makes this a producer story rather than a data story, and it is why prevention landed before any retirement was attempted: a second deletion without the guard would have been undone the same way the first was. With the guard in place, retirement is now durable.

§3 — What the apply must do that the proof did not

The program was proved on a disposable graph and deliberately never touched production. The apply owes three things the proof could not provide:

  • Fresh authority derived inside the applying invocation. The 78-row figure is a projection over the prior read-only census and its retained per-row parent maps, and the node's own manifest says so. It is not a production preview. This programme has been overtaken three times by cohorts fixed before an intervening authorized transaction, and the rule that fixed it is to build and hash the manifest in the same invocation that applies it.
  • Receipts recovered by run_id and manifest digest. Never by an operation-name query. A committed dual-bound transaction once read as a clean refusal because the recovery probe looked up the wrong key.
  • A collateral proof that does not overlap concurrent writes. If another session is writing an axis, the digest covering that axis is measuring their work, not this repair. Narrow to a dimension this node owns.

Refusals are outcomes, not obstacles. A row the program declines — because current derivation still authorizes its incumbent tip, or because removal would leave a derivable parent path absent — is recorded and left alone.

§ Decisions

Apply to the whole unauthorized class, or only the two export-blocking rows?

The whole class. The two export-blocking rows are not special — they are the two members of the class that happened to form a cycle an exporter noticed. Repairing only those leaves 76 edges the current derivation does not authorize, each of which can surface later as another cycle, another withheld identity, or another wrong parent in a released catalog. The guard makes retirement durable, and the same signed apply costs the same whether it carries 2 rows or 78.
