Plan · standard names · S19

Select, don't generate

Wherever the pipeline asks a model to write one of a known set of things, a judgment can choose instead. A standard name is spelled from a closed vocabulary. A link points at a name that exists. A family has one best template. Choosing is cheaper, cannot invent a token, and gives the same answer for the same concept. Each pattern here is a prototype that earns a node only by its numbers.

§1 — The patterns, and what is owned elsewhere

The patterns come from the TypeSafe cookbooks (hierarchical classification, rerank, entity alignment, composite scoring, feature discovery) and the study of discovery's judges (run jev-harness-study). Three Jev uses are owned by other plans and are not repeated here:

  • review, owned by sn-review-through-jev;
  • physics-domain assignment of standard names and near-duplicate alignment, owned by sn-catalog-grouping §3 and §4;
  • the DD-path domain classifier that names inherit from (today gpt-5.5 in imas_codex/graph/dd_domain_classifier.py), owned by discovery-judgments-through-jev §6.

Every prototype here measures through sn-judgment-evaluation and is built unwired.

§2 — Grammar segments chosen from the vocabulary

Given a DD path, its documentation and its enriched description, Jev answers one Choice per grammar slot over that slot's closed ISN vocabulary: physical base, subject, component, operator, locus and process, plus "none" where a slot is empty. Large vocabularies are walked as a tree, with a beam of three and the geometric mean of the choices as the path score, which is the hierarchical-classification cookbook's method. Code renders the name through the ISN renderer. So the result can never contain a token the grammar lacks, and the same concept always yields the same tokens.

Composition is cheap today (USD 21 of all-time spend), so the case is consistency, not cost. There are two possible deployments:

  • a cross-check, where a composed name whose segments disagree with Jev's selection is flagged to review;
  • a candidate generator, used beside the composer.

Done when: on golden A's positives and the human-edit target spellings, the fragment reports exact-name match, per-slot accuracy, and agreement across the members of each species family (whether all seventeen boundary densities receive the same base, operator and locus). The composer's figures on the same sources sit beside them, along with cost per name. The recommendation follows from those numbers by a rule fixed here, before the run:

  • Cross-check if flagging composer-against-Jev disagreement separates golden A's negatives from its positives with AUC at or above 0.70, and the interval's lower bound is above 0.60.
  • Generator if Jev's exact-name match on the positives is within 0.02 of the composer's, and its family agreement is higher.
  • Both if both conditions hold; neither if neither does.

§3 — Links that point where their label says

Link labels. A Noul per name: link asks whether the link text describes the target's description. The 2026-10-12 smoke read found flux_surface_averaged_beryllium_density_at_plasma_boundary linking "beryllium density at the plasma boundary" to itself rather than to the unaveraged quantity. Deterministic code catches self-links. The judgment catches a link to the wrong neighbour.

Done when: on a coordinator-labelled sample of at least 150 links, including every self-link found, link-label AUC is reported with its interval.

§4 — Prompts that see the right neighbours

The compose and documentation prompts carry a comparator block of nearby names and a set of scored exemplars, both selected by embedding similarity. Rerank each with rerank_pool from imas_codex/discovery/base/judgment.py: one Score per candidate for its relevance to the item, with the embedding order kept on any failure. A rerank can never do worse than the order it replaces, so it is exempt from the deployment rule and adopted on a positive measurement.

Done when: labelled-only nDCG@10 for the comparator block is reported before and after on a coordinator-labelled set of 30 items. A held-out batch run both ways reports first-pass review acceptance under the same reviewer. A test shows the embedding order survives a failed rerank.

§5 — Read the riskiest entries first

A person's reading time is the scarcest resource in the release: the WEST polish pass, then the physicist's review. Order both by a Jev risk composite of the named checks most likely to have failed, so the first hour of reading finds the most defects.

Done when: on goldens A and C, the recall of known defects in the first 10%, 25% and 50% of the risk order is reported. Random order and the incumbent's review score order are reported beside it.

§6 — Acceptance learned from judgments

The feature-discovery pattern: treat Jev's answers (check probabilities and dimension distributions) as features, and fit a small, inspectable model (logistic regression first) on golden A's calibration split to predict acceptance. A fitted weighting can find combinations a hand-set composite misses. It is adopted only if it beats the hand-set composite on the validation split by more than its interval, and its weights are published beside it.

Done when: the validation AUC of the learned model and of the hand-set composite is reported with intervals, with the fitted weights. The section closes with an adopt-or-not verdict and its reason.

§7 — The family template chosen, not defaulted

When sn harmonize rewrites a family from its anchor, the anchor sets every member's template, so a weak anchor spreads its weaknesses. Today select_anchor in imas_codex/standard_names/harmonize.py picks it by heuristic. Jev asks one Score per member: how well would this member's documentation serve as the template for the whole family? It reads the member's documentation, the family's pattern and the house-style template. The highest-scoring member is the candidate anchor.

Done when: on ten families, each is harmonized twice in a scratch graph, once from the heuristic anchor and once from the Jev anchor. The fragment reports the lint findings after each and the documentation review scores of the members, and the Jev anchor is adopted only if its families show fewer findings with no lower scores.
