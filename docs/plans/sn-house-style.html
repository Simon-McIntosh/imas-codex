Plan · standard names · S18

One definition, one notation

The catalog defines the flux-surface average in five notations, one of them wrong, and opens its WEST entries in four styles. Each entry passed review on its own, so consistency has to be authored once and then enforced. Choosing the definitions is the coordinator's and the lead's work; applying them is the pipeline's.

§1 — Why a house style, and why it is authored

The measurements are in the consistency census. In short: 72 entries re-derive the flux-surface average, 57 the volume average and 35 the normalized toroidal-flux coordinate. The 80 boundary-locus names gloss "plasma boundary" eight different ways, and 24 of them equate it with the separatrix, which is wrong for a limited plasma. The poloidal field is written three ways. None of this is visible to per-name review, which is why WEST scores a median 0.94 on documentation while reading as inconsistent.

An LLM asked to "be consistent" with a handful of siblings will drift again on the next batch. What converges is a written authority: one entry per shared concept, stating its definition, its one equation, its symbols and the phrases it must never take. Choosing those entries is physics judgement. It is done once, in review with the lead, and is not a pipeline run. Everything downstream — generation, review, the lint and the harmonize command — reads that authority and never restates it.

§2 — The conventions registry

A versioned package at imas_codex/standard_names/conventions/, with a pydantic model and a loader that refuses an invalid file. It has three YAML files, each keyed by the ISN grammar tokens a name's parse produces, so the entries that apply to a name are selected from its parse and never from a text search.

A test shows that for flux_surface_averaged_argon_density_at_plasma_boundary the selector returns exactly the flux-surface-average concept, the plasma-boundary locus, the density notation and the species-density template, and nothing else.

§3 — Authoring the entries: the coordinator polish a pipeline cannot do

The coordinator drafts every entry needed by the WEST roster first, then the wider corpus. Each draft starts from the best existing accepted documentation, the DD text and the standard textbook definition. The lead locks the three physics choices in the decisions below, and every other entry follows them. Measured scope for WEST: the lint in §4 lists which concepts and symbols the 220 entries actually use, and that list, not a guess, is the authoring worklist.

This is deliberately not dispatched to an LLM worker. A worker drafting definitions reproduces whichever variant is most common, and the census shows the most common variant is sometimes the wrong one.

Done when: every concept, symbol and pattern the §4 lint finds in the WEST roster has a registry entry. The three decisions below are locked. The lead has read the concepts file.

§4 — A deterministic conformance lint

imas_codex/standard_names/conventions/lint.py reads a name's description and documentation against its selected entries and returns findings in five classes: a forbidden variant of a registered concept's equation; a non-canonical symbol for a registered quantity; a forbidden locus gloss, such as "separatrix" for plasma_boundary; an opening that does not match the pattern template; and a sign-convention paragraph present or absent against the COCOS rule. It is pure: no graph writes and no model calls. It is the instrument the harmonize command and the reviewer both read.

Done when: on fixtures, the carbon entry's dl/B equation is flagged and the argon entry's canonical one is not. A boundary gloss reading "separatrix" is flagged. A canonical entry yields zero findings. Each check has a revert-sensitive test. A census over the live WEST roster is recorded with its per-class counts, as the baseline sn-west-prototype-release measures against.

§5 — Generation and review read the registry

The documentation prompts (imas_codex/llm/prompts/sn/generate_docs_system.md, generate_docs_user.md, refine_docs_*, review_docs_*) gain one block, rendered from the entries selected for the item. It replaces the free-text consistency advice those prompts carry now; it does not sit beside it. The reviewer receives the lint findings as deterministic input. The route half exists and is unwired: imas_codex/standard_names/review/pipeline.py extracts Layer 1 audit findings and sets audit_findings on the render context at line 1964, but no template under imas_codex/llm/prompts/sn/ reads that variable. So no audit finding has ever reached a reviewer, which is the open followup f-scai-audit-findings-reach-no-template this plan inherits. Render the findings, the lint's among them, in the review templates. An unresolved lint error caps the documentation score below the acceptance threshold.

Done when: a rendered prompt for a flux-surface-averaged name carries the canonical equation and no unrelated entry (test). A rendered review prompt for a name with an audit finding contains that finding's text, and the same test fails with the template line removed. A review over a seeded non-conforming document cannot accept it, and the same document with the finding fixed can (test, with the cap removed as the counterfactual). The duplicated consistency prose is gone from the prompts.

§6 — What this absorbs, and what it leaves alone

sn-catalog-audit-instrument set out to build an audit that finds what independent review finds, calibrated against a known red cohort. Its read-only grouped review target landed on 2026-09-21. Its remaining purpose — a catalog-level instrument — is this plan's §4 lint, which is deterministic and needs no calibration against a model. That plan is superseded by this one. Name changes — renames, folds and supersedes — are not this plan's. They go through sn edit under sn-catalog-grouping §4.

§ Decisions

Where does the conventions registry live?

ISN already carries locus definitions. Concepts, notation and templates exist nowhere. An ISN release adds a dependency to a one-week closure.

Which form defines the flux-surface average?

Both correct forms appear in the catalog. The line form matches transport-code usage; the surface form is coordinate-free. Exactly one is written; the other may be named as equivalent in prose.

How is the plasma boundary glossed?

24 boundary entries call it the separatrix. That is true only for a diverted plasma.

Which opening does every documentation entry use?

WEST opens in four styles: "The … is …" (77), "This quantity is …" (55), another noun phrase (53) and "<Name> is …" (33).
