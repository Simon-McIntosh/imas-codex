Plan · standard names · S19

Review as named checks

Review and the refine loop it drives are 89% of what the standard-names pipeline has spent. Review is a judgment, and judgment is what Jev does. The obstacle is not capability but plumbing: refine reads the reviewer's prose. Replace that prose with a list of named checks that failed, and review can move to Jev while the language model keeps the writing.

§1 — What review does today, and what blocks the move

The inventory of 2026-10-12 (run sn-judgment-inventory) traces review end to end. Name review (_run_rd_quorum_cycles, defined at imas_codex/standard_names/workers.py:7758) and docs review (_review_single_batch, defined at imas_codex/standard_names/review/pipeline.py:1882) each score four dimensions from 0 to 20. The total over 80 is the accept gate, computed in code. A primary and a secondary model run, and an escalator runs when any dimension disagrees by more than 0.20.

The free-text comments are load-bearing in two places:

  • Refine renders reviewer_comments_per_dim_*, a JSON string parsed with fromjson in refine_name_user.md and refine_docs_user.md, as its instruction list.
  • The fanout trigger keyword-scans the same comments (should_trigger_fanout, defined at imas_codex/standard_names/fanout/trigger.py:105 and called at workers.py:7070).

That dependency is why the discovery plan left standard-name review as "evaluated only". It is also the reason this plan starts by naming the checks.

The incumbent's misses make the quality case alongside the cost case. All 61 names the WEST binding audit rejects are accepted with passing reviews (sn-judgment-evaluation §1).

§2 — A taxonomy of named checks

Every failure the reviewer can find becomes a check with an id, an axis, the dimension it docks, one Jev question (a Noul whose true case is the defect, or a categorising Choice where the defect is one of several forms), and the evidence fields it reads. Sources:

  • the defect list in review_names.md: malformed physical base, novel token in a closed segment, non-canonical operator join, advisory-alias collapse, ambiguity in isolation, a dropped distinguishing axis, an over-specialised parent;
  • the four docs dimensions;
  • the WEST worklist's defect classes, and the wrong-object description class;
  • the house-style checks of sn-house-style §4;
  • the 136 distinct reasons written in human sn edit corrections.

The taxonomy lives beside the review prompts as data, not prose.

Done when: every check has a Jev question and evidence fields. The 136 human edit reasons are each mapped to a check or listed as unmapped, and at least 80% map. A test fails when a check names an evidence field that the review state does not carry.

§3 — Name review through Jev, measured, not wired

Build the Jev name review as question and state builders that nothing calls yet. Following discovery's categorise-first result, each dimension is asked as categories with the decision derived in code, and each failed-check question is a separate Noul or Choice. The state is the candidate name, its grammar segments, kind, unit, description, source DD paths with their documentation, and sibling names. Each neighbourhood field records whether it was observed, since unknown is not empty.

The state's context is selected, not just retrieved. The sibling names, comparators and scored exemplars it carries are reranked by Jev from their embedding shortlist, with the embedding order kept on failure (sn-selection-over-generation §4). The lead ruled on 2026-10-12 that a shortfall against the incumbent means this design (the prompt, the templates, and the context search and its rerank) needs work. So each design iteration is a measured arm, not a reason to stop.

Run it over golden A from sn-judgment-evaluation §4.

Done when: the prototype's evidence fragment reports:

  • the paired AUC of Jev against each of the six incumbent models and against the quorum decision, with 95% intervals;
  • the option-order flip rate and the frozen-state variation;
  • cost and latency per name;
  • the verdict under the deployment rule of sn-judgment-evaluation §7.

An arm that hands Jev the incumbent's own comments is excluded, since the point is to measure Jev without them.

§4 — Documentation review through Jev, claim by claim

The docs rubric already defines physics accuracy as "a claim-level verification against the DD ground truth". That is the citation-check pattern:

  • Code splits the documentation into claims.
  • Each claim gets a Choice — supports, contradicts or says nothing — against the DD documentation and the enriched description.
  • One contradiction is a veto, because an averaged score would hide it.

Description quality, documentation quality and completeness take categorising questions with concrete levels. The house-style conformance checks are added as named checks.

Done when: paired AUC against the incumbent on golden B (not on the incumbent's own docs reviews) is reported with intervals, along with the variation, the option-order flip rate, the cost, and a per-claim confusion table on the planted-defect subset. A documentation entry whose one claim contradicts its DD source is rejected even when every other dimension scores at the top, and the test fails when the veto is removed.

§5 — Refine reads the failed checks

The refine prompts render the failed checks as their instruction list: id, the criterion text, the evidence it pointed at, and the segment or sentence concerned. The fanout trigger becomes the maximum probability over the checks that call for retrieval, compared with a calibrated threshold, which retires the keyword list in refine-trigger-keywords. The free-text comment field remains for people and no code path reads it.

Done when: an A/B over a held-out cohort compares one refine rotation driven by checks with one driven by comments. It reports the post-refine acceptance rate judged against golden labels rather than by the reviewer that requested the refine, and the cost per accepted name. should_trigger_fanout reads no comment text, and a test fails when a keyword list is reintroduced.

§6 — The cascade

Jev reviews every candidate:

  • Above the calibrated accept threshold with no failed check, it accepts.
  • With any failed check above its threshold, it routes to refine with those checks.
  • Only the uncertain band, where the decision is close and the distribution spread, goes to one chat reviewer, not a quorum.

Thresholds come from the calibration split. The cascade runs in shadow first, through the store of sn-judgment-evaluation §6, and decides only after shadow agreement and the §3 and §4 verdicts pass the deployment rule.

Done when: on a fixed cohort run both ways, the fragment reports the share of items that reached the chat reviewer, spend per accepted name before and after, and non-inferior AUC on the golden validation split. The incumbent quorum path remains callable for comparison until §7.

§7 — Delete what Jev took over

For each decision that passed the rule, delete the incumbent's code path and seat rather than leaving both. That covers the quorum cycles that no longer run and the review seats beyond the one chat reviewer the cascade keeps. The comment-keyword trigger is not here: §5 retires it when it switches the trigger to check probabilities. A decision that did not pass keeps its incumbent and its recorded numbers.

Done when: the deleted paths and seats are listed with line counts. A test asserts that the quorum cycle function is no longer defined, that no review seat beyond the cascade's single chat reviewer resolves through get_model. Each assertion fails when its deleted path is restored. The LLMCost phase split over the next production run shows review spend by judge kind.
