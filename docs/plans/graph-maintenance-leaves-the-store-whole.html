§2 — Landed: the stop waits for the job, and the push waits for an idle graph

410162d5b makes stop_neo4j_job (imas_codex/cli/services.py) the one owner of stopping the graph job:

  • It sends SIGTERM to the server JVM, cancels the job, and returns only after the job id has left squeue. A failed squeue counts as still listed.
  • _clean_neo4j_locks refuses while any Neo4j JVM is alive on the node.
  • The export and load stop no longer swallow a failed stop, and their job detection raises when squeue cannot answer.

Eight tests in tests/cli/test_neo4j_stop_waits_for_exit.py pass on the change. On the committed code, 5 fail and 3 error (exit 1).

184996eb8 turns the push into a daily check (imas_codex/graph/offsite.py). A push falls due a week after the newest offsite copy. A due push defers to the next day while other clients are working on the graph, which it measures with SHOW TRANSACTIONS:

  • Transaction ids are one sequence across every session, so the gap between eleven probes over ten minutes, less the probes themselves, counts other clients' transactions.
  • On the idle graph it advanced by exactly one in 60 s, the probe itself.

The deferred-push test fails when the busy check is removed. The runbook "When the graph goes away" is in imas_codex/graph/AGENTS.md, with a pointer in the root AGENTS.md.

§5 — Graph lifecycle commands work from a compute node

From a SLURM step, graph start, stop and export fail before doing anything. They reach the scheduler through _run_remote (imas_codex/cli/services.py), which runs ssh iter whenever the host matches none of the facility's login_nodes patterns, and port 22 is refused there. squeue, sbatch and scancel all work locally on a compute node. Node-side commands (_run_on_node) also need a route. On 2026-10-12 ssh to the graph node was refused from both the compute node and the login node, and _term_neo4j_on_node fell through to scancel.

The repair runs scheduler commands locally whenever the scheduler answers locally, and routes node commands through the scheduler instead of ssh (srun --overlap --jobid, on the graph job's own allocation). The node route is confirmed by the decision below.

  • On a host where squeue answers locally, the scheduler commands run without ssh.
  • Node commands use the chosen route.

From a compute node, imas-codex graph status reports the job without an ssh error, and its log is quoted.

§6 — No pattern kill on the login node

Neo4jOperation._stop_neo4j (imas_codex/graph/neo4j_ops.py) still runs three pkill -15 -f patterns on whichever host runs the export: neo4j_.*community.sif, Neo4jCommunity and neo4j.*console. On the shared login node they match any session's temporary Neo4j, test instance or admin run. _stop_login_services runs pgrep -f 'neo4j_.*community.*\.sif' inside a bash -c whose argv carries the same pattern, and kills the first match. On 2026-10-12 it reported Killed login Neo4j process (PID 501330), and nothing recorded what that process was. The remote lifecycle script that _neo4j_lifecycle_bash (imas_codex/graph/remote.py) generates for five export, load and restart paths runs pkill -u "$USER" -f "java.*neo4j" in its stop_neo4j, which takes every Neo4j JVM the account runs on that host, including temporary and throwaway instances.

The repair resolves each kill to pids it can attribute: the instance's own pid file, or processes whose working directory or bind path is the graph data directory. It prints them with their command lines, then signals only that list. No step selects by pattern alone.

§ Decisions

How do lifecycle commands reach the graph node?

The SIGTERM and lock cleanup run on the node that hosts the job. On 2026-10-12, ssh to that node was refused from both a compute node and the login node.

Recommended: srun --overlap --jobid . It needs no ssh route, runs inside the job's own cgroup, and works from wherever the scheduler answers.
