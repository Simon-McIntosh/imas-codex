Plan · standard names · S18

The WEST prototype

The WEST batch is the first set of names a physicist will judge, and it sets the bar every later batch is held to. By the pipeline's own measures it is ready. Read as a set, it is not: one in five bindings carries a recorded name defect, and the documentation agrees with itself only by accident. This plan takes the batch from "every entry passed" to "the entries read as one catalog", and only then releases it.

§1 — Starting state, measured 2026-10-12

The frozen roster imas_codex/standard_names/manifests/reviews/v0.4.0rc7+west-task-2e.sn_names.yaml holds 220 names for the 342 sources of imas_codex/standard_names/manifests/west_production_dd_paths.yaml. 218 are accepted on both axes, with a median name score of 0.975 and documentation score of 0.938. Measured per source on 2026-09-15, 340 of 342 sources are carried, and the two exclusions are understood (calorimetry/group/component/energy_total back at extracted; camera_x_rays/camera/camera_dimensions at its attempt cap).

What the scores miss is already written down. The binding-by-binding judgement in the WEST name repair worklist found 74 of 341 bindings (21.7 %) carrying a name defect, reconciled to 61 repairs (51 renames, 10 splits) behind six unresolved contradictions. The shared-identity description judgement found seven bindings whose description names the wrong object, among them an X-point read as the magnetic axis and the outer strike point read as the inner (the description truthfulness record, which also holds the replacement sentences). The consistency census adds four documentation opening styles, conflicting definitions of shared concepts and five roster names with no physics domain. None of this was acted on, because the repairs are paid work that was never authorised and the release plan was busy with its own machinery.

§2 — Name repairs, ruled on once

Names first, because documentation follows a name and harmonizing an entry that is about to be renamed is wasted spend. The coordinator brings three things to the lead in one sitting: the six contradictions in the worklist, each with the options and a recommendation; the 61 repairs, grouped by kind so they are ruled on as classes rather than one by one; and the WEST pairs from sn-catalog-grouping §4. The lead rules and authorises a spend ceiling. The repairs then go through sn edit --hint DIRECTION --reason WHY and the ordinary review quorum. No spelling is invented outside the worklist. The seven wrong-object descriptions take the replacement sentences already written for them, through the documentation route.

The seven came from one audit's sample, so the rest of the roster is checked the same way rather than assumed clean. Code splits each roster entry's description and documentation into claims. Jev asks one Choice per claim: does it support, contradict or say nothing about the bound DD source's documentation. Every contradiction is read by the coordinator. This check is the citation-check pattern, measured on golden C of sn-judgment-evaluation §4 before its findings are trusted. Until it passes, it orders the coordinator's reading rather than deciding anything.

Done when: every worklist row and every contradiction carries a recorded ruling (apply, or decline with a reason). Every applied repair is accepted on the name axis, or held with its reviewer verdict. The seven descriptions are replaced. The roster-wide claim check is reported: claims checked, contradictions found, and the coordinator's verdict on each. Actual spend is recorded beside the authorised ceiling. The roster is re-minted, and the re-mint resolves every manifest source to a live identity or a stated exclusion.

§3 — Harmonize the batch

Run sn harmonize --apply --batch west-task-2e once sn-harmonize-command §3 and the WEST registry entries of sn-house-style §3 exist, with a cost limit set from the per-name figure sn-harmonize-command §4 measures.

Done when: the lint reports zero errors over the roster. Every entry is accepted on the documentation axis at or above 0.85. The per-class finding counts before and after are recorded against the sn-house-style §4 baseline. A second report-mode run over the batch plans no work.

§4 — A person reads every entry

The coordinator reads all of the roster against one checklist, grouped by pattern family as sn-catalog-grouping §2 defines it, so siblings are read side by side. The grouping comes from the family function directly, not from the staged packet order of §5:

  • the description is true of every binding the identity holds;
  • there is exactly one display equation, and it is the canonical one;
  • symbols follow the registry and are defined on first use;
  • the locus is glossed as the registry says;
  • the sign convention is present exactly when the COCOS type requires it;
  • every link resolves;
  • no typical values, recipes or padding.

If sn-selection-over-generation §5 has shown that a risk order finds defects faster than random order, the reading follows that order within each domain. A failure is fixed through sn edit with a hint and goes back through review. It is never hand-edited in the graph. This is the polish no run can do, because it is the one step that sees the batch the way its reviewer will.

Done when: docs/evidence/sn-west-prototype-release/polish-ledger.md carries one row per roster name (pass, edited, or withheld with a reason) and no row is open. Every edited row has been re-reviewed to acceptance. A "pass" is not self-certified: a read-only review node re-reads a random sample of 20 pass rows against the same checklist, and any disagreement reopens that row and fails this gate until it is resolved.

§5 — The batch arrives grouped the way a physicist reads

Domains come from sn-catalog-grouping §3. Within a domain, entries are ordered by pattern family, so a reviewer meets the seventeen species of one quantity together and can check them against each other. That ordering does not exist yet. order_entries_by_hierarchy in imas_codex/standard_names/catalog_ordering.py, called from the export at imas_codex/standard_names/export.py, sorts a domain topologically over HAS_PARENT and HAS_ERROR edges and knows no pattern family. Add the pattern family from sn-catalog-grouping §2 as the primary key within a domain, and keep the hierarchy order inside each family.

Done when: no roster name carries a null domain. In the staged catalog, every pattern family appears contiguously within its domain. The assertion is shown able to fail: with the family key removed from the ordering it reports the split family (asserted by a test over the staged files).

§6 — The re-cut and the pull request

Cutting is coordinator work from the main checkout, because the release CLI refuses a detached HEAD. The catalog repository's own runbook governs pushing there. The residue carried in from the retired release plan is resolved before the cut, and each item is first confirmed to still reproduce:

  • a roster declares which set it carries and its own content hash, and a freeze refuses a version that already exists with different bytes;
  • the rehearsal reaches the leg that produces its own accounting;
  • the export gate chain passes for the WEST scope, with the two permanent exclusions waived by exact path;
  • the two recovered names carry accepted documentation;
  • the two vocabulary admissions the tail waits on are either landed upstream or recorded as exclusions;
  • the half-width quantity that the grammar cannot spell is likewise either landed upstream or recorded as an exclusion.

Done when: a candidate is cut and its exclusion ledger accounts for all 342 sources (emitted plus each exclusion with its reason). The pull request is open and links REVIEWING.md as markdown. The roster hash is recorded on the plan.

§8 — What this plan does not do

It does not harmonize the rest of the corpus. That follows WEST, through the same command, once the prototype has been judged. It does not take on the integrity residue parked in sn-integrity-backlog. Where one of those items blocks a step here, it is pulled in by name with its measurement, not by reopening the backlog.
