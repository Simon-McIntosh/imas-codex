Plan · standard names · S18

sn harmonize

sn run composes and documents one name at a time, which is right for producing names and wrong for making them agree. The unit of consistency is a family or a shared concept. This command takes that unit, measures it against the house style, and rewrites its documentation from one anchor outward.

§1 — Why a command beside sn run, and why this name

The pieces exist and are scattered. harmonize.py computes drift and a family worklist, and its module docstring still points at an sn harmonize --report command that no longer exists. sn run --families resets a family's documentation and runs a docs-only flush. sn review --target groups reviews the drift worklist read-only. None of them knows the house style, and all three group by HAS_PARENT, which the consistency census shows is the wrong family.

The name is harmonize, not refine. "Refine" already means the per-name refine pools inside sn run and the sn release-refine-claim command, so a second meaning would mislead every reader of a log. "Harmonize" is the word the module, the prompts and the retired family-harmonization plan already use for this act.

§2 — One surface, and the two it replaces

imas-codex sn harmonize takes one scope — --batch <manifest> (a roster token such as v0.4.0rc7+west-task-2e, resolved by resolve_batch_token), --family <seed name>, --concept <registry id> or --all — and one mode:

  • --report (the default): read-only. For each pattern family in scope, it lists the members, the anchor, the drift metric and the lint findings by class. It also prints a scope total, which is the number every later step is judged against.
  • --apply: the documentation rewrite of §3, with --dry-run printing the planned calls and an estimated cost, and --cost-limit bounding the spend.

The lint is read, never rebuilt. Its source is the AuditReport in imas_codex/standard_names/review/audits.py: the lexical lint, the house-style findings of sn-house-style §4 and the documentation gates, composed by run_all_audits, plus link integrity (run_link_integrity). run_all_audits always runs the embedding preflight first, which re-embeds and writes, so the report cannot call it. The lint composition moves into its own function in audits.py; run_all_audits calls it after the preflight, and the report calls it directly. There is then one list of lint calls, not two. Families are enumerated through one mechanism: build_worklist carries a second parentless grouping beside assemble_family, and only one survives.

In the same change, delete --families from sn run and --target groups from sn review, and update their tests and documentation. There is one route to family harmonization afterwards, not three. The helpers only those routes reach go with them: _refuse_grouped_review_scoping and _report_drifting_families in imas_codex/cli/sn.py, mark_families_for_regen (keyed on HAS_PARENT, the grouping §1 retires) and lint_links (a duplicate of run_link_integrity with no production caller) in harmonize.py. build_worklist stays: sn status calls it for its sibling-family drift count, so only its duplicate grouping goes.

Done when: sn harmonize --report --batch v0.4.0rc7+west-task-2e runs against a fixture graph and prints per-family findings, and writes nothing. With --family it prints the same rows for one family. Both deleted flags are gone from imas_codex/cli/sn.py, and a test asserts each is rejected as an unknown option. None of the retired helpers is left without a production caller. The CLI test suite shows no added failures against its base.

§3 — Apply: the anchor first, the members from the anchor

For each pattern family in scope:

  1. Anchor. Choose the anchor with the existing select_anchor. Regenerate its documentation with the selected registry entries and the family template in the prompt, then pass it through the ordinary documentation review axis. A family whose anchor does not reach acceptance stops there and is reported. Members are never written against an unaccepted anchor.
  2. Members. Regenerate each member's documentation with the accepted anchor in the sibling block the docs prompt already carries. Member-specific physics — a different charge-state range, a different sign convention — is stated inside the shared template, never averaged away. Each member is then reviewed the same way.
  3. Verify. Re-run the lint over the family and record before and after counts.

Names and identities are never touched: this is a documentation-axis operation, so every identity, source binding and spend record survives. Names already recommended into a catalog pull request are refused, with the refusal naming each one, unless --force is given with a reason that the run records. The refusal reads imas_codex/standard_names/protection.py, which already owns "this name is committed, do not move it" (automatic_deletion_protections names approved and a recorded catalog pull request): it gains the roster and contested reasons, and the command reuses its evidence rather than a second query. The lead ruled this on 2026-10-12. "Recommended" covers:

  • members of a frozen review roster under imas_codex/standard_names/manifests/reviews/ whose candidate request is open;
  • names at name_stage approved, accepted through a merged catalog request;
  • names at contested, edited by a reviewer during one.

Moving one of these would change text a physicist has been asked to review, or has already reviewed. The previous documentation is snapshotted before reset. sn harmonize --apply calls mark_members_for_regen in imas_codex/standard_names/harmonize.py directly on the pattern family's members (from fetch_pattern_family); it already snapshots each member's documentation, resets the documentation pipeline and stamps a scope run id, so no family-level wrapper is needed. Name-level fixes go through sn edit.

Done when: on the 17-member boundary-averaged density family, an apply leaves zero lint errors, one opening template and one flux-surface-average equation. Every member stays accepted on the documentation axis. A second --apply over the same scope plans zero calls. An anchor deliberately failed in a test leaves its members untouched. A family containing one member of an open candidate roster and one approved name is refused for both without --force, and harmonized with it, with the reason recorded on the run. The refusal test fails when the guard is removed. A test shows the snapshot exists before the reset, and that the family can be restored from it.

§4 — Convergence and cost, measured on a real scope

Before the WEST run, prove the command on one non-WEST family per pattern kind (species, component, locus). For each, record calls, spend, wall time, lint findings before and after, and documentation scores before and after. The scores answer the one question the lint cannot: whether making entries agree made any of them worse.

Done when: three families are applied with those figures recorded in the plan's evidence. No member's documentation score falls below the acceptance threshold. The per-name cost is known well enough to put a stated limit on the WEST run. The comparison is proven able to see a regression: a fixture member whose rewritten documentation scores below threshold is reported by name, so an unchanged column passes only because nothing fell.
