Plan · standard names · S18

sn harmonize

sn run composes and documents one name at a time, which is right for producing names and wrong for making them agree. The unit of consistency is a family or a shared concept. This command takes that unit, measures it against the house style, and rewrites its documentation from one anchor outward.

§1 — Why a command beside sn run, and why this name

The pieces exist and are scattered. harmonize.py computes drift and a family worklist, and its module docstring still points at an sn harmonize --report command that no longer exists. sn run --families resets a family's documentation and runs a docs-only flush. sn review --target groups reviews the drift worklist read-only. None of them knows the house style, and all three group by HAS_PARENT, which the consistency census shows is the wrong family.

The name is harmonize, not refine. "Refine" already means the per-name refine pools inside sn run and the sn release-refine-claim command, so a second meaning would mislead every reader of a log. "Harmonize" is the word the module, the prompts and the retired family-harmonization plan already use for this act.

§2 — One surface, and the two it replaces

imas-codex sn harmonize takes one scope — --batch <manifest> (a roster token such as v0.4.0rc7+west-task-2e, resolved by resolve_batch_token), --family <seed name>, --concept <registry id> or --all — and one mode:

  • --report (the default): read-only. For each pattern family in scope, it lists the members, the anchor, the drift metric and the lint findings by class. It also prints a scope total, which is the number every later step is judged against.
  • --apply: the documentation rewrite of §3, with --dry-run printing the planned calls and an estimated cost, and --cost-limit bounding the spend.

The lint is read, never rebuilt. Its source is the AuditReport in imas_codex/standard_names/review/audits.py: the lexical lint, the house-style findings of sn-house-style §4 and the documentation gates, composed by run_all_audits, plus link integrity (run_link_integrity). run_all_audits always runs the embedding preflight first, which re-embeds and writes, so the report cannot call it. The lint composition moves into its own function in audits.py; run_all_audits calls it after the preflight, and the report calls it directly. There is then one list of lint calls, not two. Families are enumerated through one mechanism: build_worklist carries a second parentless grouping beside assemble_family, and only one survives.

In the same change, delete --families from sn run and --target groups from sn review, and update their tests and documentation. There is one route to family harmonization afterwards, not three. The helpers only those routes reach go with them: _refuse_grouped_review_scoping and _report_drifting_families in imas_codex/cli/sn.py, mark_families_for_regen (keyed on HAS_PARENT, the grouping §1 retires) and lint_links (a duplicate of run_link_integrity with no production caller) in harmonize.py. build_worklist stays: sn status calls it for its sibling-family drift count, so only its duplicate grouping goes.

Done when: sn harmonize --report --batch v0.4.0rc7+west-task-2e runs against a fixture graph and prints per-family findings, and writes nothing. With --family it prints the same rows for one family. Both deleted flags are gone from imas_codex/cli/sn.py, and a test asserts each is rejected as an unknown option. None of the retired helpers is left without a production caller. The CLI test suite shows no added failures against its base.

§3 — Apply: the anchor first, the members from the anchor

For each pattern family in scope:

  1. Anchor. Choose the anchor with the existing select_anchor. Regenerate its documentation with the selected registry entries and the family template in the prompt, then pass it through the ordinary documentation review axis. A family whose anchor does not reach acceptance stops there and is reported. Members are never written against an unaccepted anchor.
  2. Members. Regenerate each member's documentation with the accepted anchor in the sibling block the docs prompt already carries. Member-specific physics — a different charge-state range, a different sign convention — is stated inside the shared template, never averaged away. Each member is then reviewed the same way.
  3. Verify. Re-run the lint over the family and record before and after counts.

Names and identities are never touched: this is a documentation-axis operation, so every identity, source binding and spend record survives. Names already recommended into a catalog pull request are refused, with the refusal naming each one, unless --force is given with a reason that the run records. The refusal reads imas_codex/standard_names/protection.py, which already owns "this name is committed, do not move it" (automatic_deletion_protections names approved and a recorded catalog pull request): it gains the roster and contested reasons, and the command reuses its evidence rather than a second query. The lead ruled this on 2026-10-12. "Recommended" covers:

  • members of a frozen review roster under imas_codex/standard_names/manifests/reviews/ whose candidate request is open;
  • names at name_stage approved, accepted through a merged catalog request;
  • names at contested, edited by a reviewer during one.

Moving one of these would change text a physicist has been asked to review, or has already reviewed. The previous documentation is snapshotted before reset. sn harmonize --apply calls mark_members_for_regen in imas_codex/standard_names/harmonize.py directly on the pattern family's members (from fetch_pattern_family); it already snapshots each member's documentation, resets the documentation pipeline and stamps a scope run id, so no family-level wrapper is needed. Name-level fixes go through sn edit.

Convergence repairs. One forced apply over the 17-member family did not converge it, and a no-spend diagnosis (record) found why: the template, the equation and the anchor all reached every prompt, but nothing downstream enforces them. The evidence ranks the repairs as:

  1. insertion plus validation of the opening and the equation, together (§6);
  2. graph-wide link resolution in the report (§5);
  3. the run's anchor pinned (§7).

Each is its own section with its own negative control. The family is applied again only after all three land. This section keeps the apply mechanism and the outcome they must produce together.

Done when: after §5 to §12 have landed, an apply over the 17-member boundary-averaged density family converges in one pass: zero lint errors, one opening template, and no flux-surface-average equation other than the registry's canonical form. Every member stays accepted on the documentation axis. A second --apply over the same scope plans zero calls. An anchor deliberately failed in a test leaves its members untouched. A family containing one member of an open candidate roster and one approved name is refused for both without --force, and harmonized with it, with the reason recorded on the run. The refusal test fails when the guard is removed. A test shows the snapshot exists before the reset, and that the family can be restored from it.

The scores answer the one question the lint cannot: whether making entries agree made any of them worse.

§6 — The opening and the equation are written, then checked

The documentation axis accepts on the review score alone. The house-style template_opening finding is only a warning, so 16 of 17 non-conforming openings were accepted. Generation also runs with restates_equation=False, which leaves the flux-surface-average equation free in all 17 members. The diagnosis ranks one repair first, opening and equation together: insertion plus validation. A refusal alone prevents a false acceptance but cannot give a one-pass result.

  • Insertion. The selected template is instantiated with the member's subject and written as the documentation's first line by construction. The equation comes from the concept registry, not from the anchor. Each concept holds exactly one canonical equation, in the ISN conventions/concepts.yml. Where the entry has restates_equation: true, that equation is written into the documentation in its one form. Where it is false, as for the flux-surface average, the documentation names the concept and links to it. The prompt partial imas_codex/llm/prompts/sn/_conventions.md drops its "unless needed to define this quantity" clause, which left all 17 forms free, and gives the canonical form instead: an equation the documentation does state is written exactly that way.
  • Validation. Before persist_reviewed_docs in imas_codex/standard_names/workers.py, a document is refined, not accepted, if any of these holds:
  • its first line matches none of its selected templates;
  • it carries a display equation for a registered concept in a form other than that concept's canonical one, or one that matches its forbidden_variants.

A canonical restatement is the converged form, not a defect. The lead's ruling defines the flux-surface average by its surface form and forbids only a second, line-form equation. The defining-equation gate also asks an averaged quantity for its one display equation, which is that average.

  • The check reuses the existing template_opening lint and the registry's variant patterns.

Done when: with the model call stubbed:

  • a generated document with a wrong first line is persisted with the instantiated opening;
  • for a concept with restates_equation: true, the persisted documentation carries the canonical equation;
  • a document that still fails either check after insertion is routed to refinement, with the finding as its reason, even at a review score of 1.0;
  • a document that states the flux-surface average in a non-canonical form is routed to refinement, and one that states it in the canonical form is accepted;
  • a name with no selected template is accepted on score.

Each test fails with its mechanism removed, and each red run is recorded as a negative control.

§7 — A run keeps the anchor it chose

select_anchor ranks current accepted scores. A partial run that reset the anchor let a replan pick another member, and a score tie picked a third by id. A run records the anchor it chose against its scope run id, in imas_codex/standard_names/harmonize.py, and a continuation of the same scope run reuses it. A new scope run selects normally. Score ranking stays the rule for the first choice.

Done when: with the graph stubbed, a recorded anchor is reused after it is reset and another member outscores it, and a family with no recorded anchor selects normally. The reuse test fails with the pin removed, and that red run is recorded as the negative control.

§8 — One cost cap covers the whole family

The second forced apply over the boundary-density family spent USD 6.26 against a USD 5.00 cap, then stopped unstamped. Two defects caused it. -c/--cost-limit is applied to each drain batch, so the anchor batch (USD 1.03) and the member batch (USD 5.23) each received the whole cap. And the dry run's estimate of USD 0.85 was about a seventh of the real cost, which §12 repairs.

The cap bounds the sum over one family: the anchor and its members together, including the review that follows each regeneration. The members' share is whatever the anchor leaves. The live apply builds the drain's CampaignBudget in imas_codex/cli/sn.py (~6164, with per_batch_cost_cap=cost_limit); harmonize.py's own CampaignBudget() (~1106) is only the fallback when no budget is passed. The repair belongs at the apply's construction site, and the fallback must hold the same rule.

Done when: a stubbed test shows that a family whose anchor spends 60% of the cap leaves its members exactly the remaining 40%, and that the members stop at the cap. The test fails if the cap returns to per-batch.

§9 — Every sibling link is returned

The second apply raised link_missing_reverse from 6 to 12. Regenerated documentation links its siblings, and those siblings do not link back. First find, from the twelve findings on the live family, which side adds the links and why the reverse is not written. The causes could be the prompt's sibling block, the order in which members regenerate, or the lint's definition of a reverse link. Then make the apply leave none.

The preferred mechanism is deterministic: after the members converge, each member's documentation gains a link to every sibling that links to it. A prompt instruction that the model may ignore is not the mechanism. A reverse link is added only when it is true; a sibling link that should not exist is removed instead.

Done when: the fragment docs/evidence/fragments/sn-harmonize-command/shc-reverse-links.html names the cause of each of the twelve findings. A stubbed apply over a fixture family whose regenerated members link one-way ends with zero link_missing_reverse findings, and it fails with the reverse step removed.

It adds the equation \psi = \psi_{\mathrm{LCFS}} with its symbols, and the forbidden variant the separatrix.
