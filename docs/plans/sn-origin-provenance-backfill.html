§1 — The residue was never the constraint

The graph-wide integrity programme drove every tracked defect class to zero or to a named refusal, and the strategic question that followed was whether to stop repairing and instead delete and regenerate names and documentation from their sources. That question was framed as waiting on the residue getting small enough. It is not waiting on that. The residue is already small. It is waiting on 1,091 identities that will not say what they are.

The 278 are what make the strategy unpriceable. A regeneration scoped by origin must decide what to do with a live, accepted name that declares no origin, and there are only two options: treat it as pipeline output and risk destroying human curation, or treat it as a protected edit and silently retain stale generated text. Neither is knowable from the data as it stands, so the strategic choice cannot be made honestly at any residue count.

A second axis fails the same way: 978 names carry a null status, the ISN lifecycle field, which is 1.00 present in catalog_edit and 0.01 in pipeline. Same story, same likely fix, and it should not be a separate campaign.

§2 — The evidence says this is a rule, not an adjudication

The null cohort carries the generative fingerprint at 0.98 across three independent markers, and carries no catalog-import fingerprint at all — imported_at and catalog_commit_sha both at 0.00 against 1.00 and 0.98 in catalog_edit. A name that was never imported from the catalog cannot be a catalog edit. So on the evidence these are pipeline names whose origin was simply never stamped, the backfill is a rule rather than a judgement call, and the cost falls by an order of magnitude.

§3 — One marker disagrees, and that decides the gate

source_types sits at 0.98 in the null cohort, matching catalog_edit at 1.00 against pipeline at 0.08. One marker points the other way, and a rule keyed on it reaches the opposite conclusion from the same data.

So explaining source_types is a gate, not a footnote. Either it is not the catalog marker it appears to be, or the null cohort has mixed provenance and the import markers are absent for some other reason. Both readings are consistent with what has been measured, and they imply different backfills. If the rule and the anomaly disagree, the rule is not yet understood and must not be run.

This is deliberately strict because the failure would be silent. A backfill that stamps origin=pipeline on a genuine human edit does not error; it removes that name's protection from every future regeneration, and nothing downstream would report it.

§4 — Prove the rule on answers already held

A rule that classifies unknowns cannot be validated against those unknowns. It can be validated against the cohorts whose origin is already declared: assert the rule re-derives catalog_edit for the 1,372 and pipeline for the 426 before it is trusted on the 278. Any misclassification in that control is a defect in the rule, discovered for free.

This is a positive control on a rule rather than on a scan, and it is the generalisation of a lesson that cost two sessions repeatedly on 2026-08-25: an instrument that fires is not an instrument that is aimed. Making the rule re-derive answers already held is how aim gets proved rather than assumed.

The 705 superseded null-origin names are handled separately. Historical lineage does not need the same treatment and sweeping them in would inflate the cohort under mutation for no benefit.

§ Decisions

How should the 1,091 undeclared origins be settled?

Measured rule. The import fingerprint is absent at 0.00 across the whole null cohort while the generative fingerprint is present at 0.98, and a name never imported from the catalog cannot be a catalog edit — so this is decidable from evidence rather than requiring judgement per identity. Human adjudication of 278 identities is expensive and would produce the same answer the markers already give. Stamping without explaining source_types is rejected: one marker contradicts the rule, and a wrong stamp silently removes a human edit's protection from every future regeneration with nothing downstream reporting it.

Are the 705 superseded null-origin names in scope?

Separately. Historical lineage does not need a declared origin to be safe from regeneration, since a superseded name is not a regeneration target. Including them would quadruple the cohort under mutation for no decision benefit.

§ Followups

Explain source_types, prove the rule on the known cohorts, then backfill origin and status

Gate order matters: source_types is explained first, then the rule is asserted to re-derive catalog_edit on 1,372 and pipeline on 426, and only then does it run on the 278 live accepted and the wider 1,091. The 978 null status values fold into the same node. The 705 superseded are excluded. No stamp is written while the anomaly is unexplained.
