§1 — This is damage from one import, not an absence of stamping

A catalog.yaml import was used to recover catalog state. It was a footgun: it cleared generation provenance on the identities it touched and relabelled others, and the damage is still in the graph. Every earlier reading of this cohort — including two in this plan's own history — described it as provenance that was never written. That was wrong. It was written and then destroyed, which is why recovery is the right verb and backfill is not.

Two framing errors to retire, because both sent earlier work in the wrong direction.

1. source_types=['dd'] is not a provenance defect. 1,085 of the 1,091 carry it, and the pipeline's only input is DD paths — so ['dd'] is the normal case, not a symptom. It records the SOURCE KIND. origin records the EDITORIAL AXIS: whether a human shaped the identity. Treating one as evidence about the other conflated two orthogonal things and produced a “cohort that will not declare itself” out of names that are declaring exactly what they should.

2. Import markers are not an inverse of editorial origin. A rule keyed on imported_at/catalog_commit_sha failed its positive control at 5 of 426, and the five counterexamples — electron_density, normalized_toroidal_flux_coordinate, safety_factor, toroidal_magnetic_field, vertical_coordinate_of_camera — all share one imported_at of 2026-07-04T21:21:17.079Z and one catalog_commit_sha a2f8831c…. That is not five scattered errors; it is a single dated event leaving its fingerprint. The marker fails because it records that the import happened, never what the identity was before it.

The null cohort still carries its generative fingerprint at 0.98 across three independent markers. These identities know they were generated; only the field that says so was cleared. Recovery is therefore a derivation from evidence the graph already holds, not an inference from absence.

And the same table undercuts a number this project has been quoting, including in the sprint that authored this plan. Between 18% and 30% of accepted catalog_edit identities carry a generation model, a generation timestamp or a refine chain. Those were produced by the pipeline and relabelled. So “2,096 human-curated identities” is an overcount of unknown size, and every argument resting on it — including the case against regenerating — rests on a figure that has not been measured properly.

Richer evidence exists beyond those three fields and should be used where they are absent: LLMCost carries standard_name_ids, so any identity that ever cost a provider call is pipeline-generated by construction; and review records, DocsRevision chains and REFINED_FROM lineage each independently witness generation.

§3 — Recover, and prove it on the answers already held

The rule must be keyed on generation evidence rather than on import markers, and it must clear the same bar the marker rule failed: re-derive the declared origin of all 1,798 accepted controls with zero misclassifications before it is trusted on anything undeclared. That control is what caught the previous attempt after its one contradicting signal had resolved in its favour, so it stays.

Two properties make this rule more likely to clear it. It keys on evidence the import did not touch, so the 2026-07-04 event does not confound it. And it has a one-directional guarantee the marker rule lacked: an LLMCost row linking an identity is proof of generation, never of authorship.

The 705 superseded nulls stay out of scope — historical lineage needs no origin to be safe — and status, cleared by the same import and null on 978 identities, is recovered in the same pass.

§4 — Close the footgun, or this recurs

Recovery without prevention buys one clean measurement and the next import undoes it. This programme has already met that exact pattern twice today: a HAS_PARENT edge a governed repair had removed was live again because the producer was never guarded, and the fix that held was the guard rather than the second deletion.

So the import path must lose the ability to clear or overwrite origin and status on an existing StandardName. A catalog round-trip is entitled to record that it happened — imported_at and catalog_commit_sha are legitimate — and entitled to nothing else on the editorial axis. An import that can silently relabel a generated identity as human-curated is a data-loss path wearing the costume of a recovery tool.

§ Decisions

What evidence should origin be recovered from?

Generation evidence. Import markers already failed their positive control at 5 of 426, and the five counterexamples share one imported_at and one catalog_commit_sha — so the marker records that an import occurred, never what the identity was beforehand, and cannot be an inverse of editorial origin. Generation evidence survived the import at 0.98 across three independent markers in the affected cohort, is untouched by the 2026-07-04 event, and carries a one-directional guarantee the markers lack: an LLMCost row is proof of generation and never of authorship. Human adjudication is rejected as unnecessary for identities that still carry their own generative fingerprint.

What may a catalog import write on an existing identity?

Import provenance only. A catalog round-trip is entitled to record that it happened via imported_at and catalog_commit_sha, and entitled to nothing on the editorial axis. The current path cleared origin and status on 1,091 identities and left five generated names carrying catalog markers, which is data loss rather than recovery. Recovery without this guard buys one clean measurement before the next import undoes it — the same lesson the HAS_PARENT rewire taught today, where the guard held and the second deletion would not have.

§ Followups

Recover origin and status from generation evidence, then close the import write path

Derive from generation evidence, prove zero misclassifications on the 1,798 accepted controls before touching anything undeclared, and measure how many catalog_edit identities carry a generative fingerprint so the human-curated figure stops being quoted unmeasured. Then remove the import path's ability to clear or overwrite origin and status, with a test that fails if it can.
