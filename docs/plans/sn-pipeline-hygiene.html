§4 — A whole-catalog release candidate opens a fork pull request

The release CLI opens a review pull request only for batch releases, so the whole-catalog candidate v0.4.0rc8 reached the fork as a tag with nothing for a reviewer to read. A whole-catalog candidate should open the same kind of review request on the fork. Nothing in this section pushes to the upstream catalog repository.

Done when: a whole-catalog release against a stand-in fork remote opens one review pull request on the fork, whose body uses markdown links rather than bare URLs; the same run against an upstream remote refuses before any push; tests cover both, and the batch path is unchanged.

§5 — A release can run from a fenced worker

The release CLI refuses a detached HEAD, and every worker runs in a detached worktree, so only a coordinator in the main checkout can cut a tag. A release is ordinary pipeline work and should be dispatchable.

Done when: a release dry run inside a detached worktree completes and reports the tag it would cut; the real cut from such a worktree either succeeds against a stand-in remote or refuses naming the one step that needs the coordinator; the main-checkout path is unchanged; the guard that stops a release cut from an unmerged revision still fires.
