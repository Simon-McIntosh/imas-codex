§2 — Submission protocol (binding)

Each defect travels as its own independent contribution. No batching, and no step is skipped because a previous item cleared it.

  1. Search first. Search the Data Dictionary repository exhaustively for an existing issue or pull request covering the same path or the same contradiction — open and closed. Record every search performed and its result. A duplicate report is worse than none: it costs maintainer attention and fragments the discussion.
  2. Branch from the latest develop. Every change is crafted against a freshly fetched upstream develop, never against a stale local copy or a release tag.
  3. Open a GitHub Issue. State the contradiction with the exact path, the quoted prose, the declared unit, and the observed value semantics. The issue is the durable record and stands on its own.
  4. Open a pull request that closes that issue. One issue, one PR, one defect. The PR body references the issue so merging closes it.
  5. Show it here and wait. The full issue text and the full PR text are presented in the session for review, individually. Submission happens only after explicit approval of that specific item.

No AI attribution anywhere. Issues, PR titles, PR bodies and comments carry no generated-with footer, no co-author trailer, and no tool self-credit. Authorship is the user's.

§3 — Why these are upstream rather than local

The semantic-integrity programme repaired every defect it could reach and recorded fail-closed refusals for the rest. The remaining row is a refusal of the second kind: the naming pipeline behaved correctly and the guard refused a wrong attachment. Renaming the Standard Name would encode the DD's contradiction into the vocabulary; attaching the near-miss path would bind wrong physics. Neither is acceptable, so the contradiction must be resolved where it lives.

The sensor-direction pair demonstrates the authority boundary: DD authority now supplies the dimensionless unit 1, so those two local holds are closed without a naming-side workaround.

§4 — Vocabulary question, tracked separately

field_map/grid/phi has no Standard Name because the closed ISN grammar rejects field_map_grid as a discretization artifact rather than a physics locus. That refusal was recorded as permanent on the reasoning that the vocabulary is fixed. That reasoning is withdrawn. ISN and the Standard Names develop in lockstep, and a grammar refusal is a prompt to ask whether the vocabulary should gain a token — not an automatic verdict against the name.

The open question is whether the toroidal angle of an error-field-map grid point has a physics identity worth naming, or is genuinely a storage artifact. If the former, it is an ISN vocabulary rotation; if the latter, the existing refusal stands on its merits rather than on assumed fixity.
