§1 — The window, and why it closes

Composition runs on a local, free seat, so a rename costs nothing but wall clock today. The moment a name is approved through an upstream pull request its spelling becomes catalog authority, and every later correction is a published-catalog migration with downstream consumers attached. 2,689 live names exist and 253 carry the defects below, of which 225 are already publishable — one approval from frozen. That asymmetry is the entire argument for doing this now rather than after the WEST candidate merges.

The meaning of every affected name is unchanged. These are rendering and grouping defects, so descriptions and documentation stay exactly as they are and the migration is a rename with provenance, not a re-derivation.

§2 — Defect one: the operator renders away from its operand

Operators are not a segment. They are a wrapping layer of 35 unary_prefix, 13 unary_postfix and 3 binary forms, and they render at the outer edge of the name. The canonical segment order puts object, geometry, position and region after the base, so a postfix operator ends up separated from the base it transforms by the whole locus tail, landing against the wrong noun.

§3 — Defect two: an indexed operator renders its index before its operand

derivative_with_respect_to_toroidal_flux_coordinate_of_area_of_flux_surface states the coordinate before the thing being differentiated. derivative_with_respect_to is unary_prefix with indexed: true and index_params: [coord], and the template emits the index immediately after the operator token. Nesting compounds it: time_derivative_of_derivative_with_respect_to_toroidal_flux_coordinate_of_volume_of_flux_surface.

Measured surface: 13 names — 9 derivative_with_respect_to_* and 4 time_derivative_of_*. The smallest defect with the clearest fix, which is why it is the demonstrator.

§4 — Defect three: a vector component is not a distinguished family dimension

Family grouping exists: 1,598 of 2,689 live names carry HAS_PARENT, and the parent is the bare base. But the children of a base mix component variants with qualifier variants indiscriminately — magnetic_field has 13 children in which poloidal_magnetic_field sits beside vacuum_magnetic_field and plasma_magnetic_field. Nothing marks one as a member of a component set, so a missing component is invisible to every reader and to the catalog site.

Measured surface. Of 505 component-prefixed stems, 345 carry only one component. Partitioned by the base's declared kind: 176 are true vector components where a sibling is expected; 80 have a direction word that is not a component segment at all; 87 sit on a scalar base where the direction is intrinsic (poloidal_magnetic_flux, poloidal_diffusivity); 2 need the structured parser. A missing sibling among the 176 may still be a data-dictionary coverage fact rather than a naming defect, so completion is per-name evidence, not a sweep.

§5 — Order of work

Smallest and most certain first, because each stage proves the migration machinery for the next. Nothing is renamed until a no-write comparison has produced the exact rename list.

  1. Shadow diff. Render all 431 roster names through current and proposed templates with the graph held fixed and no writes at all. Output is the exact rename list and its size. Free.
  2. Demonstrator — indexed operator template. 13 names. Proves grammar change, prompt change, regeneration and rename provenance end to end.
  3. Arity rule, postfix. 87 names.
  4. Arity rule, prefix. 149 names, only once postfix validates.
  5. Component axis in the schema, then carried into catalog.yml so the published sidecar exposes the family grouping the site needs.
  6. Sibling completion across the 176, informed by the axis rather than by a name-prefix heuristic.

Renaming and family completion touch the same names, so they are deliberately sequenced rather than combined: doing both at once would make the diff unreadable and leave no way to attribute a regression to either.

§6 — Development posture

The grammar is edited in the upstream package, so it is installed editable from the sibling checkout for the duration and pinned only once settled. One hazard is specific to this workstation: every dispatched worker shares the main checkout's environment, so an editable grammar becomes visible to the whole fleet at once. That is the point — it is what makes turnaround fast — but it means a broken grammar breaks every concurrent worker, so each grammar change is gated by the suite in the main checkout before any worker wave opens.

Four separate quantities are each blocked on a token the ISN closed vocabulary does not have, and they were raised as four independent asks against four different plans. They are one deliverable. §8 — The migration: re-render the whole live cohort

The rendering rules landed; the stored spellings did not move. A live census measured 149 renderer changes over 2,974 live names — 141 prefix and 7 postfix under the locus-tail rule, plus one indexed-operator name — with zero reparse failures and zero IR mismatches. Until those identities are re-rendered, the reviewer's four largest findings remain true of the catalog even though the grammar that produced them is fixed.

Scope is the whole live cohort, not the WEST roster. Lead ruling: a rendering rule that applies to the grammar applies to every name the grammar produced. Migrating only the batch would leave the catalog internally inconsistent and would guarantee a second migration later, against names that by then carry published authority.

The operation is parse, re-render, supersede — never regeneration and never a string rewrite. Re-generation would spend LLM calls and risk a different name for unchanged meaning; a string rewrite carries no provenance and no guarantee the result parses. The shadow diff proved this path end to end without a single LLM call: 350 proposals, all parsing, zero collisions, zero merges. Descriptions and documentation are untouched throughout, because these are rendering defects and the meaning of every affected name is unchanged.

A full-cohort parse is unavoidable and is the point. The delta is discovered rather than predicted — you cannot know which identities move without parsing all of them. It also surfaces what a render-only check cannot see: the same census found 7 pre-existing parse failures, one of which turned out to need a rejected token rather than a new one. Round-trip equality is the acceptance gate, so every proposed spelling is reparsed and its IR compared before anything is written.

§9 — The beta family: one quantity, and a token to withdraw

The reviewer asked why both beta and plasma_beta exist. The measured family is larger than the pair and carries three separate defects.

Beta is by definition a plasma quantity, so the qualifier is redundant. Lead ruling. plasma_beta (accepted) and normalized_toroidal_plasma_beta (accepted) both carry it; poloidal_beta and toroidal_beta already do not, so the corpus is internally inconsistent about its own convention. Note that normalized_toroidal_beta already exists as superseded: a previous rename moved the correct spelling into the redundant one, so this migration reverses an earlier one and needs a revival route rather than a fresh mint.

The family is a physics relation, not a list. Lead: 1/β = 1/βp + 1/βt, with βN the normalized form. So beta is TOTAL beta, and poloidal_beta and toroidal_beta are its two components. That exposes a documentation error rather than a spelling one: the description on beta currently reads "Toroidal beta (β_tor)", which is a different quantity that already has its own accepted name. Correcting it is a genuine meaning repair and is the one place in this programme where a description must change.

The iron-core β token added for the vocabulary gap must be withdrawn. beta_inclination was accepted in §7 as a geometry qualifier for the oblique iron-core angle. The graph contradicts it: beta_angle_of_ferritic_element and beta_angle_of_passive_loop were both superseded in favour of tilt_angle_ and vertical_angle_ spellings, so the project already rejected β as a prefix for a geometric angle and recorded the alternative. The sibling it was chosen to pair with is alpha_angle_of_iron_core_segment, which is accepted and live. No name uses beta_inclination yet, so withdrawing it is clean; the iron-core angle takes a descriptive spelling consistent with the superseded precedent instead.

§ Decisions

operator-renders-by-arity

Lead ruling 2026-09-04. An operator whose operand is a single base renders immediately after that base; an operator wrapping a composite keeps the outer position; the locus or object tail always comes last. One rule covers both reported cases, and it makes the discriminator ARITY rather than operator kind - which matters because a measured counter-case exists: flux_surface_averaged_ratio_of_square_of_A_to_square_of_B genuinely averages the ratio, so rendering that operator inward would assert something false. Under the rule voltage_of_ion_cyclotron_heating_antenna_amplitude becomes voltage_amplitude_of_ion_cyclotron_heating_antenna, and root_mean_square_of_wave_current_of_antenna_strap becomes wave_current_root_mean_square_of_antenna_strap, while the averaged ratio is unchanged. Surface: 87 postfix names of which 13 are acute, and 149 prefix names. Postfix lands first and prefix only once postfix validates, because a prefix operator more often wraps a composite.

indexed-operator-template

Lead ruling 2026-09-04, and the confirmed DEMONSTRATOR for the programme. An indexed operator renders operator, then operand, then index: derivative_of_area_of_flux_surface_with_respect_to_toroidal_flux_coordinate rather than derivative_with_respect_to_toroidal_flux_coordinate_of_area_of_flux_surface. derivative_with_respect_to is unary_prefix with indexed true and index_params coord, and the template emits the index immediately after the operator token, before the thing being differentiated. Surface is 13 names, 9 derivative_with_respect_to and 4 time_derivative_of, and the fix resolves the nested case too. It goes first because it is the smallest defect with the least ambiguity, so it proves grammar change, prompt change, regeneration and rename provenance end to end on a surface small enough to audit by hand.

component-is-a-family-axis

Lead ruling 2026-09-04. A vector component becomes a distinguished dimension of the name family in the graph schema, and that distinction must travel into catalog.yml so the published sidecar exposes close family grouping for presentation. Family grouping already exists - 1598 of 2689 live names carry HAS_PARENT onto the bare base - but a base's children mix component variants with qualifier variants indiscriminately: magnetic_field has 13 children in which poloidal_magnetic_field sits beside vacuum_magnetic_field and plasma_magnetic_field. Only a component set has a completeness property, so without the distinction a missing component is invisible to every reader and to the catalog site. Completion scope is the 176 stems whose base carries kind vector or tensor, partitioned out of 345 lone-component stems: 80 have a direction word that is not a component segment, 87 sit on a scalar base where the direction is intrinsic such as poloidal_magnetic_flux and poloidal_diffusivity, and 2 need the structured parser. A missing sibling among the 176 may still be a data-dictionary coverage fact rather than a naming defect, so completion is judged per name.

rename-before-completion

Lead ruling 2026-09-04. Renaming and family completion touch the same names and are sequenced rather than combined, because doing both at once makes the diff unreadable and leaves no way to attribute a regression to either. Nothing is renamed until a no-write shadow comparison has rendered all 431 roster names through current and proposed templates with the graph held fixed, producing the exact rename list and its size; that comparison is free. Order: shadow diff, the indexed-operator demonstrator, arity postfix, arity prefix, the component axis in the schema and its carriage into catalog.yml, then sibling completion across the 176. Descriptions and documentation are unchanged throughout - these are rendering and grouping defects, so every migration is a rename with provenance rather than a re-derivation.

editable-grammar-during-development

Lead ruling 2026-09-04: install the standard-names grammar editable from the sibling checkout for the duration and pin only once the grammar has settled, cutting the release-and-pin turnaround out of every iteration. One hazard is specific to this workstation and must be respected rather than discovered: every dispatched worker shares the main checkout's environment through the .venv symlink, so an editable grammar becomes visible to the whole fleet the moment it changes. That is what makes turnaround fast, and it also means a broken grammar breaks every concurrent worker, so each grammar change is gated by the suite in the main checkout before any worker wave opens. The pin is restored to a released version before the WEST candidate is approved.

operator-moves-only-past-a-locus-tail

Lead ruling 2026-09-04, narrowing operator-renders-by-arity on shadow-diff evidence. An operator is repositioned ONLY when the name carries an of_, at_ or due_to_ locus tail, and it lands between the base group and that tail. A name with no tail keeps its natural prefix reading. Arity was the wrong discriminator: applied by arity alone the rule fired on 183 of 350 names that already read correctly and made them worse - accumulated_ammonia_count became ammonia_count_accumulated, and flux_surface_averaged_magnetic_field_magnitude became magnetic_field_flux_surface_averaged_magnitude. Both reported cases carried a tail, which is what they had in common and what the first formulation missed. Tail-gating cuts the surface from 350 to 165: 148 prefix with a tail, 6 postfix with a tail, and the 11 indexed-operator names. Measured on a no-write comparison over 4937 identities.

rendering-rule-not-a-rename-pass

Lead question 2026-09-04, answered: the fix lives in the ISN RENDERER, so it is a rule rather than a one-off shuffle, and a brand-new name is born canonical without anyone remembering anything. A prompt instruction was rejected as the primary mechanism because the composer is non-deterministic and a prompt rule measurably failed to shift a proposal on retry earlier the same day; prompt guidance stays only as reinforcement. The migration of existing names is therefore NEITHER re-generation nor string shuffling. Re-generation would spend LLM calls and risk returning a different name for unchanged meaning; a string rewrite would carry no provenance and no guarantee the result parses. The correct operation is parse the current spelling to its segments, re-render under the new template, and land the result as a supersede with provenance. The shadow diff proved that path end to end without a single LLM call: 350 proposals, all parsing, zero collisions, zero merges.

composite-exemption-covers-nested-operands

Lead ruling 2026-09-04. The composite exemption must hold recursively, not just for the outermost operator. Measured leak: flux_surface_averaged_ratio_of_square_of_toroidal_flux_coordinate_gradient_magnitude_to_square_of_major_radius rendered as ..._to_major_radius_square, so the exemption protected the outer flux_surface_averaged operator while the rule reached inside the ratio and reordered its second operand. Two names are affected. An operator anywhere within a composite operand tree keeps its position, because a reader cannot tell which operand a moved operator belonged to once the tree is flattened into a surface string.

the-name-is-the-decomposition

Lead correction 2026-09-04, superseding the sidecar half of component-is-a-family-axis. The published catalog needs NO segment-decomposition field: the site depends on the standard-names package and decomposes each name itself, and the grammar round-trips by design, so the spelling already carries the structure. Confirmed against the catalog repository, whose pyproject pins imas-standard-names[quality,docs] and therefore already holds the parser. This coordinator had proposed emitting per-name segments so the site would not re-parse, and that proposal was wrong in a way worth recording, because it is the same defect class this programme keeps closing: shipping a derivable fact as a second copy invites drift. The one thing the site does require is that the pin be current, since a name rendered under a newer grammar cannot be decomposed by an older parser.
