§1 — A shipped plan's last clause is still false

sn-graph-identity-convention shipped at impl 1.0 with a three-part done-when. Its final clause reads: no guidance file names a spelling the schema no longer declares. Measured 2026-08-25 at commit 53d185e6, that clause is false — including in the schema itself and in the guidance file for this very subject.

This is not a criticism of that plan's detector; it is a statement of what a property detector structurally cannot see. The static Cypher-property check compares queried property names against LinkML declarations, and it is green. Prose in a description, and a line-number pointer into a file that has since shifted, are not property references. They are invisible to it by construction, which is why the clause passed review while remaining untrue.

A new plan rather than a reopen: that plan's verdict on the migration itself is sound and its detector genuinely works. Flipping it back would erase the signal that the schema-wide rename closed.

Renaming them would be a large diff that changes no graph behaviour while risking the writers this programme depends on.

§4 — Fix the pointer style, not just the numbers

Re-pinning three line numbers into a 3,600-line schema would restore the pointers and guarantee they rot again on the next slot insertion — this migration moved them by roughly twenty lines. The durable repair is to cite class and slot name, which a reader can grep and which survives any edit that does not rename the slot itself. That is also the form the surrounding guidance already uses for every other reference.

§ Decisions

How should guidance reference a schema slot?

Class and slot. The line anchors rotted within hours of a single rename that shifted them about twenty lines, and a pointer a reader cannot grep is worse than no pointer because they cannot tell whether they are missing context or chasing a ghost. Re-pinning restores the pointers and schedules the same failure.
