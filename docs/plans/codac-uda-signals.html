Plan · ITER plant data

CODAC UDA signals in the graph, and the rename to iter-codex

An agent or a person finds an ITER plant signal by description, loads it over a bounded window, and plots it. The scanner and loader are built under the current project name; the rename follows in stages once the live standard-names work is at rest.

§1 — Where this starts: what the prototype and the live coordinator established

The graph is being extended from IMAS science data to ITER plant data, and the project is to be renamed from imas-codex to iter-codex. The first plant source is the CODAC UDA archive. A throwaway prototype (scripts/codac_uda_prototype/, report at docs/evidence/fragments/codac-uda-signals/prototype-report.md) measured the following on 2026-11-14.

§2 — A reader runs under the archive client's module environment from one call

Delivers. Project code running in the Python 3.12 environment can run a script under a facility data system's declared setup commands and interpreter on the local host, in one invocation, and receive its structured result. The CODAC UDA reader lives with the project's other facility-side scripts and is reachable this way.

Done when. A focused test shows a local run with a declared setup command observes the environment that command sets, and that a local run with no setup command behaves exactly as before. A live control lists one variable through the same call from a compute partition and records count and elapsed time in the landing record. Negative control: with the setup step removed, the same test fails because the client is not importable.

§3 — The schema can hold an archive, a pulse and a pulse category

Delivers. The LinkML schemas and facility configuration represent: a CODAC UDA data system for ITER with its setup, interpreter, named archive roles and read limits; an archive endpoint that is not an MDSplus server; a pulse with a string identity, absolute start and end in nanoseconds and its archive; and a pulse category with pulse membership. Operator-reserved endpoints are representable as excluded and are refused before any connection.

Done when. The generated models build; schema-driven tests pass; a fixture pulse with a non-numeric identity round-trips; and the ITER facility configuration validates with the new data system while every other facility's configuration validates unchanged. Negative control: a configuration naming an operator-reserved endpoint as a readable role is rejected by validation.

§4 — The variable catalogue for a named cohort is in the graph

Delivers. A registered CODAC UDA scanner. For a cohort of variable patterns declared in the private ITER configuration, each archive variable is a facility signal owned by the ITER facility, carrying its exact archive selector, its unit and description as the archive reports them, and the data-access record that reads it. Each signal records two archive roles separately: the archive whose listing supplied its metadata, and the archive verified to serve its data, which is unset until a read has returned samples from it. Each signal also records whether it is sampled continuously or archived on change, where the archive or a read establishes it. The scan is resumable and reports how many variables it enumerated, wrote and skipped, with reasons.

Done when. For one declared cohort, the number of signals in the graph equals the number the archive lists for the same patterns, counted independently in the landing record; a second run writes no duplicates; a sample of ten cohort signals has its data-serving archive confirmed by a bounded read that returns samples, with the counts confirmed and unconfirmed in the landing record; the pulse listing for one declared category returns the same count as an independent listing of that category; and the scan ran on a compute partition (rigel or all_debug). Modified graph statements pass under the graph marker. Negative control: a scan interrupted part-way reports itself incomplete and is not counted as a finished cohort; and a signal listed on an archive that returns no samples for it keeps its data-serving archive unset.

§5 — A signal is loaded by identity over a bounded window, with honest sampling

Delivers. A loader that takes a graph signal identity and either an absolute time window or a pulse, plus a sampling mode (raw, envelope or binned) and explicit sample and byte limits, and returns time and value arrays with the signal's name, unit, description, time base, the query issued and the sampling evidence. Whether the result is decimated is reported as true, false or unknown, and is never taken from the client's own flag alone. Structured-record fields and string-valued signals are loadable. Results are cached by archive, selector, bounds and sampling settings.

Done when. One live two-second interval of one signal loads in raw and in envelope mode from a compute partition, with sample count, time span and elapsed time in the landing record; a repeat load is served from the cache; a request beyond the limits is refused before any fetch. Negative control: a paged raw read issued without the explicit no-decimation setting fails the cadence test, as it does in the prototype.

§6 — An agent finds a plant signal and reads it through the MCP server

Delivers. The existing signal search returns CODAC UDA signals for ITER beside other facilities' signals, and a facility read tool loads one by identity over a bounded window. The tool returns metadata, basic statistics and a reference to an internal file holding the arrays; arrays are inlined only under a strict byte limit. The tool is absent in the data-dictionary-only mode and accepts no host or endpoint from the caller.

Done when. Through a running server, a search for a described quantity returns a cohort signal, and the read tool returns its statistics for a two-second window, both recorded in the landing record; the tool list in data-dictionary-only mode does not contain the read tool; a response never exceeds the transport's bounded size. Negative control: a call supplying an endpoint or an unbounded window is refused.

§7 — A loaded signal is plotted and summarised

Delivers. From one loaded signal, or several overlaid on a shared time axis, a figure and a summary: sample count, time span, minimum, maximum, mean and sample interval, with envelope and archived-on-change statistics labelled as such and never presented as raw-sample or time-weighted values. The section also delivers the save function these figures go through: one function that draws the figure and refuses to write it when any text extends beyond the canvas or two text items overlap, naming the offending items. Figures follow the plot style rules.

Done when. A live signal and a two-signal overlay are rendered and inspected, with the internal file paths in the landing record; a synthetic-data figure is committed under docs/figures/codac-uda-signals/ and embedded in the evidence. Negative control: a figure with a label beyond the canvas is refused by the save function this section delivers, and no file is written.

§8 — A variable name yields a candidate plant component and control function

Delivers. Each scanned variable carries the plant-system and component code and the control-function token parsed from its name under the ITER signal and variable naming convention (IDM 2UT8SH), with the parser's provenance and an explicit outcome: parsed, partly parsed or not conforming. The original selector is preserved byte for byte. A plant-component entity exists in the schema with a parent hierarchy, and a parsed variable links to its component as a candidate, not as a verified identity.

Done when. For the scanned cohort the landing record gives the counts in each parse outcome and a sample of twenty parses checked by hand against the convention, using invented names in tracked files; no variable receives a component the parser did not derive. Negative control: a name that does not follow the convention is recorded as not conforming and gets no component.

§ Decisions

Does the Python import package become iter_codex , or does only the user-facing name change?

The package name is in 138,394 places and in every in-flight worktree. Changing only the distribution, command and MCP key is far smaller, and leaves an import name that no longer matches the product.

Are the fork and the iterorganization upstream repository renamed, and who does it?

A repository rename is outward-facing and needs the organisation's agreement. GitHub redirects the old address, but release automation, registry ownership and badges move with it.

What do the two servers advertise after the rename?

Today the client key is imas-cx and the data-dictionary server is imas-dd . The data-dictionary server is about IMAS and both sessions consulted say it keeps its name.
