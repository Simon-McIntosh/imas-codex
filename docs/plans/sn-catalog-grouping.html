Plan · standard names · S18

Group names by what they share

A family is assembled from HAS_PARENT edges, so seventeen species variants of one quantity are seventeen families of one. A domain is copied from the IDS a name was extracted from, so electron_temperature is filed under MHD. Both groupings come from provenance. This plan makes them come from the grammar and the physics.

§1 — Why the grouping is wrong

Measured in the consistency census, §4 to §7. Across 46 species families of four or more members, the median share of members opening their description differently is 0.90, because the family-anchor rule in the docs prompt never sees a sibling. No accepted name carries the ISN domain core_plasma_physics, while transport holds 850 and 207 have no domain. Vocabulary overlaps such as neutral against neutral_state produce pairs at cosine 0.98 whose descriptions do not say what separates them. 38 names have bit-identical embeddings from text that is not their own.

§2 — Pattern families from the grammar

A pattern family is the set of live names whose ISN parse is identical except along one variation axis: subject or species, component, locus, region or device. Build it in imas_codex/standard_names/families.py, which already owns family detection and axis ordering, from the canonical segment columns the graph carries. Then make fetch_sibling_family in imas_codex/standard_names/context.py and assemble_family in imas_codex/standard_names/harmonize.py use it. The physical_base fallback in assemble_family is retired: a seed with no parent edge gets its pattern family. A family-eligible HAS_PARENT edge stays as a second, explicit route only because the operator axis is not one of the five pattern axes, so a parent and its operator-derived children have no other route. The section records how many live families only that route produces, so a later change can retire it on a number. There is one definition of a family, and the docs prompt, the harmonize command and the catalog ordering all read it.

The locus axis varies only across loci that place one quantity somewhere: the ISN locus registry's position, geometry and region types (at, over, along). An entity locus (of) names a different object each time, so it is part of the invariant signature: radial_coordinate_of_<owner> over 34 distinct owners is grammar ancestry, not prose parallelism, which is why f2d15655b excluded locus ancestry from documentation families and why that exclusion stands. An empty locus is a value of the axis only beside position, geometry and region loci, so electron_temperature and electron_temperature_at_magnetic_axis are family-mates while no two entity owners are.

This also closes the vector-component residue of the retired grammar-refinement plan: the component axis is already parsed into sn.component, and a pattern family over it is the "distinguished dimension" that plan asked for. No schema field is added.

Done when: the 17 flux_surface_averaged_<species>_density_at_plasma_boundary names resolve to one family of 17 in a test over a fixture graph. A name with no axis sibling resolves to a family of one, not an error. The live count of pattern families with three or more members is recorded, beside the HAS_PARENT count it replaces.

§3 — Domains from the DD graph, derived one way, kept consistent

Lead rulings, 2026-10-13 to 2026-10-16. The DD graph supplies a name's domain candidates. The IDSs are grouped into domains first, and the lead settled that map with 25 changes. On 2026-10-16 the lead reversed the 2026-10-13 ruling against a name-level classifier: a name's domain is decided by Jev, as one Choice per name over the candidates the DD supplies. Those candidates are the source paths' domains, the source IDSs' mapped domains, the band umbrellas and general, with the IDS prior and each candidate's scope text in the state. That Choice was measured and beat set precedence and the IDS-first rule (merge 9845ff555). The work left is one writer that stores the decision and keeps the graph consistent, and the repair of the live names.

Every source node carries a domain, but the per-path classification is degenerate. 61,337 of the 61,366 DD nodes carry exactly their IDS's domain, and so do 12,030 of the 12,038 paths the classifier in imas_codex/graph/dd_domain_classifier.py labelled with an LLM (gpt-5.4, last run 2026-07-22). Electron density in core_profiles therefore reads transport, and every summary quantity reads general. The names then drifted from even those values: most of the 560 carry a more specific domain than a general summary source. Several rules write a name's domain today: compose copies the source's, consolidation promotes by rank, a derived parent takes its children's most frequent domain, and further sites in imas_codex/standard_names/graph_ops.py coalesce or copy whatever value is to hand.

Edges carry every source domain, by design. The edge writer in _write_standard_name_edges writes one HAS_PHYSICS_DOMAIN edge per entry of source_domains, so a name stays discoverable from every domain it draws on; 123 live names carry more than one edge, which is correct. The catalog-edit writer behind sn reclassify instead deletes all of a name's edges and leaves one, and the derived-parent writers set the scalar without writing edges at all. The defect is the disagreement between writers, not the multiplicity.

Why the DD domains echo their IDS. Diagnosed on 2026-10-13 by scg-dd-domain-diagnosis; its evidence is commit 5b31377c7 until it lands at docs/evidence/fragments/sn-catalog-grouping/scg-dd-domain-diagnosis.html. The DD build MERGEs every path and SETs physics_domain to its IDS default unconditionally (build_dd.py, the path upsert), without clearing domain_source or domain_classified_at. The classifier then selects only paths whose domain_source is null, so it never revisits them. The 12,011 classifications of 2026-06-18 were overwritten by the rebuild of 2026-07-22, which re-classified only 23 paths. Separately, the classifier prompt's vocabulary table lists 21 of the 32 domains, omitting core_plasma_physics among others, and its worked example maps electron temperature in core_profiles to transport. Measured on the DD sources of the labelled names, a name's labelled domain is among its sources' stored domains for 11 of the 20 lead-approved names and 63 of the 150, and among a fresh classification's for 11 and 67. The graph holds no Cluster nodes, so the cluster-weighted rank is empty and pick_primary_domain falls back to alphabetical order: the name domain it derives matches 1 of the 20.

The design.

  1. One source of truth. IMASNode.physics_domain, written only by the DD classifier (its three tiers and imas_codex/definitions/physics/path_domain_overrides.json). Find why its output echoes the IDS domain and fix the classifier, not its consumers. Measure it on the DD sources of the 170 labelled names in docs/evidence/fragments/sn-catalog-grouping/scg-domain-label-sheet.json (the twenty the lead approved and the 150 the coordinator labelled) before and after the fix. The fix has two parts: the build writes the IDS default only on a path that carries no classification, so a rebuild never discards one; and the prompt's vocabulary is rendered from the PhysicsDomain enum, so it cannot fall behind it, with the worked example corrected. Then re-classify the DD paths that are standard-name sources, recording domain_source. The re-classification spends LLM budget and runs only on the lead's approval of its ceiling.
  2. One decision, one writer. A name's source_domains is exactly the set of its current DD sources' domains; a derived parent's is the union of its children's. Its physics_domain is the measured Jev Choice over its candidates. That decision is stored with the candidates it chose among, so it is reproducible and the audit can check it. When Jev cannot decide a name, because the call fails or no candidate clears its confidence floor, the name keeps its current domain and is reported as undecided. It never receives a guessed one. The selectors that decide a name's domain today stop deciding it: select_primary_domain and maybe_promote_domain in imas_codex/standard_names/domain_ranking.py, which the audit and the consolidation, export and catalog-import writers call, and the derived parents' most-frequent-child rule. Compose, consolidation, catalog import, export and every graph-ops writer go through the one writer. It sets physics_domain, source_domains and the HAS_PHYSICS_DOMAIN edges together, one edge per entry of source_domains, so the three cannot disagree. A correction the lead approves for a name the Choice gets wrong is recorded with its reason and applied by the same writer.
  3. A consistency audit in the standard-name audits. For every live name it checks that physics_domain is set and equals the stored decision or a recorded correction, that source_domains equals its sources' set (its children's, for a derived parent), and that its HAS_PHYSICS_DOMAIN edges are exactly source_domains. Its counts are the instrument for the repair.
  4. Repair through the writer, as an ordinary graph-ops operation with no hand Cypher. It runs after the DD re-classification and after sn-integrity-backlog §38 restores the lost DD sources, because a name with no source has no candidates to decide among.

Done when: the fixed DD classifier is measured on the DD sources of the labelled names, and its accuracy without overrides is reported beside the diagnosis's figures above, for the twenty and the 150. After re-classification and repair, each of the twenty lead-approved names carries its approved domain, reached through the stored Jev decision or through a lead-approved correction that records its reason. The standard-name DD source paths are re-classified with domain_source recorded. A DD rebuild over a classified path leaves its domain and domain_source unchanged, shown by a test that fails with the old upsert. Every writer of a name's domain goes through the one writer, shown by a test that fails when a writer computes its own. The consistency audit reports zero on every check over the live names, against the census above, apart from the undecided names it lists. §4 — Near-duplicate spellings, adjudicated once

Generate the worklist by extending synonym_check in imas_codex/standard_names/audits.py, the existing name near-duplicate detector, with the unit filter and the threshold as parameters. Do not add a fourth near-duplicate pass beside it, fetch_review_neighbours in context.py and nearest_registered_token in vocab_semantic_dedup.py. The worklist holds live pairs with the same unit, embedding cosine at or above 0.95, and different spellings (one differing token is enough, so neutral against neutral_state is in), excluding the §5 vectors. Scope it to pairs with at least one WEST member first.

Jev first judges each pair in the shape of the entity-alignment cookbook:

  • one Score with three levels — distinct quantities; related and needing a ruling; the same quantity;
  • a companion Noul per grammar segment, asking whether the two names differ there.

The worklist is then ordered by that verdict, and every pair arrives showing where it diverges. Golden D is binary, so for measurement the Score is read as one number: the probability of its top level, the same quantity. That number's AUC against golden D's synonym-versus-distinct labels is reported once the synonym side exists (sn-judgment-evaluation §5, at least 40 lead-ruled pairs). The middle level routes a pair to the coordinator and is not scored. Until that measurement exists, the verdicts order the coordinator's reading and decide nothing on their own, so the adjudication need not wait for the golden. The coordinator classifies each overlap rather than each pair, since one ruling settles every pair the overlap produces:

  • Distinct — both names stand. The house-style template for each gains the sentence that separates them, for example a charge-state-resolved quantity against its species total.
  • Synonym — one spelling survives, and the other is folded into it with sn supersede or renamed with sn edit. Never by hand, and never deleting an identity that carries spend.
  • Vocabulary overlap — the grammar offers two tokens for one meaning (neutral and neutral_state, at_divertor_target and of_divertor). The ruling is an ISN vocabulary decision, filed upstream with the measured pairs.

Done when: every overlap touching the WEST roster carries a recorded ruling with its pairs. Every synonym ruling inside the roster has been applied through the sanctioned route, and the roster still resolves. The rest of the corpus has a worklist in the same format, ready for the post-WEST pass.

§6 — One domain precedence, kept in the guidance and used by the classifier

The DD-path measure (scg-domain-path-measure, merged at 14a60fdcc) found that the Jev tree and the chat classifier make the same mistakes, at the same rates. Across both classifiers' confusions there are 82 confused domain pairs. In 43 of them the guidance is silent; in the other 39 it separates the pair. The lead's ruling of 2026-10-14: "our categorization of our categories is wrong if we cannot sort them, or we need to better define a tie-break strategy with a preferred node, such as preferring equilibrium over balance of plant."

A precedence already exists. FALLBACK_RANK_TABLE in imas_codex/standard_names/domain_ranking.py ranks every domain:

  • core physics first, with equilibrium at the top;
  • then heating and current drive;
  • then edge;
  • then diagnostics;
  • then operations and plant;
  • then data management;
  • then general.

select_primary_domain uses it to choose a name's domain from its source paths. The path classifier never sees it, so the two disagree on exactly the paths where two domains fit.

Make one precedence the classifier's tie-break, kept in one place:

  • Move the order into imas_codex/definitions/physics/domains.yaml as precedence, with a one-line rationale for each band.
  • domain_ranking reads it.
  • The guidance loader in imas_codex/definitions/physics/__init__.py refuses an order that misses or repeats a domain of ISN's vocabulary.
  • The tree's questions, rendered in imas_codex/graph/dd_domain_classifier.py (the category and domain question builders that decide_domain_tree calls), state the rule: when more than one option's scope fits the path, choose the one earliest in the precedence. Render each level's options in precedence order.
  • Keep the order as it stands. The lead adjusts it on reading the fragment; this section does not re-rank.

Done when: stubbed tests show the following.

  • select_primary_domain and the rendered domain question read the same order from the guidance file.
  • The loader refuses an order with a missing or repeated domain.
  • The rendered questions carry the tie-break rule and list options in that order.
  • Each test fails with its mechanism removed.

The fragment prints the order beside its bands' rationale.

§7 — Domain scopes that sort, and path labels by rule

In the 39 confused pairs the guidance separates, both classifiers follow the guidance and the label disagrees. The labels were inherited from names. A name such as electron_temperature spans core and edge profiles, so its edge paths carry a core label. Instrument geometry also falls between diagnostic families: bolometer apertures are labelled plasma diagnostics, but the guidance says radiation. A domain set whose definitions cannot sort these paths is wrong, so the specification is repaired before any classifier is tuned.

For each confused pair in the path measure, decide which of two things it is.

  • A definition defect. The two scopes claim the same quantity. Rewrite one scope in domains.yaml so that the two exclude each other, with an excludes entry naming the neighbour.
  • A genuine overlap. The quantity belongs to both domains. It is resolved by §6's precedence, and the guidance says so.

Then label the 201 measured paths at the path level by rule. Each path takes the domain the revised scopes give it, with precedence settling a genuine overlap. List every label that changes, with the rule that changed it. Never take a label from a classifier's answer.

Done when: the fragment docs/evidence/fragments/sn-catalog-grouping/scg-domain-scopes.html gives every confused pair its verdict, definition defect or genuine overlap, with the scope edit or the precedence that settles it. It lists every changed path label with its rule. The revised domains.yaml loads under its existing tests and passes the §6 loader. A re-score of the tree's saved path answers against the new labels, with no paid call, reports path-level accuracy beside the old figure.
