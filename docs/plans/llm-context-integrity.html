LLM Context Integrity and Typed Prompt Envelopes

The reported Standard Name folds are symptoms of a wider authority bug: related evidence is injected as though it proves identity. This plan replaces raw prompt concatenation with typed, inspectable context for every active imas-codex LLM call site.

Workstreams and closure gates

  1. Freeze: executable call-site/template/field inventory, rendered prompt hashes and a human-labelled contamination corpus.
  2. Type: LinkML/Pydantic authority envelope, strict rendering, independent static/dynamic fingerprints and exact token receipts.
  3. Migrate: every active service call site; no legacy dispatcher, permissive undefined field or raw context concatenation remains.
  4. Prove: production-faithful golden rendering, cross-item leakage tests, ninth-plus source coverage, frame/plane preservation and per-seat allowlists.
  5. Release: full service suites and a mechanical inventory comparison show complete coverage before downstream hardening starts.

§ Decisions

How much of the imas-codex LLM surface must migrate before WEST?

The audit found 23 structured-dispatch expressions, 22 active, across Standard Names, DD enrichment, facility discovery, mapping, and benchmark paths. Partial migration would leave the same untyped authority-pollution class reachable elsewhere.

Locked by the lead: every LLM call site must receive a proper review of dynamically injected and templated context before WEST. The migration is project-wide, not a Standard Names-only patch.

What LLM work may proceed while context authority is being rebuilt?

Broad paid generation or review could make graph debt worse before the renderer and authority envelope are corrected.

Locked by the lead. Broad production generation and paid review remain paused until typed context, adversarial goldens, and dispatcher gates pass. Exact gated recovery may proceed only through the hardened path.
