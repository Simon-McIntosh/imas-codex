§1 — The census, and the two different things inside it

A StandardNameSource is an extracted Data Dictionary quantity that should produce a standard name. Of 9,900 such rows, 5,441 are bound to a name through a PRODUCED_NAME edge and 4,459 are not. The unbound population is not one thing:

The 1,652 stale rows are not a defect and this plan does not touch them: a source rebinds when its name is superseded, so residue there is the mechanism working. Naming that explicitly matters, because a census that reports 4,459 unbound sources as a single backlog overstates the problem by more than a third.

§2 — 1,283 extracted quantities that never became a name

These carry status = 'extracted' and no producer edge: the pipeline pulled the quantity out of the Data Dictionary and never composed a standard name for it. That is throughput, not damage — but it is throughput nobody has counted, and it sets the ceiling on Data Dictionary coverage. For scale, 5,072 of 61,366 IMASNode paths currently carry a standard name; most of that gap is program incompleteness rather than defect, and this 1,283 is the part already extracted and therefore cheapest to close.

The work is a bounded sn run composition pass, not a repair. Before running it, establish how many of the 1,283 are eligible under the current admission rules rather than assuming all are — a source that was extracted before a rule tightened may now be correctly inadmissible, and composing it would mint a name the review pool then rejects.

§3 — 1,413 skipped, and 398 of them say nothing about why

This is the half that is a defect. A skipped source is permanently excluded from composition, so the reason is the only thing standing between a deliberate exclusion and a silent one. 398 rows carry no recorded reason at all.

The mechanism is known and it is narrow: non_nameable_reason is written only when source_status == 'skipped' (imas_codex/standard_names/graph_ops.py:12324), and it never reads last_error — so a source that failed with a diagnostic and was later marked skipped loses the diagnostic. The same shape appears in the failed population: rows carrying failed with an empty last_error.

Two deliverables, and the first is the one that lasts: make the write path unable to record a skip without a reason, then reconstruct the missing 398 from whatever evidence survives and mark as unknown the ones where nothing does. An honest unknown is a finding; a blank field is not.

§4 — Why this is separate from the deletion recovery

The deletion incident of 2026-09-08 left 67 standard names absent and their sources unbound, and it would be easy to fold this backlog into that recovery because both surface as unbound sources. They are different work and folding them would put a 1,283-name composition job behind a recovery that must not wait for it. The recovery is owned by the deletion-protection plan; this plan owns the sources that never had a name in the first place.

Lead direction, 2026-09-17: it must be possible to generate all names from a manifest, and the fact that a residue is hard does not license carrying it as an exclusion.
