Closing the Residual Standard Name Integrity Classes

Why this plan exists

sn-graph-wide-integrity reached a measured close, was marked shipped, and then reopened when two naming principles were made binding: a name must be self-describing, and every Standard Name should have a source. Those principles turned its closing disposition of 17 unsourced identities back into a live worklist, because attached had been recorded as a disposition rather than as a claim that each legacy identity gained a producer.

This plan carries the residue to zero or to named refusals. It is deliberately a separate plan: the parent plan's own sections are a historical record of how each class was found, and grafting a second closure pass onto them would make that record unreadable.

§1 — Finish the flux-surface umbrella retirement

Ready. Nothing blocks this. The umbrella area_of_flux_surface is a taxonomy node masquerading as a quantity: its only producer is the synthetic derived: row the reconcile mints for bare parents, its description names a category rather than a physical quantity, and its children span three different units (m^2, Wb^-1.m^2, m) so no physical parent relation can hold.

One of three invocations has applied: both flux-coordinate derivative children now sit under poloidal_plane_cross_sectional_area_of_flux_surface, which is where the DD derivative relationship already put them — darea_dpsi and darea_drho_tor differentiate profiles_1d/area, one of that identity's 21 producers.

§3 — Attach the sixteen reverse-search candidates

The reverse dictionary search found unit-agreeing exact DD paths for 16 of the 17 then-unsourced identities, across 51 distinct semantic queries and 577 inspected path and cluster groups. Nine are clean — the candidate agrees on unit and no canonical identity already owns the path. Seven need adjudication first, because attaching them would bind a second live identity to a path a canonical name already holds, recreating the dual-bound defect this programme spent 19 signed repairs removing.

Five of those seven were resolved as lineage supersedes and have landed. The remainder are: fast_ion_charge_state_power_at_inside_flux_surface, which must wait on the Data Dictionary issue in §6 because attaching it now encodes a contradiction; and neutron_flux_due_to_fusion, whose rank-1 candidate is unit s^-1 against a name unit of Hz — dimensionally identical and now correctly agreeing under the dimensional adjudicator, so it is attachable.

The one identity with no candidate is toroidal_trapped_thermal_ion_charge_state_torque_density_due_to_collisions, and that negative is sound: every unit-agreeing torque path makes trapped describe the source distribution and thermal the recipient, while the name conflates both onto the recipient. Retired on physics, not on a rank-limited miss.

§6 — Upstream and cross-repository follow-through

Data Dictionary. Of four measured contradictions, the duplicate search reduced the worklist to one: the sensor direction X and Z pair were already fixed by merged upstream PR 242, and the ion-state torque path already exists on develop, making that one ours to remeasure rather than theirs to fix. The genuine defect is filed as issue 294 with PR 295 closing it. The PR notes that the species-level waves_coherent_wave_profiles_1d_ion pair carries the identical wording and offers its inclusion; awaiting the maintainer's preference.

Naming, under the self-describing rule. mass_density states neither subject nor aggregation in its name while its description claims a charged-species sum, so it is a name question for ordinary review rather than a docs edit. The catalog already carries the three-rung ladder mass_density → plasma_mass_density → total_plasma_mass_density, and ISN carries total as one of two aggregation tokens, so the vocabulary supports the distinction. This generalises: every short spelling whose meaning lives only in prose is now suspect, which is a catalog-wide audit belonging to the documentation-quality programme rather than to binding repair.

Reckon tooling. Four tool defects and three documentation gaps were measured while running this work. They belong to the reckon repository, not here, and need their own authorization: cross-backend session reuse silently attempts to resume a foreign thread and fails indistinguishably from quota exhaustion; crew resume returns success when it did not launch; crew complete cannot be amended once a live pointer is gone; and the observe classifier could separate quota exhaustion from a session collision, since only the stream distinguishes them.

§7 — Execution notes learned the expensive way

These cost real waves during the predecessor and are restated because they will bite again.

  • Prove a mutation absent by receipt run_id and manifest digest, never by an operation-name query or a bare counter total. A zero-write audit that counted receipts by operation name reported an already-committed 19-row transaction as refused.
  • Every apply derives its own cohort and re-reads its counters inside the applying invocation. Fixed cohorts computed in an earlier node are stale the moment any authorized transaction commits.
  • One production mutator at a time. Two concurrent signed applies void each other's out-of-allowlist immutability proofs. Parallel width comes from evidence and disposable-graph nodes.
  • A supersede target must pass the naming principle before the batch is authored. A target challenged after the apply has already committed cannot be un-chosen.
  • Check that the machinery can produce the measure before making it a gate. Three contracts in the predecessor demanded measures no code path could emit: a suite-wide zero-failure with a known out-of-fence flake, a single invocation spanning mutation kinds the loader refuses by design, and a release program that did not exist.
  • Never background a test run and then poll it. Two nodes lost their turns to exactly that pattern, finishing the work and delivering no manifest. Redirect to a log ending with an exit marker and read it once.
  • Generated models are gitignored and regenerate per worktree. A schema fix can read as still-broken in the main checkout until build-models --force runs there.
