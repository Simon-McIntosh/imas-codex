§4 — EDDB units parse

The map stage writes unit conversions, and it reads each source's unit to do so. EDDB stores units as free text. 1,482 JT-60SA signals carry a unit normalize_unit_symbol (imas_codex/units/__init__.py:96) cannot parse, among them uST (480), n/day (371), MPaG (187), KA, DEG, DegC, oC, KV and the Pa*m3/s family. jt60sa-discovery-completion parked this as followup f-jdc-004 because it belongs to DD binding, and this plan adopts it.

A FacilitySignal carries its unit as a string. The schema gives it no HAS_UNIT relationship; only SignalNode has one. The map stage reads the representative's unit string and parses it through the same pint registry: the claim projects rep.unit, and analyze_units (imas_codex/ids/tools.py:167) compares it with the IMAS field's unit. So the repair is a parse, not a link. The JT-60SA spellings are added to imas_codex/units/data_dictionary_unit_aliases.txt, the one alias file the registry loads (imas_codex/units/__init__.py:48). That file already carries per-source spellings, including case-sensitive MDSplus aliases, so it stays the single owner, and every path parses the same spelling the same way. A spelling that names no physical unit is listed as unresolved with its count, never guessed. Unit is one such spelling; gauge pressure (MPaG) is another, because it is not an absolute pressure.

§6 — Every home, audited

Draw 40 JT-60SA sources across the EDAS categories. Label each for every DD home it has, in any IDS, without seeing its candidates. Unlike the mapping-candidate-selection §3 labels, the IDS is not fixed first, so a second home such as the plasma current's measured constraint in equilibrium is scored. Under the recommended defaults every source routes escalated, so the measures read the stored candidate edges:

  • the share of labelled homes whose section is in the source's escalated list (its top five and their cluster siblings), and the same share at node level;
  • how many sources have homes in two or more IDSs, and how many of those homes the list carries;
  • section-level precision of a Jev-alone selection at the §3 thresholds, computed from the stored probabilities;
  • the share of sources with no DD home that a floor of 0.1 would have caught.

§7 — Map JT-60SA

Run imas-codex imas map run jt-60sa once for each IDS that holds a candidate, with --no-activate and under a USD 10 cap on the reasoning seat. The map stage then maps each source into every IDS of its picks, checking each mapped field against the picked node's section. Validation runs per IDS. Activation is a separate decision, made after the audit.

§8 — Jev rerank in DD-path search

The candidate stage already reranks DD paths with Jev for each source. The search_dd_paths tool, which a person uses to check or correct a binding, does not. discovery-judgments-through-jev §9 is building a search-time Jev rerank for code and wiki search; its prototype raised nDCG@10 from 0.25 to 0.51. The DD-path tool reuses that rerank owner and does not build a second one. Its own measure uses mapping questions: the plasma current's homes, where flux-loop positions live, which IDS holds a coil current.

§ Decisions

How does a signal in no SignalSource reach the mapping pipeline?

Lead approved §3 on 2026-10-07, and §3 is written for this option. detect_signal_sources gains a final pass that makes each signal it left ungrouped a one-member source through its own MERGE, so every mapping stage keeps keying on SignalSource and no second claim path is built for bare signals.

When are JT-60SA mappings activated?

The recommendation is after the audit, per IDS. Validation checks that a binding executes, not that it chose the right home.
