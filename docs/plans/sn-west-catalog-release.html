WEST Catalog Release and Graph Fold-Back

This plan does not repair, generate or approve the WEST cohort. It consumes a frozen human-reviewed packet from the hardened current graph, publishes only those exact dispositions, and proves reversible graph/catalog parity.

Hard entry gate

  • The complete pre-WEST hardening sprint is closed on a committed, independently validated graph/code/schema baseline.
  • The expert-review plan has an explicit disposition and content hash for every WEST row.
  • No open claim, scope, run, durable admission, ambiguous DD resolution or unexplained semantic hold is present.

§ Decisions

Does the unreleased WEST cohort receive special graph protection?

Special protection would preserve known semantic defects and make the human batch differ from the graph-wide quality standard.

Locked by the lead: WEST names are not protected. Only already published catalog authority and test fixtures retain their normal safeguards.

How does the published catalog carry each name's physics domain?

PR 7's preview showed every name Uncategorized with a blank detail view. Root cause: imas-standard-names 0.8.0 lists physics_domain in yaml_store._STRIPPED_FIELDS (tolerated on load, dropped before entry-model validation) while its own catalog site reads entry physics_domain for the Domain grouping; the codex exporter had been narrowed to model-declared fields and stopped emitting it.

Lead ruling 2026-09-02: a field the catalog site depends on cannot be a stripped legacy field in the same release; do not work around, fix properly in ISN. physics_domain is DD-authoritative on every standard name, so it becomes a required field on StandardNameEntryBase validated against the existing PhysicsDomain enum, is removed from _STRIPPED_FIELDS, and the site keeps reading it. The exporter emits it because the model declares it. A new ISN release carries the change and the imas-codex and catalog-tooling pins move to it before the WEST candidate is re-cut.
