§1 — Why this plan exists

This plan exists so the WEST release stops being blocked by work it does not depend on. Names were generated across roughly half the DD catalog deliberately and broadly, to shake out errors. That succeeded — it surfaced a large number of genuine defects — but the exploratory half is not a release set, and repeatedly widening scope into it has delayed the one thing the parent plan exists to do: get a human into the review loop.

Everything here is real and tracked. None of it is release-blocking for sn-west-review-rehearsal, and the split was made by measurement rather than by judgement — see §2 for the method.

§2 — How the split was measured

Every open defect was partitioned by asking one question of the live graph: does it touch a path in the 355-source WEST manifest, or a name that a WEST path produces? 262 names are produced by at least one WEST path. Anything outside that set landed here.

§3 — Orphaned names: 151, and the number is the finding

A name with no producing source has lost its entire justification. The heal surfaced these rather than auto-superseding them, because whether the concept survives is a human decision. By stage: 114 exhausted, 22 accepted, 10 pending, 5 reviewed.

The 114 exhausted ones are cheap: a name that reached the refine cap and then lost every source is dead twice over and can be superseded in bulk. The 22 accepted are the real work — each was catalog-eligible, so each needs a decision: supersede, or re-source from a DD path that genuinely realizes it. Three worked examples showing why this is judgement and not bookkeeping:

  • tritium_density and deuterium_density were sourced solely from neutron_diagnostic/reconstructed_emissivity/fuel_ratio — a dimensionless ratio. The names are real physics that deserve re-sourcing from actual density paths; the attachment was the defect.
  • time_derivative_of_bremsstrahlung_count_at_detector_pixel had one source, a plain intensity path. The concept was invented from a mis-attachment and should go.
  • The six *_measurement_direction_unit_vector_of_strain_gauge names lost their sources to the dimensionality rule (the DD tags unit vectors m). Those are registry-excepted DD defects, so the names are right and the detachment needs reviewing.

Do not bulk-supersede the accepted 22. Do not fabricate a source for any of them.

A line-of-sight point legitimately carries both a sightline name and a beam-tracing name; bremsstrahlung_visible/channel/radiance_spectral carries both spectral_bremsstrahlung_radiance and spectral_radiance. §4b — Names leave the graph without a ledger row

The deep sweep (2026-07-29) proved the deletion side of the ledger is open: 296 StandardNameChange rows cite a to_name with no surviving node (refine 172, campaign_docs_refine 113, reclassify_domain 5, backfill_refine 3, regenerate 3), and perturbed_particle_energy — alive and docs-quarantined mid-campaign — left via a bulk DETACH DELETE that writes no ledger row (the reset paths at graph_ops.py:5199/:5052/:5066/:3108). The invariant to establish: no StandardName leaves the graph without a ledger row naming the operation that removed it — every delete path writes its change record, and a graph-quality test asserts no ledger row cites a nonexistent name unless a deletion record explains it.

§5 — Write-path gating and the guard's blind spot

Per-path verdicts with file:line are recorded in the write-path verdicts. Three of the four ungated paths land here (the fourth, persist_refined_name, is WEST-blocking):

  • write_standard_names — the bulk persist writes the DD-side projection with no guard at all, so an import-shaped batch bypasses the compose gates entirely.
  • bind_sources_exclusively / retarget_standard_name_sources — exclusive rebind onto a different name is a fresh claim about every source moved, and it deletes the prior edges, so an ungated rename both mis-attaches and destroys the evidence.
  • reconcile_standard_name_dd_edges — already applies the unit rule; extend it to the full guard. Cheap and additive.
  • The recovery-snapshot replay needs no write-time guard but is a non-exclusive MERGE, so it leaves a replayed set coexisting with a later recompose. Make a consistency reconcile mandatory immediately after any rebuild, in the same operation.

Four paths must NOT be gated — the derived-parent materializer, the orphan-parent reconcile, the provenance edge reattach, and the snapshot replay. Each re-establishes an edge against the same name or builds scaffolding the guard was never calibrated for; gating a faithful reconstruction with a newer rule destroys history rather than protecting it.

The guard's blind spot. A missing geometry-representation rule: a path under …/geometry/{thick_line,outline,rectangle,oblique,arcs_of_circle}/… describes a solid conductor's poloidal cross-section, not an optical path, and must not realize a line_of_sight/beam name. 29 attachments are wrong this way and the guard accepts every one — both sides are metres so the dimensionality rule is silent, and the locus tokens are not hardware words. Zero thick_line paths are in the WEST manifest, which is why this sits here rather than in the release plan. Separately, the *_outline_of_* family is damaged and unsized: vertical_outline_of_antenna_strap has swallowed 15 unrelated paths (cryostat, vessel, contour-tree, iron-core outlines). Do not rebind thick_line paths into that family.

§6b — Unit authority: the null-unit parents, and a shipped verdict to overturn

Eight accepted names carry no unit at all (measured 2026-07-29) — every one an unrealized origin='derived' structural parent: effective_particle_energy, greenwald_density, hydrogenic_density, total_hydrogenic_density, difference_of_total_hydrogenic_density_and_neutral_state_density, current_of_antenna_strap, flux_due_to_e_cross_b_drift, square_toroidal_flux_radius_gradient. Their bases (energy, density, current, flux) are exactly the ones ISN marks inherently dimensional — yet the validator only flags unit='1' on such bases, and unit=None slips through as validation_status=valid.

The lead has challenged the shipped adjudication (sn-dd-unit-curation §4, 2026-07-23) that recorded effective_particle_energy and perturbed_particle_energy as “intentional unit-less normalised-coordinate parents”: a report listing names asserting an energy as “unit-less” does not read as correct. The challenge is well-founded twice over — the dimensionless role already belongs to the normalized_* child (a parent that is itself a normalized coordinate makes the child a normalization of a normalization), and perturbed_particle_energy no longer exists in the graph at all while the shipped “intentional” record still cites it — a ghost disposition. Work: lock D-parent-units below; repair the eight per the locked policy; find how perturbed_particle_energy left the graph and whether other shipped dispositions cite ghosts. Precision from the ISN sweep (2026-07-29): the null-unit check EXISTS and fires (_check_none_unit_with_quantitative_kind, validation/semantic.py:593) — the gap is that run_semantic_checks has exactly one caller (the codex LLM-candidate ladder, guarded by a unit assert), so the derived-parent mint path never reaches it; and unit=None crashes the scalar-entry canonicalizer with a raw TypeError (models.py:347) that codex swallows as [pydantic:unknown]. The same mint-path hole admitted 7 internal_state_* derived parents that fail the validity oracle outright (the species peel left a bare state token) — 15 accepted names corpus-wide fail the oracle, none in the WEST batch. So the fix is: the derived-parent mint runs the oracle and the unit rule (B3 option 2 — a dimensional base requires a unit sourced from the child, exempting dimensionless/dimension-transforming operators), plus a rotation-sized None guard in ISN's canonicalizer.

§7 — Sequencing and budget

Compose is free (local GPU); review is the only paid stage, measured at $0.27/name. A graph-wide review of the ~890 sources awaiting compose is therefore roughly $150–250 — real money, and the reason this is a separate plan rather than a tail on the release.

Recommended order, cheapest-signal-first:

  1. Settle the fan-out invariant (§4). Free, and it decides whether 240 of the 1458 violations are defects at all.
  2. The embed dimension mismatch (§6). Independent, breaks a whole capability, probably small.
  3. Find the supersede-without-retarget path (§4, 596 cases). One code fix likely collapses the largest class.
  4. Gate the three write paths + add the geometry rule (§5). Free, and it stops the defect classes regenerating.
  5. Then the orphan decisions (§3) and a budgeted graph-wide review — in that order, because gating first means the review does not have to be repeated.

§ Decisions

D-fanout — may one DD path legitimately produce two live standard names, or is single-valued PRODUCED_NAME the invariant?

Fresh live audit on 2026-08-02 found 340 competing non-WEST sources. Of these, 334 already had a scalar selecting one candidate, 239 included a catalog-edit candidate, only 222 had exclusively accepted-valid targets, and representative pairs were competing generic versus specific or geometrically incompatible interpretations. WEST repair proves one live source target is achievable while semantic hierarchy remains represented by name relationships. Therefore fan-out is a provenance defect; retain the strict checker and repair the data and writers.

D-orphans — how to treat the 151 names left with no producing source?

Live recovery established a conservative evidence split: rebind names only when catalog, DD, structural-parent, scalar-plus-relationship, or safe history evidence is unique; retire identities only when every authoritative source is absent; leave ambiguity visible for individual review. This policy produced zero remaining provenance-orphan names with a durable change ledger.

D-parent-units — must an accepted derived structural parent on an inherently-dimensional base carry a unit?

Eight accepted derived parents carry unit=None; the ISN validator flags unit='1' on inherently-dimensional bases but not unit=None. The shipped sn-dd-unit-curation §4 verdict recorded two of them as 'intentional unit-less normalised-coordinate parents' — challenged by the lead 2026-07-29: the dimensionless role belongs to the normalized_* child, and one cited name (perturbed_particle_energy) no longer exists in the graph.

Locked by the lead 2026-07-29: parent units are REQUIRED, and the unit must match the PARENT'S OWN quantity — not blind child inheritance. A parent can have a normalized_* child, so parent and child units will not always match: the unit is derived from what the parent's name asserts (its base semantics), with child-sourcing valid only when the child is not a dimension-transforming variant (exempt the dimensionless / dimension-transforming operator sets, e.g. normalized, perturbed). Consequences: the derived-parent mint runs the validity oracle and this unit rule (a dimensional base with no derivable unit is un-mintable, not silently null); the ISN canonicalizer gains the None guard so a missing unit raises the promised validation error; the eight null-unit parents are repaired to their own dimensional units (energy J or eV per catalog convention, density m^-3, current A, the operator-transformed and binary cases per their own semantics).
