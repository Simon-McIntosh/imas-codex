Can the rubric express the defects the audit found? Four of six, and the gap is a field rather than a dimension

Question. The name audit found 74 defective bindings over 61 identities that the review pipeline had already scored and accepted. Before asking why the reviewer missed them: if a correct reviewer had noticed each defect, was there a dimension to score it on and a field to carry the correction? A rubric that cannot express a defect makes a reviewer's correctness irrelevant. Read over the ten reviewer prompt files in imas_codex/llm/prompts/sn/ and the structured output models in imas_codex/standard_names/models.py the reviewer must fill.

The rubric is mostly not the reason. For two of the four expressible classes the prompt's language is sharper than the audit's own: it calls source-fidelity "the #1 silent failure" and its worked example is a strike-point path from this very cohort — a source path .../strike_point_inner_r substituted by a divertor-target spelling, "MUST be capped ≤ 6/20 with the mismatch cited" (review_names_system.md:142). The rubric names the family the audit later found defective and the cut shipped anyway, so for most classes the constraint is upstream: in the comparators the reviewer is shown, and in the fact that a per-identity review never holds two members of one container at once.

The genuine expressiveness gap is one field. A review model whose only correction slots are revised_name: str | None and suggested_name: str | None (models.py:1406) cannot propose a split — and a split is the repair for the one class the name audit called unrepairable by a reader, found 10 times over 24 bindings. A reviewer wanting to say "split this into three, here is which binding gets which" can only write prose into issues: list[str], which nothing downstream reads as a correction. Widening this is not a prompt edit; the natural shape is a per-binding list.

The second gap is one sentence, and the two prompts contradict each other. The docs prompt hands the reviewer the binding list under an instruction to penalise its use — "- **Source paths** (provenance context — dock if cited in output)" (review_docs_user.md:19, identically review_docs.md:148) — while the name prompt calls the same field the "authoritative bound-source cohort" (review_names_user.md:121). A docs reviewer that asked "does this documentation hold for every path in source_paths?" would find the measured strike-point contradiction immediately, and physics_accuracy plus revised_documentation would carry it. The dimension and the field are both there; the instruction that would make the reviewer look is not, and the instruction that is there points the other way.

The ordinal convention is encoded, and well. review_names_system.md:20-38 states it under its own HARD heading, names the reviewer verbs ("approve, or refine"), carves out the false positives (first_wall, a start that names a state), says what to emit instead (a vocab_gap), and is backed by a structural recogniser in code rather than asserted only in prose (_is_ordinal_point_sample, imas_codex/standard_names/workers.py:2685). Its two gaps are reach, not content: it appears in 3 of the 10 reviewer prompt files — absent from every docs and description prompt, where the audit's most-repeated description defect lives — and it lands on no dimension, so a reviewer following it has no told place to dock. The validator that clears an unparseable suggestion (models.py:1445) does not clear an ordinal one, because an ordinal-qualified name parses cleanly.

What this does not establish. This node read prompts and models; it changed no prompt, no model and no code, and it did not run the reviewer. Whether a reviewer actually uses the dimensions it has is a different question and belongs to the capability-gaps node.
