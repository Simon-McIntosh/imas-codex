Implementation. The per-candidate match lists are built first and then allocated with the same share-then-spend pass the semantic channel uses: every candidate receives max(1, unit_cap // batch_size) before the remainder is spent. The deduplication pass regained its terminal cap, sized at the sum of the two internally capped channels — unit_cap + semantic_cap, where unit_cap = max(k, batch_size) and the semantic channel is capped at min(max(k, batch_size), 60). At the defaults k=10 over a 15-item batch the returned neighbourhood holds at most 30 comparators; at the helper's 60-item ceiling, 120. The docstring previously called k a cap while neither channel was capped at k.

Evidence that could have failed. Two focused tests in tests/standard_names/test_review_comparator_budget.py pin the returned list: one asserts the per-candidate allocation above, one asserts the returned length equals the stated bound at saturation. The negative control replaced per_candidate_allowance = max(1, unit_cap // len(batch_names)) with per_candidate_allowance = unit_cap, restoring the first-come budget; the allocation test then failed with {'m': 10} while the bound test still passed, so the two tests discriminate. On all_debug, the full tests/standard_names/ suite recorded zero added failures against base revision d31f8cb92: 34 failures/errors at base, 23 at head, none introduced. The eleven that pass at head are export and manifest tests importing neither review/enrichment nor review/pipeline, and the comparison is asymmetric in the base's disfavour. The cause of that asymmetry was recorded here as a missing .env; that was wrong, and the measured cause is a missing .git. The base suite ran from an archive extraction, and _manifest_iso_timestamp (export.py:2652) refuses an export whose provenance it can resolve from neither a Git checkout nor SOURCE_DATE_EPOCH, raising export provenance timestamp unavailable. All eleven are export and manifest tests driving that path; none imports review/enrichment or review/pipeline, and all eleven pass in a real checkout. The direction of the argument is unchanged — the asymmetry can only make the base look worse, so it cannot manufacture the zero-added result — but the absolute base figure of 34 carries eleven failures inflicted by the measurement method, and the comparable figure for a checkout is 23, which is the head figure.

The general form, since it will recur. A git archive extraction is the honest way to measure a base revision while peers mutate the shared checkout, but it silently removes provenance that the export path requires. Any archive-based gate in this repository must supply it explicitly:

export SOURCE_DATE_EPOCH=$(git -C <repo> show -s --format=%ct <sha>)

Verified directly in the extraction: without the variable the call raises the refusal above; with it set the same call returns a timestamp. This is the same defect class as a job whose cd into a node-local directory fails and falls back to the shared checkout — a setup fault that reports itself as a plausible test count rather than as an error.
