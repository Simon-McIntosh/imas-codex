read_plan restored across the project

Every read_plan call in this project failed, whatever plan it asked for, on a path that was not the caller's plan. Resource resolution walks the whole documentation tree and raises on the first contract violation, so a layout fault in one research directory presented as a total read outage. Two concurrent sessions worked around it for a full day by reading each plan's plan-version meta tag directly.

After the sweep, 3 of 3 requested plans return with titles, versions, statuses and content digests: typed-resource-path-contract, sn-graph-identity-convention (v43, shipped) and sn-repair-operator-consolidation (v37, shipped). Verified independently from the main checkout after merge, because the docs server reads the main working tree and the fix existed only in a worktree until then.

The guard is proved to fail, not merely to pass

34 files accumulated under a rule that already existed, because the rule only fired at read time deep inside an unrelated call. The replacement walks the tree applying reckon's imported TYPE_ROOTS rather than a local restatement of them — a second transcription of that list is exactly the drift that once produced an 87-versus-34 miscount, since archive is not a typed root.

The test passes on two cases: it fails on a deliberately nested fixture, naming the offending path, and it accepts a legal evidence/archive/ path at two segments. A guard that has only ever seen a clean tree cannot be distinguished from a guard that cannot see, and it would be the thirty-fifth file that found out.

A second, older fault the move exposed but did not cause

With the nested-path error cleared, read_plan failed next on duplicate identities: three archived landing records under docs/archive/ each declared plan-slug=dd-graph-hygiene, the same slug as the live plan docs/dd-graph-hygiene.html. Four files claimed one identity and the three archives shadowed a real plan.

The worker stopped and asked rather than choosing a disposition the plan did not settle. They are section landing records, not three independently executable plans, so they are now reckon-type=evidence with identities derived from their already-unique basenames and a plan-evidence-for back-reference. They were not moved — docs/archive/ is not a typed root, so their paths were always legal — and not renamed, because the sprint-label fragments in their basenames are artifacts, which the naming rule exempts. Exactly one declaration of that slug now exists.

The instruction to stop again on a fourth distinct pre-existing defect was not triggered. A fail-closed contract exposing a queue of latent identity faults is itself a finding; a worker quietly draining it converts a measurable queue into an invisible one.
