What the collection error was hiding — cumulative evidence

This record consolidates what the hidden-suite-failures plan proved on 2026-09-01. The plan opened on a whole-tree census of 12,021 passed / 49 failed / 145 skipped / 1 xfailed taken the moment collection was restored, and it closes on the same command reporting every one of those 49 ids green. Every result below is reconciled against the committed run ledger at docs/state/imas-codex/crew.json and the manifests under ~/.config/reckon/crew/runs/. Dense count-to-commit mappings are tables; causal findings are prose. No figure is included because none of these relationships is clearer drawn than counted.

§3 — Every one of the 49 carries a verdict

Twenty of the 49 were repaired by their author at 8ee947b0 before this plan executed. The remaining 29 were triaged from a fresh run of exactly the seven files the census names, with the declared test extra provisioned into the shared root environment (torch 2.10.0+cpu): 162 passed, 1 failed, 6 skipped in 64.87 s. The verdicts were 28 environmental artifacts and one wrong premise; no row was a defect to fix here and none was owned elsewhere. Twenty-seven of the 28 were the missing test extra; the twenty-eighth was a remote-cleanup timeout that passed in 3.66 s once the environment was sane.

The wrong premise was test_missing_credential_explicit_graph_selection_exits_not_run. Its setup set NEO4J_PASSWORD to the default and believed that made the subprocess credentialless; project environment loading supplied the live credential anyway, so ambient graph state chose the branch. The repair overrides the credential probe inside the subprocess conftest, so the credentialless branch is deterministic: the test passes 1/1 with the live graph reachable and 1/1 with every NEO4J_* variable cleared, and it still pins the missing-credential message rather than the configured-graph-unavailable one.

§4 — The recurrence guard is delivery, and the extra fails once and loudly

The plan's own probe had shown that detection already existed: CI ran the bare whole-tree suite and was red on all 55 concluded runs, while 65 of 120 runs on main were cancelled by cancel-in-progress and reached no conclusion at all. The repository's half of the repair is one line in .github/workflows/test.yml: cancel-in-progress now evaluates ${{ github.event_name == 'pull_request' }}, so a superseded pull-request run still stops early while every push to main keeps its recorded conclusion. The first attempt wrote the expression bare, which GitHub would have rejected at workflow validation; it was ledgered work-rejected and the delimited form landed on the second attempt. The consequence half, a promotion gate judging by delta and treating a cancelled run as absence of evidence, is reckon's and is tracked there.

The optional-dependency posture was locked as provision-the-extra: torch was already declared in the test extra and CI already installs it, so the eighteen torch failures were an unprovisioned local environment, not a missing declaration. One pytest_collection_modifyitems preflight now exits once with USAGE_ERROR and the message uv sync --extra test when torch is absent and a torch-dependent suite is selected. Two subprocess regressions pin the blocked and the provisioned paths.

Closing figure: 49 became 0, and the 3 that appeared were the worktree's

One bare whole-tree run at revision 34531f99 reported 12,070 passed / 3 failed / 142 skipped / 1 xfailed in 584.93 s, against the opening 12,021 / 49 / 145 / 1. Both runs account for 12,216 outcomes. Every one of the opening 49 ids is green. The 3 residual ids were new and were then reproduced individually from both the worktree and the main checkout: all three passed in both layouts. They were artifacts of running the whole tree from a detached worktree whose .venv is the main checkout's: the run collected tests from the worktree while importing some modules from the main checkout's editable install, so a mocked path, a hashed prompt directory and a Cypher property inventory each disagreed with the source tree the test believed it was measuring.

The repair kept the genuine half. The four Cypher properties the checker flagged (StandardName.review_resubmit_count, StandardNameSource.run_id, FacilityPath.claimed_by, FacilityPath.claimed_at) are real persistent writers and are now declared in LinkML, with ten obsolete runtime allowances removed from the checker inventory; the two layout-sensitive tests now derive their paths from the imported module's __file__. build-models regenerates cleanly and no generated file was committed.

The lesson the figure leaves behind: a whole-tree run is a property of one source tree, so it must be taken from a checkout whose imported modules and collected tests are the same tree. A worktree sharing the main checkout's environment is the wrong place to take it unless every test resolves paths from the module it imported.
