§7 — Hand-off rows carry the target's COCOS label

build_mapping_handoff in imas_codex/ids/handoff.py now fills cocos_label and the new cocos_label_source on every signal row. They come from the nearest node on the target's HAS_PARENT chain that carries cocos_transformation_type, with the target itself as hop 0. The binding's own cocos_label is no longer read. A target whose last segment is time always carries none, because a time coordinate is never COCOS-transformed.

§18 — A plain pytest run resolves the tests package

The cause was narrower than the section first stated. The lead's shell exports PYTHONPATH=/home/ITER/mcintos/Code/reckon, and reckon has a regular tests/__init__.py. imas-codex's tests/ was only a namespace package, and Python prefers a regular package anywhere on sys.path over a namespace portion. So tests resolved to reckon's, and every tests.* import failed. A pythonpath setting alone did not help. The fix makes tests/ a regular package with an empty tests/__init__.py, and sets pythonpath = [".", "tests"]. The "tests" entry keeps four modules working that import standard_names… or conftest as top-level names.

Worker commits da9269af5 and 3db7c7e5a are merged at 26f7197b1. With the lead's PYTHONPATH, --collect-only tests/ went from 17 collection errors at the base to none (14,598 collected). With no PYTHONPATH it also collects cleanly once the generated models.py is current. One run caught it mid-rebuild at 08:54 and reported a transient COCOSClass import error that no longer reproduces. The negative control deletes tests/__init__.py with the lead's PYTHONPATH, and the facet-admission run then fails at collection.

Follow-on: the "tests" entry puts tests/ on sys.path, so its subfolders graph, tools, search and discovery could shadow same-named packages. The cleaner form rewrites the four modules to import tests.… and drops that entry.
