§3 — every signal reaches the map

Merged to main at beb620e1b, from node singleton-signal-sources (commits b90e7fd27, 1b8457bbf and c3df10965). detect_signal_sources gains a final pass. Each discovered signal that the grouping threshold leaves ungrouped becomes a one-member SignalSource keyed by its accessor, or by its id when it has no accessor, with itself as representative. The pass writes through the function's own MERGE, so the three-member threshold for shared groups is unchanged. create_signal_source, which had no caller, is deleted.

Verification. The default gate passed with 1773 tests. A graph-marked round trip on live Neo4j checked a fixture facility with three ungrouped signals, one of them channel-like, and one three-member pattern. The first run produced four sources (member counts 1, 1, 1 and 3) and six MEMBER_OF edges, and a second run wrote nothing. The channel-like signal is now claimed for enrichment. An enriched one-member source reads enriched, and claim_sources_for_candidates returns it. Two negative controls failed as required: skipping ungrouped signals, and dropping the null-accessor fallback. The independent review scored 111/120 with no added failures, and its four follow-ons were folded into the node.

Measured for JT-60SA. 1,969 discovered signals have no source today, and none matches the channel-element patterns enrichment bulk-skips. The pass therefore adds 1,969 representatives to enrichment and changes no skip decision. It takes effect the next time the signals preflight runs, which is the §2 enrichment run.

Carried forward. The query selects only discovered signals with no source. A signal that arrives alone in a later scan, for a pattern that is already a group, becomes its own one-member source and does not join that group. That is correct, because it reaches the map either way. It costs one extra candidate judgment per such signal.

§4 — EDDB units parse and compare through pint

Merged to main at c9f9e3052, from node eddb-unit-normalisation (seven commits, 897fb3473 to 66cdc2c16). EDDB units are parsed by the shared pint registry and formatted by the same U formatter as the DD graph build, and two spellings are compared by pint. That is the lead's ruling of 2026-10-07.

  • Case variants (KA, KV, Mpa, KeV, DEG, DegC, oC) resolve through @alias, so Celsius keeps its 273.15 K offset.
  • Glued exponents (m2, m3, Pam3) are units of their own without a symbol. A ^ in a symbol is re-read as an exponent chain, which made 1/m2 re-parse as m^0.5.
  • A registry preprocessor folds deg. C, on 44 signals, to Celsius; pint had read it as degree times coulomb.
  • V.S is left unresolved, because pint reads it as volt times siemens where the catalogue means a weber.
  • units_are_equivalent judges two spellings the same unit when they have equal dimensionality and a conversion factor of exactly 1.

Verification. The gate passed with 892 tests, against 496 at base, with no added failures. A round-trip test runs over every JT-60SA and DD unit string. Every graph Unit id (415) normalises exactly as at base, so no Unit node changes identity. Negative controls failed as required for the Celsius offset, the ^ symbol and the deg. C fold. The coordinator probed in a fresh process in each round. It found the first head's recursion, which broke degC and count project-wide, and the m^0.5 round trip. Independent reviews scored 114, 112 and 113 out of 120.

Census. Of 76 JT-60SA unit strings, all resolve except these, each listed with its count and reason: the empty unit (1,710 signals), gauge pressure MPaG, the device count Unit, the neutron-yield rates n/day and n/s (a bare n would shadow the nano prefix), and V.S.

Carried forward. A space-only deg C, without the period, is not folded. The catalogue does not use it, so this is latent.
