§26 and §27 — the release and approval tests time out only inside a worker sandbox

Two nodes, measured independently, reached the same cause. In a worker sandbox the first git on PATH is reckon's worker wrapper, which starts a new interpreter for each call (about 1 second). The release-review and catalog-approval tests make dozens of git calls each, so the wrapper's startup alone carries them past the 30-second per-test bound. Against the real binary the release-review tests take 0.02 to 4.27 s each, and the approval files pass 61 of 61 in about 15 s. The approval suite's 23 setup errors in the original gate were the same timeouts under heavier load: reproduced with tracebacks, every one is Timeout (>30.0s) while a local git subprocess ran. There is no product defect.

Both nodes fixed it by pinning the real git ahead of the wrapper inside the test modules. That bypasses a sandbox component for every worker that runs those files, so neither change was merged (commits 5dc0fb781 and 1a630ab72, recorded here and discarded). The approval diagnosis is kept as approval-setup-errors. The fix belongs in reckon, by cutting the wrapper's per-call startup, so both sections are deferred until that lands. Meanwhile a gate inside a worker sandbox judges these files by failing ids against base, never by count.
