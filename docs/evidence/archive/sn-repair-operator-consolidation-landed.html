The refusal reasons are asserted by exact string, because a migration that changes which rows refuse has changed physics semantics even when the counts match: target would lose its last producing source; target has a live structural child; and fresh signed-manifest closure does not match authorized SHA-256 for untouched collateral drift.

The doctrine is built in rather than remembered. There is no caller row list and no declared count anywhere in the operator: apply rebuilds its own preview and re-reads its counter baselines inside one transaction, and a mixed cohort applies the deterministic maximal refusal-free subset. Those are exactly the three lessons that cost earlier sessions three overtaken cohorts.

Also recorded: the first attempt reported itself blocked rather than passing, because all nine graph cases had skipped for want of an endpoint. A skipped graph case is not-run, never a pass — the node was right to refuse, and the fix was a provisioning recipe another node had already proven in the same session, not a design change.

The seven remaining operators migrate one at a time, each deleting its own body

A prior-art scout mapped all seven remaining bespoke entry points at commit 86cf6bb2 before the first migration node was authored: 7/7 carry an authority shape, mutation program, guard set and an existing disposable-Neo4j suite, across 6 suite files. That last number discharges the §8 prerequisite — the three operators recorded as having no suite now have one, so no migration is gated on writing a baseline first. Record: migration reuse map.

Two constraints follow from the map and both bind every remaining node. The migration lane is one deep: every migration edits both graph_ops.py and signed_manifest.py, so no two may run concurrently. And the closed registries are extended by name — never by broadening an existing program ambiguously and never by admitting caller-supplied Cypher — for HAS_STANDARD_NAME, HAS_UNIT, HAS_ERROR/HAS_LOCUS, authority joins, permitted orphan hand-off, and branching mutation programs.

Committed authorities were read on their original bytes throughout and nothing was re-signed, which is the locked read-existing decision holding under execution rather than merely being asserted.

The ineligible-source row is the one worth studying, because there a helpful guard would have been a regression. Every other operator here refuses a release that would strip a target's last producing source. This one is designed to orphan names and hand them to a separate workflow, so its fixed guard set carries permitted-orphan-hand-off and deliberately omits last-producing-source. A migration that reused the neighbouring guard tuple would have read as safer, passed a superficial review, and refused the very rows the operator exists to process. That hazard was named in the node's measure rather than left for the migration to notice.

Serialization is settled and will not be retired. Locked 2026-08-25: consolidation targets code volume only, so the disjoint-collateral proof is unnecessary and that deliverable closes as a decided no. The measurement behind it: five nodes ran concurrently in one session with no conflict, and what actually queued the work was the shared-source-file conflict across graph_ops.py and signed_manifest.py — which the mutator constraint does not touch. Applies cost nothing and are dominated by a GraphClient connect measured between 54.8 s and 196.9 s, so concurrent transactions would optimise the cheapest step, while the session's own findings showed the live hazard is state changing between preview and apply. Full record: dual-authority migration.

Ten of ten, and the verification that says so has a positive control

Every one of the ten targeted operators now reaches the graph through apply_signed_manifest, and no bespoke implementation survives. The claim is checked fail-closed rather than by a grep that returns nothing: a scan that locates def apply_signed_manifest in the same pass — proving the pattern can find a definition — reports 0 of 10 bespoke defs across graph_ops.py, provenance_lifecycle.py and signed_manifest.py.

That control is not ceremony. Six of the ten install their legacy public name dynamically, so a naive search for the literal string reports them absent for the wrong reason. Without a row that fires, an all-zero result is indistinguishable from a broken pattern — which is the same failure that produced a 2.5× over-count of path violations and three silent followup zeros elsewhere in this programme on the same day.

Each migration carried its own equivalence gate, and each relocation was proved rather than asserted. Byte-identical transaction cores at 18,878 / 17,200 / 14,358 / 9,969 / 1,005 / 1,127 bytes, every suite byte-unchanged, every refusal reason verbatim, every replay write-free. Two gates guarded regressions that a reasonable migration would have introduced: the ineligible-source operator keeps a deliberate orphan hand-off where reusing the neighbouring last-producer guard would have read as safer, and the structural-edge operator delegates to the single canonical writer so the rewire authorization guard stays load-bearing instead of intact-but-bypassed.

Serialization is settled by lead decision as keep-strict-serialization, so the disjoint-collateral proof is unnecessary rather than outstanding. Its reopen condition is recorded on the decision: measured evidence that apply-transaction time actually dominates.
