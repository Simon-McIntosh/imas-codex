§3 — the apply mechanism, anchor-first

sn harmonize --apply runs each pattern family as an anchor-gated, two-batch documentation campaign on the existing campaign runner (imas_codex/standard_names/campaign.py, which now accepts an explicit batch plan). The anchor batch (select_anchor) is snapshotted, reset, drained and reviewed first. If the anchor does not reach acceptance, its members are never reset, and removing that gate turns the test red. Otherwise one member batch follows, scoped to exactly the other members. A second apply over an unchanged scope plans zero calls, read from the harmonized-family stamp. --dry-run writes nothing and prints the planned calls and estimated cost. All of this is proven on fixtures with the pool drain stubbed. Gate: 166 passed against 161, no failures. Merge 5366d23bf. Independent review 104/120. Follow-ons, folded into the guard node: sn harmonize --help still calls report the only mode and the docstring says read-only; the new drain closure duplicates the campaign's.

§7 — a run keeps the anchor it chose
