sn-embedding-coverage-gate — cumulative execution evidence

The plan asked what to do about a failing release gate: fix the coverage, relax the bar, or withhold identities. All three options assumed the gate measured what it said it measured. It did not, and that is the result worth keeping.

The gate’s premise was inverted — it was never finding corruption

Landed 2026-08-25 — node n-gatescope, commit 2c9d3bb0. Record: gate-scope-change.

The failing assertion’s own message reads “Embeddings were written then lost — possible data corruption.” But all 26 failing rows carried embedded_at with neither a description nor an embedding. Nothing had ever attempted to embed them, so nothing was written and nothing was lost. Their lifecycle split was 14 superseded, 8 drafted, 4 pending, 0 accepted — every one a name still in flight.

So the gate was failing releases on unfinished work, and would keep doing so as new drafts arrived, which is what made downgrading it expedient rather than chosen. The assertion now adds name_stage = 'accepted' only where name_stage is a declared schema slot for that label, so labels without a lifecycle keep the original graph-wide predicate and no unguarded property reference was introduced. Verbatim before 1 failed, 1 warning in 19.08s; after 1 passed, 1 warning in 9.19s; all labels 8 passed, 5 skipped, 1 warning in 9.96s.

The node was required to state plainly that the 26 became unasserted rather than repaired, so a green suite could not be mistaken for a fixed corpus.

The producer was crediting candidates it skipped

Landed 2026-08-25 — node n-embedstamp, commit 6bb1f9fa. Record: preflight-stamping-repair.

run_embedding_preflight in imas_codex/standard_names/review/audits.py appended null-description rows to needs_embed, persisted item.get("embedding") even when null, unconditionally stamped sn.embedded_at = datetime(), and reported refreshed_count as len(needs_embed). That is the root cause of every one of the 26. Persistence and refreshed accounting now require a non-null vector.

The regression test was proved honest by counterfactual rather than asserted: a two-candidate fixture gives 1 failed, 1 warning in 26.60s against the unguarded producer and 1 passed, 1 warning in 15.00s repaired, writing and counting exactly one real vector while leaving the null-description candidate unstamped. Existing review-pipeline suite 22 passed, 1 warning in 34.11s. This matters more than the rescope: without it the stamping would keep minting rows that look embedded and are not, now beneath a gate that no longer looks at them.

Two rollbacks, and a refusal that was upheld

The node first blocked twice inside signed_manifest._collateral_snapshot and refused to substitute raw Cypher, which was correct and was upheld. Both transactions rolled back completely — 0 mutated, StandardNameChange and PRODUCED_NAME identical before and after, 0 receipts — so nothing was left half-applied. The operator was slow rather than hung: it materializes every tracked node and relationship with full property maps and hashes them client-side, twice per apply. Its cost is recorded as a separate shared-module defect rather than fixed inside a data-repair fence.

The authority was re-derived inside the applying invocation rather than replayed from the blocked attempt’s saved file, and its payload digest afa7af26 came back identical. That is a useful negative result: the population had not drifted in the interval, and it is now measured rather than assumed.
