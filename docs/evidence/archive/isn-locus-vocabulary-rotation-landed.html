isn-locus-vocabulary-rotation — cumulative execution evidence

The plan asked whether a missing locus token was warranted, and expected to rotate the vocabulary if it was. It did not rotate. The answer is a settled refusal, and the record is kept because a negative result reached through two contradicting adjudications is worth more than the token would have been.

The first adjudication recommended adding the token

Landed 2026-08-25 — node n-locusadjudicate, commit 2ec2f04e. Record: locus-adjudication.

It measured a real family rather than the single row that motivated the plan: 3 DD coordinate paths under b_field_non_axisymmetric/time_slice/field_map/grid — r, z, phi — two of them beyond the target, behind a schema sanity count of 61,366/61,366/61,366 with a firing positive control. It found no grid or map token among the runtime loci and confirmed the strict parser rejected all three intended identities. On that evidence it recommended warranted, and the disposition was locked accordingly.

The coordinate base was settled separately, and survives the reversal

Landed 2026-08-25 — node n-basetoken, commit faaa985f. Record: coordinate-base-convention.

The adjudication had proposed major_radius for the r leaf while using vertical_coordinate and toroidal_coordinate for z and phi. Measured against the corpus: 29 accepted radial_coordinate_of_* identities against 0 accepted major_radius_of_*, the zero controlled by six rows found under the same prefix scan, all superseded or quarantined, behind schema sanity 2,302/2,302/2,302.

The decisive fact was stronger than the census: major_radius is not a registered base at all. ISN 0.8.0rc67 carries 175 physical and 35 geometric bases; radial_coordinate is geometric, radius is physical, major_radius is in neither. The first adjudication's own strict-parse rejection — no matching physical base or geometry carrier — had been reporting the missing base all along, and was read as a missing locus. No conflation risk was introduced: accepted radial_coordinate_of_electron_cyclotron_launcher_mirror already describes a major-radius coordinate in cylindrical R, φ, Z, while normalized minor-radius and flux-coordinate tokens carry the other meanings explicitly.

Reading the registry source reversed the recommendation

Landed 2026-08-25 — node n-locusreadj, commit 31ee3e95. Record: curation-policy-readjudication.

The first adjudication derived its evidence from get_grammar_context(), which serves tokens and definitions but not the governing curation-policy comments in locus_registry.yml. Read directly, the policy decides the question:

Census: 181 registry tokens, 105 entity-typed, with token-key matches of grid 0, mesh 0, ggd 0 and field_map 0. A registry-wide zero that broad reads as a boundary someone drew, not a gap nobody noticed. Exactly two tokens are explicit non-material abstractions, coordinate_system and ion_state, and neither is a discretization precedent.

The instrument was checked rather than trusted: the installed 0.8.0rc67 package and the ISN checkout registry are byte-identical at SHA-256 d54a8d8a. So the first adjudication's blind spot was where it looked, not version skew. An interim coordinator census of 160 tokens and 89 entities, quoted in an earlier plan revision, was an undercount from a strict-shape regex and is superseded by these figures.

Asked for the strongest case against its own recommendation, it gave one: a coherent three-path family, no available substitute, and two abstract entity precedents. It loses to an explicit discretization boundary and a registry-wide zero.
