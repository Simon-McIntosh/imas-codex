- `fit`: the existing asset supplies the right mechanism or a directly reusable specification pattern.

## Reuse order for the specification nodes

1. Build the static checker around `GraphSchema.get_all_slots()` and reuse `graph_search()`'s fail-closed diagnostics. Lift the misspelled-property test shape from `test_query_builder.py`; keep `test_schema_compliance.py` only as the reverse-direction boundary. Generalize `docs_review_property_coverage()` into the runtime coverage callable.
2. For the axis spelling, derive permissible values and induced slots through `GraphSchema`; make the current `names`/`_name` mismatch fail before changing the enum. Reuse the disposable persistence fixture to prove non-zero stored coverage before and after `names → name`.
3. For the foreign-key rename, derive the three-label universe and cardinality from LinkML. Reuse the edge traversal and transaction boundaries in `refresh_renamed_source_mirrors()`, then add `LLMCost` list migration and preserve the `size(list)` cost divisor. Keep DocsRevision ids opaque and unchanged.

The receipt deliberately does not claim that any candidate alone completes a change. In particular, live graph schema-compliance tests do not replace a repository static checker, and hardcoded two-axis fixtures do not satisfy the plan's schema-derived-universe requirement.
