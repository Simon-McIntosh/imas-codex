A discovery run is one ordered stage registry with access probes

imas_codex/cli/discover/sequence.py holds one ordered tuple of nine Stage records in dependency order: paths, code, documents, wiki, signals scan, signals enrich, signals check, candidates, mapping. Each record carries the access it needs, the facility-config keys it requires, the stages it reads, the pending-work predicates that decide whether it has work, and the model seat the stage's own monitor guards. Predicates are module:function specs resolved lazily through importlib, so a test patches the source module and no predicate is reimplemented here.

imas-codex discover run FACILITY --dry-run evaluates every stage in registry order and prints each one with its outcome and reason, invoking nothing. Access is probed through the three checks every discover command already uses, imported unchanged from imas_codex/discovery/base/services.py: neo4j_health_check, ssh_health_check and wiki_auth_check. No probe is written anew. A stage reads one of runnable; skipped: not configured when a required config block is absent; skipped: unreachable when a probe fails or a pending-work query raises; skipped: nothing to do when its predicate is false.

imas_codex/discovery/documents/pipeline.py gains the public has_pending_work(facility) the documents stage calls: true when either private check (images to fetch, images to score) is true. The private checks raise on a failed query, so a graph fault reaches the caller as an exception and the stage reads skipped: unreachable, never skipped: nothing to do.
