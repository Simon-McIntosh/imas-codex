The pipeline's own domain writers route through the one writer

Four paths outside the graph-ops module authored a name's domain. Each now sets none of its own: the composing path asks the stored Jev decision for every name it persisted and writes it through imas_codex.standard_names.domain_decision.write_name_domain, and the three read paths read the stored value rather than deriving one.

One projection had to keep the node property's own name

The first cut of check_catalog projected the stored value through a WITH sn, sn.physics_domain AS stored_domain and returned stored_domain AS stored_domain. The value read fine against the graph and read as absent everywhere else: the comparison consumes a row whose domain key is physics_domain, so every entry compared as domain-diverged — catalog: 'equilibrium' against graph: None even when the node stored the domain. A test double cannot rewrite the projection it stands in for, which is what made the rename visible. The query now returns sn.physics_domain AS physics_domain and the three tests that had gone red (TestFoldBackReadsTheSidecar twice, plus the folded-prose half of the post-copy guard) pass again.

Blocked: four assertions still encode the superseded contract, outside the fence

Four assertions in three test files state the behaviour this node removed. They are not regressions of the change — each asserts the removed fallback — and repairing them is a scope request rather than an edit this node may make: the three files are outside the granted write fence.

  • tests/standard_names/test_domain_selector.py — test_pure_callers_use_selector asserts _resolve_physics_domains(["general", "transport"]) == ("sentinel", [...]) and expects the sentinel among the recorded calls; test_pure_callers_ignore_arrival_order asserts _resolve_physics_domains(domains) == ("transport", domains). Both assert the selector is reached from _resolve_physics_domains, which now returns (None, sources). The same file's domain_priority.domain_key assertions are untouched and still pass — domain_key legitimately keeps the selector. The repair is to drop the _resolve_physics_domains assertion from each test (and the third entry of the call list in the first).
  • tests/standard_names/test_post_copy_divergence_comparison.py — _graph_rows supplies resolved_physics_domains: ["equilibrium"], a key the query no longer returns, so test_folded_prose_passes_while_content_is_identical sees a domain divergence that is an artifact of the fixture. The repair is to supply physics_domain: "equilibrium" in that helper.
  • test_node_without_domain_but_sourced_domain_passes is the removed fallback stated as a contract: "the guard must resolve the domain the way the exporter does — from the producing sources". Under the settled contract a node storing no domain compares with no domain, so this test should be rewritten to assert the divergence is reported (or retitled to match), never deleted.

Nothing else in the gate is red. The remaining two files' failures are the base's: test_review_release_checkout.py fails identically at the base revision, and test_release_rehearsal_writes_nothing.py reaches a live git remote from a default-tier test.
