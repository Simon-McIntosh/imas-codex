Rendering the DD classifier vocabulary from the PhysicsDomain enum

The DD domain classifier prompt (imas_codex/llm/prompts/imas/domain_classifier.md) offered a hand-typed vocabulary table listing 21 of the 32 installed PhysicsDomain values. It omitted core_plasma_physics and ten others, so the classifier could never return them, and its worked example tied electron temperature under core_profiles/profiles_1d/electrons to transport. The table is now rendered from the enum itself, so it cannot fall behind: the frontmatter declares schema_needs: [physics_domains], and the body iterates physics_domains delivered by _provide_physics_domains in imas_codex/llm/prompt_loader.py. The heuristics now state the core-profile rule in terms of what a quantity is: a kinetic profile of the core plasma belongs to core_plasma_physics, while a flux, diffusivity or confinement time belongs to transport. The IDS name stays an informational, not a decisive, signal.

The provider supplies values only, not scope text. _provide_physics_domains reads a LinkML schema at imas_codex/definitions/physics/domains.yaml for per-domain descriptions and categories, but that file does not exist, so the function takes its fallback branch and returns every domain with an empty description and the category uncategorized. The rendered table is therefore a bare bullet list of values with no scope sentence beside any of them. The canonical scope descriptions do exist downstream, in PHYSICS_DOMAIN_DESCRIPTIONS in the installed imas-standard-names grammar package, but the codex provider does not read them. This fragment records that gap rather than adding a second source of descriptions to the prompt, per the node brief; a follow-on should either ship the schema file or have the provider source the descriptions from the grammar package so one vocabulary carries its own scope text.

Two tests hold the change. One renders the prompt and requires every PhysicsDomain value to appear. The other injects a sentinel domain into the provider and requires it to render, so the vocabulary tracks the provider rather than a frozen table. Both fail against the hand-typed table: restoring that table makes the rendering test report the missing domains and exit non-zero (receipt negative-control.log, EXIT=1).
