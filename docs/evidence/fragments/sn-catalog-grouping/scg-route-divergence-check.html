Are the three catalog-import divergence failures added by the routing change?

The route node scg-name-domain-route-pipeline edits check_catalog in imas_codex/standard_names/catalog_import.py: the comparison previously re-derived each name's domain from its PRODUCED_NAME sources through select_primary_domain, and now reads the stored physics_domain scalar that write_name_domain wrote. Its review counted three added failures in tests/standard_names/test_catalog_import_divergence.py::TestPublishRefusesDivergedTree. This measures whether they are added by that change or present at base.

Method

Two clean trees were extracted with git archive into node-local TMPDIR=/tmp/reckon-crew-scratch/r-20261022T150223442727-scg-route-divergence-check, each given the same five generated files copied from the main checkout. In each tree the one test file was run alone, in sequence, with PYTHONPATH set to the tree and UV_PROJECT_ENVIRONMENT the shared project environment (/home/ITER/mcintos/Code/imas-codex/.venv), under the repository's default per-test timeout of 30 s. Each log's header records its tree revision, the load average at start, the resolved working directory, and the path each arm's catalog_import module was imported from; that last value lies inside the tree the arm claims, so neither arm loaded the other's code.

The durations show the margin is the whole story. At head, test_uncomparable_tree_still_publishes spent 18.80 s in setup and 11.21 s in call — 30.01 s against a 30 s bound. At base the same test spent 12.02 s in setup and 11.21 s in call. The node was heavily loaded throughout (load average 85.70 at base start, 58.08 at head start), and the pass/fail line is a coin-flip at the boundary.

Why the routing change cannot cause these

All three tests replace the function the routing change edits. publish.py:523 imports check_catalog inside the function, so the tests' patch of imas_codex.standard_names.catalog_import.check_catalog binds, and the check_catalog the routing node rewrote never runs in any of the three. The behaviour the tests assert is set by the patched stub, not by the changed code; the only variable left between the arms is wall-clock. This is consistent with the timeout signature and with the head arm passing a test the base arm failed.
