Are the three catalog-import divergence failures added by the routing change?

The route node scg-name-domain-route-pipeline edits check_catalog in imas_codex/standard_names/catalog_import.py: the comparison previously re-derived each name's domain from its PRODUCED_NAME sources via select_primary_domain, and now reads the stored physics_domain scalar that write_name_domain wrote. Its review counted three added failures in tests/standard_names/test_catalog_import_divergence.py::TestPublishRefusesDivergedTree. This measures whether they are added by that change or present at base.

Method

Two clean trees were extracted with git archive into node-local TMPDIR=/tmp/reckon-crew-scratch/r-20261022T150223442727-scg-route-divergence-check, each given the same five generated files copied from the shared main checkout. In each tree the one test file was run alone, in sequence, with PYTHONPATH set to the tree and UV_PROJECT_ENVIRONMENT the shared project environment, under the repository's default per-test timeout of 30 s. Each log's first line names the revision, the tree and the command; its header also records the load average at start and the path each arm's catalog_import module was imported from. That last value lies inside the tree the arm claims, so neither arm loaded the other's code.

The durations are the whole story: every failing case sums to almost exactly the bound. In the base arm, test_in_sync spent 17.01 s in setup plus 13.03 s in call, and test_uncomparable 15.32 s plus 14.68 s — 30.04 s and 30.00 s against a 30 s per-test bound. In the head arm they were 20.97 + 9.03 and 17.79 + 12.22 — again 30.00 s and 30.01 s. The node was loaded throughout (load average 43–62 at arm starts), and the pass/fail line for these two cases is decided by load.

Why the routing change cannot cause these

All three tests replace the function the routing change edits. publish.py:523 imports check_catalog inside the function, so the tests' patch of imas_codex.standard_names.catalog_import.check_catalog binds, and the check_catalog the routing node rewrote never runs in any of the three. The behaviour the tests assert is set by the patched stub, not by the changed code; the only variable left between the arms is wall-clock.
