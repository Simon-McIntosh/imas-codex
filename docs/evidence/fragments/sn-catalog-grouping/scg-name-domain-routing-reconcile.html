A catalog-written name's domain has one owner: the structural tail pass

Two nodes routed the graph store's StandardName domain writes through domain_decision.write_name_domain. The lineage half landed first (merge ed50a9115) and made the structural edge pass _write_standard_name_edges write every name in its batch through the writer, from the name's stored decision and its DD sources. The catalog half deleted the promote-on-higher-rank domain write from graph_catalog.write_standard_names and handed the tail pass the batch without the domain fields, on the reading that the tail pass mints no domain edge.

Those two readings cannot both hold. After the lineage half, the tail pass is a domain writer; if the catalog path delegates to it, a StandardName written by write_standard_names gets its domain, its source domains and its domain edges from exactly that one application. The merge keeps that path and discards the catalog half's reading. The conflict in tests/standard_names/test_graph_edge_writers.py is resolved to it.

The owner, and why

Candidate ownerEffect on a catalog-written nameVerdict
the structural tail pass, inside write_standard_names one application per name in the batch, from the name's stored decision and DD sources; it also reaches every closure parent and every name rederive_structural_edges passes through the same function. chosen — the path already exists, is the one the lineage half landed, and covers names the catalog path materializes but never writes itself.
an explicit call in write_standard_names before the tail pass two applications for every name, because the tail pass writes the same names again. rejected — twice for every name.
the tail pass, with the catalog path's names excluded from its domain write one application, but only by changing the tail pass's interface and exempting the names the catalog path just wrote. rejected — contradicts the lineage half's contract and costs an interface for no behavioural gain.

A payload domain is therefore ignored: the tail pass withholds physics_domain and source_domains from the batch it hands the edge pass, so the payload can neither mint an edge of its own nor supply a source set the writer would have to overwrite. A name that carries no stored decision is written undecided and keeps the scalar it already holds, which is the writer's documented contract.
