What a DD rebuild would change

Properties affected. An IDS node's physics_domain is set from this map at build_dd.py:1177 into ids_info and written by _batch_upsert_ids_nodes at build_dd.py:3364, so a rebuild re-writes all twenty-five IDS nodes to their new domain. Each IMASNode path's default domain also comes from the map (build_dd.py:3495), written by _batch_create_path_nodes at build_dd.py:3583. Nothing else in the map's two readers writes a graph property.

Stored path-classifier domains are not overwritten. The path upsert assigns the IDS default only on a path that carries no classification: physics_domain = CASE WHEN path.domain_source IS NULL THEN p.physics_domain ELSE path.physics_domain END (build_dd.py:3583–3586). A path the classifier labelled (domain_source non-null) keeps its stored domain and its provenance through the rebuild. The build path upsert does not write domain_source itself.

Narrowest route to refresh only the IDS nodes. The IDS-node domain write lives only in _batch_upsert_ids_nodes (build_dd.py:3331), whose sole caller is the full build at build_dd.py:1899; there is no standalone IDS-domain command, and imas-codex imas dd build rebuilds every version. The narrowest existing route is a bounded graph write over the twenty-five IDS nodes alone — UNWIND $rows MATCH (i:IDS {id: row.id}) SET i.physics_domain = row.domain — leaving the IMASNode defaults to be picked up by a later build on the paths that still carry no classification. Selecting and running that refresh is the coordinator's call.
