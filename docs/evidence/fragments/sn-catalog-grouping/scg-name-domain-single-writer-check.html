A guard keeps a name's domain to the one writer

tests/standard_names/test_name_domain_single_writer.py reads every Python module under imas_codex/standard_names/, extracts each string constant that parses as Cypher, and refuses three writes made outside domain_decision.write_name_domain and the functions it reaches: a SET of a standard name's physics_domain or source_domains; and a MERGE, CREATE or DELETE of a HAS_PHYSICS_DOMAIN relationship from one. It reads clauses rather than text, so WHERE sn.physics_domain = $domain is a read and does not trip it.

Downstream of that, the check records what it already knows. The two derived-parent materialisers in graph_store/graph_lineage.py still seed their parent's scalar from the children's most frequent domain before calling the writer, which is the rule §3 retires and which no node of this section has removed yet. Those two are named in EXEMPT_SITES with their reason, and a second test fails when that table and the writes actually present disagree — so an exemption that is retired must be deleted, and a new direct write cannot join it silently.

What the check still reports

Two direct scalar writes remain, both in imas_codex/standard_names/graph_store/graph_lineage.py: parent.physics_domain = coalesce($physics_domain, parent.physics_domain) in the single materialiser and its batched twin. The value is computed there — Counter(child_domain_list), the most frequent child domain, with ties broken alphabetically — and the writer is then called with an undecided decision that keeps the current scalar, so the retired rule is still the origin of a derived parent's domain. Retiring it is the open piece of §3's one-writer item; until then the guard holds every other writer at zero:
