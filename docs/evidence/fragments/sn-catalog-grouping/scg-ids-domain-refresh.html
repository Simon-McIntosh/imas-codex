The IDS domain refresh applied the map to the graph

The corrected IDS-to-domain map is now in the graph, written through one reusable route: imas_codex.graph.build_dd.refresh_physics_domains (build_dd.py), exposed as imas-codex imas dd refresh-domains [--dry-run]. Each IDS's domain is read from physics_categorizer.get_domain_for_ids — the build's own reader — not from the JSON, so the route and the build can never disagree, and it writes only where the stored value differs. On each changed IDS's paths it writes the IDS default only on a path that carries no classification, the same domain_source IS NULL guard the build's path upsert applies at build_dd.py:3583.

The apply moved 25 IDS nodes and 2,399 unclassified paths. No classified path was touched: over the changed IDSs the paths carrying a domain_source stayed at 17,886 before and after, and their domains are bit-identical (recorded per row in the reversal file below). A second dry run immediately afterwards reported zero IDS changes and zero path changes.

The route

refresh_physics_domains(client, *, dry_run=False) reads every :IDS node, compares each row's stored physics_domain to the map's target, and returns ids_total, ids_changed, path_changed, path_changed_count and applied_path_count; the last three carry the before and after value of every changed row so the run can be reversed. The two statements it writes set exactly one property each: SET i.physics_domain = row.after over the IDS rows, and SET p.physics_domain = $domain over the guarded path statement. Nothing else is written, so path_count, dd_version and the lifecycle fields keep their values. Each statement was checked with EXPLAIN against the live graph.
