Measuring the two-level domain tree against the chat classifier

The two-level Choice asks Jev a physics category first and a domain within that category, and multiplies the two probabilities into a per-path confidence. A path the tree does not score above a threshold falls to the free-text chat classifier, so the two-level arm is a router over the chat arm, not a replacement for it. This benchmark measures the routed classifier against the chat classifier on held-out domain labels and settles the threshold under a rule fixed before the run.

The rule

Adopt when, on the validation rows, both hold: the tree's derived name-domain accuracy is at least the chat classifier's accuracy minus 0.03, and its total spend (Jev tree plus chat fallback) is below the chat classifier's spend on the same paths. The threshold is chosen on the calibration rows only; every figure below is reported on the validation rows.

Verdict: adopt. On the 77 validation names the tree reaches 0.597 against the chat classifier's 0.610 — within the 0.03 tolerance — while its spend on the same validation paths is $0.166 against the chat classifier's $0.305, about 45% less.

Paired difference and its interval

The paired difference (tree minus chat) on the 77 validation names is −0.013, with a central-95% percentile bootstrap interval of [−0.039, 0.000] over 1,000 resamples (seed 123). The interval does not exclude zero (its upper bound is exactly 0.0, its lower bound is negative), so the validation set cannot distinguish the two accuracies. The interval is a mean of paired 0/1 outcomes; bootstrap_interval in the evaluation module is AUC-typed and cannot express that statistic, so the same percentile policy is applied to the paired difference instead.

Per-domain validation accuracy

Each row is one labelled domain on the validation split; the grey dot is the chat classifier, the blue dot the tree, and the rule between them the difference. Domains the tree answers are those whose names clear the threshold; the two classifiers coincide where the names route to chat. The largest disagreements are auxiliary_heating (chat 0.714, tree 0.571) and, marginally, radiation_measurement_diagnostics and spectroscopy, where both classifiers are perfect.

Confusion against the first benchmark

The first benchmark's leading coordinator confusions were magnetohydrodynamics → none (5), gyrokinetics → none (4), and auxiliary_heating → waves (3) paired with radiation_measurement_diagnostics → spectroscopy (3). The tree reproduces the first two exactly: on the validation names both classifiers leave gyrokinetics (2) and magnetohydrodynamics (2) unanswered, showing those confusions are a label-sheet property rather than a classifier property. The auxiliary_heating confusion persists and deepens: the tree sends 2 of those 7 names to waves against the chat arm's 1, so the tree's one clear regression is a category-boundary choice between heating and the waves that carry it.

Changes to the benchmark entry point

run_classifier_bench gained a keyword-only use_tree option that routes each batch to _classify_batch_tree and keeps the chat path as the default; the tree seat is passed through unchanged while the chat arm still takes ensure_model_prefix. The import of DEFAULT_BATCH_SIZE, referenced but unimported, was added: without it the function raised NameError before any classification, so no prior gold run could have measured anything. The new test tests/standard_names/test_role_bench_classifier_tree.py fails if the option is dropped or the routing is swapped.

Negative control

Rescoring the recorded chat answers on the validation names through the same derivation and scorer reproduces the chat baseline at no cost, and scoring the tree's answers through that same scorer yields a different accuracy (0.597 against 0.610), so the scorer can tell the two classifiers apart. Re-running the driver without --fresh reads the complete tree cache and rewrites the results JSON and figure with no paid call.
