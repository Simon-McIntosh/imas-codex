Physics domains from IDSs first, with hierarchy and Jev tie-breaks

Read-only census: no graph write, no LLM call and no Jev call. The source-path loader, the two control selectors and the paired-bootstrap scorer are the preceding rule comparison's; this node adds the IDS map as a prior, a per-IDS path mix, and a designed tie-break.

1. The use case

A domain is read by five kinds of consumer.

  • Graph build and classification. imas_codex/graph/build_dd.py:3495,3528,3583 sets a path's domain from its IDS default on the rebuild, and preserves a classified value. imas_codex/graph/dd_domain_classifier.py:1589,1601 classifies the paths. imas_codex/graph/dd_graph_ops.py:125 coalesces on upsert. imas_codex/standard_names/graph_ops.py:3387-3409 merges one HAS_PHYSICS_DOMAIN edge per source_domains entry.
  • Catalog export and grouping. imas_codex/standard_names/export.py:2164-2189 groups entries into per-domain buckets and records domains_included; :844-864,3299-3327 excludes an entry with no domain. imas_codex/standard_names/batching.py:11 keys a name-only batch by domain and unit. imas_codex/standard_names/consolidation.py:49-117 merges a group's domains into one scalar plus a union. imas_codex/standard_names/families.py:665 prints the domain as a family column.
  • MCP search filters. imas_codex/llm/server.py:2414,2508,2559,2611,2792,3184,3302 take a domain filter per name and per signal; imas_codex/llm/sn_tools.py:345-414 matches a name's scalar or any value in source_domains. imas_codex/llm/search_tools.py:327,751-785,1012,1750 post-filters signals, docs and code. imas_codex/graph/domain_queries.py:85,98,459 holds the Cypher. imas_codex/llm/search_formatters.py:649 renders the domain into result text.
  • Documentation and review prompts. imas_codex/llm/prompt_loader.py:576-629,928 renders the domain vocabulary and the per-category scope into every prompt declaring physics_domains; imas_codex/standard_names/review/consolidation.py:189-323 groups review items by domain; imas_codex/standard_names/harmonize.py:519-653 attributes domain-scoped lint findings to a family.
  • Name derivation. imas_codex/standard_names/domain_ranking.py:19-29, imas_codex/standard_names/domain_priority.py:10-29, and imas_codex/standard_names/enrichment.py:78-117.

Three properties follow, and the design is judged against them. A name needs exactly one scalar domain, because a filter has one value to match and export opens one bucket; it may carry several source_domains so it stays discoverable from every domain it draws on. The domain must be stable: the precedence is a tie-break read independently by the classifier and by name selection, so a derivation that moved with cluster relevance could never be audited. And it must be human-browsable: the scope text is rendered into prompts a person reads, and the chat category list is ordered by the same precedence.

2. Where a domain comes from today

The IDS map imas_codex/definitions/physics/ids_domains.json holds 87 entries, one domain each, over 21 distinct domains, created 2025-12-17. core_profiles maps to transport and summary to general; both are entries the paths below contradict.

The build reads that map through imas_codex/core/physics_categorization.py:23-42 and applies it at build_dd.py:3583-3588, preserving an existing value when domain_source is set. The classifier (dd_domain_classifier.py) decides in four tiers: infrastructure metadata to null (line 321), a Jev two-level decide_batch tree (line 1240, question rendering 1009-1025) with a chat fallback (line 794), inheritance from the nearest classified ancestor (line 369), and path_domain_overrides.json (line 37, applied at line 63). Jev is reached only through _safe_decide_batch (lines 1067-1083), called at lines 1125 and 1152; there is no judge_rows and no rerank_pool in the file. The tree's state (lines 1009-1025) carries the path, its IDS, description, documentation, unit, parent and siblings, and never the path's own stored domain. The name derivation is domain_ranking.select_primary_domain (line 19), whose rank is domains.yaml's precedence read through load_domain_precedence — not a graph cluster index.

So Jev is used now at exactly one place: the DD path classifier's first tier. Measured over the paths, the current domain_source histogram is inherited_from_parent 34,654, none_metadata 7,925, llm_classified 7,551, none 6,750, jev_tree 4,480, deterministic_override 6. Jev wrote 4,480 paths and the chat fallback 7,551; the rest is inheritance and metadata. Nothing writes a name's domain through a Jev judgment today.

The two stored findings both hold as fixed at HEAD. The tree read its answer at the wrong level: result[0] was read as the answer instead of answers[DOMAIN_QUESTION], so the second-level question was never asked and every path fell through to chat. The answer is now unwrapped through its question name by _answer_for (lines 1028-1041), used at line 1164 for the domain level and line 1178 for the category level. The chat renderer dropped the documentation field: _format_batch_user_prompt (lines 879-895) now emits documentation at line 886. The candidate-domain list is a separate render (llm/prompts/imas/domain_classifier.md, lines 34-48, via _domain_option_text at 931-946) and renders each domain's description, scope, includes and excludes.

3. How the IDSs group

Over 61,366 DD paths in 87 IDSs, 1 IDSs carry a single domain, 72 are mostly one domain and 15 are mixed. 42 IDSs have a modal domain other than their map's, and 42 are contradicted outright, under half their paths carrying the mapped domain.

4. The IDS-first rule, measured

A source IDS votes once for its mapped domain and once for each domain its own source paths carry; the rule takes the domain with the most IDS votes. A tie is broken by the declared hierarchy: the core-physics IDS tier, then the precedence band of the guidance file, then the rank, then the domain name. Tier 0 is an IDS whose mapped domain sits in the guidance's core-physics band; every other IDS is tier 1, so a plasma-state IDS outranks a diagnostic IDS on a shared quantity. The reversed variant puts the band first and measures the lead's ordering question directly.

Approved plus calibration selected ids_first_tier_then_band_corrected before validation was read. Validation was then read once for it and the two controls.

Correct answers, written as correct out of the cohort size, in the order approved, calibration, validation: set_precedence approved 9 of 20, calibration 53 of 73, validation 52 of 77; ids_then_paths approved 9 of 20, calibration 56 of 73, validation 53 of 77; ids_first_tier_then_band approved 8 of 20, calibration 51 of 73, validation not read; ids_first_band_then_tier approved 8 of 20, calibration 51 of 73, validation not read; ids_first_tier_then_band_corrected approved 9 of 20, calibration 55 of 73, validation 54 of 77; ids_first_band_then_tier_corrected approved 9 of 20, calibration 55 of 73, validation not read.

Set precedence reproduces the figures the precedence rule was measured at before, so the harness is the earlier measurement's. The IDS-first rule does not beat the controls everywhere, and the selection above is not evidence that it does. On the approved set the corrected variant ties both controls and the uncorrected variant loses a name; on calibration the corrected variant sits one name behind the IDS-then-paths control; it leads on validation alone, by one name, and one name on 77 lies inside the paired-bootstrap interval. What the IDS map buys is therefore not accuracy over a plurality of source paths: it is a stated prior, a derivation whose tie-break can be written down and audited, and a tie set small enough for a Jev step to settle.

5. The Jev tie-break, designed not run

1396 live names reach a tie and 12 more reach the rule without a strict IDS majority, so 1408 of 2677 live names (52.6%) would reach it, against 6 in approved, 35 in calibration, 1334 in unlabelled, 33 in validation. The primitive is a TypeSafe Choice; the question is authored by code and the model supplies the judgment, exactly as the hierarchical-classification cookbook decomposes it — the code owns the traversal and the model picks among the siblings at the level reached. Its state carries the name, description and unit, the source IDSs and their mapped domains, and the source paths with their stored domains. Its criteria are the tied candidate domains only, each keyed to the guidance scope text so the model sees what each domain covers and excludes. Its probability combines with the IDS prior as a posterior over the tied set: the Choice distribution re-weighted by the IDS support share and renormalised, so the model breaks the tie rather than choosing from nothing. Read the answer only when its confidence clears 0.5, the docs' floor for genuine uncertainty; below it, the precedence rank decides and the case is logged for a ruling.

A second Jev step the cookbook's shape suggests is re-deciding the IDS map itself: one Choice per IDS over the 32 domains, with the IDS's name and a sample of its paths as state and the domain scope text as criteria. That is 87 calls, one per IDS, and it would supply the corrected map this node instead derives by rule.

Cost estimate. 1408 tie-break calls for the live catalogue, plus 87 for the IDS map, is 0 spend at rest and one call per name at repair time. Each call's state is the name, its description and its source bindings, roughly 400 to 700 tokens, and its criteria are the tied domains' scope text, roughly 30 to 60 tokens each. The pages read carry no price table for Jev, so the estimate is stated in calls and tokens rather than in currency: 1408 calls at about 1,000 input tokens each, under a million tokens for the whole catalogue, and 87 calls for the map.

Docs read for this design: the installed skill typesafe-ai/SKILL.md; live docs.typesafe.ai/llms.txt; the hierarchical_classification cookbook; primitives/choice.md; confidence.md.

6. Recommendation

Adopt the IDS-first rule with the corrected IDS map as the one derivation of a name's scalar domain: candidate domains are the source IDSs' mapped domains and the source paths' stored domains, the support vote is the IDS count, and the tie-break is the declared hierarchy above. Keep the IDS map as the prior it is and repair only the entries its own paths contradict, rather than re-deriving it. Reach for the designed Jev tie-break only on the names the rule leaves tied.

The three designs on the same three sets. Set precedence answers approved 9 of 20, calibration 53 of 73, validation 52 of 77; the IDS-first rule approved 9 of 20, calibration 55 of 73, validation 54 of 77. The umbrella measure run beside this node reached at best 12 of 20 approved, 51 of 73 calibration and 52 of 77 validation across its thresholds, and 11, 53 and 52 for the variant it selected — its fragment is sn-catalog-grouping/scg-name-domain-umbrella-measure.html, and this node does not re-measure it. So the umbrella rule leads on the approved set, where an umbrella is what the lead approved, and no rule separates from the controls on calibration; only validation favours the IDS-first rule, by one name. Adopting it and the corrected map would change 1,481 live names against the stored values, the same order as the set-precedence rule's 1,477, so the cost of the choice is a repair pass either way.

Two things only a ruling settles. Whether the corrected map or the map as stored is adopted: the sets do not separate them, and the 23 entries the paths contradict include the IDSs whose every source path carries the mapped domain's own child, as core_profiles does for core_plasma_physics. Whether a diagnostic IDS outranking no plasma-state IDS is intended: the tier puts a plasma-state IDS first on a shared quantity, and the reversed variant measuring the band first is what the lead's ordering question asks.
