The catalog-side domain writers route through the one writer

After the graph-store split, two modules on the catalog side of imas_codex/standard_names/graph_store/ set a StandardName's domain themselves. Each now leaves the domain to imas_codex.standard_names.domain_decision.write_name_domain, which sets physics_domain, source_domains and one HAS_PHYSICS_DOMAIN edge per entry of source_domains in one transaction.

Sites, before and after

SiteBeforeAfter
graph_catalog.write_standard_names, the promote-on-higher-rank block (was graph_catalog.py:348-434) Read each node's scalar and source_domains, merged the incoming payload domains with merge_source_domains, chose a scalar with maybe_promote_domain, then wrote both back with SET sn.physics_domain = coalesce(...), sn.source_domains = coalesce(...). No edges. Deleted. The write path no longer sets a domain at all; the composing path already hands every persisted winner to write_name_domain. A payload domain is ignored, which the test pins.
graph_refinement.persist_refined_name, successor provisioning (was graph_refinement.py:917-918) Wrote new.physics_domain = $physics_domain and new.source_domains = $source_domains from the caller (the sn edit rename passes the predecessor's scalar), with no edge writer. The provision writes neither field. After the transaction commits, the successor's domain is written by write_name_domain: its stored Jev decision when the predecessor carries one, the predecessor's scalar otherwise (undecided, with that reason recorded), a carried correction only when the rename preserves meaning, and the edges from the migrated sources.

Read-only sites, verified and left alone

  • graph_audits.py — physics_domain appears only in a filter (n.physics_domain = $domain) and in the domain census' projections. No write, no change.
  • graph_claim_scope.py — filters and projections only (n.physics_domain = $domain_filter, s.physics_domain AS physics_domain). No write, no change.

One writer contract change and one gap

write_name_domain gained an optional fallback_domain. A successor minted by a rename holds no scalar, so "an undecided name keeps its current value" had nothing to keep; the fallback seeds it from the predecessor without the caller writing the property itself.

The derived-parent rule the brief names is not in these four modules. Its writers — _materialize_derived_parent_rows, _bootstrap_missing_derived_parent_targets, _validate_derived_parent_identity and the parent.source_domains = CASE promotion beside them — live in graph_lineage.py, outside this node's fence, so they are recorded outside scope rather than changed here.
