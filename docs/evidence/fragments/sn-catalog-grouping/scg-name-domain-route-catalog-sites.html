The catalog-side domain writers route through the one writer

After the graph-store split, two modules on the catalog side of imas_codex/standard_names/graph_store/ set a StandardName's domain themselves. Each now leaves the domain to imas_codex.standard_names.domain_decision.write_name_domain, which sets physics_domain, source_domains and one HAS_PHYSICS_DOMAIN edge per entry of source_domains in one transaction.

Correction. The graph_claim_scope.py entry above is wrong: the file does perform a write. In the source-pinning path the "absent path" branch builds each StandardNameSource with physics_domain: src.physics_domain and the CREATE (source:StandardNameSource {…, physics_domain: src.physics_domain, …}) at about line 845 stores it on the source node. The value is the DD path's own IMASNode.physics_domain, copied onto the source as snapshot provenance when the source is pinned; it is not a decision about a standard name, and it writes no StandardName scalar and no HAS_PHYSICS_DOMAIN edge. It therefore does not belong with the one writer, which sets a name's scalar, source-domain set and edges together: this write belongs with the DD source-snapshot materialization, whose ground truth is the DD classifier's IMASNode.physics_domain. It is a read of that ground truth copied beside the source, so it is consistent with the single-source rule rather than a second selector. The rest of that entry — the filter and the projection — is read-only, so only the "no write" claim is corrected; the site needed no change.

One writer contract change and one gap

write_name_domain gained an optional fallback_domain. A successor minted by a rename holds no scalar, so "an undecided name keeps its current value" had nothing to keep; the fallback seeds it from the predecessor without the caller writing the property itself.

The derived-parent rule the brief names is not in these four modules. Its writers — _materialize_derived_parent_rows, _bootstrap_missing_derived_parent_targets, _validate_derived_parent_identity and the parent.source_domains = CASE promotion beside them — live in graph_lineage.py, outside this node's fence, so they are recorded outside scope rather than changed here.

The invariant that guarded the old write

TestWriteCypherInvariants::test_physics_domain_uses_coalesce asserted that coalesce( and physics_domain co-occurred in this path's Cypher, so a null payload could not clobber a stored domain. A value that must be preserved is not the contract any more, so the test now asserts the stronger property: the catalog write's Cypher carries no physics_domain and no source_domains, its structural edge pass mints no HAS_PHYSICS_DOMAIN edge, and a companion assertion drives write_name_domain through a recording client so the deferral names a real destination that sets all three. The write does not depend on the client's class

The successor's domain write sat behind isinstance(gc, GraphClient). A proxy, subclass or wrapper a caller handed in therefore skipped physics_domain, source_domains and the edges with only a debug log — a dropped domain behind a message nobody reads. The branch is now a capability check: any client the call path accepts reaches write_name_domain, and a client that offers no query raises TypeError naming what would have been lost rather than skipping.

The check runs where the client is acquired, before the rename transaction opens. It used to sit after tx.commit(), so an unsupported client left a committed successor with no domain — a half-written rename that the refusal came too late to prevent. The unwritable-client test asserts both halves: the TypeError and the absent successor.

Two statements in the same function still bound physics_domain and source_domains as Cypher parameters after the provision stopped setting those properties. The parameters are gone from both.
