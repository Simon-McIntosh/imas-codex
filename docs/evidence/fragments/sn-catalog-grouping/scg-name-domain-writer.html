One writer for a name's domain, with its Jev decision stored

A standard name's physics domain was authored by whichever writer reached it first. This node gives it one writer and one stored decision, so the scalar, the source set and the HAS_PHYSICS_DOMAIN edges can no longer disagree and the audit can check the scalar against something reproducible.

The writer's contract

imas_codex.standard_names.domain_decision.write_name_domain(gc, sn_id, decision, *, correction=None) reads the name's current state and writes all three together in one Cypher statement (domain_decision._WRITE_DOMAIN):

  • source_domains — exactly the set of the name's current DD sources' domains, through StandardName <-PRODUCED_NAME- StandardNameSource -FROM_DD_PATH-> IMASNode. A derived parent, with no DD source, takes the union of its children's domains (the children's DD domains where they have any, their stored source_domains otherwise).
  • physics_domain — the recorded correction when one exists, otherwise the stored decision. An undecided name keeps its current value: the writer never guesses.
  • The HAS_PHYSICS_DOMAIN edges — rewritten to exactly one per entry of source_domains, the stale ones deleted in the same statement.

One statement means one transaction, so a partially written name is not a state the graph can reach. The returned NameDomainWrite carries what was set and why.

The stored decision and its fields

The candidates are exactly the ones the measurement derived, from the same guidance file the measurement read (imas_codex/definitions/physics/domains.yaml): each source path's stored domain, each source IDS's mapped domain from imas_codex/definitions/physics/ids_domains.json, the band umbrella of every band those candidates fall in, and general. The Choice is the runner's build_state and build_question, called through the same decide_batch the runner used; there is no second client and no product import of an evidence script.

Seven slots on StandardName (standard_name.yaml) hold it, so a decision is reproducible from what is stored, not re-derived:

SlotHolds
domain_decision_candidatesthe options offered
domain_decision_choicethe chosen domain
domain_decision_probabilityits probability
domain_decision_modelthe model that decided
domain_decision_atwhen it was decided
domain_correctiona lead-approved domain, which stands above the decision
domain_correction_reasonwhy the correction was made

A name below the floor, or whose call fails, is undecided: it keeps its current domain, and the audit reports it with the reason. The undecided reasons are named verbatim — no answer returned, a choice outside the candidates, an answer with no probability, or a probability under the floor.

The confidence floor, and its derivation

CONFIDENCE_FLOOR = 0.68, derived from the calibration answers in the node's results JSON as the highest observed probability at which at most 5% of the calibration names fall strictly below it. With 73 calibration probabilities sorted ascending, the 5% budget is 3.65 names, so the floor is the larger of the two adjacent observed values whose count-below still fits: 0.68, below-fraction 3/73 = 4.1%.

Accuracy of the answers that clear it:

CohortCorrect / answeredAccuracy
calibration56 / 700.800

pooled120 / 1590.755

The pooled figure is the one to hold a repaired name to: about three in four answered names are right, and the rest are reported undecided rather than written.

The audit now checks the decision, not a re-derivation

imas_codex/standard_names/domain_audit.py no longer calls select_primary_domain. Check 2, physics_domain_not_stored_decision, compares the scalar against the recorded correction or, failing that, the stored decision — the same order the one writer applies. The audit also lists the undecided names with their reasons and reports their share of live names in DomainAuditResult.as_dict()["undecided"].

What the next node must route through it

Every other writer of a name's domain is now a second writer and must be routed through domain_decision.write_name_domain. Named by module and function, as found on the tree this node ran against:

  • compose — imas_codex.standard_names.workers.compose_worker and imas_codex.standard_names.workers.compose_batch, which set source_domains from a single raw domain beside the name they write.
  • consolidation — imas_codex.standard_names.workers.consolidate_worker and imas_codex.standard_names.consolidation.consolidate_candidates.
  • catalog import — imas_codex.standard_names.catalog_import.record_catalog_import_provenance and the name-writing path it feeds.
  • export — imas_codex.standard_names.catalog_release, whose exported name records carry the scalar and must carry the stored decision beside it.
  • reclassify — a name's domain is currently set by imas_codex.standard_names.graph_ops.reclassify_standard_name_domain, which writes the scalar, source_domains and the edge in one statement of its own.
  • derived parents — imas_codex.standard_names.graph_ops._materialize_derived_parent_rows (and the parent.source_domains = CASE promotions beside it), graph_ops._bootstrap_missing_derived_parent_targets and graph_ops._validate_derived_parent_identity.
  • graph-ops sites that set or promote a domain — imas_codex.standard_names.graph_ops.write_standard_names, graph_ops._write_standard_name_edges (the HAS_PHYSICS_DOMAIN edges, one per source domain) and the batch sync at sn.physics_domain = coalesce(b.physics_domain, ...).

None of them is routed by this node: that is the next node's work.
