Pattern family — one definition, entity loci held invariant

The pattern family is now the single family definition. Its invariant signature is the invariant segments plus the entity locus: the object column carries the ISN entity token, and two names describing different entities are never family-mates. The position, geometry and region loci stay variation axes, and the empty value of an axis is one of its values — so electron_temperature and electron_temperature_at_magnetic_axis remain family-mates.

Two further definitions are removed. The invariant segment set is stated once and the members and census Cypher project and compare it through shared helpers, so the columns cannot drift from the constant. The parentless worklist bucket in build_worklist now groups by the same signature instead of by physical_base. The base quantity is reported as a parent only when a node actually backs the token, which retires the phantom parent whose token matched no name.

The locus rule is read from the ISN registry (load_locus_registry()): the segment a token fills is decided by its registered type. The registry holds 105 entity, 72 position, 7 region and 3 geometry loci.

Controls

Entity locus. Two tests assert that the 34 registered entity tokens yield no cohort. With the entity locus dropped from the invariant set both fail — the fixture collapses them into one 34-member family — and with the rule present both pass. The 17-member boundary density family still resolves to 17 under both, keeping the control honest.

Cypher execution. The fixture graph decides membership by the columns the issued Cypher compares, read back from the query text, so a test fails when one invariant column is dropped from the members query.
