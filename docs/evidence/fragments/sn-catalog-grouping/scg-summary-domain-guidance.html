A summary quantity takes the domain of the physics it names

The guidance told the classifier that a summary container decides the domain of everything filed under it, so a DD path such as summary/fusion/neutron_rates/total/value could read as a data product rather than as neutronics. The graph holds that reading: eight of the seventeen labelled summary paths below carry data_management in the graph today, and the stored answers agree with the paths' physics labels on only 0.3529 of them. The rule is corrected here, the classifier's path selection is corrected with it, and both changes are measured at the path.

Changed classifier rule

Only structural paths needed a description to reach Tier 1, so a quantity leaf whose enriched description was missing was sent to the LLM with nothing but the DD placeholder Value in front of it. carries_own_subject (imas_codex/graph/dd_domain_classifier.py) now requires every path to carry a subject of its own — an enriched description, or documentation that is not a container placeholder — and _query_unclassified_paths drops the rest from the Tier-1 selection, so they fall through to the inheritance pass that already exists (_inherit_remaining_unclassified) rather than being classified on the word “Value”. No second classification path is introduced.
