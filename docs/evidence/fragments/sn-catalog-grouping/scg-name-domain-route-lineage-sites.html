The lineage half of the graph store writes a name's domain one way

The graph-store modules that persist lineage — the catalog-edit reclassification, the structural edge pass and the two derived-parent materializers — each set a standard name's physics_domain, its source_domains or its HAS_PHYSICS_DOMAIN edges on its StandardName node on its own. This node routes every StandardName domain write in those modules through domain_decision.write_name_domain, which sets the three together in one transaction.

Sites before

FileFunctionWhat it wrote directly
graph_foundation.py reclassify_standard_name_domain one statement deleting the name's domain edges, then SET name.physics_domain, SET name.source_domains = [$domain] and one MERGE (name)-[:HAS_PHYSICS_DOMAIN]->. The chosen domain became the source set, and every other source domain was discarded.
graph_lineage.py _write_standard_name_edges a cohort-wide UNWIND that merged a HAS_PHYSICS_DOMAIN edge for the payload's source_domains plus its scalar, never deleting a stale edge, so the edges could exceed the source set.
graph_lineage.py _materialize_derived_parent_rows (single) the materializer set parent.physics_domain to its children's most frequent domain and parent.source_domains to their union, and wrote no domain edge at all.
graph_lineage.py _materialize_derived_parent_rows_batched the cohort-wide STRUCTURAL_CLOSURE_BATCH_MATERIALIZE query did the same two SETs for every parent in the batch.

Sites after

  • Catalog edit. reclassify_* records the domain as a reclassify_domain StandardNameChange and hands it to the writer as a DomainCorrection carrying its reason. The scalar becomes the correction; source_domains stays the name's DD sources' domains; the edges become exactly that set.
  • Structural edge pass. The edge pass reads the cohort's stored decisions in one query and calls the writer once per name the graph holds, so a name's edges are rewritten to its source set instead of merged into it. A name with no stored decision is written undecided and keeps its current domain.
  • Derived parents, single and batched. Both materializers keep the children-derived scalar, drop their source_domains SET, and hand each materialized parent to the writer, which sets source_domains (children's union, computed from the graph) and writes one edge per entry. A parent whose stored Jev decision exists takes that decision.

The recorded gap

A derived parent has no Jev decision of its own today: the Choice is asked of composed names, not of the parents their structure implies. Where no stored decision exists the materializer's children's-most-frequent rule still supplies the scalar and the writer keeps it, so the current rule survives unchanged. The writer is therefore authoritative for the source set and the edges on every path, and for the scalar wherever a decision or correction exists. Deciding derived parents through Jev is not part of this node and is recorded here rather than guessed at.

Left alone, and why

  • graph_source_bindings.py (merge_standard_name_sources) and the materializers' sns.physics_domain assignment write a StandardNameSource, not a StandardName. A source's domain is an input to a name's decision, not the decision.
  • graph_cost_and_claims.py and graph_parent_lifecycle.py read physics_domain as a claim scope or a filter and write none.
  • graph_foundation.py's _scalar_domain is a read helper.

Evidence

The path test tests/standard_names/test_name_domain_writer_lineage_sites.py plants a name whose DD source carries equilibrium, runs reclassify_* to magnetic_field_diagnostics on a disposable graph, and reads all three back: the scalar is the correction, the source set and the edges are {equilibrium}. Reverted to the direct write the same test fails, because the correction slot is never recorded.

The suite gate ran tests/standard_names/ -m 'not slow' -n 8, which covers the default tier and the graph-marked tier in one selection, from separate git archive trees under the run directory with a per-arm --basetemp. Base (970cdb0d9) reports 103 failed ids; head (dd5794b76) reports 103 — zero added and zero removed. The graph-marked path test runs green at head under -m graph against the repo's disposable Neo4j fixture.
