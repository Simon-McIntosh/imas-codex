Threshold set to 0.8

[tool.imas-codex.sn-domain-tree].threshold is now 0.8 (pyproject.toml:381, comment moved with the value). get_sn_domain_tree_threshold() reads it (imas_codex/settings.py:1480) and the tree routes a path below it to chat (imas_codex/graph/dd_domain_classifier.py:1207).

The build's path upsert keeps a classified domain

Confirmed from the code, not assumed. The path upsert in imas_codex/graph/build_dd.py:3583 writes the IDS default domain only where the node has no classification yet: 

path.physics_domain = CASE
    WHEN path.domain_source IS NULL THEN p.physics_domain
    ELSE path.physics_domain
END,

That condition is also what makes the reset recoverable: a reset clears domain_source, so the next build's upsert may write the IDS default again, and the classify phase re-fills the field from scratch.

g07: a spent reset that wrote nothing, and its recovery

The first plasma_profiles pass was killed at its launch ceiling after 590 s with its Tier 1 unwritten. Its reset had already run — 3,577 nodes cleared to domain_source empty — so plasma_profiles was left carrying no classification at all. The build writes a batch only that completed, so the pass's USD 1.68 bought nothing.

Recovery ran the same IDS without a reset, as the contract requires: a second reset would have been the second reset for that group. The drain pass wrote 885 Tier 1 classifications and 2,562 inherited ones in 656 s (EXIT=0), and a third pass then reported Tier 1 candidates: 0 paths — classify found nothing left for plasma_profiles.

The 201 rule-labelled paths, read back from the graph

On the 113 of the 201 paths whose IDS belongs to a completed group, the graph's domain matches the rule label on 95 = 0.8407, against the plan's estimate of 0.89. The whole-graph readback over all 201 is 0.7413.

The eleven new misses are all summary/*, and all land on data_management rather than the quantity's physics: summary/fusion/neutron_rates/total/value reads data_management against a label of neutronics, and five summary/global_quantities/* and summary/gas_injection_rates/* paths do the same against core_plasma_physics and fueling. By source, summary took 584 paths through chat and 1,890 by inheritance from those parents; the /value leaves read only "Value" as documentation, which is what the classifier had to work from.

That is a classifier behaviour, not a labelling defect — a container IDS whose children restate other IDSs' quantities is being classified by its container. It is the reason the coordinator stopped the run here.

The other misses are a coordinate path taking its parent's subsystem domain, e.g. core_profiles/profiles_1d/grid/rho_pol_norm reads transport against a label of equilibrium.

The build's tree wiring test

tests/graph/test_dd_build_classify_tree.py pinned the seat threshold to 0.9, so lowering the setting to 0.8 turned three of its five cases red. It now derives its two routing probes from the value the accessor returns — one just below the bar, one just above — and asserts the accessor against the pyproject.toml section rather than against a literal. 5 passed at head (EXIT=0), and the two routing cases also pass under an IMAS_CODEX_SN_DOMAIN_TREE_THRESHOLD=0.95 override, so they track the seat rather than a pinned value.
