Enrichment context — ranking the prompt's code and wiki chunks by relevance

Signal enrichment fills its prompt with a handful of retrieved code and wiki chunks. Both fetches previously took the nearest embeddings as the relevant ones. Each now retrieves a 30-candidate pool above its existing score floor (parallel._fetch_code_chunks at 0.45, wiki.fetch_semantic_wiki_context at its caller's floor), passes the pool, the enrichment query and each candidate's text to judgment.rerank_pool, and keeps the reranked top k — 3 for code, the caller's k for wiki. When the rerank returns no ordering the fetch keeps the embedding order and logs why, because ranking is not a gate. The rerank returns the batch's real decision cost, which the fetch hands to the run and the run adds to its cost total.

The benefit was measured on 15 JT-60SA signal sources. Selection rule: group every jt-60sa FacilitySignal by the enrichment group key the pipeline uses (edas:<category>, the part of the name before the first /), then take the 10 groups with the most members plus the first 5 single-member groups by key, so multi-member and one-member sources are both represented. For each source the code and wiki queries are built exactly as the enrichment worker builds them, and both fetches are run twice — once with the rerank bypassed (the embedding top-k) and once through the product fetch (the reranked top-k). Labelling method: each kept chunk was read against the source's members and its group key and marked relevant when it names or describes the diagnostic, device subsystem, or physical quantity the group's signals belong to, closely enough to supply a true, useful statement in the group's description; generic access-layer and equilibrium-calculation code and unrelated subsystems do not qualify. Precision is taken at the kept count — 3 chunks per fetch, 3 code and 3 wiki per source — and the reported spend is the rerank's own returned cost, not an estimate.

Mean precision at the kept count over the 15 sources: code 0.022 (embedding) to 0.178 (reranked), wiki 0.111 to 0.267, and 0.067 to 0.222 across both fetches — a 3.3× rise. Total real decision spend for the 900 judgements was $0.0215, about $0.0014 per source. The gain is concentrated in the one-member magnetic-probe sources, whose embedding order keeps general equilibrium and plotting code while the reranked order promotes the MECS plasma-position-and-shape-control pages that actually concern a magnetic-probe channel; the large cryogenic and control-system groups gain little because the corpus holds no subsystem-specific content for them, and their precision stays low under both orders.

The rerank's paid decisions are charged to the enrichment run at the cost the decision service returns for the batch (rerank_pool's third return value, summed from decide_batch), so the enrichment cap covers them, and a batch the service could not serve contributes nothing. The relevance rerank reuses the seat the code relevance judgements already use and adds no seat of its own.
