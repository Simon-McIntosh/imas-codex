Member names carry only the segments that vary

extract_member_identifier built the member identifier from the first N numeric runs of the accessor, where N was the count of NNN in the group key, so it was blind to which runs actually differ between members. A JT-60SA accessor carries the reference shot, so every identifier began with 101173 (e.g. 101173/81). The identifier is now built only from the numeric runs whose value differs across the source's members; a constant run belongs to the group and is dropped, and several varying runs still join with /. individualize_members passes the member accessor set through, so the varying positions come from the source's own members rather than from a positional count. Delivered in imas_codex/discovery/signals/parallel.py with tests/discovery/test_member_identifier.py pinning the three cases and tests/discovery/test_signals_pipeline.py still green (49 passed, EXIT=0).
