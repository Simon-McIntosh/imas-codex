DD-path search rerank — one call into the shared owner behind a mode switch

search_dd_paths reorders its hybrid hits through rerank_candidates in imas_codex/llm/search_tools.py — the shared search-time owner the code and wiki search tools already use — rather than carrying a second rerank of its own. The switch is a construction-time decision: GraphSearchTool(..., rerank=…), plumbed through Tools(..., rerank_dd_paths=…). The MCP server sets it on for a full or facility server and leaves it off for a read-only or DD-only server, so an external query spends no judgement. Each hit rides its own candidate dict under _hit, with its path as the locator and its documentation and description as the judged text, so the judged order maps back to the hits without a path lookup (paths are not unique across IDSs). A failed or slow judgement returns the embedding order unchanged, so the result is never worse than the search that produced it.

How the label sets were built

The 15 questions live in tests/tools/fixtures/dd_mapping_questions.json (168 labelled paths). Each label set is enumerated from the live graph by path name and documentation, not from memory: a Cypher match over the IMASNode id enumerates every path whose name is the queried quantity, and every one that exists is graded 3, so a quantity with a home in five IDSs is graded 3 in all five. The rule:

  • 3 — a DD path that stores the queried quantity itself, in any IDS. For plasma current: equilibrium/time_slice/global_quantities/ip, plasma_profiles/global_quantities/ip, plasma_initiation/global_quantities/ip, core_profiles/global_quantities/ip, magnetics/ip, magnetics/method/ip, and the decay-time and summary ip copies.
  • 2 — a reference or setpoint of it: the pulse_schedule control paths (pulse_schedule/flux_control/ip, pulse_schedule/pf_active/supply/current, pulse_schedule/position_control/magnetic_axis/z), the constraints copies, the vacuum_toroidal_field/b0 reference field.
  • 1 — a closely related quantity: a toroidal current density where the current was asked, a cross-sectional area or a plot-grid cell where the volume was asked, a fit structure, an error field.

Two carve-outs keep grade 3 to the quantity itself. ferritic/object/volume and spi/injector/fragment/volume store a solid object's volume rather than the plasma volume, and are graded 1; magnetics/rogowski_coil/current stores the plasma current seen by a Rogowski contour rather than a coil current, and is also graded 1. The enumeration behind every set is in label_enumeration.log.

nDCG@10 and precision@5 on the completed labels

The measurement (log measurement_completed_labels.log) scores the same retrieval twice on the same labels, at k=10, against the live graph and a live Jev judge: once in the tool's embedding order (rerank=False) and once after the rerank (rerank=True). Precision@5 counts grade 3 only, so a grade-2 setpoint or a grade-1 neighbour in the top five does not count.

On the completed labels the rerank is net-positive: nDCG@10 rises from 0.3451 to 0.4102 and precision@5 from 0.2667 to 0.3333. 7 questions improve, 4 degrade and 4 are unchanged. The largest gains are flux loop voltage (0.3962 → 0.9587, the loop's own voltage lifted above the v_loop and constraint paths), magnetic axis position (0.4795 → 0.7446, precision@5 0.0 → 0.8, the rerank replaces grid/psi_magnetic_axis with real axis-position paths) and electron density (0.1564 → 0.3492).

The first measurement is superseded

A first measurement on labels that named one home per quantity reported the rerank as net-negative (nDCG@10 0.3324 → 0.2860). That result is superseded, and the reason is the defect the completed labels remove: a DD quantity lives in several IDSs, and those labels graded only the equilibrium and summary homes, so a reranked order that surfaced other real homes scored as if it had returned unrelated paths. For plasma current the reranked top five were plasma_profiles/global_quantities/ip, plasma_initiation/global_quantities/ip, equilibrium/time_slice/global_quantities/ip, core_profiles/global_quantities/ip and magnetics ip — every one a real home — yet only two were labelled, so the better order scored worse. The labels, not the rerank, set the sign of that measurement.

The three cases to watch

  • plasma volume — improved, with a caveat. The rerank puts radiation/process/profiles_1d/grid/volume first and equilibrium/time_slice/global_quantities/volume second. Under the completed labels both are grade 3 — the radiation path is the same "volume enclosed inside the magnetic surface" the equilibrium volume is — so nDCG@10 rises 0.2935 → 0.3590 and precision@5 0.2 → 0.4: not a failure by the labels. It is a plot-grid copy of the quantity, though, and a reader who asked for the plasma volume wanted the equilibrium global quantity, which the rerank demotes to rank 2. The metric cannot see that intent, so this is recorded as label-correct but intent-questionable rather than as a clean win.
  • electron temperature — a real failure. The rerank promotes pellets/time_slice/pellet/path_profiles/t_e to rank 1 and sawteeth/profiles_1d/t_e to rank 2, pushing the canonical core_profiles electron temperature out of the top five. nDCG@10 falls 0.5900 → 0.4168 and precision@5 0.8 → 0.4. A pellet path profile is not the electron temperature profile; the judge preferred its text.
  • coil current — a real failure. The rerank promotes pulse_schedule/pf_active/supply/current to rank 1, above the real coil-current homes pf_active/coil/current and coils_non_axisymmetric/coil/current. nDCG@10 falls 0.4740 → 0.2946 and precision@5 0.4 → 0.2. A supply-current setpoint is not the coil current.

Two of the three flagged cases are genuine rerank failures — a pellet path profile ahead of the electron temperature profile, and a supply-current setpoint ahead of the coil current. The third (plasma volume) is label-correct but intent-questionable. The rerank wins on the whole set because it lifts the loop voltage, the magnetic-axis position and the electron density by more than these two lose.

The switch honours the server mode

AgentsServer.__post_init__ sets the module-level switch to not (read_only or dd_only), so a full server reranks and a read-only or DD-only server — the public containers — never does. A directly-constructed Tools or GraphSearchTool defaults the switch off. The tests pin all four: full reranks, read-only never, DD-only never, default off.
