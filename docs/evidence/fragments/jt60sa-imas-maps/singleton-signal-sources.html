One-member sources for signals grouping leaves ungrouped

Change

detect_signal_sources created a SignalSource only for an accessor pattern with at least min_instances members. A signal in a smaller pattern carried no source, and every mapping stage keys on a SignalSource, so such a signal could never be mapped. The function now runs a final pass: each signal the threshold leaves ungrouped becomes a one-member source keyed by the signal itself, with the signal as its representative, created through the function's own MERGE so the threshold is unchanged. The key is the accessor, which is unique per facility; a signal whose accessor is null falls back to its id, so no signal is dropped. The unused create_signal_source in imas_codex/discovery/base/grouping.py, which had no caller, is deleted; detection now owns source creation.

Measure

uv run --no-sync pytest tests/discovery tests/ids -p no:cacheprovider exits 0 — 1773 passed, 5 skipped, 4 deselected. The unit tests assert the set of (group_id, group_key, member_count) the pass writes, not call order: a lone signal forms a one-member source with itself as representative, a sub-threshold pattern forms two one-member sources rather than a shared group, and a null-accessor signal is keyed by its id rather than dropped. The live -m graph test builds a fixture facility of three ungrouped signals — one of them channel-like, its accessor ending _01 — and one three-member pattern, asserts three one-member sources and one three-member source after the first run and no new source or edge after a second, then enriches a one-member source and shows claim_sources_for_candidates claims it — 1 passed.

Negative control

Made to skip ungrouped signals, the final pass fails exactly the one-member source tests: 4 failed, EXIT=1. A second control drops the null-accessor fallback (key = r["accessor"]): the null-accessor case fails alone, 1 failed, EXIT=1. Both mutations were reverted.

The removal check and the grep the plan names

The done-when's literal grep -rn create_signal_source imas_codex/ tests/ does not print nothing: it also matches the unrelated detect_and_create_signal_sources in the MDSplus discovery worker (imas_codex/discovery/mdsplus/graph_ops.py), which the plan leaves in place. The word-boundary form grep -rnw create_signal_source imas_codex/ tests/ prints nothing, so the removed symbol is gone and the literal gate was over-broad. The plan's grep is corrected to the word-boundary form.

Interaction with the channel-element enrichment skip

claim_signals_for_enrichment bulk-skips numbered channel signals, marking them skipped with reason channel_element; that guard excludes any signal already MEMBER_OF a source, because grouping enriches the representative and propagates. A channel-like signal that grouping left ungrouped was therefore bulk-skipped and never enriched; with a one-member source it is claimed individually instead. The -m graph fixture pins this: its channel-like signal (CHANNEL_SENSE_01) is asserted to be claimed by claim_signals_for_enrichment once it carries a source.

Quantified for JT-60SA with one bounded read-only count over the four guard regexes: zero JT-60SA signals match the channel-element pattern in any status — 0 of 5534 discovered, 0 of 763 checked, 0 of 1 enriched. So the bulk-skip is a no-op at JT-60SA and this change alters no JT-60SA enrichment behaviour. Of the 5534 discovered signals, 1969 were ungrouped and now each receives a one-member source; none of those 1969 is channel-like.
