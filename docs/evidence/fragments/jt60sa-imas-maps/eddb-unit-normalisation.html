EDDB unit spellings — parsing the catalogue's free text

The EDDB catalogue writes units as human text: letter case varies (KA, Mpa, DegC), digit exponents are glued to the symbol (m2, m3), and products are glued (Pam3). The alias file parses these without claiming a name pint already owns; a case variant and a glued form are both defined through @alias, so 20 degC, 20 DegC and 20 oC each convert to 293.15 K.

Each glued spelling is a unit in its own right, defined without a symbol. A symbol containing ^ is not usable: pint reads ^ as the right-associative **, so a negative power of such a unit formats as m^2^-1, which re-parses as m2-1 = m0.5 rather than m-2. The invariant the definitions hold to is the round trip: normalize_unit_symbol output, parsed again, must be the same unit as its input — equal dimensionality and a conversion factor of exactly 1, the comparison analyze_units and the DD build already make. Because equivalence, not the string, is what matters, spellings that denote one unit are grouped below under that unit regardless of how they are written. A bare n is not defined: it shadows the nano prefix's parse space and breaks count itself, so the neutron yield spellings stay unresolved with a reason.
