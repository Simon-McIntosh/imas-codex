What the live run does not isolate. A paired run on the pre-fix workers.py (the main-tree file at e94cedbd8^) also wrote bindings (magnetics: 8 bindings, 1 escalations), because the two pre-selected sources were already claimable and the mapping pass claimed them before any assignment claim existed. The defect the commit fixes — a mapping pass that exits while an in-run assignment still holds the claim — requires a source the assignment pass selects during the run, i.e. an escalated source with mapping_disposition IS NULL and a magnetics candidate. On jt-60sa all four escalated sources with a magnetics candidate already carry a disposition (no_imas_equivalent / facility_specific), so the count of claimable escalated magnetics sources is 0 and the in-run release path is not reproducible on this graph without manufacturing state. The unit gate and its declared mutation isolate the fix; the live run confirms the post-fix pipeline maps pre-selected sources and leaves no-selected sources unbound.
