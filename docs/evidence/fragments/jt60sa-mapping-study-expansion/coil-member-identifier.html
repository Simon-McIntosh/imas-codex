A coil array reads its member identifier from the facility pattern

_member_identifier in imas_codex/ids/handoff.py took a singleton array's identifier from the array name's trailing number. The JT-60SA MMSYS coil currents carry the member in the middle of the name, before the acquisition chain (curEF5LKAT, curCS1HiTe, curUFPLKAT, cur1TFLKAT), so no trailing number exists and all 40 MMSYS rows exported a null identifier. Which part of a name is the member is facility knowledge, so it now lives in facility configuration: a per-source-group regular expression with a named group member, declared by the new signal_member_patterns slot in imas_codex/schemas/facility_config.yaml and set for MMSYS in imas_codex/config/facilities/jt-60sa.yaml as ^cur(?P<member>.+?)(?:TFLKAT|LKAT|HiTe)$. _member_patterns compiles the facility block, and _member_identifier reads the row's group pattern first; a group with no pattern keeps the trailing-number rule, and an array the pattern does not match keeps a null identifier.
