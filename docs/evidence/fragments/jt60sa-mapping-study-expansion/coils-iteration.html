MMSYS coil currents through the mapping loop

The study maps the JT-60SA MMSYS coil-current signals onto pf_active and tf and exports a hand-off document for imas-ambix. The MMSYS group carries 28 coil-current sources — the TF (cur1TFLKAT, cur2TFLKAT), the central solenoid (curCS1–curCS4), the equilibrium field coils (curEF1–curEF6), and the low/upper field-protection and disrupter coils (curLFP*, curUFP*), each with a high-temperature and a low-temperature winding where both exist — all read through eddbreadTime('E101173', 'MMSYS', '<name>', t1, t2). This node ran the per-system loop of the plan (§8) over that cohort.

The loop as it ran

The candidate stage took the cohort as its focus — discover jt-60sa --only candidates --focus <28 ids>. The plan writes this stage as --only map, but the discovery sequence accepts only the domain name candidate at that slot and refuses map as an unknown discovery domain, so the valid token is candidates. The map loop then cleared and re-ran per IDS on the local seat: imas map clear jt-60sa pf_active --yes, imas map clear jt-60sa tf --yes (both cleared nothing — no prior mapping existed), then imas map run jt-60sa -i pf_active -i tf.

The ids-mapping seat ([tool.imas-codex.ids-mapping] in pyproject.toml) served every step: model local/deepseek-v4.1-flash, model-route ambix-local, endpoint-class local-free, reasoning-effort high. The run spent $0.0000 on the seat — it is local and free — and issued each choose_targets and map_signals_<ids>/<section> step against http://98dci4-gpu-0003:18802/v1.

Blocker — the mapping cannot finish inside the node budget

The map loop runs a single worker per phase and holds its per-source LLM batches in memory (state.mapping_batches): the validate worker persists the IMASMapping — and therefore writes the MAPS_TO_IMAS edges — only once an IDS has mapped its entire source set in one process. So a time-limited run persists nothing, and two concurrent processes would each persist a partial mapping rather than one complete one. A single process is the only correct shape, and it must chew through the facility-wide source set for the IDS: the escalated backlog for pf_active + tf is 56 sources, of which only the 28 cohort sources are this study's subject; the rest are unrelated escalated signals the IDS carries. --focus scopes which sources get candidates generated, not which the choice and map stages consume, so the loop cannot be narrowed to the cohort by the loop options alone. At the measured pace (about two sources per minute per phase, the local seat returning in 25–40 s per call) the remaining work is roughly 35 minutes of single-process wall clock — more than the 60-minute node budget allowed after the rich candidate stage.

The node therefore set status waiting: a single-process map run was relaunched with a 60-minute budget and is in flight. When it completes it writes the IMASMapping for pf_active and tf to the graph; the resume then exports to /work/projects/imas_gpu/jt60sa/handoff/jt-60sa-coils-handoff.json, verifies it with check_handoff_document, checks each of the 28 cohort sources is a signal row or an unexpanded row with a reason, and completes this fragment with the exported and refused counts.

Negative control: none. This is an operational run whose check is check_handoff_document on its own output plus a per-coil coverage count; there is no code under test to mutate. The exported and refused counts in the measure table are read from the run's own log and the graph, and the zero MAPS_TO_IMAS count is the honest state — the run has not yet reached the persist step.
