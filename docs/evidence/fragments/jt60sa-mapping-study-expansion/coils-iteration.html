MMSYS coil currents through the mapping loop

The study maps the JT-60SA MMSYS coil-current signals onto pf_active and tf and exports a hand-off document for imas-ambix. The MMSYS group carries 28 coil-current sources — the TF (cur1TFLKAT, cur2TFLKAT), the central solenoid (curCS1–curCS4), the equilibrium field coils (curEF1–curEF6) and the low/upper field-protection and disrupter coils (curLFP*, curUFP*), each with a high-temperature and a low-temperature winding where both exist — all read through eddbreadTime('E101173', 'MMSYS', '<name>', t1, t2). This node ran the per-system loop of the plan (§8) over that cohort and produced the hand-off export.

The loop as it ran

The candidate stage took the cohort as its focus — discover jt-60sa --only candidates --focus <28 ids>. The plan writes this stage as --only map, but the discovery sequence refuses map as an unknown discovery domain and accepts only candidates at that slot. The map loop then cleared and re-ran per IDS on the local seat: imas map clear jt-60sa <ids> --yes then imas map run jt-60sa -i pf_active -i tf, run unbounded from the main checkout once two engine defects were fixed. The export then ran imas map export jt-60sa -i pf_active -i tf --out /work/projects/imas_gpu/jt60sa/handoff/jt-60sa-coils-handoff.json, and the document passed check_handoff_document — format imas-codex-mapping-handoff, version 1, DD 4.1.1, both IDS status generated.

The ids-mapping seat ([tool.imas-codex.ids-mapping] in pyproject.toml) served every step: model local/deepseek-v4.1-flash, model-route ambix-local, endpoint-class local-free, reasoning-effort high. The run spent $0.0000 — the seat is local and free.

A current is the same current under any COCOS convention, so the label travels as a sign convention for the receiving side to honour; the value transform carries the amperes unchanged.
