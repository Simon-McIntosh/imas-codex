Error mappings come only from error signals

derive_error_mappings in imas_codex/ids/mapping.py ran two passes. The first walked every direct data mapping's IMASNode target to its HAS_ERROR children and wrote an error_derived binding from the same value source onto each error field — claiming a measured value is also its own uncertainty. The hand-off export dropped those rows, but the stage still wrote them and every other consumer of the graph saw them. This node removes that first pass and the deduplication that guarded against it. The second pass, match_error_signals_to_imas, which maps sources that really are uncertainties, is retained unchanged: an error field is now bound only when a facility source classified as an error signal stands behind it, and an error field with no such signal is left unmapped.

The exclusion branch in imas_codex/ids/handoff.py classifies an error_derived row as unexpanded when the field was filled from the same signal that feeds its data field. It is left in place as a guard against error_derived rows still present in older graphs, and the test that exercises it (test_builder_expands_members_and_keeps_missing_values_as_null) still passes in the gate above.
