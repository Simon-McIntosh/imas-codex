Error-signal matching reads the run's own data mappings

match_error_signals_to_imas in imas_codex/ids/mapping.py cross-referenced error signals against persisted direct MAPS_TO_IMAS edges. The pipeline calls derive_error_mappings from imas_codex/ids/workers.py before persist_mapping_result runs, so on a first pass after map clear no data binding existed in the graph and no error signal was ever mapped — the run's own data_mappings argument was ignored. The matcher now builds its parent lookup from the in-memory data_mappings the caller passes, deriving each binding's group key from its source_id. The graph supplies only the HAS_ERROR children of the matched target, a data-dictionary relationship. The include_direct_error_signals flag is removed: error-signal matching is the only pass, so its name no longer gated a stage that could be switched off.
