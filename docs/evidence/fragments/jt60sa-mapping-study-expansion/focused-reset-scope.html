A focused reset touches only the focused sources

What changed. The --reset-to branch in imas_codex/cli/discover/signals.py scoped its reset by scanner and category but ignored --focus, so discover jt-60sa --only signals --focus X --reset-to discovered reset every eligible JT-60SA signal before enriching only X. The branch now renders the same predicate the §1 claims use — build_focus_predicate('n', focus_items) — into the reset's extra_filter and passes focus_items as a query parameter, so the reset is narrowed to the named sources.

Unit measure. tests/discovery/test_signals_focus_reset.py runs the stage with --focus and --reset-to discovered against a fake GraphClient that evaluates the reset query's focus filter. A focused reset emits n.id IN $focus_items and passes the focused source ids into reset_to_status; a signal of an unnamed source keeps its enriched status.
