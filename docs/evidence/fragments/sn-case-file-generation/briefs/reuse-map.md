## One record per name

the per-name artifact is decomposed across sections instead of sitting behind one record: §2 produces "a case file ... each with a digest", then a separate run against "the file's own completeness check", then a token-size distribution, then §4's blocker entry, §3's per-arm row and §1's packet-digest check — six shapes for one per-name artifact, each re-reading the same graph neighbourhood; the deep alternative is one case-file record carrying content, digest and completeness verdict together, with §2's completeness run a field of the record and §3's arm consuming the record rather than re-collecting it

## Benchmark report and held-out handling: existing owners

§3 proposes a per-arm report (share right with interval, blocked by type, cost, time, tokens) and §2 a case-file completeness check, and neither section says why the existing report and validation cannot be extended instead: `imas_codex/standard_names/advisory_benchmark.py:81` (`FrozenBenchmarkReport`) already stores frozen per-row verdicts with message-hash validation, cost summaries and argument validation, `imas_codex/standard_names/benchmark.py:227` (`BenchmarkReport`) already carries per-model right/wrong rows with `:1869` (`render_comparison_table`), and `imas_codex/standard_names/docs_holdout_eval.py` already keeps held-out material apart from development material
