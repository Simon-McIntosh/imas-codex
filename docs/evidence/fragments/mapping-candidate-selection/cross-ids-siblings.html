Cross-IDS cluster siblings widens each source's shortlist

A source's Jev top five candidates are now expanded through their cross-IDS DD clusters. expand_cluster_siblings(source, facility, candidates, judgments, *, gc) in imas_codex/ids/candidates.py takes the CLUSTER_SEED_COUNT (5) candidates with the highest first-call p_same_quantity, calls related_dd_search(gc, path, relationship_types="cluster") on each, and joins every new sibling as a Candidate whose arms are {cluster} (CLUSTER_ARM), deduplicated on path, dropping any path already in the shortlist and capped at CLUSTER_SIBLING_CAP (10). Each seed's SearchHit.see_also is filled with the sibling paths its own cluster contributed. The siblings are judged in a second decisions call booked to the candidate_cluster_judgment cost step, because the sibling set depends on the first call's ranking; candidate_worker calls the expansion between judge_candidates and route. route now returns a Route.selected set marking every candidate at or above the select threshold, and _candidate_records emits each record's arms. The edge gains an arms property on MAPPING_CANDIDATE, written by write_candidates and refused unless it is a list of strings, alongside the existing non-boolean route refusal. The margin rule is retired: the map-select-margin key, RouteThresholds.select_margin and its read in get_mapping_route_thresholds are gone.

Two behaviours fail closed. A failed second decisions call makes expand_cluster_siblings return None: the siblings exist but were never scored, so candidate_worker releases the claim and writes no candidates, leaving the source unjudged for a retry rather than recording it as fully judged on its first-call candidates alone; the empty-pair return is kept only for the genuine no-sibling case. _candidate_arms refuses an absent arms value instead of defaulting it to empty, because the only producer always emits it and an absent value means provenance was dropped.
