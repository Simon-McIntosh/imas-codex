One count-checked owner for the SignalSource to IMASNode edge

Every create and delete of a MAPS_TO_IMAS edge now lives in imas_codex/ids/graph_ops.py. write_mapping_binding(binding, gc) MATCHes both endpoints, MERGEs the edge and reads the RETURN count(r) AS written row; a reported count of zero raises CandidateWriteError, and a result carrying no row at all fails the same way, so a binding whose source or target IMASNode has vanished fails loudly. persist_mapping_result and the error-derivation writer both call it, and the unused create_signal_source is removed with its test. clear_mapping_bindings(facility, ids_name, gc) owns the delete; imas map clear and --clear call it instead of issuing their own Cypher. _candidate_record type-checks a judgment's route rather than coercing it with bool(), so a route string can no longer mark a candidate selected. imas map status reports candidate routes through count_candidates_by_route, which moves into graph_ops.py beside the candidate writers. imas map run drops --skip-errors (same as --stage data) and --skip-metadata (parsed but never read).
