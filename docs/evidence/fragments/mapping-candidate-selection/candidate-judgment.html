Jev pair judgment and routing in ids/candidates.py

The candidate module now owns judgment and routing beside retrieval. route_ids(description, *, gc) asks one Choice over every IDS (its name and one-line description offered as criteria) and returns the three most probable IDSs; judge_candidates(source, facility, candidates) asks one batched same_quantity noul per candidate in a single decisions request and returns one PairJudgment (path, p_same_quantity, model, judged_at) per candidate; route(judgments, thresholds) orders them by p_same_quantity and returns a Route (decision, top-N shortlist). Both calls travel the shared call_decisions layer. Thresholds come from get_mapping_route_thresholds() (RouteThresholds): the select threshold and floor default unset, the margin to 0.10 and the shortlist to 5. A decisions transport failure returns no route, leaving the source unjudged; a malformed answer is raised, not swallowed. Model seat [tool.imas-codex.mapping-candidates] = typesafe/jev-1.13; the questions are the frozen wording in imas_codex/llm/prompts/mapping/candidate_judgment.md.
