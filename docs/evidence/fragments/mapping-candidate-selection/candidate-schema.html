MAPPING_CANDIDATE edges: schema, write and clear

Declares the candidate relationship and the two functions that own it. Write paths: imas_codex/schemas/facility.yaml, imas_codex/ids/graph_ops.py, tests/ids/test_candidate_persistence.py.

Declaration

  • SignalSource gains slot mapping_candidates, range: IMASNode, multivalued, annotated relationship_type: MAPPING_CANDIDATE. The generated schema context reads ('SignalSource', 'MAPPING_CANDIDATE', 'IMASNode', 'many').
  • SignalSource gains field candidate_route (string), null until judged.
  • Edge properties written by write_candidates: rank, retrieval_score, ids, choice_probability, p_same_quantity, model, judged_at, route.

Functions in graph_ops.py

write_candidates(source_id, judgments, route, gc) replaces a source's MAPPING_CANDIDATE edges in one statement: it deletes the prior edges, UNWINDs the judgments inside a CALL subquery that MATCHes both the SignalSource and each IMASNode, counts the edges written, then releases the mapping claim (mapping_claimed_at and mapping_claim_token to null) and sets candidate_route. The route is set with CASE WHEN written = $expected THEN $route ELSE null END: it lands only when every judgment persisted, so a shortfall leaves the route null and the next pass re-judges the source rather than treating it as done. The statement still raises CandidateWriteError when the release has run, so a candidate whose node has vanished fails loudly without stranding the source. The subquery keeps the count row when the judgment list is empty, so a no_candidate decision with no edges still records its route.

clear_candidates(facility, gc) removes a facility's candidate edges and resets candidate_route, returning {"edges_removed": n, "routes_reset": m}.
