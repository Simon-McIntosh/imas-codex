Both registry consumers read the grammar's template sentences

The grammar's template_sentences is now the source of the sentences a name selects: each selected template's opening, and then its note once per distinct note. Two imas-codex consumers were reading AppliedTemplate.documentation alone and so never saw the note.

Writer (imas_codex/standard_names/workers.py): _instantiated_template_sentences fills every placeholder a sentence carries from the name's own segments — only {subject} and {locus} are ever fillable, so a sentence needing {zone} or {component} renders nothing — and returns the first renderable opening with the notes that render. _documentation_with_registry_form writes that opening at the model opening's line and appends each note once, immediately after it; a note already present in the written documentation is not written twice. A name with no renderable opening and no renderable note keeps its model opening unchanged, so electron_temperature is untouched while upper_triangularity, whose two selected openings both need an unfillable placeholder, gains only its note.

Gate (imas_codex/standard_names/docs_gates.py): _template_findings checks the opening as before and additionally reports a template_note finding, on registry entry template:<base>, for each distinct note a selected template carries that the documentation omits. A note appearing anywhere in the body satisfies it.

No second rendering of a template sentence exists in imas-codex: both consumers now resolve sentences through the grammar accessor, and neither reimplements the selection or the note deduplication.
