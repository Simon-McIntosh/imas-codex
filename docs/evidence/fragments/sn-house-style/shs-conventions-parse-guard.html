One parse guard in the conventions owner

conventions_context_for in imas_codex/standard_names/context.py now catches the public grammar's ParseError and returns None, logging the name at DEBUG, so a name the local build cannot parse yields no conventions instead of raising. Only the parse error is caught; any other failure still propagates. The per-call-site helper _conventions_for_prompt was removed from workers.py, whose three render sites call conventions_context_for directly, and the fourth site in review/pipeline.py was already unguarded and now inherits the guard.

Evidence

Four new tests in tests/standard_names/test_conventions_parse_guard.py: an unparseable name returns None; a parseable name still selects; a non-parse failure propagates; and a docs review batch driven through _review_single_batch with an unparseable name completes with conventions is None. Against the base revision with the guard removed, two of the four fail (the guard tests) while the review batch raises out; the log at logs/negative_control.log records 2 failed, EXIT=1. Its passing arm runs 962 tests with zero failures at base and 966 (the four new tests included) with zero failures at head.
