Report-only judge stage beside the audit stage

A deterministic pattern decides what it can: a forbidden variant written exactly as its registered pattern, a forbidden symbol spelling, an opening matching a selected template. The cases the registry states only as equivalence classes — an equation written in one of several equivalent ways, a gloss that equates two loci, an opening that paraphrases a template — cannot be decided by a pattern. Those go to an asynchronous judge stage that runs beside the audit stage in the review pipeline.

A judged entry is a selected concept that carries forbidden variants: a concept with none has nothing a pattern cannot decide. For each judged entry the stage asks one categorising Choice through the shared decisions owner (decide_batch), booked under the sn-judge seat. The results join the same per-name findings list the reviewer receives, each line marked report-only:judge:concept_form. A report-only finding is never booked into the error-lint findings the score cap reads, so it never caps a score. A name whose selected entries carry no forbidden variant makes no call.

The stage lives in imas_codex/standard_names/review/judge_stage.py and is wired into enrich_review_worker in imas_codex/standard_names/review/pipeline.py, where the audit findings are attached per batch.

Wiring and report-only guarantee

With the decisions owner stubbed at the judgment layer's acall_decisions seam, the enrich worker asks exactly one Choice per judged entry per name, and the results appear in the batch's per-name findings marked report-only. The guard test fails when the stage is unwired from the pipeline: with the judge block disabled the guarding test id test_one_choice_per_judged_entry_reaches_the_reviewer_findings fails and the run ends non-zero. A report-only result leaves the reviewer score uncapped, because the cap reads only the error-lint findings the judge never writes. A name with no judged entry makes no call.
