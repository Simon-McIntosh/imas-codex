Jev decides the name review; documentation stays with the paid panel

The deciding switch was one boolean for both review axes, so turning Jev on for names turned it on for documentation in the same edit. The lead's ruling of 2026-10-22 splits them on the evidence: on the cohort's shared items Jev's name accept rate is +4.3 pp against the incumbent's, with a 95% interval of −4.3 to +13.9 pp — within noise, so the name axis can be handed over. On documentation Jev accepts 49 shared items the incumbent refines and none the other way, so that axis stays with the paid panel until the disagreement is labelled. The switch therefore becomes per axis, the setting names the name axis only, and the paid 5% audit keeps sampling whichever axes Jev decides.

1. The switch reads the axis

In imas_codex/standard_names/review/cascade.py, deciding_enabled() becomes deciding_enabled(axis: str) -> bool. [sn-review].cascade-deciding accepts four forms: absent or false (neither axis decides — shadow mode), true (both), a list drawn from "name" and "docs" (Jev decides those, the incumbent keeps the rest), and nothing else. A list naming an unknown axis, a bare string, a number or a mapping each raise ValueError naming the accepted forms, so a typo cannot silently leave an axis deciding when it should shadow, or the reverse. The one call site passes its axis: if deciding_enabled(axis): at the cascade's route store, and the paid audit runs inside that branch, so with names deciding and docs shadowing the sample draws from names only.

2. The setting

In pyproject.toml, [tool.imas-codex.sn-review] gains cascade-deciding = ["name"] with a three-line comment stating the forms and that documentation stays with the paid panel until its disagreement with Jev is labelled. The evidence is the Jev-only dry run over the fixed cohort, where 1 of 231 name items was undecided and the accept rate on shared items sits close to the incumbent's — the ruling's basis for handing over names. Documentation is held back because 76 of 219 docs items were undecided on no usable judgment errors and Jev accepted 49 shared items the panel refines, a disagreement the diagnosis node classified rather than resolved. One setting reverts the whole change.

3. The audit's two follow-on test repairs

The construction-site guard no longer counts nested partials. It walked the workers module's AST for any partial(_persisting_quorum_cycles, …) anywhere in the source, so a decorator or a further partial layer around the wrapper left the inner partial in place and the guard still saw two sites and passed — it could not fail on the wrapper case it exists to catch. The guard now collects each adjudicate_review call site and asserts the site's own incumbent argument is the partial the seam recognises, as the site's outermost expression. test_the_site_guard_rejects_a_wrapped_partial makes the failure mechanism explicit: on a source whose site passes _traced(partial(_persisting_quorum_cycles, …)) it asserts the old count-based expression still finds the inner partial, and that the site guard rejects the wrapped expression.

The group-id test no longer injects the value it reads back. test_audit_row_carries_the_group_id_its_own_cycle_rows_carry stubs only the model call and drives the real workers._run_rd_quorum_cycles, which builds the cycle rows and returns the group id with them. It asserts the returned records all carry that group id, then that panel_audit._audit_record given that verdict carries the same one — the audit row joins the cycle it observed, and no value is fabricated in the fixture. test_the_group_id_assertion_detects_a_row_that_invents_its_own_group shows the claim is falsifiable: with _audit_group_id replaced by one that mints its own id, the row's group id differs from the panel's.

The declared mutation makes deciding_enabled ignore the axis: with a list of axes it returns True instead of testing membership, so a docs item is decided by Jev while the setting says it shadows. Applied to a scratch tree at the head revision, the run reports 1 failed, 1 passed, 13 deselected at EXIT=1, the red id being test_names_deciding_leaves_documentation_with_the_incumbent[docs-False] — the docs arm returned jev_cascade_accept where the incumbent's verdict was required.
