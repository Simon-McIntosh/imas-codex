Lineage-recovered cases added to the blind refine sheet

The rebuild driver now falls back to a refined descendant when a case's own two recorded identities hold no DD source. The measured detail is in the rebuild fragment, which the same run rewrites.

What changed

  • The driver gains one bounded lineage read: (descendant)-[:REFINED_FROM*1..6]->(ancestor), restricted to a descendant whose name_stage is neither superseded nor exhausted and that holds a DD PRODUCED_NAME source. It is added to the read adapter's allowlist, so the refusal of an unlisted query still holds.
  • The descendant's source is taken exactly as the existing resolver picks one for a bound name, and the case is injected with it, so the sheet builder runs unchanged and writes a row indistinguishable from a recovered or a direct one.
  • Two sourced descendants resolving to different DD paths leave the case ambiguous: it stays out and both candidates are recorded. No choice is made.
  • The arm key carries case_source_routes (lineage with the descendant id, else direct), the ambiguous cases with both candidates, and the agreement control.
  • A planted source_route on the sheet is refused.
