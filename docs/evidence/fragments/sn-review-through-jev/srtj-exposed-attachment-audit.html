Nine attachment-audit tests that never ran now pass: one product defect, six stale expectations

Putting every graph-marked standard-names test on the disposable Neo4j made nine tests in tests/standard_names/test_attachment_audit.py execute for the first time, and all nine failed. They were not one cause. Three failed inside recover_terminal_attachments because the recovery's own postflight proof could never hold: the statement stamps name.updated_at in the same SET clause that removes the binding, and the preserved-state hash included that stamp, so every applying run compared the pre-recovery value against the time it had just written. That is a product defect, fixed at the normalizer that builds the payload. The other six failed inside reconcile_attachment_consistency because a deliberate contract change landed 2026-10-21 in 93e04a526 — a rejected attachment that is its name's only producer is now held and reported, not detached — and the tests were never updated with it; they were skipped at the time. Five of the six are corrected to keep exercising the detach path by leaving a second, consistent producer standing; the sixth asserts the hold the product now performs. No assertion was deleted or weakened.

1. Product defect: the preserved-state proof included a field the mutation writes

Reproduced at base e2fee62a4 before any repair, on the disposable graph: 3 failed at EXIT=1, each with TerminalAttachmentRecoveryConflict: terminal recovery postflight proof did not hold raised at attachment_audit.py:2373. Instrumenting the refusal reason at that point showed the postflight refusals carried preserved terminal graph state drifted after recovery for every row, and that the name's property set after the mutation contained updated_at = neo4j.time.DateTime(2026, 10, 27, 11, 3, 23, 194000000) while the seeded pre-state carried none.

Two commits made the contradiction, six days apart: 7b2e1476b introduced the terminal recovery and its preserved-state proof, and ebcc255a5 (2026-09-06, every write to a name stamps its modification time) appended name.updated_at = datetime() to the recovery's SET block — one of the four attachment-audit writes that commit names. The payload in _terminal_recovery_preserved_payload already excluded the source-side fields the recovery writes, through _TERMINAL_RECOVERY_MUTABLE_SOURCE_FIELDS, and filtered the name's source_paths; the name's stamp was the one written field it still hashed. The suffix of that commit message — leaving them out made staleness and drift checks downstream read a false age — is why the remedy is on the proof, not on the stamp.

The fix drops updated_at from the name's preserved properties, beside the existing source_paths filter, so the proof covers exactly the state the mutation does not write. The closure, participant and relationship hashes are untouched, and require_producing_sources remains as the backstop. Verdict for all three: product defect, test left as written. Ids: test_terminal_recovery_graph_mixed_unique_and_shared_targets, test_terminal_recovery_graph_shared_target_is_atomic_and_idempotent[2], test_terminal_recovery_graph_shared_target_is_atomic_and_idempotent[6].

2. Stale expectations: the hold contract of 2026-10-21

At base these six failed with a single shape: the attachment was not detached. The captured warning names it — reconcile_attachment_consistency: 1 attachment(s) held — detaching would leave these live names with no producing source — and each test's fixture seeds exactly one producer for the name.

The contract changed in 93e04a526 (2026-10-21, hold a stranding attachment rather than aborting reconcile), whose message states the mechanism: detachment left the name sourceless, require_producing_sources raised inside the transaction, and the whole apply — including the family apply after it — aborted on every run for a name the pass could not repair. The commit touched attachment_audit.py alone. It introduced the skipped_stranding/held_stranding buckets and classified these verdicts into them before the detach.

Five tests keep their detach assertions and now seed a second, consistent producer through a new _seed_surviving_producer helper (camera_ir/channel/camera/up/z, which the guard accepts), so the detach path is still the path under test: test_reconcile_detaches_and_reroutes, test_reconcile_keeps_history, test_reconcile_is_idempotent, test_accepted_attachment_survives_without_the_flag, test_source_backing_a_good_name_keeps_its_status. One assertion inside the first moved with the fixture rather than being weakened: source_paths must now read exactly the surviving path instead of the empty list, because a surviving producer leaves its own path there. The sixth, test_orphaned_name_is_reported, has no honest surviving producer — its subject is a name whose only source is wrong — so it asserts the contract that now holds: skipped_stranding == 1, held_stranding[0].sn_id == sn_id, detached == 0, names_orphaned == [], and the name stays drafted. Its docstring now says held-and-reported rather than orphaned. Verdict for all six: stale test, corrected to the contract of 93e04a526.
