One disposable-Neo4j convention for the standard-names tests

Outcome

Two test files demanded opposite values of NEO4J_URI, so no session could run both: test_source_refresh.py refused any endpoint equal to the project graph, while test_panel_audit_sample.py demanded NEO4J_URI name the disposable one. Worse, the refusing guard resolved the “project graph” through NEO4J_URI, so once a run pointed that variable at a disposable endpoint the guard compared the endpoint against itself and refused everything. The five source-drift tests therefore errored at setup in the merged graph gate.

One session-scoped fixture in tests/standard_names/conftest.py now owns the convention for the package: it attaches to a supplied disposable endpoint or starts an empty instance of its own, names that endpoint in both NEO4J_URI and IMAS_CODEX_TEST_NEO4J_URI for the test's duration, and refuses loudly when the endpoint is the project graph’s. Both files’ local guards are deleted. The five drift tests run and pass.

The fixture keeps no copy of the Apptainer launch. The copy it replaced had two defects, both now fixed in the owner or removed with it: a start that never reached Bolt readiness left the container and its JVM running, and two free ports chosen one after the other could be the same port. The owner creates its own bind-mounted directories, so no caller can fail on a missing one.
The refusalCollects every address the project graph answers to with NEO4J_URI withheld — the loopback port a login node's profile names, and the address service discovery reports for the scheduled instance, which is what a compute node connects to — and fails the run when the endpoint is either. Both are needed: the loopback spelling alone refuses nothing on a cluster whose graph runs on a service node. Neither is resolved by opening a tunnel, so reading an address stays a read.
An unrunnable instanceFails with the error rather than skipping. A disposable instance these tests cannot start is a broken gate, and a skip would report it as an absence of work.
Profile checkAfter the environment is set, the fixture fails if the profile ignores NEO4J_URI, because a test that builds a bare GraphClient() would then reach past the instance it was given. The check is stated as what it proves: with the override in place the profile returns the override, so it says nothing about the project graph — the refusal is what protects production.

An empty instance carries no DD-resolution authority, and the drift scan reads one to stamp each source snapshot. The scan’s Cypher is what those tests prove, so test_source_refresh.py’s graph fixture serves the authority from the package’s synthetic rows — the same boundary the mock tier uses — while every query still runs on the disposable graph.

The refusal, shown firing

Two tests, split by what they need. test_the_shared_fixture_refuses_the_project_loopback_address takes the address from the profile and runs in the default tier, so an ordinary run with no cluster service still exercises the guard. test_the_shared_fixture_refuses_the_scheduled_graph_address carries the graph marker and reads the node from squeue rather than from the resolver the guard uses, so a resolver that had narrowed to the loopback spelling — as one did — cannot keep it green. Both require the refusal twice: from the check, and through the fixture body with IMAS_CODEX_TEST_NEO4J_URI set to that address. A disposable address is accepted in the same breath, so neither test can succeed by refusing everything.

With conftest.py taken from the earlier commit, whose refusal collected only the loopback spelling, the loopback test passes and the scheduled test fails: Failed: DID NOT RAISE <class 'Failed'> — the address the guard did not know is the address a compute node uses. With the fixture’s refuse_project_graph(uri) call replaced by a no-op, both fail, and the failure is what the log records rather than the assertion: the loopback arm reaches _wipe and gets ServiceUnavailable on localhost:7687, and the scheduled arm reaches _wipe at the live graph and gets neo4j.exceptions.AuthError: ... Unsupported authentication token, because the fixture sets NEO4J_PASSWORD empty and the project graph refuses an unauthenticated write. That is the guard’s importance measured directly: without it the fixture proceeds to wipe the project graph and is stopped only by a credential it does not have.

A full -m graph selection at that address stops even earlier, in tests/conftest.py’s endpoint probe (Graph-marked test selection was not run: Explicit Neo4J test endpoint is not available, exit 5), before any fixture executes. That pre-check is the first line of defence and covers the case where the disposable instance is missing altogether; the fixture’s refusal is the second, and the committed test is what exercises it.

A failed start leaves nothing running

The launch was the fixture’s own copy of the owner’s work, so it carried the obligations without the cleanup: an instance that never reached Bolt readiness stayed up, holding its JVM and its memory on the node every session on the machine shares. Two things were wrong at once. The start had no failure path, and the two ports it asked for were chosen one after the other, each socket closed before the next was bound, so the kernel was free to hand out the same port twice.

The copy is gone. The fixture asks the owner for an empty instance — start_temp_neo4j(..., load_dump=False), a keyword added because an empty instance is what a test wants and there is no dump to load — and stops it through the owner, with the scratch directory removed in a finally so a failed stop still leaves no tree. A readiness failure now stops what the start began: the wait raises, and the process group created in its own session is signalled before the exception leaves. The port pair is chosen with both sockets bound at once, so the two cannot collide.

test_a_failed_start_leaves_no_process_behind holds that in place. It replaces the launch command with a long sleep — so the arm costs nothing and starts no container — and requires the failure to leave the process reaped. With the owner’s stop_temp_neo4j call removed from the failure path, the command fails, and the arm’s assertion reports the failed start left its process running.
