The tests/graph writers run on a disposable instance, and a collection guard keeps them there

The parallel-fixture work routed every graph-marked test in tests/standard_names to a shared disposable Neo4j. Its writer audit found five graph-marked tests in tests/graph that still built a bare GraphClient() and wrote through it, so a pytest -m graph tests/graph/ run landed fixture rows in the project graph: one in test_code_reference_links.py and four in test_dd_unit_correction_reconcile.py. That is invisible in a green run — the writes land, the assertions pass, and the only trace is data the project graph did not ask for. The five now run on a disposable empty instance; the reading tests, such as the SN quality tests and the DD unit drift invariant, stay on the live graph by design; and a collection-time guard refuses a graph-marked writer that reaches a bare client without the disposable fixture.

1. One disposable instance, bound per test

The disposable machinery is not rebuilt. tests/graph/conftest.py imports the starters the standard_names package already owns — _start_empty_neo4j, _detach_store_removal, _wipe and refuse_project_graph — rather than starting a second kind of instance. The address is created once per session (_disposable_neo4j_address, or the endpoint a run advertises through IMAS_CODEX_TEST_NEO4J_URI) but it binds no environment: a graph-marked test that only reads the live graph must keep seeing the live graph for the whole session. The environment is bound by the function-scoped disposable_graph fixture and undone when that test ends. Binding it session-wide would have redirected every later live-graph reader to the empty instance — the writers would pass and the readers would silently measure nothing.

The refusal runs before the wipe. refuse_project_graph resolves the project address with NEO4J_URI withheld, so it compares the disposable endpoint against production rather than against itself; the fixture then checks that the graph profile still honours NEO4J_URI, because that is the wiring that makes a bare GraphClient() land on the instance it was given.

Each writer gets the deterministic data it asserts on. The code-reference test seeds the one Facility row (jt-60sa) its reference resolution reads before opening its rolled-back transaction. The reconcile writers take _disposable_gc, which serves the same synthetic DD-resolution authority the mock tier uses: the authority is a property of the DD version rather than of a graph, so an empty instance carries none and resolve_dd_unit raised DD resolution graph authority is empty until the synthetic rows were served. The drift invariant test_no_live_dd_node_contradicts_the_registry keeps the live _gc, because it reads the project graph on purpose.

2. The collection guard

pytest_collection_modifyitems in tests/graph/conftest.py inspects each graph-marked test in the package. It reads the test function's AST for a bare GraphClient() (a construction with no uri argument), or a request for a client fixture resolved from the process environment (_gc, graph_client, graph_with_schema), and for a write: a write-named helper call (reconcile_…, link_…, create_…, …) or a Cypher write keyword in the string argument of query/run/execute_query/execute_write. A test that both constructs and writes is refused with pytest.UsageError naming its node id, unless it requests a disposable fixture. Only Cypher arguments are inspected, not every string literal: an early revision scanned all strings and refused a reader whose docstring contains the word set.

A write one call away is still a write. The guard parses the test's module as well as the test function, and follows calls to functions defined at its top level, so a test whose only statement is _seed_nodes(client) reads as the writer that helper makes it. Recursion is bounded by the set of helper names already visited, so a recursive helper cannot loop. Measured on a planted pair: from the test function alone the delegating writer reads (writes=False, bare_client=True) and would pass the guard; with the module in hand it reads (writes=True, bare_client=True) and is refused. What the guard still cannot see is written beside the hook — a write inside an imported helper or a fixture body, Cypher assembled at runtime or sent through a method outside the four inspected, a client obtained inside a helper from the environment when the test never names GraphClient, and a write reached through a class method or a callable value. Each is visible to a reader of the test; the guard is the backstop for the ordinary shape.

The guard's decisions are tested rather than asserted once by hand. tests/graph/test_graph_writer_guard.py builds synthetic collection items over planted functions defined in that same file — the attributes the hook reads, obj, fixturenames, fspath, nodeid and get_closest_marker — and puts each case to the hook: it refuses the bare-client writer and the delegating writer; it passes the writer that requests disposable_graph, the reader holding a bare client, and the reader whose docstring mentions a write keyword; it ignores a test outside the package and an unmarked one; and one refusal names every offender and only the offenders. Eight tests, all passing, in logs/guard-tests.log. They carry no graph marker, so they run in the default arm and cost nothing to run.

The guard is also shown refusing a planted writer through pytest itself. test_zz_planted_graph_writer.py in the head tree, a graph-marked test that does GraphClient() and client.query("CREATE (:PlantedProbe …)") with no disposable fixture, is refused at collection: the run prints ERROR: graph-marked tests that write must run on the disposable graph (request the 'disposable_graph' fixture): tests/graph/test_zz_planted_graph_writer.py::test_planted_writer_without_disposable_routing and exits 4. It is then removed. The log logs/guard-refusal.log opens with the revision and the literal command that produced it.

3. Gate and controls

The gate is pytest -m graph tests/graph/ at base (6e9edb8bf) and head (004d9f1e5), each from a separate git archive tree under the run's node-local scratch, each with its own --basetemp. The base arm deselects the five writers so the base run cannot write to the project graph; they are the hazard under repair and their base arm is the live write the node must not perform. Head: 18 failed, 275 passed, 65 skipped, 1 xfailed at EXIT=1 — the same eighteen pre-existing live-graph content and schema failures and five more tests passing, the five writers. Added failure ids: 0, and none removed, compared as sorted FAILED/ERROR id sets from runs made with -rfs so both kinds reach the summary. Logs: logs/base-graph.log, logs/head-graph.log. One base attempt is in the record as a retry: the project graph answered no connection for that run (16 setup errors plus a refused -m graph selection an hour earlier), and the identical command passed once the graph was serving, so the arm is judged on the clean run rather than on the outage.

The default-marker arm pytest tests/graph/ selects the non-graph-marked tests in the package, including the eight guard tests. Base: 2 failed, 639 passed at EXIT=1; head: 2 failed, 647 passed at EXIT=1 — the same two pre-existing failures and the eight new guard tests passing. Added failure ids: 0. Logs: logs/base-default.log, logs/head-default.log.

The five writers pass on the disposable instance. The focused run over both files reports 6 passed, 3 deselected at EXIT=0 — the five writers plus the live drift invariant — with the disposable Neo4j started and torn down in the run (logs/writers-probe.log).
