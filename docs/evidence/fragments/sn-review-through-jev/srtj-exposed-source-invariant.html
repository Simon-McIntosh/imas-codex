1. Product defect: a status-less source was not counted as a producer

The producer count read OPTIONAL MATCH (source:StandardNameSource)-[:PRODUCED_NAME]->(sn) WHERE source.status <> 'stale'. Cypher evaluates null <> 'stale' to null, which a WHERE treats as false, so a source that carries no status property at all was filtered out of the optional match and the name was counted as sourceless. The clause is now coalesce(source.status, '') <> 'stale': only an explicit stale reading is excluded. A stale source is one whose DD entity no longer exists, which is why excluding it is right; a source that was never given a status is an ordinary producer. The clause arrived in 302d01357; the null-safety was missed there and at the same shape elsewhere (see the scope note).

The failing id is test_real_invariant_allows_one_source, which seeds exactly one source with no status property and requires the write to be allowed. It passes at head and fails again under the node's negative control.

2. Four fixtures seeded a graph the detach never produces

Verdict: stale test data, not a product defect. The contract that governs. 24b8638cc (2026-10-18) added the require_producing_sources postcondition to the signed-manifest detach path, six lines after the existing live_producers < 1 and live_children < 1 check. The invariant it calls is narrower than that check and says so in two places: _derived_parent_cypher exempts a parent only when its origin is derived and it has a live child (5e8360b22), and attachment_audit composes that same clause in rather than restating it, documenting the exemption as "a superseded name, or a derived parent with a live child". test_real_invariant_refuses_missing_origin — passing both before and after this node — asserts the deliberate counterpart: a non-derived parent with a live child is still refused without a producer. Relaxing the invariant to accept any structural parent would have contradicted a contract held by a green test and weakened the guard for every writer, so it was not the fix.

The fixtures, though, seeded only the 58 authority rows being detached, each carrying status: 'stale', plus a structural child per preserved target. That state is not real: detaching a stale source removes a path that no longer exists in the DD, while the name is still produced by the paths that do exist. A read-only query against the project graph shows it — area_of_diagnostic_aperture holds 23 producers, all attached; electron_density 9; vertical_outline 10 — while the fixture gives these names none, so after the detach the fixture reads as sourceless. _seed_signed_live_rows in tests/standard_names/test_stale_source_detach.py now models that surviving producer: one attached source per preserved target. The refused rows' targets stay unseeded, so the last-producer refusal tests still fire exactly as written.

The four ids, each passing at head unchanged in its assertions: test_complete_signed_admission_cohort_applies_and_replays_without_writes, and test_each_widened_signed_shape_releases_its_complete_source_closure at [derived-source], [multi-binding-dd] and [scalar-mismatch].
