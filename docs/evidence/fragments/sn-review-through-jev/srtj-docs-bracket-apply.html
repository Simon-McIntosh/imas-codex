How to restore

The restore record srtj-docs-bracket-apply-restore.json holds every changed document's text before and after, keyed by id. Restoring means writing each document's before text back to the StandardName.documentation property of its id. The runner does it in one command, and verifies the write:

uv run --no-sync python docs/evidence/fragments/sn-review-through-jev/srtj-docs-bracket-apply-run.py \
  --restore-from docs/evidence/fragments/sn-review-through-jev/srtj-docs-bracket-apply-restore.json

It prints restored=814 wrong=0 and exits 0. The path was exercised during this run: the catalogue was restored from the record and the normaliser re-applied, so the record is known to reproduce the pre-apply text rather than merely to hold it. Full before/after text also sits in the run directory at dryrun-full.json, and the apply record's own restore_record_bytes names the committed record's size.

The committed restore record is 2,426,870 bytes, above the landing contract's 300,000-byte guidance for a repository data file. It is committed because this node's done-when names it as the deliverable and a restore record without the text restores nothing. The coordinator may move it to the run directory if the size is judged not worth the repository cost; the run directory already carries the identical payload.
