Mechanism of the eleven added failures

Both failing files call persist_reviewed_docs with a mocked GraphClient whose query side effect supplies the readback rows. Recording the mock’s call count inside the failing test gave gc.query.call_count == 0 and a returned stage of ''. The function documents '' as its claim-token-mismatch no-op, so the preflight saw no rows and returned before any write. The two test files are unchanged between base and head (git log c5b7f76ed..c71dd6056 -- <file> is empty for both), so the code changed underneath them.

At base the function read rows = gc.query(...) directly, which the mock intercepts. At head the same read runs inside with gc.session() as session: tx = session.begin_transaction(); graph = _TransactionQuery(tx), so the mocked gc.query is never called. git blame over that block returns ed9dbace65, which is an ancestor of 8e4327db0 and not of base.

The downstream node’s own record confirms the reading: srtj-review-holds-channel.html states that claim verification, hold writes and score persistence share one transaction after ed9dbace6, and that its committed gate passed its own ten disposable-Neo4j tests plus 61 focused tests with zero added failures. Those focused tests are its own files; test_review_cascade.py and test_bare_doc_link_normalize.py were not among them, which is exactly the gap this gate measures.
