The paid panel audited beside the deciding Jev route

When [sn-review].panel-audit-rate is above zero and cascade-deciding is on, a decided item still runs the paid panel on a deterministic fraction of items and the panel's verdict is stored beside Jev's as a non-deciding row (resolution_role="audit", resolution_method="panel_audit"). The rate is read from [sn-review].panel-audit-rate and defaults to 0.05; zero turns the audit off. The item's stage, score and route are Jev's: the audit is attempted only after the route is stored, and its result never reaches the returned decision.

The sample is a stable hash rather than a running counter, so a replay picks the same items without any stored position. audit_selected(axis, item_id, run_id, rate) draws the first 64 bits of sha256("sn-review:panel-audit:v1" \0 run_id \0 axis \0 item_id) and selects when the draw, scaled to the unit interval, is below the rate. Over 20,000 name ids at rate 0.05 the draw selects 1,031 (5.16%), and a replay selects the identical set; the same ids under a different run id select a different set. A rate of 0 samples nothing and a rate of 1 samples everything, and those two bounds are returned before any hashing.

The audit row carries judge_kind="jev" and is_canonical=false, which is the clause update_review_aggregates already uses to exclude a shadow row, so the row is excluded from review count, mean score and disagreement without a change to the aggregate query. Being a judge record rather than an incumbent record also keeps it off every mirroring path, so it cannot set a score on the StandardName. The offline regression plants two incumbent reviews at 0.4 and 0.5, writes an audit row for the same item, and asserts the aggregate stays at count 2, mean 0.45 and no disagreement; the assertion is red before the exclusion and green after.

The panel runs through the quorum's non-persisting path. The deciding path hands the cascade a callable that writes the quorum's canonical review rows before returning its verdict, and those rows would reach update_review_aggregates and move the audited item's own score — the outcome the audit exists not to touch. quorum_without_persisting(incumbent) recognises that wrapper and rebinds it to the cycle runner with the same keywords, so the panel still runs and only its returned verdict is read; any other callable is passed through unchanged, so a stub runs exactly as its caller gave it. The test drives that real seam with the cycle runner stubbed and the review writer captured: it asserts the only row written is the audit's, that no canonical row lands, and that the aggregate over the resulting review set stays at count 2, mean 0.45. A persisting callable reached through some other wrapper would not be recognised, which is the limit of the match.

The audit spends through the same budget pool as the decision. It reserves a lease under a per-axis phase before running the panel, and a refused lease records a skipped audit and returns Jev's decision unchanged. A panel that raises, and a panel that returns no verdict, are recorded the same way. A skipped audit is a row rather than an absence, so a gap in the sample is visible: the row carries audit_skipped with the reason and resolution_method="panel_audit_skipped". A manager that refuses only the review_audit_* phase leaves the decision at Jev's score and route, runs the panel zero times and writes exactly one row, the skipped one.

The report function is read-only. panel_audit_report(since=..., axes=("name","docs")) reads the audit rows in the window, pairs each against the Jev route recorded on the row itself, and returns one PanelAuditAxisReport per axis with the sample size, the agreement count and rate, the count of each disagreement direction, the skipped count and the tally of skip reasons. A skipped audit carries no pair and is counted outside the sample, so a rate near zero reads as a small sample rather than as perfect agreement. A row that carries neither a skip reason nor both routes is counted as skipped too, with a reason naming what it lacks, and a row whose comments are not readable JSON is counted the same way; nothing is dropped uncounted, because a row discarded in silence reads as a smaller sample rather than as a defect. On a stubbed backlog of six name rows (three paired, one skipped by a refused lease, one missing the panel route, one unreadable) and one documentation row:

name: sample=3 agreement=1 rate=0.333 disagreements={'jev_accept_panel_refine': 1, 'jev_refine_panel_accept': 1} skipped=3
    reasons={'review audit lease refused': 1, 'audit row carries no panel_route': 1, 'audit row comments are not readable JSON': 1}
docs: sample=1 agreement=1 rate=1.000 disagreements={} skipped=0
