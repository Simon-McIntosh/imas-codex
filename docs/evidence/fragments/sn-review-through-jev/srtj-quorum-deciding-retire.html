What was deleted, and what still runs

Jev decides both review axes, so the quorum no longer decides or persists a review for an item it judged. The persisting cycle wrapper is deleted, the incumbent-first fallback is replaced by the cascade's single chat reviewer, and the seats that only the deciding path used are accounted for below. The quorum survives as the 5 % panel audit only: what the audit runs is the non-persisting cycle runner, which is untouched.

Review seats

No configured seat became unreachable, so none was deleted. [sn-review.names].models and [sn-review.docs].models still resolve through get_sn_review_*_models(), but no longer as a deciding chain: the audit panel is the only caller that runs all of them (_run_panel_audit passes the whole list to the non-persisting runner on its sample), and the chat reviewer takes the first seat of that same list. Deleting seats 2 and 3 would have shortened the audit panel and changed the drift measure the lead ruling keeps. What was removed from the seat resolution is the deciding consumer, not the seats.

No review seat resolves through get_model: no member of MODEL_SECTIONS names a review seat, and test_no_review_seat_resolves_outside_the_chat_reviewer_and_audit_panel pins that, plus the chat reviewer's seat being drawn from the panel's configured seats. imas_codex/settings.py and pyproject.toml therefore needed no change for this deletion.

Added, with line counts

  • imas_codex/standard_names/review/cascade.py: _chat_seat (5 lines) — the one place the configured chain is narrowed to the head the chat reviewer runs. It is the fallback's seat rule, used by an unjudged item and by a judged item whose axis is in shadow mode, so both take the same reviewer rather than a chain.

Kept, and why

  • _run_rd_quorum_cycles — the cycle runner the audit panel runs through panel_audit.quorum_without_persisting. It persists nothing, so keeping it keeps the audit non-deciding.
  • panel_audit.quorum_without_persisting and the 5 % rate and storage — the lead ruling keeps the drift measure.
  • The single chat reviewer, now introduced as _persisting_chat_review: it runs one seat, refuses a chain, and writes the one canonical row for an item Jev could not judge.
  • The unjudged shadow row and its count beside the route shares.

Tests

tests/standard_names/test_review_deciding_paths_retired.py adds six tests, and each either reads an expectation that does not come from the code it checks or drives the code it names. The seat test compares the resolver against the seats pyproject.toml declares (a section's own models plus every profile's, read with tomllib), so a chain that silently loses its profile seats is caught rather than agreeing with itself. The retained runner is driven for real: two configured seats run two cycles against a stub structured-call double with the graph writer patched, so the test asserts two records returned and zero canonical rows written. The unjudged test asserts the four values the fallback is responsible for — the item, the axis, the unavailable judge's label and the reason returned by decisions_key_absent_reason — rather than a tuple the stub built. Every one was shown to fail when its path is broken: shortening the names chain to its top-level seats fails the seat test, writing records inside _run_rd_quorum_cycles fails the runner test, and returning the full chain from _chat_seat and substituting a generic reason each fail the unjudged test. Each mutation's run is recorded in logs/negative-control-tests.log.

Seven tests in tests/standard_names/test_review_quorum_pool.py were deleted (357 lines). Each asserted how the reviewer chain cycled inside a pool batch — cycle 0 + 1 always, cycle 2 on disagreement, group ids and per-cycle cost — which is the deciding path this node removes: a batch item now reaches the cascade and, unjudged, takes one chat seat. The chain's own cycle semantics are still covered where the audit runs them, by test_rd_quorum_integrity.py and test_panel_audit_sample.py.
