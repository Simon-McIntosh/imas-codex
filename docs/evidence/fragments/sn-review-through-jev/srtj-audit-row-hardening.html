The paid-panel audit refuses an incumbent it cannot prove non-persisting, and its row names the cycle it observed

The audit runs the paid panel beside the calibrated Jev route, and its whole safety argument rests on the panel running through a non-persisting seam: the deciding path hands the cascade a callable that writes the quorum's canonical review rows, an audited item must read the same verdict without those rows, and the seam is what drops the write. That seam recognised the persisting wrapper by object identity and returned everything else unchanged, so it failed open — any future construction site the recognition did not cover would have run a persisting callable and moved the audited item's score, silently defeating the audit. Three changes harden it: the seam now refuses what it cannot prove; the audit row carries the review group id its cycle's rows use; and the module docstring's count of the audit's guards is corrected.

1. The non-persisting seam fails closed

The seam still recognises the persisting wrapper structurally — a functools.partial of workers._persisting_quorum_cycles carrying the quorum's keyword arguments — and rebinds it to the cycle runner, keeping every argument and dropping only the write. A callable that declares itself with a true non_persisting attribute is returned unchanged; in practice only a test stub declares this. Anything else is now refused with UnrecognisedIncumbent, naming the callable in the message. The cascade already converts an exception from the incumbent into a skipped audit row, so the refusal is recorded as a skipped item whose reason names the unrecognised callable rather than being run.

Three tests in tests/standard_names/test_panel_audit_sample.py hold the seam. test_seam_refuses_an_incumbent_it_cannot_prove_non_persisting passes an undeclared, non-persisting-looking callable and asserts UnrecognisedIncumbent is raised with the callable's repr in the message. test_seam_returns_a_declared_non_persisting_callable_unchanged asserts the declared stub is returned by identity. test_every_quorum_construction_site_builds_the_recognised_partial reads both construction sites out of the workers module's source by import — by import, never by file path — parses them and fails if either stops building the exact partial the seam recognises, so a new construction site the seam does not cover is caught at review rather than at runtime.

The refusal is also shown end to end. test_unprovable_incumbent_is_skipped_without_running_the_panel drives the cascade at a rate of one with an undeclared incumbent: the Jev stage, score and route are unchanged, the captured panel call list is empty (the callable never ran), and exactly one row is written with panel_result is None and UnrecognisedIncumbent in its audit_skipped reason.

Its declared negative control restores identity-only recognition so an unrecognised incumbent runs unchanged; the fail-closed test must fail. Applied to the head tree the mutation returns the incumbent instead of raising, and the run reports 2 failed, 14 passed, 1 skipped at EXIT=1 — the two red ids are test_seam_refuses_an_incumbent_it_cannot_prove_non_persisting and test_unprovable_incumbent_is_skipped_without_running_the_panel. The log is logs/negctl-fail-closed.log.

2. The audit row carries its cycle's review group id

The audit row is a judge record — judge_kind='jev', resolution_role='audit', is_canonical=False, cycle_index=-1 — and carried no review_group_id. It now takes the panel's own group id from the quorum's returned verdict, so the audit's verdict names the cycle it observed; a skipped audit ran no cycle and is given its own id, because the writer requires one on every review record.

Two unit tests assert the row's group id: test_audit_row_carries_the_panel_review_group_id passes a panel result carrying a group id and requires the row to carry the same one; test_skipped_audit_row_carries_a_review_group_id requires a truthy group id on a skipped row.

The row is then proven on a real graph, unstubbed. test_the_real_writer_stores_the_audit_row_and_the_aggregate_ignores_it drives the audit row through the real write_reviews into a disposable Neo4j that the test starts empty and plants its own StandardName in. The profile is pointed at the disposable instance through NEO4J_URI, and the module-scoped fixture refuses unless the profile resolves to that endpoint — so the write cannot reach the project graph. The fixture also refuses the project endpoint by resolving it with NEO4J_URI withheld, which recovers the address this checkout would otherwise reach instead of comparing the disposable URI against itself. The test seeds a canonical baseline row, writes the audit record, reads the rows back (two rows; the audit row carries review_group_id, is_canonical=False, judge_kind='jev', cycle_index=-1 and the jev_route/panel_route comments), then runs update_review_aggregates and asserts the aggregate is the canonical baseline alone — count one, mean 0.44, no disagreement — so the audit row demonstrably does not move the audited item's score. It loads no export dump. Run with the disposable instance it reports 17 passed at EXIT=0; the log is logs/head-panelaudit-full.log.

Its declared control drops review_group_id from the audit row's record.update. Applied to the head tree the run reports 2 failed, 14 passed, 1 skipped at EXIT=1, the red ids being test_audit_row_carries_the_panel_review_group_id and test_skipped_audit_row_carries_a_review_group_id. The log is logs/negctl-review-group-id.log.

3. The docstring's guard count

The module docstring announced Three things keep the audit from deciding anything: above four bullets. It now reads Four things, so the prose agrees with the four guards beneath it — a stable sampled set, a non-canonical judge row the aggregate already excludes, the non-persisting seam, and a skipped audit that never fails the decision.

Gate and spend

The gate is the delta on four files — test_panel_audit_sample.py, test_review_cascade.py, test_review_shadow_store.py, test_cascade_atomicity.py — each arm run once with --timeout=300, no live-graph write to the project graph and no LLM call, against the base revision extracted from 26b0ce3a1 and against the head worktree. The base arm ran 93 passed at EXIT=0 (logs/gate-base.log); the head arm ran 100 passed at EXIT=0 (logs/gate-head.log). The head arm adds no failure.
