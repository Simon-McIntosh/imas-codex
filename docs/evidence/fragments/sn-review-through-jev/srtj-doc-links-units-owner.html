The prose-bracket check reads its unit verdict from the unit owner

The documentation gate classifies a bracketed string as notation rather than prose when it holds a unit, and the predicate that decided this carried its own unit vocabulary: a 26-symbol set and a prefix set, both duplicating what imas_codex.units already owns through validate_unit and the alias data. A factor was notation only if it appeared in that copy, so a unit the owner knows and the copy lacked — siemens, ohm, kiloohm — was read as prose, and a bracket holding one was reported as a phrase that should have been a link. The same predicate also carried a numeric-interval branch that decided nothing. Both findings come from the review of the bracket repair at merge ead4d99c8.

1. One unit vocabulary

Each factor of a bracket's content is now resolved through imas_codex.units.validate_unit; _UNIT_SYMBOLS and _UNIT_PREFIXES are deleted from imas_codex/standard_names/doc_links.py. The shape guard _UNIT_FACTOR_RE stays, because it constrains what can be a factor rather than which symbols are units, and the module now imports the owner at module level, as docs_gates already does for resolve_dd_unit.

The verdicts the existing tests pin are unchanged: m^-3, K, 10^20 m^-3, m/s, 0, 1 and 1 are notation; banana, total plasma current and the core boundary are prose. The owner adds verdicts the copy lacked: ohm, kohm and S are now notation where they were prose.

2. The dead numeric-interval branch

The branch at the head of _is_prose_bracket tested _NUMERIC_INTERVAL_RE.fullmatch and returned notation. Every string that regex matches — 0, 1, -2.5, 3 — carries no letter, and the letter test immediately below it already returns notation for exactly those inputs, so the branch could not change an answer. It and its regex are deleted, and 0, 1, 1 and -2.5 are pinned as notation by tests so the verdict survives the deletion.
