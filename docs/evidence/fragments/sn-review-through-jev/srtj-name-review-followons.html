The Jev name review reads an unrun audit as unknown and refuses an unsplittable Choice

Three follow-ons against imas_codex/standard_names/review/jev_review.py, the name-axis judge that nothing in the pipeline calls yet. The module is not wired and no threshold is settled; the review's cost and latency behaviour is unchanged.

Changes

ChangeBeforeAfter
An audit that never ran An audit-decided check was recorded answered: True with failed: finding is not None even when no audit_report was supplied, so an audit that was never run read as answered-and-not-failed — the unrun audit read as a pass. _item_record records an audit check answered only when an audit_report was supplied; with no report the check is unanswerable and its derived decision is unknown, consistent with the module's own rule that an absent call is never read as an acceptance. A report that carries no finding for the name still answers the check (the audit ran) and accepts it.
A Choice the split cannot read The comment promised a check whose options cannot be split is refused at table construction, but _question_def built the criteria with no refusal and check_failed read options[0] unconditionally, so a mis-authored options list was mis-decided silently. choice_acceptable_form states the taxonomy's own rule in one place — a Choice lists its acceptable form first and the defective forms after it, so the split is the first option against the rest — and refuses a question whose options carry no readable acceptable form (fewer than two options, or a blank first option). _question_def calls it at table construction and check_failed reads the acceptable form through it.
A plan reference in a comment The NOUL_FAIL_PROBABILITY comment cited a superseding per-check threshold from a plan deliverable. The comment states the mechanism: the model returns a probability rather than a verdict, and the fail is derived at that midpoint in code rather than asked of it.
