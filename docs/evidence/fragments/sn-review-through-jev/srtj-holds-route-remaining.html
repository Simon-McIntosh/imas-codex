Documentation vetoes routed through review holds

The two remaining places where a refusal to accept a documentation was expressed by lowering a judged score now raise a review hold instead. The reviewer's score is preserved exactly as written, and the refusal is a separate, triageable ReviewHold node on the name. Acceptance is decided by the existing predicate, which already reads open holds, so a held document cannot be accepted by any path.

Site 1 — the documentation lint cap

imas_codex/standard_names/review/pipeline.py, _cap_docs_scores_for_lint_errors, called from _review_single_batch in the target == "docs" branch.

  • Before: an entry carrying an error-severity lint finding had its reviewer_score driven below the acceptance threshold. The judged score moved, so the refusal was indistinguishable from the reviewer's own low opinion of the document.
  • After: the finding is recorded on the entry under audit_cap_finding as before, and the name receives a docs_lint_error hold through raise_hold. The score is not touched. The pass log line states the kept score.
  • Persistence check: the docs write (write_docs_review_results) stores scores only and never sets docs_stage; acceptance is decided later by persist_reviewed_docs and promote_stranded_reviewed, and both already read open holds. No write outside the review package was required, so the stop-and-report condition did not apply.

Site 2 — the cascade contradiction veto

imas_codex/standard_names/review/cascade.py, _route, consumed by adjudicate_review's deciding branch.

  • Before: a failed claim_contradicts_source check lowered mapped, which became both decision_score and the score the route was judged on. The route read refine, but the score itself had been moved by the veto.
  • After: mapped keeps its mapped value, decision_score and selected_score keep the judged values, and the route carries a cascade_contradiction hold. sync_route_holds reconciles it against the name in the deciding branch, beside the route record. jev_review.py was not edited.
  • The hold is raised only for the contradiction veto itself. Every failed check also routes to refine, so a nonconforming answer that is not a contradiction refuses the document without raising a hold whose finding text says the claim contradicts its source.

Every hold ends with the check that raised it

A review of the first revision found that both kinds added above were raised and never cleared. clear_holds_not_raised is the only writer of status='cleared', and the documentation review's own re-check passes the set registry_conformance, banned_prose, documentation_contradiction — so neither new kind appeared in any re-check. A hold would then outlive the finding that produced it: the refine pool re-claims a passing row with an open documentation hold, holds it again on its next pass, and walks docs_chain_length to the rotation cap, ending exhausted. That is a permanent refusal where the score clamp it replaced recomputed on every pass.

  • Repair: each check now reconciles its own kinds on every pass, in both directions. The lint cap raises docs_lint_error when a finding stands and clears it on a later pass over the same names that finds none; a deciding cascade route raises cascade_contradiction when the veto fires and clears it when a later route reports none. Both call clear_holds_not_raised with exactly their own kind, so neither asserts anything about another check's holds.
  • An absent check is not a passing check. The lint map is None when the checks did not run for a batch, distinct from an empty mapping, which means the checks ran and found nothing. Only the empty mapping reconciles; a caller that omits the map releases nothing.
  • The release runs through the same promotion the hold channel already used, so a document whose only blocker was the resolved finding is accepted at the score the reviewer gave it, and one that is quarantined or has no winning review is still left at reviewed.

Site 3 — the release-by-dismissal path

imas_codex/standard_names/review/holds.py, _promote_if_eligible, run when the last open hold on a document is cleared or dismissed.

  • Before: the release re-derived the acceptance rule from a passing score alone. A row with a quarantined validation status, or with no reachable winning documentation review, was accepted by dismissing its last hold.
  • After: the release applies PROMOTE_STRANDED_DOCS_WHERE — the predicate the stranded promotion pass already uses — which requires an accepted name axis, a non-quarantined row and a reachable winning documentation review, on top of the acceptance score and an empty open-hold set. It is the same predicate, imported, not a second copy of its terms. Two tests now plant exactly those two excluded rows and assert dismissal leaves them at reviewed.
  • The promote_stranded_reviewed row in the standard-names guide now names the open-hold requirement alongside the score.

No documentation score is clamped

No refusal to accept a documentation anywhere in imas_codex/ is expressed by lowering a documentation review score. The backing grep, clamp-grep.log, searched every .py file under imas_codex/ for a min(…) applied to a review score, for audit_cap_finding, and for every docs_lint_error and cascade_contradiction occurrence.

  • The grep's score hits are all elsewhere. They are discovery scorers bounding values into [0, 1], a vocabulary-promotion statistic, a review-spread diagnostic, and map_decision_score, which is a fixed calibration curve mapping a rubric score below the accept cutoff into the range below the threshold. It is driven by the rubric score, not by a hold or a veto, and a veto at a passing score no longer moves it.
  • The only writer of audit_cap_finding is the lint-cap site, and it writes the finding without touching the score.
  • The two kinds are raised only at the two routed sites — docs_lint_error from the pipeline and cascade_contradiction from the cascade route.

Deviation from the brief

The brief names the hold kinds lint_error and contradicts_source. Neither is in the hold owner's declared kind set, so raising either would fail validation. The owner already declared docs_lint_error and cascade_contradiction unused, and both are in the generated schema's enumeration; those are the kinds used. The declared kind set is unchanged.
