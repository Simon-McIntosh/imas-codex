Q3 — can refine clear it? (code and stored text only; no LLM call)

Yes the refiner receives the note; yes a refined text without the claim passes the same check; and the note for this name is in the branch of the prompt that is no longer rendered.

  • The note reaches the refiner through the per-dimension channel. The clamp writes it to comments_per_dim_docs["contradicts_source"] (workers.py:11255), and claim_refine_docs_batch reads that property back and folds it into prior_docs_reviews (graph_ops.py:25709–25720). The prompt renders it at imas_codex/llm/prompts/sn/refine_docs_user.md:118 ({% set _cur_comments_docs = reviewer_comments_per_dim_docs %}) and iterates every key at lines 131–136, so an unknown key such as contradicts_source is printed alongside the four real dimension names. The note is therefore delivered, keyed as if it were a scoring dimension.
  • It is delivered only when failed_checks is undefined. The same block is guarded at refine_docs_user.md:119–131 by {% if failed_checks is defined %}, which takes precedence over the per-dimension else branch. On the §5 check-driven path the refiner is told the failed checks and not the per-dimension comments, so a contradiction note carried only in comments_per_dim_docs is dropped from the prompt exactly when the check-driven path is active. The two paths carry the same finding through mutually exclusive slots.
  • A refined text without the claim passes. The veto is recomputed from scratch on the new text: _documentation_contradiction_note re-splits the documentation into claims (jev_review.build_docs_state, workers.py:11072) and re-asks check:claim_contradicts_source: for each (workers.py:11078–11084). Nothing in the check consults the previous text or the stored note. So a refined text that no longer asserts “The quantity has no mandatory locus or aggregation.” yields no contradiction answer and no veto. The stored text shows this is what the system is asking for: the two 2026-10-17 firings for this name carry different claim sentences — an earlier wording that already concedes the point (“the applicable locus and aggregation convention are specified by a more specific realization”) and a later one that returns to the bare disclaimer — and both were vetoed against the same DD sentence.
  • What the note does not give the refiner is the distinction it needs. The rendered note is the claim and the DD text only (workers.py:11119–11122): “<path>: <reason>; DD: <text>”. It does not say whether the DD sentence is a specialisation of the generic name or a denial of it. For electrostatic_potential the same note is emitted against plasma_profiles, edge_profiles and core_profiles paths in succession, each pairing the same disclaimer with the same sentence, so a refiner that satisfies one source re-barely-phrases and trips the next. The stored history is consistent with that: the wording moves between firings while the veto stands.

What is defective, and the fix I recommend for each

  1. Confirmed defect — the veto reports a generic name's silence as a contradiction of a specialised source. Classification of the 45 triples puts 28 in this class (mine, not measured): a claim that the generic quantity imposes no locus or aggregation, checked against a DD source that is a locus-specialised instance of it, which is a specialisation relation rather than a denial. Recommended fix: distinguish the two relations in aggregate_docs_review / the claim_contradicts_source question — a source that is a strict specialisation of the claimed quantity must answer supports or says nothing, and only a source that denies the claim may set contradiction_veto.
  2. Confirmed defect — the same veto channel carries an unavailable comparison. 17 triples pair a prose claim with DD text that states nothing to contradict (Value, Component along Y axis, One scalar value is provided per element in the grid subset.). _documentation_contradiction_note already has an unavailable branch for a missing answer (workers.py:11123–11137) but routes a thin-but-present source through contradiction_veto. Recommended fix: treat a DD source whose text carries no definitional content as unavailable for the claim check — report “claim comparison unavailable”, do not clamp the score.
  3. Confirmed defect — the anchor gate strands a whole family behind one non-converging member. electrostatic_potential has never been reset by a family apply, though it is eligible for reset, because the batch that holds it is never reached when the anchor does not converge (harmonize.py:1696–1706), and the anchor is stuck at docs_stage='pending' with no accepted score. Recommended fix: let the apply proceed with a family whose anchor fails to converge, or demote a non-converging anchor and re-select one, so a single stuck member cannot strand its siblings; report the stranded family so the hold is visible where it is taken.
  4. Confirmed defect — the refiner receives the veto note through mutually exclusive prompt slots. The per-dimension branch that renders contradicts_source is only taken when failed_checks is undefined (refine_docs_user.md:119–131), so the check-driven path cannot show the refiner the hold's own note. Recommended fix: render the stored comments_per_dim_docs findings on both paths, or carry the contradiction finding as a failed check so the two channels cannot disagree about what the refiner was told.
