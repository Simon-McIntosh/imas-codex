Patch target rule

The AST scan covered 1113 Python test files and found 728 literal paths shaped like imas_codex.standard_names.graph_ops.NAME or workers.NAME: 727 map to a top-level symbol, while the one graph_ops.__dict__ path is a module-introspection target. A plain re-export does not preserve those mocks because a moved function resolves globals in its defining module.

Mixed rule: rewrite direct function patch targets and direct callers to their owning module when a focused test file is touched; retain narrow forwarding functions on graph_ops and workers for the remaining callers during the split. The forwarder injects its factory/cross-domain callables into the moved function at call time, so an existing graph_ops.GraphClient patch still changes the dependency used by that call. Never use alias-only re-exports for a patched dependency. The facade is a bounded migration bridge, not a second implementation; delete each wrapper after its callers and patches have moved.
