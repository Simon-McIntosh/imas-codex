Feasibility and first work

The local dispatch allowance is 230,000 tokens with 40,000 reserved for plan and brief: source files may consume at most 190,000. The unmodified graph_ops.py alone is 241,545 on the measured tokenizer, 51,545 above that allowance and 11,545 above the entire window. Therefore no first node that writes graph_ops.py can satisfy the requested per-step local limit. This is a hard arithmetic conflict, even if its new module and tests cost zero. The first graph-touching changes require a metered Codex lane or an explicit local admission exception. The working split below uses the lead’s “Codex for holds, then split” order and states that exception; it does not claim that the bootstrap nodes fit locally.

  1. Hold-sync owner, metered. Move the raise/clear/recheck loop to one owner around persist_reviewed_docs and the workers’ docs review route, keeping the judged score. Gate those two named test files and a live -m graph arm for changed Cypher; make a raised hold refuse acceptance, then clear on the deciding axis.
  2. Docs-regeneration re-stamp, metered. Keep documentation freshness and hold recheck coherent when persist_generated_docs and persist_refined_docs write a new text. Write paths: imas_codex/standard_names/graph_ops.py, imas_codex/standard_names/workers.py, tests/standard_names/test_source_refresh_docs_requeue.py, tests/standard_names/test_persist_stages.py.
