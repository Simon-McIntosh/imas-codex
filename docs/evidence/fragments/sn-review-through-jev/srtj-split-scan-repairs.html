The split's eight broken tests follow their subject

The integration gate found eight failures added by the graph_ops / workers split, none a behaviour regression. Measured against this node's own base, the pair proves the repair: at base 3cb42fc7c all eight fail, six as assertion failures and two of them as AttributeError on a missing cache_clear, and at committed head f9b87381d all eight pass. Base eight-id arm 8 failed, 5 passed (EXIT=1); head eight-id arm 13 passed (EXIT=0). The whole-file arm over the same eight files reads 9 failed, 95 passed, 16 deselected at base (EXIT=1) and 1 failed, 103 passed, 16 deselected at head (EXIT=1), so exactly the eight the split broke are repaired and no other test in those files changed state. The one failure left at head is test_metadata_invariants.py::TestComposeWorkerInjection::test_physics_domain_injected_from_source, red at base for its own reason and left alone. The pre-split revision 7da806df3 is not the base of this pair: the eight pass there because the code had not yet moved, so pairing against it would show a green base arm that proves nothing.

Every structural scan now reads its owning package rather than one file. tests/standard_names/source_scan.py supplies the file set — workers.py plus worker_tasks/*.py, and graph_ops.py plus graph_store/*.py — and exposes it four ways: per-module (path, source) pairs for line scans, per-module (path, ast) pairs for AST scans, and joined text for substring scans. Concatenation is never parsed, because several of these modules open with from __future__ import annotations and a joined text is not a valid module. The split is still moving code, so a scan pointed at one new module would break again at the next step; the file set is globbed, so a module added later is covered without touching a test.
