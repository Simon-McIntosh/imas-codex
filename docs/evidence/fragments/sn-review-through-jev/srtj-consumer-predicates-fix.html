The cause is in the test, not in any consumer: the hold channel rewrote persist_reviewed_docs to run its claim check, its hold reads and its score write inside one gc.session() transaction, so the test's client-level gc.query side effect is never called, the preflight reads no rows and the writer returns its documented token-mismatch no-op ''. 2. The fix

The persistence arm now drives the writer through the transaction it actually uses. _PersistGraph implements session(), begin_transaction(), run(), commit(), rollback() and close(), answers each statement by what it asks for — the open-hold read, the claim preflight, the hold-clear count, the write — and also answers the client-level query the name-axis writer still uses, so both axes run against one fake. It is handed the same open-hold rows the case's route declares, so the hold read is fed the hold the route raised rather than an assumption that no hold exists.

The three arms now assert the hold contract instead of a second copy of the score rule. Persistence keeps assert stage == ("accepted" if expected_accept else "reviewed"), which now reaches the writer. The claim-predicate arm requires the hold owner's own clause to be present in the emitted predicate — assert review_holds.has_open_docs_hold_where() in captured["eligibility_where"] — and admits the item on eligible or bool(route.holds), so a page that dropped the clause fails even where a score happens to agree. The export arm asserts what the score gate is (bool(exported) == (score >= min_score), with below its complement) and then asserts the refusal where the export enforces it, by running _classify_export_population over a candidate carrying the stage the persistence arm just stored: the document is published exactly when the route accepted it. Together the two assert the protection end to end — a vetoed document is left at reviewed by the hold and is never published from that stage.

No product file changed. cascade.py, holds.py and export.py were read and left alone: the point of the diagnosis is that they already carry the rule, and the failure was that the test could not reach it. persist_reviewed_docs and the claim predicates live in graph_ops.py, which this node may not edit, and no edit was needed there.
