Retiring the comment-keyword refine trigger

The refine fan-out now fires on failed checks alone. should_trigger_fanout takes check results and a threshold, and nothing else: the comment path, its keywords, dims and char_cap parameters, and the trigger_source selector are gone. The free-text comment field stays on the node for people, and the refine-chain history reader in imas_codex/standard_names/chain_history.py is untouched.

The threshold, and where it came from

The check arm runs at a failure probability of 0.5. That value is read from the A/B run's own record, not chosen here. In r-20261018T101616902704-srtj-refine-ab-run the per-check record carries failure_probability and a failed flag: across the 120 cases the checks the run failed have a minimum probability of 0.50 and a maximum of 1.00 (362 checks), and the run's passed checks top out at 0.49 (3478 checks). So 0.50 is the cut the arm classified failures at. It is the same constant the review module applies (CHECK_FAIL_PROBABILITY = 0.5, jev_review.py:98) and the same default the one surviving setting carries (refine_trigger_check_threshold = 0.5).

Nothing was recalibrated: the retired keyword path is replaced by the exact value the measured arm used.

Tests and the gate

tests/standard_names/test_fanout_trigger.py holds the two guards the plan asks for. The first fails if should_trigger_fanout acquires any comment input, by signature and by the trigger module's source. The second fails if a keyword-list setting is reintroduced, checked by both import (FanoutSettings.model_fields) and settings load (load_settings()), with pyproject.toml checked for the retired keys.

The gate ran the fanout package tests, the refine call-site tests (test_refine_failed_checks.py, test_review_cascade.py, test_refine_scope_continuity.py, test_dup_guard_integration.py, test_fanout_trigger.py) and the confinement lint. Base arm 187 passed, EXIT=0; head arm 178 passed, EXIT=0 — no added failures.

The declared negative control restores the keyword setting and its reader. Applied, the new test module is 3 failed, 3 passed, EXIT=1 — including test_no_keyword_trigger_setting_by_import_and_settings_load. The mutation was then removed and the source restored.
