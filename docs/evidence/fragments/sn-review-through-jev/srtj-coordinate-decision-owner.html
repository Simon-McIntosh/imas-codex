One owner decides whether a name is a coordinate, and the holdout scores with the name it is scoring

The defining-relation gate exempts coordinate, position and locus names from stating a defining equation: their documentation says which frame and axes give the value, and a dimensional identity with a DD unit would be a tautology. The decision was taken twice. docs_gates._names_a_position read the structural parse itself and treated a parse failure as "not a coordinate", while derivation._geometric_coordinate_check already owned the question and consults the model-level parser when the structural parse refuses a name. Separately, the documentation holdout called score_documentation without documenting_name, so it failed coordinate documents on defining_equation that the production lint at review/audits.py passed. Both are fixed: the decision lives once, in derivation.is_coordinate_name, and the holdout passes each row's catalog name.

1. The derivation module owns the decision

The public function derivation.is_coordinate_name(name) returns true when the structural parse's base.kind is geometry or its projection.shape is coordinate, and, when the structural parser rejects the name, falls back to the module's existing model-level geometric-coordinate check, _geometric_coordinate_check(name). The exemption's class is unchanged: coordinate, position and locus names keep exactly the set they had, because the structural branch is the old predicate and the model branch only adds names the structural parse could not read. docs_gates imports the owner at the gate and its second copy is deleted; grep -n _names_a_position over the tree now finds nothing.

The defect reproduces on main 041f31120: docs_gates.py:370 defines _names_a_position and derivation has no such symbol, so the gate never consults the owner. The probe log is logs/reproduction.log.

One honest caveat about the model-level fallback. On this base, with imas-standard-names 0.10.1, the name the review probed does not reproduce the model-only condition: magnetic_axis_position is rejected by the model parser as an UnknownBaseTokenError and by the structural parser as a ParseError, and _geometric_coordinate_check returns no edge (recorded in the same log). Exhaustive probes over axis × geometric-base compositions and over the 85 names of the documentation holdout found no name that the structural parser rejects while the model-level check recognises it, so the fallback is proven by test rather than by a catalogue name. The fallback is not decorative: it is the branch that makes the owner's answer hold when the structural grammar lags the model grammar, which is the condition the review found.

2. The holdout scores with the name it scores

Both score_documentation calls in evaluate_docs_holdout now pass documenting_name=row["catalog_name"] — the catalog arm and the generated arm — so the holdout's defining_equation verdict is taken by the same decision the production lint uses. Reproduced on main: the coordinate document below returns fail with documenting_name=None and pass with documenting_name='radial_position, which is exactly the divergence the review reported.

The holdout's current 85 rows carry no coordinate name, so no stored verdict moves today; the divergence was latent and would have mis-scored the first coordinate document the holdout admitted.

3. Tests

Four tests in tests/standard_names/test_coordinate_decision_owner.py. test_the_gate_keeps_no_second_owner_of_the_decision asserts docs_gates carries no _names_a_position and that the public owner exists, so a re-introduced copy is caught. test_model_level_parser_alone_recognises_a_coordinate makes the structural parser refuse every name and asserts is_coordinate_name("vertical_coordinate") is still true and that the gate passes a frame-only coordinate document — the fallback is exercised, not merely present. test_holdout_and_lint_agree_on_a_coordinate_document runs evaluate_docs_holdout("catalog", rows=[row]) on one coordinate row and run_documentation_gate_checks on the same name and document, and requires both to pass defining_equation. test_non_coordinate_quantity_still_needs_a_defining_relation requires electron_temperature to be no coordinate, to fail defining_equation in the holdout, and to raise the lint finding — the exemption does not widen.
