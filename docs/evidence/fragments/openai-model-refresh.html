Every OpenAI reference in pyproject.toml moved to the newest model of its tier, after a live probe

Seven pyproject.toml references still named OpenAI models from the GPT-5 generation while the production seats had already moved to gpt-6.1-sol and gpt-6-luna. Each stale reference was repointed to the newest model of the same tier, but only after one real, minimal call per target model through the repository's own LLM call layer (imas_codex.discovery.base.llm.call_llm, the path a seat takes, with the checked-in pricing table applied).

No pricing entry was removed, and why

Removal is conditional on the route being referenced nowhere else. Each of the three cases the brief named is still referenced in imas_codex/ or tests/, so removing its price would break a live route or a test rather than retire a stale row:

  • gpt-5.6-luna — proxy route in imas_codex/config/litellm_config.yaml, fallback slate in imas_codex/settings.py, and the priced-route fixtures in tests/core/test_settings.py and tests/standard_names/test_benchmark_roles.py.
  • gpt-5.5 — proxy route, fallback slate, a retired-name assertion in tests/core/test_gpt6_seat_rotation.py, and two tests/standard_names/ bench fixtures.
  • gpt-5.4 — proxy routes for gpt-5.4 and gpt-5.4-mini, fallback slates, a CLI docstring example, and eight tests/standard_names/ and tests/discovery/ fixtures.

The reference scan is pricing-reference-grep.txt in the run directory. Those references sit outside this node's write scope; they are reported to the coordinator rather than edited here.
