The ITER plant signal graph holds the reviewed ontology, and nothing else moved

The schema, the writers and readers, and the live ITER graph now agree on one plant form. The classes were relabelled, the plant-context document merged into the shared document class, the two duplicate memberships retired, the archive field-code class populated, and a control node bound to the plant nodes a source states for it. Every step is counted in one graph census taken before the migration and one taken after it, and the two censuses are compared by an instrument that fails on any difference it was not told to expect.

ITER holds 652 127 relationships before and 592 120 after, the net loss being the two retired duplicate memberships — 90 314 links — and the scalar properties that mirrored them on 90 314 signals, less the 30 031 field-code links, 13 source-row links, 4 control bindings and 259 facility memberships that replace them. PlantConnection is declared and holds no node, which is the form the ontology agreed: the class exists for a later source and nothing in the graph asserts a connection today.

The field-code class is populated from the graph's own sources

259 catalogue codes exist on ITER signals. Every one of them became ArchiveFieldCode nodes, each linked from every signal that carries the code (HAS_FIELD_CODE, 30 031 links over 30 031 signals) and from the signal-list row that established it (FIELD_CODE_SOURCE_ROW, 13 rows). 69 declared readings cover 39 of those codes and name the role the reading implies: 29 measurement, 16 state, 11 setpoint, 9 command and 4 alarm; 47 readings came from controls metadata and 22 from a signal-list row. 6 472 signals carry a code with a reading; 226 codes carry none and stay unestablished rather than guessed. Three codes carry two readings each and are recorded as a conflict rather than resolved; six declared readings name codes that appear in no catalogue entry and stay as declarations without a node.

The private configuration's field_code_table reader is retired: the table builder no longer reads the declared readings out of the private configuration, because the graph nodes are now their store. The private configuration keeps every entry unchanged as the private copy of what was retired, and neither it nor any reading text appears in a tracked file.

A control node records only the plant nodes a source states

One first-level control root holds a binding after the migration: the magnet root, bound to four plant breakdown nodes, from one pilot signal list whose 185 rows state the binding. The binding carries the identity of the document that states it, and it lives in private cache, not in this record. Ten other first-level roots stay unbound because no source in the graph states a plant node for them; a second pass would bind zero more. The binding was written only where a signal-list row names both the root and the plant node, so no pairing was inferred from a name or from a hierarchy.

The seven plant-context documents merge into one shared class

Seven PlantContextDocument nodes became Document nodes in the shared class, carrying the same identity, title, content role and context code, joined to the same plant nodes by DOCUMENT_PLANT_STRUCTURE. No document was created and none was left in the old class, and the seven links were renamed in place, so every plant node that had a document still reaches it. The shared class already carried 808 ITER documents; it carries 815.

A second run changes nothing

The migration hashes the state each pass starts and ends at. The dry run reports 953d0f6c… before and after, the applied run moves 953d0f6c… to dfea2c08…, and the repeat pass over the migrated graph starts and ends at dfea2c08…, reporting zero relabelled nodes, zero renamed parent links, zero migrated documents, zero duplicate memberships removed, zero pending field codes and zero bindings it would add. The digest covers every node and relationship of the classes the migration is allowed to touch, so an unchanged digest is an unchanged graph.

Two negative controls, both detecting what they were built to detect

A change outside the migration is reported and removed. A probe node written under another facility's identity moves that facility's count from 584 852 to 584 853; the comparator reports the difference and a difference in the label census, and the probe is then removed, with the count read back at 584 852. The transcript reads CONTROL_PROBE, CONTROL_RESTORED, CONTROL_DETECTED. The probe left by an earlier run of the same control was removed, and a recount taken afterwards moved by exactly that one facility node and nothing else.

The migration refuses a class outside the approved set. Naming StandardName on the command line stops the run before it opens the graph, with UnapprovedNameError: ['StandardName'] is outside the classes and relationships this migration may touch and EXIT=1, recorded in logs/negative-control-unapproved-label-20261123T215500Z.log. The refusal is what turns "only the classes in scope change" from a claim about the code into a property of every run.

Restore

The private before-image holds every node and relationship the migration read, so the graph can be returned to its earlier form from it:

uv run python -m iter_codex.graph.plant_ontology_migration \
    --facility iter --restore /home/ITER/mcintos/.cache/imas-codex-codac-uda/ontology-migration/20261123T190518Z/before-image/before.json

The image, its restore command and every census and test log named here live under ~/.cache/imas-codex-codac-uda/ontology-migration/, outside the repository. No signal name, document identity or reading text appears in this record or in any other tracked file.
