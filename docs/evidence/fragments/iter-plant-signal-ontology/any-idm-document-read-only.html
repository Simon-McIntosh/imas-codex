The read-only client fetches any well-formed document identity

The document gate no longer keeps a list of identities. It now validates the form of the request: the configured path, exactly the three query keys uid, version and action, no repeated key, no fragment, action=get_document, a version of the shape v<digits>[.<digits>]*, and an identity of one to sixty-four characters from letters, digits, underscore and hyphen. Everything else is refused at the same transport chokepoint as before, before any network call.

Every other rule of the request policy is unchanged: GET and HEAD are the only methods, the origin and Host header must match the configured document origin, the sign-in boundary still applies, and the per-identity and session request budgets still count document reads. A write method sent to a valid document URL is refused by the method rule, which runs before the document gate, so the write refusal tests pass unchanged.

Rate limit and its default

The document origin has its own pacer, separate from the general client pacer, and its interval is read from the private configuration key document_min_interval. When the key is absent the interval is 1.0 s. That default is chosen because one document fetch is two transport requests (a HEAD size probe and then the GET), each able to carry a file of up to 50 MB, and a one-second floor bounds that bulk transfer more conservatively than the general read interval of 0.5 s. A configured value must be a finite, non-negative number; a boolean, a string, a null, a negative number or a non-finite value is refused at construction rather than silently loosened to the default.

Identity list

document_identities is ignored, not removed. The private configuration still carries the key, and construction no longer reads it. One test fixture deliberately keeps a fictitious entry to show the key is optional and has no effect. The main checkout's private configuration therefore needs only the existing document origin and path, and optionally document_min_interval.
