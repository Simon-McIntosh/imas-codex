Widening the signal full-text index to the words a searcher types

The Neo4j full-text index facility_signal_text backed only name, description and node_path, so a query that matched a signal through its alias code or a catalogue phrase found nothing — the JT-60SA handbook writes 4451 A231 for the EF5 supply's DC voltage and no indexed field carries that string. The index definition is the class-level fulltext_index annotation on FacilitySignal in imas_codex/schemas/facility.yaml; SchemaIntrospector.fulltext_indexes() derives the property tuple from it and GraphClient.ensure_fulltext_indexes() creates the index from that tuple. The definition now reads: facility_signal_text:name,description,node_path,keywords,aliases,unit,source_description All seven are FacilitySignal attributes declared in the same schema (keywords, aliases, unit, source_description alongside the original three). The live index was dropped and rebuilt from the schema with ensure_fulltext_indexes() and is ONLINE carrying the seven properties. Every figure below was produced in the node worktree at revision 9b092e8bd against the live graph, facility jt-60sa.

The control: a query only the new fields can match

The check is check:alias-code-places-its-own-signal-in-the-search-top-10. It issues the raw index query '4451 A231' — the alias code the handbook uses, present in no name, description or node_path — counts the index hits, then runs the product search _rank_signals and requires the target jt-60sa:general/ef5_volpsdc in the top 10.

The four-arm table on the head

The golden harness tests/llm/test_signal_search_goldens.py scores four arms over the labelled questions — current_tool (the product _rank_signals), additive_rule (the product's additive formula frozen), vector_only (the vector pool alone) and rrf — against a seeded-permutation control. It grades each arm's top 10 against the fixture labels and refuses with UnlabelledCandidates if any arm's top 10 holds a candidate with no label.

Every lifted candidate is labelled

The widened index lifts signals into an arm's top 10 that the narrow index never surfaced, and the harness refuses to score an arm whose top 10 holds an unlabelled candidate — so every lifted candidate had to be graded before the head would run. Grading follows the fixture's own rule: 3 a measurement of the queried quantity, 2 a commanded, reference or setpoint value of it or the same quantity at an adjacent point, 1 related hardware, 0 read and judged irrelevant. A candidate scan over three passes (the Neo4j vector search is approximate and drifts between calls, so a single pass under-reports) confirmed every arm's top 10 labelled, and the head then ran green. Fifty-six candidate labels were added across seventeen questions, all in facility jt-60sa, all signals enriched at or after the 2026-10-11T21:08:54Z cutover.
