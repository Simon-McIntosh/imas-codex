Reprocessing the JT-60SA signal catalogue

The wish the reprocess serves is that every one of the 15,111 JT-60SA signals carry a description written by the current pipeline, so that a search for a measured quantity can find the signal that carries it rather than a sibling that inherited the group's template. The facility-wide census taken after the last scope finished reads 15,111 signals, 0 left at discovered, 0 without a description, and 0 whose stored embedded_text_hash disagrees with a hash recomputed from its own description. Every scope was reset from 2026-10-13T11:53:35Z, the start of the individualised-description reprocess, so no signal was left enriched from before it.

The reset is the one step that could have silently done nothing, so it carries a negative control. Before the fix whose effect the reprocess measures, 1,441 JT-60SA signals were enriched before 2026-10-11T21:16:46Z. After the reprocess that count is 0: no signal predates the reprocess start. Each scope's own reset log asserts its reset count, and each scope's post-reset census corroborates it — a scope reads its signals back at discovered with no description before enrichment runs. A census that had found them still described would have meant the reset never ran.

210 signals carry no signal_role and are excluded from any role judgement. Every one of them is a member of a SignalSource whose representative the role classifier called underspecified, so the classifier never had a quantity to name for them. They are a property of the classification, not a shortfall of the reprocess: their descriptions were rewritten like every other signal's.

The stratified sample that scoped the work

202 JT-60SA signals were drawn by a deterministic stride over each source category's sorted ids — LCDB, edas, UDDB, G-EQDSK and EQDB — so the sample carries every scanner the facility has. Seventeen of the 202 are members of a source carrying more than one member; the other 185 are single-member sources. The sample was reset to discovered once, re-enriched through the current pipeline, and then checked signal by signal.

The sample's reset carries its own negative control, and its post-reset census was captured. At 2026-10-13T11:54:27Z, immediately after the reset, the census reads 202 signals at discovered — the whole sample, with no description — which is what states that the reset actually cleared them. The reset is the one step that could have silently done nothing, so a post-reset census that had found them still described would have meant it never ran. The sample's own reset log asserts Reset 202 signals, which agrees with the census.
