Search narrows to a signal's stored role

A signal now stores the role the judge accepted for it, but nothing read that slot back, so a searcher could not ask for the measured channels and skip the setpoints, status flags and configuration parameters that describe them. This change gives search_signals a role= argument that keeps only signals whose stored signal_role is that role, and leaves diagnostic= and physics_domain= exactly as they were.

The predicate is applied in both streams the fusion draws from, before the rank cut. The vector stream gains the clause in signal_vector_search_block — the single owner of the facility_signal_desc_embedding query — and the full-text stream gains the same clause inside each of its branches. Because signal_role is not a registered index property, it stays a post-filter over the returned rows, so the ANN limit is widened to max(k*2, 50) whenever any post-filter is present: a role= search that would otherwise lose its matches to the cut still returns up to k signals. A role outside the six is refused by name rather than answered with an empty report.

The six roles come from SignalRole, the schema's own enum, so the accepted set and the stored set cannot drift. A value outside it returns Unknown role 'x'. A signal role is one of: measured, commanded, reference_or_setpoint, status_or_flag, configuration_parameter, derived_or_computed.

The rerank state now carries the stored role when the candidate has one, so the judgement that reorders the candidates sees the measured role beside the raw name, description, unit, data class and accessor. A candidate with no stored role carries no role key, which keeps the existing exact-equality assertions on the rerank payload intact.

The behaviour is covered in tests/llm/test_search_tools.py with the graph mocked, through a client that answers each stream from canned rows and inspects the query text it was handed: a role= search returns only signals of that role, both streams carry the predicate, an unfiltered search keeps every role, the ANN cut widens, an unknown role is refused by name, and each of the six values is accepted. The rerank-state tests assert the role is carried when present and omitted when absent. tests/llm/test_signal_report_rows.py asserts each row shows the stored role when present, omits the line when the signal carries none, and lists every distinct role in a family.

The scoped gate over the two files is 130 passed, 8 skipped, EXIT=0. The negative control removes the signal_role = $role clause from signal_vector_search_block and re-runs the strictest test: it fails, leaving the reference signal jt-60sa:ps/refip in a role='measured' result, EXIT=1, so the passing head is caused by the reason claimed and not by a detached assertion.

This measures the filter's behaviour against a mocked graph — that the predicate reaches both queries and the right rows survive. It does not run a live role-filtered search against Neo4j, which would also measure how many signals currently carry a stored role.
