Reprocessing the JT-60SA b260008 and CryoHRS categories

3663 JT-60SA signals in the b260008 (2959) and CryoHRS (704) categories were reset once to discovered and re-enriched through the current pipeline in three --focus scopes. 3650 of the 3663 assigned signals are finished — described, embedded, and with no hash mismatch — and 13 remain at discovered, all of them members of one source family that the pipeline never individualises. The residual 13 are reported below rather than silently counted as done.

The reset is the step that could have silently done nothing, so each scope carries the declared negative control. Immediately after each reset the scope's census found every signal at discovered with no description — the complement of the control. A census that had found them still described would have meant the reset never ran. For CryoHRS the probe scope read 150 discovered / 0 described (bulk-logs/scope1_probe.postreset.log); for b260008 the whole category read 2959 discovered / 0 described (bulk-logs/b260008.postreset.log). The 13 signals the pipeline cannot finish

The 13 stuck signals are the members of six LCDB zeff signal sources — s002_metafile, s002_xfitdata, s002_cst1, s002_ifunc, s002_used_fitdata_index and s005_topics_xfitdata. Each of those sources was classified underspecified: the catalogue entry carries too little context to describe. The individualisation pass that gives grouped members their own description selects only sources at status enriched (imas_codex/discovery/signals/parallel.py, the SignalSource {status: 'enriched'} match), so the members of an underspecified source are never reached and never leave discovered — the 11 underspecified representatives and their 13 members are a stable residual of the pipeline as it stands. Closing it is a pipeline change outside this node's write scope, and the run's 40-minute reset fence had already passed, so no further reset was permitted. The exact ids are in bulk-logs/ids_b260008_residue.json for a successor node, whose fix is cheap: the seeding half calls no model.

Total Jev spend across the four enrichment passes was $0.04, against the node's ceiling of USD 6 — the seeding halves cost nothing (their scanner reads the facility's own catalogue and calls no model), and the enrichment spend is Jev's relevance rerank over the retrieved context.

Two retries are recorded. The first reset hung retrying an unreachable jt-60sa host whose ssh configuration would not parse (Bad owner or permissions on /etc/ssh/ssh_config.d/50-redhat.conf); putting a wrapper that loads only ~/.ssh/config on PATH resolved it and the positive control returned the JT-60SA gateway. The b260008 enrichment was then killed at the harness background limit partway through and resumed in a second pass without a reset, so the reset still ran once.
