Every signal description write re-embeds its text in the same statement

write_signal_descriptions in imas_codex/discovery/signals/parallel.py is now the one place a FacilitySignal description is written. It takes the description, composes the text to embed (a caller may supply embed_text, otherwise it defaults to the description), embeds it, and sets description, embedding, embedded_at and embedded_text_hash together in one UNWIND statement. embedded_text_hash is a declared FacilitySignal slot in imas_codex/schemas/facility.yaml, so a vector whose text has moved is visible as a hash that no longer matches. The three description writes in the signals package route through the writer: mark_signals_enriched and mark_signals_underspecified write their description through it before their separate status update, and propagate_source_enrichment and individualize_source_descriptions write their descriptions through it instead of their own Cypher.

An absent vector is never recorded as a current one. When the embedding service fails, embed_descriptions_batch sets the pending embedding to None; the writer splits the batch on that and writes such an item's description alone, leaving its embedding, embedded_at and embedded_text_hash as they were, so the stored vector stays in vector search and the description no longer matching its hash marks the row for the re-embed sweep. The count left unembedded is logged as a warning rather than failing the enrichment.

Measure: the individualisation write leaves each member holding an embedding of its own description rather than the representative's copy it was propagated, and each member's embedded_text_hash follows that description. Against the writer with its embed call removed — a description-only write with no re-embed, the defect — the same test fails: EXIT=1, 3 failed, naming test_individualization_write_reembeds_each_member. The absent-vector test test_unembedded_item_keeps_its_vector_and_hash passes at head and fails EXIT=1 against the writer before the repair, which nulls the vector and stamps a current hash. The discovery suite reaches 1562 passed at head against 1559 passed with parallel.py at the base revision, so the change adds no failures.
