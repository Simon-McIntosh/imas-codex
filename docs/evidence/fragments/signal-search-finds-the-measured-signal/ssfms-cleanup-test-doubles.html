ssfms-cleanup-test-doubles — one statement-capturing double, and checks a regression fails

The signal suites each carried a private recording graph client, so a change to how a statement was captured had to be repeated in every copy. This node lands one shared double in tests/recording_graph_client.py and sharpens the role suite's checks, so each names the row, role or cost it reads rather than comparing one composite literal: the criteria check now also requires a non-empty description per role, and the accepted-row check localises each role and cost to its row. A mutation log accompanies each check, recording it failing when the value it reads is replaced by a hardcoded answer.

Changes, each with its check

One statement-capturing double. tests/recording_graph_client.py holds RecordingGraphClient, which records every (cypher, params) pair it is handed and answers with no rows. It replaces the private _RecordingClient in tests/discovery/test_signal_embedding_sweep.py and the private recording logic in tests/graph/test_dd_path_domain_upsert.py. The DD-path test keeps its domain-assignment model by subclassing the shared double (_DomainCompletingClient) and overriding query, so the capture lives in one place and the fixture's behaviour stays with the test that asserts on it. Check: grep -rn 'class _RecordingClient' tests/discovery tests/graph returns nothing, both suites run the shared class, and the DD-path test's domain assertions still discriminate the two upsert forms.

The offered criteria set is compared against a literal. tests/discovery/test_signal_role.py writes the six-role vocabulary once, as SIX_ROLES, and asserts set(criteria) == SIX_ROLES over what signal_role_questions() returns. The base check already compared the criteria set against a six-name literal, so it too failed on a lost role; what this adds is the description requirement — every role's description must be a non-empty string — which the base check did not read. Check: with signal_role_questions returning a hardcoded two-role set, the criteria assertion fails (nc-01-hardcoded-criteria.log).

Each accepted row's role and cost are checked on their own. The fake judge answers a different role per input (measured for the sensor, reference_or_setpoint for the target) and prices each decision at USD 0.002, and the test asserts each row's signal_role and cost_usd by id against the literal it expects for that row. The judge also asserts that the state it is handed carries each row's name, which is the input the name-keyed branch reads; a state delivered without the name fails there rather than quietly taking the other branch. The base check compared the whole accepted list against one literal, so it too would fail on a wrong role or a wrong per-row cost; naming each row is what says which row moved, and the per-row cost keeps a regression from hiding in the batch total. Check: with the judge's decision discarded for a hardcoded measured on every row, the accepted-row assertion fails with assert 'measured' == 'reference_or_setpoint' (nc-02-hardcoded-role.log); with judge_rows putting the batch cost on one row and zero on the other, the per-row cost assertion fails while the batch total still reads 0.004 (nc-06-row-cost.log). nc-02 is the node's declared negative control. The name guard's own falsifiability is logged beside it: with signal_role_state mutated to hand the judge an empty name, the guard fires and the batch is refused (nc-05-judge-name-guard.log), while the same mutation leaves the guard silent once the guard itself is removed (nc-repair2-control.log).

The batched response cost is compared against a literal. The fake judge prices each decision at USD 0.002 over a two-row batch, and the test asserts the returned cost equals 0.004 — a value the test supplies rather than one read back out of the module's return. Check: with the returned cost replaced by a hardcoded 0.0, the cost assertion fails with assert 0.0 == 0.004 (nc-03-hardcoded-cost.log).

The live census population is checked against an independent count. Both live census tests read the population from census_signal_embeddings() and compare it to a FacilitySignal count issued in the same test through a second GraphClient, and require it above zero. The unscoped test compares against a count of every FacilitySignal; the facility-scoped test, whose base version asserted the frozen literal result["n"] == 15111, now counts the JT-60SA FacilitySignal nodes the same way. A frozen literal does catch a census that reads nothing — nc-04 records it failing at assert 0 == 15111 — so its defect was brittleness rather than blindness: it reddens on any legitimate change in the population and sends a reader after a non-defect. The independent count also catches a scope that stops reaching the graph, since the census would then return every facility's signals while the independent count stays at JT-60SA's. Check: with the census's population hardcoded to 0, the live check fails with assert 0 == 61983 (nc-04-hardcoded-population.log).

The role measurement takes its fixture as an argument. tests/llm/measure_signal_role.py binds its fixture through --fixture, defaulting to tests/llm/fixtures/signal_role_random_labels.json, and the one loader validates both role fixtures. Check: each fixture loads and reports its row count with no spend — --load-only on the default prints 200 rows and on tests/llm/fixtures/signal_role_labels.json prints 300 rows, both at USD 0.000000, against the USD 0.02 ceiling for this check. A loader that still accepted only the stratified set would refuse one of the two.

The graph test package states what needs a live server. tests/graph/__init__.py's docstring now says that only the tests marked graph need a live Neo4j, that the default run excludes that marker, and that the package also holds guards which need no graph and run by default — which is the case the DD-path guard establishes, as it runs under the default markers. Check: the docstring's claim matches observed behaviour, since tests/graph/test_dd_path_domain_upsert.py is collected and passes under -m 'not slow and not graph'.
