The cutover move is pinned, so it carries a negative control. Reverting the fixture's enriched_at_cutover to the pre-reprocess 2026-10-11T21:08:54Z and running the pin test fails by name — the fixture's declared cutover no longer matches the canonical constant. That is the negative control fires on the pin rather than on the population it guards, which is why the harness asserts the same cutover in both places.

Re-grading pre-existing labels

The intended measure also asked that every existing label whose signal's new description names a different quantity from the text it was graded on be re-graded, listing the old and new grade. That clause is not met: no stored baseline of the prior descriptions was kept, so there is no record to diff. The golden set was re-graded wholesale over the reprocessed text (the 2,224 pre-existing labels were re-read against the new descriptions when the population was widened), but a per-label old/new pair was not captured. Re-grading with the old and new grade listed is a follow-on.
