Pooled labels on the golden signal fixture

Every arm in tests/llm/test_signal_search_goldens.py is scored on the population the fixture's predicate admits, and every candidate an arm places in its top ten carries a grade. The predicate is declared as data in the fixture (eligibility.facility jt-60sa, eligibility.enriched_at_cutover 2026-10-11T21:08:54Z) and is applied by eligible_signal_ids; filter_eligible removes every excluded candidate from an arm's order before the cut at K, so a signal enriched before the cutover is dropped rather than scored, and the slot it held is taken by the next eligible candidate. current_tool (the product ranking), vector_only (pool 100) and rrf (100-vector fused with a 50-full-text pool) are scored on this population, beside the seeded random control (CONTROL_SEED 20261012). The predicate admits 14312 of the facility's signals; the fixture labels 1551 of them across 22 questions, 11 held out.

The control is a seeded permutation of each question's labelled pool, so it measures the label set rather than a ranking. It scores lowest on mean nDCG@10 (0.5218), below every arm, which is the check that the labels carry almost no accidental rank signal. Its grade-3 recall@30 is high (0.6631) because the pool it permutes contains every graded signal, so a random order still reaches most of them within the recall window; the precision and nDCG metrics separate it from the arms.

The two Jev arms cannot be scored inside the test suite

Two findings, both structural rather than labelling gaps.

The suite refuses the paid endpoint by design. tests/conftest.py installs an autouse fixture, no_live_decisions_requests, that raises on any HTTP request to openrouter.ai/api/alpha/decisions. Both Jev arms spend on that endpoint, so with SIGNAL_SEARCH_JEV_ARMS=1 the pytest table test reaches the rerank and fails with RuntimeError: no running event loop after the guarded call raises per item. A run of the same harness functions outside pytest spends normally, which is how the deterministic table above was produced; a five-arm table under pytest therefore needs either a stub rerank or an explicit exemption from that guard, and neither exists today.

A top-10 union cannot exhaust a nondeterministic rerank. The labelling pool was the union of each arm's top ten, which is sufficient for the three deterministic arms. The rerank arms reorder a 60-candidate pool nondeterministically, so any of those 60 can reach the top ten on a given run. Four consecutive live runs each surfaced a different family the previous runs had not lifted (cryoctb_mt08nfv, psscfst_refcuref1bst, ef4_volsnuat, cryoctb_mb2ct5, then gau_p0pngdi); each was labelled and the boundary moved again. The remedy is to label the rerank pool itself rather than its top ten, which is a labelling pass of its own, or to make the rerank deterministic, and the arms should not carry a rerank pool deeper than the labelling pass reaches.
