§5 — which text a signal's embedding encodes

Decision embed-text is settled here by measurement, before any stored vector is touched. Every eligible jt-60sa signal — the 14,312 the fixture's predicate admits (enriched_at >= 2026-10-11T21:08:54Z) — is embedded in memory both ways: once on its description alone, once on a composed name — description (unit) text. Each text is then scored on §3's golden harness with a vector-only arm and an RRF arm, the RRF stream fusing the 100-candidate vector pool with the harness's own 50-candidate full-text pool, so the full-text stream is identical between the two texts and the difference is the vector stream alone. Ranking is a cosine over the freshly computed vectors; no stored vector is read or written.

Reading. Description-only is the higher text on both arms and on all three metrics. The gap is small on mean nDCG@10 (0.014 RRF, 0.025 vector-only) and larger on grade-3 precision@5 (0.018 RRF, 0.064 vector-only), so composing the name and unit into the text does not help this embedding model. The distance is not an artefact of the instrument: the description-only run reproduces the §3 harness's stored-vector arms, which were embedded on descriptions, to within 0.004 nDCG@10 for vector-only (0.6890 here against 0.6846) and 0.020 for RRF (0.7761 against 0.7963) — confirming the in-memory pipeline ranks the same population the stored index does.

Labels the comparison added. Both texts lift candidates into a top 10 that §3's pooled labelling had not reached. Every such candidate is read and graded under §3's rule; 124 labels across 18 of the 22 questions are added to tests/llm/fixtures/signal_search_questions.json, so no candidate either text lifts into a top 10 is unlabelled and no arm refuses. Grades follow each question's declared intent: a measured quantity is 3, a commanded or reference value of it (or the same quantity at an adjacent point) is 2, related hardware is 1, a different quantity is 0.

No stored vector was written. A census over every FacilitySignal — its count, the number missing an embedding or an embedded_at, and a SHA-256 digest of every signal's (id, embedded_at, embedding length) — is taken before and after the measurement and is byte-identical both times (n=61983, no_embedding=3410, no_embedded_at=3410, digest d5b7e827…f95d471b). The guard that compares the two snapshots is test_census_guard.py; run against a mutated after-snapshot it fails by name, which is this node's negative control.

Reproduction. The measurement script is signal-embed-text/measure_embed_text.py under the crew reports directory, beside the results.json, unlabelled.json and census_{before,after}.json it writes and the measure.log it ran under. It embeds name — description (unit) as name, an em-dash, description, and vector  (unit) when a unit is present. The vectors are cached (vectors_*.npy) so a re-run after a label change re-scores without re-embedding.

§5 — every signal re-embedded to its current text

reembed_stale_signal_descriptions in imas_codex/discovery/signals/parallel.py re-embeds every FacilitySignal, at every facility, whose stored embedded_text_hash is missing or differs from the hash of its current embed text, through write_signal_descriptions with the description-only text decision embed-text locked. census_signal_embeddings counts the same population through the same predicate — _SIGNAL_HASH_MISMATCH_WHERE, rendered as a Cypher WHERE over an UNWIND of each row's id and expected hash, a lone <> being null-blind in Cypher — so a row the sweep rewrote is exactly a row the census had counted.

Census, before and after. Before the sweep every one of the 61,983 FacilitySignal nodes read as a mismatch, because the embedded_text_hash slot is new and no row had been stamped: n=61983, mismatch=61983, missing_hash=61983, differing=0. The sweep wrote 61,983 rows in 514.9 s through the writer. After it the census reads n=61983, mismatch=0, missing_hash=0, differing=0, naming no row — the only mismatches left behind would be ones a concurrent pipeline rewrote.

A textless signal records its empty text's hash, not a vector. 3,410 JET signals are skipped device_xml probes carrying no description and so no text to embed. The writer records the empty text's hash for the 3,410 without writing a vector, so they stop reading as rows whose hash is merely missing and never re-enter the sweep; the writer's absent-vector guard still leaves a vector-less row's hash untouched when the embedding service fails on non-empty text, so such a row stays marked for a later re-embed.

Gate. tests/discovery/test_signal_embedding_sweep.py (3 passed). Against the predicate mutated to a lone <> — the null-blind form — the same file fails (EXIT=1, 3 failed), because a null-hash row is then never counted and never cleared. The census scripts and logs are in the run directory (reembed_sweep.py, logs/sweep.log, census.json).

Harness non-regression. The re-embed moves the graph the golden harness ranks over, so current_tool's top 10 on question switching-network-unit-terminal-voltage now holds jt-60sa:general/psc_cref3snu, which the fixture has not labelled, and the harness refuses the arm by name rather than scoring it (EXIT=1, both of two back-to-back runs). No ranking code changed — imas_codex/llm/search_tools.py, imas_codex/search/fusion.py and imas_codex/graph/domain_queries.py are byte-identical to the base revision — so the refusal is a labelling gap the improved vectors opened, not a lowering of the arm, and it is carried as a follow-on for the fixture owner.
