Every FacilitySignal re-embedded to its current text

imas_codex/discovery/signals/parallel.py gains one predicate, _SIGNAL_HASH_MISMATCH_WHERE, that decides whether a signal's stored vector still describes its text: a null hash or a hash that differs from the hash of the current embed text. It is rendered as a Cypher WHERE over an UNWIND of each row's id and expected hash. reembed_stale_signal_descriptions selects its rows with it and rewrites each through write_signal_descriptions with the description-only embed text the embed-text decision locked; census_signal_embeddings counts the same population through the same predicate, so the sweep and the census cannot disagree about a missing hash. The writer now also records a textless signal's empty text hash without a vector, so a skipped signal with no description stops reading as a hash merely missing.

Measure. A census over all 61,983 FacilitySignal nodes read 61,983 mismatches before the sweep (all missing) -> 0 after it; the sweep wrote 61,983 rows in 514.9 s. tests/discovery/test_signal_embedding_sweep.py shows the predicate counts a null-hash row and the sweep clears it, that the census names a row whose description changed after the sweep, and that a textless row records its empty hash with no vector: 3 passed at head. The negative control (predicate mutated to a lone <>, null-blind) is EXIT=1, 3 failed. Evidence: embeddings.html.
