Signal search golden harness

The harness tests/llm/test_signal_search_goldens.py scores five ranking arms and a seeded random control over the questions in tests/llm/fixtures/signal_search_questions.json, reporting mean nDCG@10, grade-3 precision@5, grade-3 recall@30 and the count of questions with no grade-3 hit in the top 30 per arm. The arms are the product ranking (_rank_signals, lifted out of _search_signals with no change in behaviour), vector-only (pool 100), RRF of the 100-vector and 50-full-text pools, and that fusion's top 60 reranked by a generic and by a role-aware Jev question. The Jev arms are not built unless SSFMS_JEV_ARMS=1, so a default run spends nothing. The fixture holds the eleven draft questions beside the eleven held-out ones, 22 questions in total, 11 held out.

Each arm refuses to score while its top 10 holds a candidate the fixture does not label, and names the candidate, so an incomplete label set can never be scored as a miss. A candidate read and judged irrelevant carries grade 0 and is scored; only an absent label refuses. On the first question, plasma current total, the product arm surfaces the Greifenberg coil currents (glw_curglw3 and neighbours) at the top and the fixture labels only dhc_obsip and psrc_calip, so the arm refuses and names them. The harness's five-arm table runs once pooled labelling reads these candidates.

Evidence a later node needs. tests/conftest.py forces a local all-MiniLM-L6-v2 embedding model for the whole session. It is dimensionally incompatible with the graph's facility_signal_desc_embedding index (384 against 256), so every vector arm fails before it ranks anything until the harness deletes IMAS_CODEX_EMBEDDING_LOCATION and IMAS_CODEX_EMBEDDING_MODEL and resolves the production backend. The harness does this in an autouse fixture; a future graph harness on this repository needs the same opt-out. The error reads as a Neo4j type error, not as an embedding configuration fault.
