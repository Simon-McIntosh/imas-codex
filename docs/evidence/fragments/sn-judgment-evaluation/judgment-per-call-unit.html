One per-call unit for both decision entry points

decide_one and decide_batch each carried their own copy of the per-call work — make the call, classify the exception, book the cost through _book_cost — so the two could drift in how a fault is read. Both now rest on one unit, ima_codex/discovery/base/judgment.py:_settle_call, which performs the call, classifies its outcome (see below). Each entry point keeps only its own policy on top of that classification: the batch maps both faults to None; the single-state caller raises the malformed answer (DecisionsValidationError) and maps the transport fault to None. Both entry points' behaviour is unchanged.

The classification is a three-value CallStatus — OK, MALFORMED (a DecisionsValidationError), and TRANSPORT (any other failure) — returned alongside the answers and reported cost in a CallOutcome. The batch's async transport awaits and captures (_await_call) and re-presents the outcome to the shared unit (_resume); neither adapter classifies anything. Cost booking moved from a single summed entry to a per successful call; the tracker's accumulated step total is identical.

Negative control

Making the shared unit classify a malformed answer as a transport fault turns the four-outcome test red: exit 1, with test_both_entry_points_share_one_fault_classification failing on DID NOT RAISE DecisionsValidationError — the single-state caller stopped raising. The source was restored and the test passes again.
