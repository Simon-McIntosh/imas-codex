A golden keeps its split when it grows

assign_group_splits re-derived the whole calibration/validation assignment from rank on every rebuild, so a copy group new to a golden moved every group ranked after it to the other split. Golden D's 47 ruled synonym pairs moved 10 of its 15 existing rows. The fix reads each golden's committed copy_group → split assignment and hands it in: every group already in the file keeps its split, and only the groups new to the file are ranked and alternated among themselves. An imbalance already in the file is kept, not corrected.

_finish gained a golden_path argument and reads the committed file's assignment through _committed_group_splits. Each builder names the golden it writes: build_name_acceptable (A), build_description_object (C) and build_near_duplicate (D); the one other caller, build_documentation_sheet (B), names the documentation sheet. The test that asserted every copy group sits in one split held by construction and was replaced by a rebuild-preservation test that can fail.
