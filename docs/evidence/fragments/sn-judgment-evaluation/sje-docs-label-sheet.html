The documentation-acceptability sheet, blind to the incumbent

Golden B asks whether one name's documentation is acceptable. It cannot be assembled from existing labels, so build_documentation_sheet draws the entries the coordinator reads by hand: live StandardName nodes at name_stage accepted or approved that carry non-empty documentation, stratified over physics domain and pattern family by the module's existing _sample and ranked by its existing split assignment. Each row carries the documentation it labels, its sha256, the DD source paths and their DD text, and the registry conventions the name selects. The sheet is written unlabelled — every label is null and the only provenance is label_source = "coordinator".

The sheet is blind to incumbent scores. No row carries an incumbent review; the live read does not touch review state and the builder drops the shared split helper's incumbent_review flag before writing. Verified over all 600 rows: no key matches incumbent|review|score|verdict|tier. A label the coordinator writes therefore cannot see the pipeline's own verdict on the name, which is what makes the sheet usable to measure that verdict.

The gate for the two covered files passes at the base revision (14 passed) and at the head (20 passed), with the six new sheet tests added. The declared negative control removes each sheet mechanism in turn — draw_rank forced to zero, the lead-overlap marking disabled, the incumbent drop removed, and copy_group set to the unit instead of the pattern family — and the four mechanism tests each turn red, exit non-zero. Determinism is exact: two builds from the same live read produce identical rows. A name whose strict parse is refused still reaches the sheet, recorded with an empty conventions block and a parse_refused flag (6 of 600 here).
