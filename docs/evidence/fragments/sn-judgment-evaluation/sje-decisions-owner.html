Candidate decisions now travel the shared judgment owner

The candidate stage carried its own private decisions wrapper (_call_judgment). It duplicated what the shared discovery judgment owner already does — the sync transport call, the fail-closed rule for a malformed answer, and the booking of the transport's reported usage.cost into a PipelineCost. The wrapper is deleted; route_ids and judge_candidates now call judgment.decide_one. Which questions the stage asks, its model and its thresholds are untouched — this is an ownership move, not a behaviour change.

decide_one is the synchronous single-state entry point beside the asynchronous decide_batch. It shares the transport but deliberately not the batch's fail-soft rule: a malformed answer raises DecisionsValidationError to the single-state caller, because a contract violation is deterministic and must be rejected, while any other transport fault returns None so the item is left unjudged and can be retried. decide_batch's own batch behaviour is unchanged. The reported cost is booked in one place (_book_cost), so the two entry points cannot drift in how they record spend.

A [tool.imas-codex.sn-judge] seat (model typesafe/jev-1.13) sits beside the discovery-relevance and mapping-candidates seats, so the standard-names judgment model resolves through get_model("sn-judge") independently of the other stages.

Gates

The gate covers tests/ids, the judgment-core suite, the decisions-key skip suite, and the two files that import the touched code. At the base revision that same gate carries one failure, TestMapRunModelSeat::test_map_run_model_check_names_ids_mapping, a signature mismatch between _run_rich_mode and its test that predates this work (the base has no no_activate parameter and the base test passes one). After the change the gate is 800 passed, 13 skipped, 1 failed — that same pre-existing failure, no new failures.

Negative control

Removing the shared owner's cost-booking line (_book_cost's cost.add(step, spent, 0)) turns the two candidate spend assertions red: test_judge_candidates_adds_reported_cost_to_the_pipeline_cost fails with KeyError: 'candidate_judgment' and test_route_ids_adds_reported_cost_to_the_pipeline_cost with KeyError: 'candidate_route' — exit 1, both red. The source was restored afterwards and the assertions pass again.
