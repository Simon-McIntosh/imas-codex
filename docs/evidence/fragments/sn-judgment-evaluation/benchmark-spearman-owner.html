Reviewer agreement now uses the tie-correct Spearman implementation

The reviewer-agreement table in imas_codex/standard_names/benchmark.py computed a local _spearman_rho that derived average ranks for ties but then fed them to the no-ties shortcut 1 - 6*sum(d**2)/(n*(n**2-1)). That shortcut is exact only when no rank ties; review scores tie constantly, so the printed agreement disagreed with the tie-correct spearman_rho that the rest of the suite already uses. The local helper is deleted and _render_reviewer_agreement now calls spearman_rho from benchmark_roles, which correlates the average ranks directly.

On the tied input x=[1,1,2,3], y=[1,2,3,4] the two figures separate: the tie-correct rank correlation is 0.9487 (rendered 0.949) while the shortcut gives 0.950. The new test tests/standard_names/test_benchmark_spearman.py builds a two-reviewer BenchmarkReport at exactly those scores, renders the table, and asserts the tie-correct value is present and the shortcut's is not.

Restoring the shortcut (a local helper recomputing 1 - 6*sum(d**2)/(n*(n**2-1)) and calling it) turns the test red: the table prints 0.950, the assertion for 0.949 fails, and the run exits 1. Restoring the correct module returns the suite to green.
