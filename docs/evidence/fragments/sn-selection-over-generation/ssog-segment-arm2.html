Segment selection, second arm: meaning-bearing options and grammar-valid slots

The first arm asked six independent Choices over each slot's whole vocabulary and let the grammar judge the result. This arm constrains what a Choice is offered. The base slot offers no none, so a source can never come back without a base. Every option is the token plus its meaning — read at call time from ISN's public loaders for physical bases, geometry carriers and the locus registry, falling through to the concept registry and to the token's registered aliases. The base is offered over an embedding shortlist of the source's most similar base tokens rather than the full enum, and the item records whether its expected base survived retrieval. Each later slot is asked only after the base is chosen, and is offered only tokens that compose with the tokens already chosen, checked through compose_canonical_ir. Optional slots keep none, and their question says most names leave the slot empty.

What meaning the vocabulary actually carries. definition_coverage() reports, per slot, how many offered tokens carry a definition from any of those sources. The count is the honest one: a token whose only meaning is its registered aliases reports zero, because an alias is a second spelling rather than a definition. Measured at head:

Live smoke — five sources

Five sources chosen to exercise the near-synonym distinctions the lead named — density/number_density, vertical_coordinate/height, toroidal_angle/angle — run once through select_segments. The whole run booked USD 0.00280 of decisions cost, under the USD 0.10 ceiling. Every item returned a base: the first row's failure is a grammar refusal with a base already chosen, not an absent base — the distinction the mandatory base exists to draw, and the first arm's largest loss (68 of 434 items). The chosen token is not always the target's own spelling; which arm selects more accurately is the measurement node's question, not this one's.
