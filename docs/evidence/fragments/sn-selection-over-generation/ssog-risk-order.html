Recall of known defects in a Jev risk order

For each golden item the named checks of its axis are read from the review taxonomy. A check's failure probability is its defect probability: a Noul's true-case probability, one minus a Choice's acceptable-form probability, or one when an audit finding class is present. The item's risk is the maximum over its checks, ties broken by the mean; the mean is carried as a sensitivity order. The incumbent order reads each item's stored review score lowest-first from the graph (reviewer_score for names, reviewer_score_docs for documentation).

Name axis: 28 Jev checks and 4 audit checks; the audit checks not decidable without a full catalog audit were excluded: duplicate_catalog_identity, grammar_round_trip_failure, lexical_convention_violation. Of 737 name rows, 718 carry a frozen judgment and 19 were judged here to fill the gap, so 0 rows carry no Jev answer (each then scores only on its audit checks). Documentation axis: 174 names, 32 reused from the frozen documentation score arm, 96 judged here, 0 calls failed, 14 names had no documentation and are unscored. The documentation composite omits the checks whose answer is a flag rather than a scored probability, so they contribute no defect probability: claim_contradicts_source. Spend: USD 0.002290 for the name gap and USD 0.013692 for documentation, 0.015982 in total, of a USD 0.50 ceiling.

The scorer's recall is checked against two orders whose recall is known in closed form: an order with every defect first must reach min(count, D)/D and one with every defect last max(0, count - (N-D))/D, at each read fraction. Every cell lands on its analytic value on all four golden and split pairs. A scratch copy whose recall is taken from the tail of the order instead of its head puts six cells per split off their value and exits non-zero, so a recall computation that stopped reading the order cannot pass the check.
