Recall of known defects in a Jev risk order

For each golden item the named checks of its axis are read from the review taxonomy. A check's failure probability is its defect probability: a Noul's true-case probability, one minus a Choice's acceptable-form probability, or one when an audit finding class is present. The item's risk is the maximum over its checks, ties broken by the mean; the mean is carried as a sensitivity order. The incumbent order reads each item's stored review score lowest-first from the graph (reviewer_score for names, reviewer_score_docs for documentation).

Name axis: 28 Jev checks and 4 audit checks; the audit checks not decidable without a full catalog audit were excluded: duplicate_catalog_identity, grammar_round_trip_failure, lexical_convention_violation. The axis carries 737 name rows and the run assigns every one of them exactly one status: 718 reuse a frozen judgment, 19 were judged here to fill the gap, 0 were asked for here and returned no answer, and 0 carry no judgment at all. The four sum to 737 by construction, and the run does not stop judging until every pending name holds one of them, so a name cannot be asked for and then left out of the record. Documentation axis: 174 names, of which 32 reuse a frozen judgment, 128 were judged here, 0 were asked for here and returned no answer, and 14 carry no documentation in the graph; the four sum to 174 by the same construction. Each axis stores that status per id under status in the results JSON and the reason for each failure under errors; verify recomputes the four counts from those rows and fails if they do not sum to the axis total. The documentation composite omits the checks whose answer is a flag rather than a scored probability, so they contribute no defect probability: claim_contradicts_source. Spend: USD 0.002547 for the name gap and USD 0.017846 for documentation, 0.020392 in total, of a USD 0.50 ceiling.

The scorer's recall is checked against two orders whose recall is known in closed form: an order with every defect first must reach min(count, D)/D and one with every defect last max(0, count - (N-D))/D, at each read fraction. Every cell lands on its analytic value on all four golden and split pairs. A scratch copy whose recall is taken from the tail of the order instead of its head puts six cells per split off their value and exits non-zero, so a recall computation that stopped reading the order cannot pass the check.

Those two arms test the recall arithmetic, not the risk that feeds it: a scorer that read a row's label into its risk would rank its own ground truth and pass both arms untouched, because both arms supply the order rather than the risk. A third control closes that path. Each split's risk vector is recomputed from every row's own stored checks, and again with the labels permuted among the rows of that split under a fixed seed, and the two vectors must be identical. The risk a row published is also required to equal the risk recomputed from its label-free inputs, so a leak on the way into the results file is caught as well as a leak in the scoring path. The control fails too when the permutation is the identity, which would compare the vector with itself and test nothing. A scratch copy whose risk reads the label reddens it and exits non-zero.

The shuffled-label band check the original brief asked for is deliberately not run. Shuffled labels destroy any correspondence between the order and the truth, so a shuffled order's recall lands inside the random band for any order whatever the scorer does; it would report agreement whether or not the risk read the labels, and is therefore not evidence about the scorer. It is replaced by the invariance control above, which tests the same property — that the risk is independent of the labels — directly, and can fail. The random 95% band rows and the random (expected) rows are kept to state what an uninformative order scores, not as a control.

The risk composite 95% interval rows are copy-group bootstrap intervals for the composite order's recall, resampled by copy group so that near-duplicate spellings do not count as independent evidence; the same numbers are stored in the results JSON under composite_interval. The grouping and the resampling are the shared owner's: _group_indices builds one index array per copy group and the draw reads a group index for each group, with replacement — the same draw the shared bootstrap_interval makes, so a drawn group can be taken more than once. The owner's interval is over an AUC and takes no statistic argument, so the recall at each read fraction is applied to each resample here while the resampling itself stays the owner's. Relative to drawing distinct groups, resampling with replacement draws more often from over-represented groups, so the interval is the wider and more conservative of the two, and a resample with one class only is redrawn rather than counted.

The random (expected) rows give the exact recall a random order has in expectation, count/N, where count is the rounded number of items a read at that fraction takes — the same rounded count the recall uses — and N is the split's item count. Each cell prints that count beside it, so the value is read against the items it was computed on rather than against the unrounded fraction.
