Everything else is held constant: the same held-out sources, the same compose seat (local/deepseek-v4.1-flash), the same reviewer seat and the same acceptance threshold (DEFAULT_MIN_SCORE = 0.85). Blocker

The locally served compose seat does not answer. A probe ran one compose call through the same harness path (_run_model with comparator_block=True) for a single-source batch under a 500 s bound; it returned TimeoutError at wall 500.0 s, so a call of the smallest possible size does not fit inside one pass. Completion-token counts are unavailable because the call never returned. The probe log is acceptance-probe.log.

The decisive shape fact: extraction emits 29 single-item batches (every batch has exactly one item), so the driver's batch size is already 1 and capping it cannot make a call fit a pass.

The lane at the probe moment read running 12, concurrent_requests 45, headroom -5, waiting 0, admission.worker_slots 0 (basis measured, requests_per_run 0.516): over the request ceiling with no worker slots, which is congestion rather than a fault. Snapshots: lane-probe-1.json, lane-probe-2.json.

Three earlier full-run attempts stalled the same way — LLM possible stall: 1 call(s) in flight, no completion for 151s / 166s — provider or governor — with extraction completing every time (29 of 40 sources admitted). The node's time fence expired before the run could be brought back under a bounded retry.

Reproduction

uv run python docs/evidence/fragments/sn-selection-over-generation/ssog-rerank-held-out-acceptance-run.py \

Note on the interval: the evaluation module's bootstrap_interval is AUC-based (it reports a paired AUC difference when scores_b is given). The driver reuses it over item-level acceptance, so the interval it yields is a paired AUC difference over the acceptance labelling, reported beside — not in place of — the raw acceptance rates.
