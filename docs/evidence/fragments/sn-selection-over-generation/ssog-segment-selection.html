Segment selection — Jev chooses each slot from the closed ISN vocabulary

Where the composer generates a name and the grammar judges it, this module selects. For a DD source (path, documentation, enriched description) Jev answers one Choice per grammar slot over that slot's closed ISN vocabulary, and code renders the chosen tokens through ISN's own renderer. Two properties follow from that order rather than from a post-hoc filter: the result can never hold a token the grammar lacks (every option offered is a vocabulary token, and an empty slot is none), and the same answer yields the same name (nothing between the answer and the name invents a segment). Every vocabulary is read live from ISN through grammar_tokens_by_segment; the module holds no snapshot.

Large vocabularies walked as a tree

A slot whose vocabulary ISN keeps as one flat enum is offered as a single Choice plus none. A slot whose vocabulary ISN already partitions is walked as a tree: the operator registry by kind (unary prefix / unary postfix / binary), the locus registry by type (entity / position / region / geometry). The tree is built from structure the vocabulary carries; nothing here authors a taxonomy over an unpartitioned enum. A path is scored by the geometric mean of its per-level choice probabilities, and a beam of three keeps the best paths at each level. A failed expansion — a call the decisions owner reports as an answer it could not produce — contributes no child, so a source left with nothing but interior nodes narrows to an empty beam and yields no path for that slot rather than re-asking the same Choice on every pass; the walk always terminates and the missing slot is recorded as a failure.

Negative controls

The declared control — remove the grammar refusal or the beam pruning and its unit test fails — holds for both mechanisms. Setting SS_SEGMENT_MUTATION=no-beam-prune keeps every path, and the beam test fails (EXIT=1); setting no-grammar-refusal renders without ISN's strict parse, and the refusal test fails (EXIT=1). At the head arm all three tests pass (EXIT=0). Logs are named in the node manifest.
