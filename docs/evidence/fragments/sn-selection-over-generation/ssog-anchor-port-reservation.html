Each arm reserves its scratch port pair for the arm's lifetime

free_port_pair() returned the first port pair free at the moment it looked. A scratch instance binds its bolt port only after its 2.6 GB dump has loaded, minutes later, so four arms dispatched together all chose the same pair and two shared one instance. That is what the four failed runs recorded: the camera-width heuristic and jev arms both report 'scratch_uri': 'bolt://127.0.0.1:28002', and the isolation check fires on a contrast the peer's own writes disturbed (marked_scratch_nodes 1770102 vs scratch_nodes 1770101 in one, 1770104 in the other). The guard was right; the port choice was wrong.

reserve_port_pair(arm) replaces it. It walks the same range, and for each pair whose ports are free it takes an exclusive, non-blocking fcntl.flock on ssog-scratch-port-<bolt>.lock, writing the holder's pid and arm into the file, then re-probes the ports under the lock before committing. A pair whose lock another arm holds is skipped. The lock is held from reservation until the scratch instance is stopped and its tree removed, released in the arm's finally on every exit path, and the release is idempotent.

The lock directory defaults to /dev/shm, the node-local store every concurrent arm can write, overridable with SSOG_PORT_LOCK_DIR. The brief's suggested /tmp is not usable here: a worker sandbox mounts /tmp read-only, and each arm's own TMPDIR is private to its run, so neither can coordinate two arms.

Four reservation processes started together, each holding its claim while the others claim, get four distinct pairs: pairs=[28006, 28002, 28004, 28000] distinct=4, EXIT=0. The same check against the unchanged free_port_pair() collides: pairs=[28000, 28000, 28000, 28000] distinct=1, EXIT=1. A claim released in process and reclaimed returns the same pair (reacquired=[28000, 28000]), so the release leaves the descriptor closed. No arm was run and no LLM call was made.
