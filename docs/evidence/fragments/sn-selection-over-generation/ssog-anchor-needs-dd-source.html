A family anchor must be entailed by a DD source

A member with no Data Dictionary producing source is no longer an anchor candidate. A family takes its documentation template from its anchor, so the opening the anchor sets for its members is only checkable against source text when the anchor has a DD source of its own. A name with none — the derived parent the held-cause record found holding fourteen of fifteen members — sets a template its own rewrite cannot be verified against, and then templates members it holds no textual authority over. Both selectors in imas_codex/standard_names/families.py now require the flag: the heuristic select_anchor and the judged scorer's candidate filter _eligible_anchor_candidate.

What the rule reads

A row is DD-sourced when :StandardNameSource {source_type: 'dd'} reaches it along PRODUCED_NAME and that source is not retired (status = 'stale') — the same producing-edge shape source_invariant.py guards writes with, so the two cannot disagree about what a producer is. One builder, dd_source_exists(alias), is the single spelling of it; every family query in the module that returns a member row projects it under has_dd_source: _PATTERN_FAMILY_MEMBERS_QUERY, the per-family collect in _family_member_collect, and _FAMILY_BASE_QUERY. member_has_dd_source(row) is the one reader.

Every ranking branch applies it, not only the top one. The accepted-parent rule reads the parent's own row when the parent is one of the members and the caller's reported state otherwise, so an accepted derived parent no longer wins by rule 1; the accepted-and-scored branch, the accepted-but-unscored branch and the last-resort branch each draw from the same eligible set. The judged scorer drops the same rows before any call is made, so an unsourced member is never asked about and never returned as the choice.

A row that carries no has_dd_source key at all is read as having no DD source. The reader fails closed: a query that projects the flag states the member's source, and a caller that drops it disqualifies the member rather than being believed. The earlier default read an absent key as DD-sourced, which invalidates its own guard — every path that rebuilds a row was then free to drop the flag and silently restore the unguarded ranking, and one did.

The flag has to survive the whole trip from the query to the selector, and it did not. harmonize._row_to_member rebuilds each member row as a fixed seven-key dict, so the flag the family query projects was discarded before assemble_family — the assembler the sn harmonize CLI calls — handed the rows to select_anchor. With the absent-flag default the guard then switched itself off on the only path the campaign actually runs, while the unit tests that hand the selector its own rows stayed green. The row rebuild now carries the key, and an absent or null flag means no DD source, so a dropped flag is a loud failure rather than a silent one.

The parent is not always one of the members, so its source state cannot be read from the member rows. select_anchor and the judged candidate filter _anchor_score_candidates take it as an explicit keyword argument, and every caller that reads a parent node projects it alongside the parent's own columns: the parent-grouping member read, the parent read, and build_worklist's per-family read in harmonize.py, and the sibling-family read in context.py. The accepted-parent rule fires only on a parent reported as sourced; a caller that does not report it leaves the rule off rather than firing it on an unverifiable parent.

A family with no DD-sourced member has no anchor

The caller already handles a family without one, and the new rule only routes more families into that existing path — no new failure mode is introduced. harmonize.build_worklist stamps "deferred": anchor is None on the worklist entry, and the planner reads it as elif anchor is None: decision, batches = "deferred", [] (harmonize.py:1253) — no batches, nothing rewritten. context.fetch_sibling_family returns anchor: None with defer semantics and still returns the siblings for structural comparison, as its own docstring states. The judged scorer returns AnchorScore(reason="no member is eligible as the family's template") rather than a default anchor. So an all-unsourced family is deferred and never templated from a member with no source to check against.

Caveats

The ten-family delta is measured on the live graph, not on the 2026-10-18 export the A/B ran against, so its anchors need not equal the recorded ones and, for six of the ten, do not. The comparison that carries the claim is the one made here, base rule against fixed rule over identical rows; the snapshot columns are context, not the measurement. The delta was measured before the fail-closed default and the parent argument landed, and is unaffected by them: both of its arms pass no parent, so the accepted-parent rule fires in neither, and every row it ranks comes from a family query that projects the flag — the arm that changed is the rule, not the rows. The DD-source column is provenance rather than documentation state and is therefore the part least exposed to that drift, but it is still a live reading. No LLM spend was incurred by this node: every arm is a pure selection over rows already in the graph.

Follow-ons

The parent-grouping path's own rows are the defect this revision closes, not an open follow-on: the inline member and parent reads in harmonize.py, build_worklist's per-family read and the sibling-family read in context.py all project the flag now, and the row rebuild carries it. A derived parent reached through the CLI's own assembler is disqualified like any other member.

Distinct from, and complementary to, the hold check owned by ssog-docs-hold-dd-bindings (_documentation_contradiction_note in workers.py): that repair stops the false hold firing on a rewritten member, this one keeps an unverifiable member from being chosen as the template in the first place.
