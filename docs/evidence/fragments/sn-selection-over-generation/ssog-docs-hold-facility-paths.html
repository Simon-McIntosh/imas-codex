A facility-only source path does not require DD text

Defect. _bound_docs_review_dd_paths in imas_codex/standard_names/workers.py returns the paths of the name's dd source bindings, but when no dd binding exists it falls back to the raw source_paths — including facility signal paths such as tcv:ip/measured. _documentation_contradiction_note takes that list as the DD paths whose text must be present. A name sourced only from facility signals therefore demanded DD text at tcv:ip/measured, was held with DD source text unavailable at tcv:ip/measured, and documentation review clamped it below DEFAULT_MIN_SCORE — although no DD text exists to compare against. This is the facility-path member of the hold's DD-source precondition; the derived- and manual-only members were closed by ssog-docs-hold-dd-bindings, whose _has_dd_source_reference fallback still read a facility path as a DD source through this helper.

Reproduction at the base revision (8fc4843c9), driven through the helper and the note directly with the model stubbed, so the run spends nothing (logs/repro_base.log): _bound_docs_review_dd_paths({'source_paths': ['tcv:ip/measured'], 'source_bindings': []}) returned ['tcv:ip/measured'] and the note returned 'DD source text unavailable at tcv:ip/measured'. The same probe after the repair (logs/repro_head.log) returns [] and None. Both the base and head probe runs printed module: .../ssog-docs-hold-facility-paths/imas_codex/standard_names/workers.py, so the worktree source is the one measured, not the main checkout's copy.

Change. The helper's fallback now keeps only source_paths entries carrying the dd: prefix, so a required DD path comes either from a dd binding or from a dd:-prefixed source path — never from a facility path. Everything else is untouched: a dd binding whose text is missing still holds, naming only the DD path, and a dd:-prefixed source path with no binding is still held.

Caller audit. _bound_docs_review_dd_paths has three callers. Its fallback change is what each expects:

  • _has_dd_source_reference — expects a non-empty result to mean the name names DD text. A facility path made this predicate answer True for a name with no DD source, defeating the fallback the sibling node added. It now answers False.
  • the docs-review request builder — sets veto_item["source_paths"] = _bound_docs_review_dd_paths(veto_item) and fetches DD context for those paths via _fetch_review_dd_context. It expects genuine DD paths to read; a facility path was fetched as DD context, a read that can only miss. It is now excluded.
  • _documentation_contradiction_note — the required DD paths whose text must be present, and the site of the defect. A facility-only name now carries no required DD path.

No LLM spend: every case in these two files returns before a model call. Generated-model regeneration was refused (read-only) and did not affect collection.

Negative control. The declared mutation — let facility source paths count as required DD paths again — is the base helper's fallback. Applied to the head tests, it fails test_facility_only_source_path_is_not_held and test_hold_predicate_reads_only_dd_sources while the rest pass (2 failed, 75 passed, EXIT=1; logs/negative_control.log). test_facility_path_with_dd_binding_holds_only_the_dd_path passes in both arms: a dd binding short-circuits the fallback, so that test is a non-regression guard that the fix does not overreach, not a mutation-sensitive one. Each accessor expectation is a literal, built without the constant that fed its input: the held case expects .../profiles_1d/j_tor while its input dd_path is prefixed dd:, so echoing the input cannot satisfy it.
