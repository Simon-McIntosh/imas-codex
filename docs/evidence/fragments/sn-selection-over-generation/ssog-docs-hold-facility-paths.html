A facility-only source path does not require DD text

Defect. _bound_docs_review_dd_paths in imas_codex/standard_names/workers.py returns the paths of the name's dd source bindings, but when no dd binding exists it falls back to the raw source_paths — including facility signal paths such as tcv:ip/measured. _documentation_contradiction_note takes that list as the DD paths whose text must be present. A name sourced only from facility signals therefore demanded DD text at tcv:ip/measured, was held with DD source text unavailable at tcv:ip/measured, and documentation review clamped it below DEFAULT_MIN_SCORE — although no DD text exists to compare against. This is the facility-path member of the hold's DD-source precondition; the derived- and manual-only members were closed by ssog-docs-hold-dd-bindings, whose _has_dd_source_reference fallback still read a facility path as a DD source through this helper.

Reproduction at the base revision (8fc4843c9), driven through the helper and the note directly with the model stubbed, so the run spends nothing (logs/repro_base.log): _bound_docs_review_dd_paths({'source_paths': ['tcv:ip/measured'], 'source_bindings': []}) returned ['tcv:ip/measured'] and the note returned 'DD source text unavailable at tcv:ip/measured'. The same probe after the repair (logs/repro_head.log) returns [] and None.

Change. The helper's fallback now keeps only source_paths entries carrying the dd: prefix, so a required DD path comes either from a dd binding or from a dd:-prefixed source path — never from a facility path. Everything else is untouched: a dd binding whose text is missing still holds, naming only the DD path, and a dd:-prefixed source path with no binding is still held.

Repair — the prefix rule broke the prepared-item round trip. A review of the first cut found that prepare_docs_review_request rewrites a veto item's source_paths to this helper's output — the paths with the dd: prefix stripped, so the DD-source read and the review prompt see bare paths — and process_review_docs_batch then runs the note on that same item. For a name whose DD path arrives only as a dd:-prefixed source path with no dd binding, the second pass saw a bare path, the prefix rule dropped it, the required list went empty and the hold was lost — the opposite of the brief's "a DD-bound item with missing text still holds". Probed on the pre-repair tree (logs/repro_roundtrip_base.log, 100a86a4d): the helper returned ['equilibrium/time_slice/profiles_1d/psi'] on the raw item and [] on its normalised form, and the note returned None. The repair keeps the provenance across that rewrite: _set_docs_review_dd_source_paths sets source_paths to the bare DD paths and records the same list in dd_source_paths, which the helper reads when present, ahead of the dd:-prefix fallback. After the repair the same probe (logs/repro_roundtrip.log) returns ['equilibrium/time_slice/profiles_1d/psi'] on both passes and the note holds.

Caller audit. _bound_docs_review_dd_paths has three callers. Its return is DD paths only, and its input may be a raw item or a prepared one:

  • _has_dd_source_reference — expects a non-empty result to mean the name names DD text. A facility path made this predicate answer True for a name with no DD source, defeating the fallback the sibling node added. It now answers False.
  • _set_docs_review_dd_source_paths, called by the docs-review request builder — expects the DD paths to normalise into source_paths for the DD-source read and the prompt, and now records them in dd_source_paths so those paths stay DD after the rewrite. A facility path was previously normalised in as a DD path and fetched as DD context, a read that can only miss; it is now dropped.
  • _documentation_contradiction_note — the required DD paths whose text must be present, and the site of the defect. A facility-only name carries no required DD path; a prepared item with a DD path still carries it.
