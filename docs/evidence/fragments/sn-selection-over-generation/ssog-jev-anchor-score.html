Each family member scored as the family's template

score_family_anchor asks one Score per eligible member — a member select_anchor would consider, meaning a non-placeholder description with documentation present. The question is "How well would this member's documentation serve as the template for the whole family?", with the member's name, description and documentation, the family's pattern, and the house-style template the grammar renders for that pattern (conventions_context_for, the accessor the docs prompt already renders its conventions block through) as state. That template is read from the family's own members — the first whose id the grammar parses — because every member shares the family's pattern, so an unparseable or absent parent id cannot leave the state's template empty. A family whose members all fail to parse is refused with a reason and no choice, never asked without a template. Its five levels, low first, are code-authored criteria:

  1. Names or describes a quantity other than the family's, or contradicts the family's pattern — templating from it would mislead every other member.
  2. Specific to this member alone: no opening or structure that could carry over to the family's other members.
  3. Reusable in parts: states the family's shared quantity but departs from the house style in terminology or structure, so a member templated from it would need rewriting.
  4. A good template: states the family's quantity and follows the house style, with only minor member-specific detail a sibling would carry harmlessly.
  5. An ideal template: states the family's quantity, follows the house style and its fill-in slots exactly, and carries no member-specific detail that would mislead a sibling.

The highest expected score is the candidate anchor; a tie falls to select_anchor's own ranking over the tied members, with the family's parent id, docs stage and description passed through when the parent is itself one of the tied members, so the heuristic's accepted-parent rule applies here exactly as it does over the whole family. A failed or unscored call leaves its member unscored and a family with no scored member returns no choice, never a default. Nothing here changes select_anchor or its callers: this node builds the scorer and spends only its own calls.
