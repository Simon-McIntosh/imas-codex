The interval is taken over the refits rather than as a bootstrap of one of them, because a single shuffle's bootstrap resamples the validation rows around one fixed randomised weight set — reporting the validation set's spread under one noise draw, not whether the fit has skill. That the fit reads no validation label is shown separately and directly by moving the validation labels between their slots with the feature vectors held in place and refitting through the same fit path, which must leave the weights identical (largest coefficient change 0.0e+00, weights_identical=True, permutation non-identity=True). What that comparison can see is measured on the same run rather than assumed of it: the same permutation pushed through a fit that reads every row must move its weights, and it moves them by 0.390 (leaked_fit_detected=True), so the control is known to be able to fail. A variant that permutes whole validation rows instead of labels would have no such power and is refused here: it moves every feature with its own label, leaving the row multiset — and so every fit that is a function of it — unchanged, so the only thing such a comparison reads is whether the solver's output shifts when its input rows are reordered. Two measured variants show the difference. Put a fit that reads every row in a canonical order, so that reordering cannot reach it, and the whole-row variant reports it as passing (largest coefficient change 0.0); the label-moving comparison reads the same fit at 0.390 and does not. Each control's own measured result is recorded with EXIT= in the run log, and the driver's exit status is the conjunction of the four, so a run with any control red cannot ship behind a zero.
