The held-out batch acceptance measure is blocked: the benchmark harness renders no comparator block, so the switch cannot move its compose prompt

The measure compares first-pass review acceptance of a held-out compose batch with the comparator rerank off (arm A) and on (arm B). The switch is IMAS_CODEX_SN_COMPOSE_RERANK_COMPARATORS, read by comparator_rerank_enabled() in imas_codex/standard_names/context.py:1037. Its required positive control is a differing rendered-message hash for at least one item between arms. That control fails: both arms render a byte-identical harness compose prompt, so the two arms are the same run and any acceptance difference between identical prompts would be noise. The finding is that the block the switch reranks is not carried by the benchmark harness at all.

The rerank reorders the nearby-name comparator block (nearby_existing_names) and is invoked only on the production compose path in imas_codex/standard_names/workers.py (_rerank_comparators_for_worker at line 4033, and the batch path at line 5897). The harness's compose step, benchmark._run_model, builds its sn/generate_name_dd user context from items, ids_name, existing_names and cluster_context only (imas_codex/standard_names/benchmark.py render site, lines 1622–1642) and never sets nearby_existing_names, so the template's {% if nearby_existing_names %} branch is empty and the block cannot be reranked.
