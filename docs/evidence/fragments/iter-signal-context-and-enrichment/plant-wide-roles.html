Roles decided across the plant from the field-code table

The ITER catalogue holds 97,525 archive signals in the graph, 30,031 of them carrying a field code. The closed-vocabulary assignment that ran on the 1,766-signal pilot system now runs over all 97,525, with the field-code table as the field-pattern source for the role axis. Values are stored only where a source states them: a linked signal-list row, the controls metadata a signal carries, the unit the archive reports, or the table's entry for the signal's field code and component kind. Each axis carries one outcome per signal, and on every axis the decided, in-conflict and undecided counts sum to 97,525.

The run reads the repaired description slots. A signal's description is the source text with description_source naming where it came from, and text composed by enrichment lives in generated_description. The vocabulary credits only a description marked as controls metadata, so a composed description cannot decide a value; where both texts exist, the reading below uses the source text and says so.

Signals decided as each role

Of the 1,732 signals whose role is decided, 1,436 are measurement, 101 state, 86 command, 63 setpoint and 46 alarm. The setpoint count is a property of the sources rather than a target: the table states a setpoint role for seven of the forty codes it examined, and those seven codes decide 56 signals; the controls metadata states a setpoint for 7 more.

The readings that could have failed

  • Every one of the 4 pilot values this run changes was listed privately and read by hand against the signal's own sources: 4 verdicts, all right, 0 wrong. Each reason states what the signal's own description says and why the earlier consensus value is withdrawn.
  • The sample of newly-decided roles was drawn and written to a private file before the storing run, with digest 693b6fe8a7080cc7b444181a8ea681e4ae6a24269b58e08aa2f08884b7e55c28. It holds ten signals credited to the field-code table and one credited to the controls metadata — every source that credits a newly-decided role, ten per source or all where fewer, since no signal-list row credits one. The storing run recomputed the sample and its digest is unchanged. Eleven signals were read by hand, one verdict and reason each: 11 right, 0 wrong, against the allowance of two wrong.
  • The reading is not a script. A file with one identical reason for every item, an empty reason, an omitted item or a verdict outside the three admitted values is refused. Six tests cover it, five of them refusals; the same file reloaded from JSON is still refused.

Checks that could have failed

  • The write stored 559 signals in 3 batches; a read-back compared 6,239 assigned values with the assignment and found 0 mismatched. A second assignment read the catalogue again, reassigned it and reported 0 changed signals.
  • The 2,114 decided units were compared with 3,345 source spellings through the shared unit authority: 0 disagreements, so two spellings of one unit (KA against kA) agree. A unit written two ways does not become a conflict.
  • The catalogue holds a setpoint: 56 signals in one plant system and one in another. A server search for the setpoint role on the system holding 56 returned 56, every item carrying the role, and a search on a system that holds none returned 0 with an empty page.
  • The server route needed a plant listing that can filter by role, because a plant listing is the only search whose page states a system's signals and their roles together. That is why the change to iter_codex/llm/search_tools.py is in scope: it admits vocabulary_role as a plant filter, validates the value against the closed role vocabulary and returns the refusal naming the permitted members, so an unknown role fails before any query runs instead of silently returning a page that carries no such role. Without it the setpoint check above could not be made through the served tool, which is the surface the section requires to work.
  • The unit arm passes at revision 6d2b4bc66: 69 passed, 1 warning in 5.57s over the assignment rules, the store path and the reading machinery. The log names the module it imported as the worktree's own file, so the arm measured this tree and not the shared environment's editable install.
  • The graph-marked statements pass at revision 6d2b4bc66: 14 passed, 1 warning in 80.73s (0:01:20), including the catalogue read and its control query, the table-driven write, a code without a table entry storing no role, a repeated assignment changing nothing, the role filter and its MCP route.
  • Removing the table as the role source and falling back to the population consensus fails two tests that pass at this head, and the failing ids are recorded in the negative-control log. The first run of this control in the mutated tree passed because the run resolved the worktree's module rather than the tree it had mutated; the log now prints the module path before the run, and the same mutation then failed as it should.
  • The declared negative controls hold: a signal whose code has no table entry and no other source stays undecided (a unit test and the 226 catalogue codes with no entry); a pilot value contradicting its own source is reported as changed (a unit test drives a hand-changed value through the comparison); and a scripted reading file is refused.
  • The changed and added tracked files were searched for real signal identities and for the archive's accession prefixes: no signal name, accessor, or document identity appears. The private receipts and both readings files live outside the repository.

What stays undecided

95,793 roles and 95,129 quantities have no source that states them. The controls feed describes many channels only as an analogue input or a signal value, the signal list has one row per component, and the table establishes an entry for 33 of the catalogue's 259 field codes. The rule fills none of that gap with a default: a code the table does not establish and no other source states leaves the role undecided, which is what the negative control requires.
