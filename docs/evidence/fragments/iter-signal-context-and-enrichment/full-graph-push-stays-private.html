Every facility graph push reads its package back private

A graph push decided whether to verify package visibility from the command's own flags: the check ran only when --facility was combined with --without-dd. The weekly offsite timer runs iter-codex graph push --cycle, which runs a full-graph push with neither flag, so the archive that carries every ITER node reached GHCR with no visibility read at all. The package rename moves the archive into iter-codex-graph, so the first cycle after the rename creates a package that nothing verifies.

The push now decides from the archive's own record of what it holds. The export writes a manifest.json into the archive carrying label_counts, and the push reads that label set, derives the facility-owned labels from the schema (every label whose nodes carry a required facility_id, which is the positive statement of what a DD-only dump deletes), and, when any of those labels is present with a nonzero count, sets the package private and then reads the visibility back from the registry. Setting it first is what protects content already uploaded: a package that came up public is made private before the push can be judged, rather than left public with ITER content inside while the push merely fails. The push then fails with a nonzero exit if the registry still reports anything other than private. A missing or unreadable label set answers that the archive holds facility content, so a scope that cannot be read cannot clear a package. The manifest is read by the reader the offsite cycle already uses (read_archive_manifest and GraphCensus.from_manifest), so the push and the cycle cannot disagree about what an archive contains. The read-back happens after the write and before the latest tag.

The registry is the fork owner's ghcr.io/<owner> when the checkout is a fork and ghcr.io/iterorganization otherwise. This node made no push and changed no live package: every registry call in the tests is faked, so the only packages whose visibility is set are the fakes' own record of the request.

The check is what catches a public package

With _require_private_package returning before it reads visibility, test_full_graph_push_refuses_a_package_that_stays_public lets the push complete and fails on the exit code and on the recorded tag: the full-graph case whose set to private does not take effect then passes the push, which is the behaviour this change removes. Restoring the check turns it green again. Three cases pin the protective behaviour: a package the registry reports public is set private and the push continues with the package recorded private; a set that leaves it public fails the push with no latest tag and no push recorded; and a package already private is never written.
