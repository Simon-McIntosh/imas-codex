The parser preserves the one-to-five-level control-breakdown path separately from the physical component. Each control-path field has one to four uppercase alphanumeric characters; VariableID has one to 24 uppercase alphanumeric or hyphen characters. Component category, sequence and field widths are treated as maxima: one to three letters, one to four digits and one to four letters respectively; the optional discriminator has at most four alphanumeric characters and takes a separating hyphen when it starts with a letter. No meaning is assigned to a category or field code. A valid VariableID outside the physical component form is a function-level variable; an invalid FunctionID or VariableID is explicitly nonconforming.

Reuse and the enrichment adapter

There is one guarded archive snapshot: snapshot_archive_signals in discovery/signals/variable_name_graph.py. Both catalogue parsing and grouping use it. The runner replays the private store through ArchiveGrouping.snapshot_records, and the code census uses ArchiveGrouping.name_schema_counts; neither measurement depends on a hardcoded table layout.

These are structural PlantComponent, ControlNode and ArchiveFieldPattern nodes, not SignalSource nodes. A component group contains different fields, while a field-set pattern spans different components. Blindly copying one representative field's description, unit or classification across either population would conflate their meanings. Existing MEMBER_OF source memberships are therefore preserved.

Enrichment needs an adapter that resolves each member's component or control-node description and the chosen pattern's field description, then supplies that composed context to a compatible existing or reconciled SignalSource. Source members must share the relevant field meaning, unit and classification established by context; code spelling alone does not establish those. The adapter must retain deterministic representatives and the existing source identity, member-count, status and claim fields, use discovery/base/grouping.py for source claim/release and shared propagation contracts, and use the signals pipeline's propagation and individualization writers for FacilitySignal status, cost, descriptions and embeddings. Pattern-field dictionaries remain reusable context rather than a second propagation mechanism. This node implements the grouping and measures the description counts; it does not claim that adapter or enrichment is shipped.
