Keeping a feed description beside its generated one

Pilot group enrichment wrote each of its 190 composed descriptions into the signal's description property, which is where the controls metadata feed stores its operator label, and left description_source empty. Every one of those 190 signals had a feed label before the run, so 190 source descriptions were replaced rather than annotated. The plant-wide role assignment reads description_source to credit a source, so it read all 190 as carrying no source and undecided the values the feed had decided for them, and that assignment is held. The repair puts a generated description in its own property, restores the 190 feed labels and their source marker, and changes the single writer so no enrichment can reach the source slot again.

One slot for what the sources say, one for what enrichment composed

FacilitySignal now declares generated_description, generated_description_source and generated_description_updated_at beside the existing description, description_source and description_source_updated_at. The schema states the rule on all six: description holds what the sources say and enrichment never rewrites it; the generated trio holds the composed text, the mechanism that composed it and when it was written.

The shared description writer is the only path in the package that writes a signal description. It chooses the slot from what the signal already holds: a signal carrying a source marker keeps its description and its marker, and the composed text goes to generated_description with its mechanism and timestamp; a signal with no source marker has description as its enrichment slot and is written there exactly as before the separation, so enrichment at a facility whose source wording lives elsewhere is unchanged. The one caller that passes the source slot is the controls feed import, which owns that text. The writer never assigns description or description_source on a signal that carries a source marker, so the separation holds at the single point where all rewrites pass through rather than in each caller. The embedding and its hash move with the text the search indexes: a generated write embeds the generated text, and a source re-import of a signal that already carries a generated description rewrites the source slot and leaves the stored vector and hash alone, because the vector describes the generated text the index serves.

Checks that could have failed

  • A test writes a generated description onto a signal that carries a feed description and asserts that the feed text, its source marker and its reported update time are unchanged while the generated text, its mechanism, its timestamp and the embedding move. With the writer's default slot switched back to description, the test fails on the mutated source text; restoring the default passes it.
  • A second test writes a composed description onto a signal with no source marker and asserts that description receives that text and that no generated slot is created, so the narrowing that protects a feed label leaves an ordinary enrichment slot working.
  • A scratch-graph test writes a snapshot, changes one signal's description by hand, and asserts the comparison reports that one signal under description mismatch, reports nothing under marker mismatch and nothing missing. It proves the instrument the repair's verification rests on.
  • A source re-import over a graph a previous import already populated changes no node and no property, which the earlier shape of the writer could only satisfy by re-embedding a row on every run.
  • Graph-marked statements for the touched packages pass on rigel: 16 passed, 0 failed.
  • The default tier over the touched packages adds no failure. The changed tree fails one test, a prompt-schema coverage walk that the unchanged base tree fails identically, and the base tree's only other failure in that run is a 30-second timeout opening a scratch catalogue database that passes in the changed tree in the same run and passed in two earlier runs of the same base tree. Both arms and their whole test ids are recorded in the run's manifest.
  • The tree carries no real accessor or description text: the fixtures use invented names, and a search for the terms the repair touched over the tracked tree returns no live value.

What this does not show

The repair restores the 190 signals that had a feed description in the snapshot. It cannot recover a source description for a signal that had none before the pilot run, and it does not judge whether any composed description is correct: the reading that measured the composed texts stands as it was. The separation prevents a future enrichment from erasing a source, but a mechanism that writes through a path other than the shared writer would bypass the test, so the guarantee is only as wide as the single-writer rule it rests on.
