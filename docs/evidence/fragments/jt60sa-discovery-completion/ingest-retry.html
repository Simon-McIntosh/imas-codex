Root cause, and the fix that cleared it. The initial pass re-failed all 29 because ingest_files (imas_codex/ingestion/pipeline.py) returned stats from its if not paths_to_ingest: return stats branch before it had attached the per-file stats["outcomes"] map. Every requested path was already reported ingested by _check_already_ingested — an ingested-shaped CodeExample with the file's facility_id + source_file existed for each — so the caller received no outcomes, and the batch handler in imas_codex/discovery/code/workers.py read each missing outcome as a failure via _mark_file_failed(f["id"], "no ingestion outcome recorded"). The fix (merged on main) attaches each requested path's own outcome on every exit, so an already-ingested path records {"status": "ingested"} rather than nothing. The resumed run exercised that path directly: its batches logged Skipping 10 already-ingested files (twice) and Skipping 9 already-ingested files, and the 29 files were marked ingested, not failed. This is the failure mode §31 item 2 set out to remove — one file's outcome decided by another's — and the fixed code closes it.
