Claims and has-work predicates skip excluded path prefixes

A facility's path-prefix exclusions were a seeding rule only: rows already in the graph under an excluded prefix were still claimed and still counted as pending work, so a discovery run churned the very subtrees the exclusion config names. Every path claim and code claim, and every has-work predicate behind them, now binds a negated prefix predicate built from one helper. build_path_prefix_filter in imas_codex/graph/query_builder.py gains a negated flag and a param argument defaulting to prefixes, so a claim that both scopes and excludes renders none(excluded IN $excluded_prefixes WHERE p.path STARTS WITH excluded) beside the scope clause and binds two distinct lists rather than overwriting one name. The new build_facility_exclusion_filter in imas_codex/config/discovery_config.py, placed beside get_exclusion_config_for_facility, resolves get_exclusion_config_for_facility(facility).path_prefixes and returns the clause with its parameters built through build_path_prefix_filter. The five path claims in imas_codex/discovery/paths/parallel.py move from render_path_prefix_clause to build_path_prefix_filter for their --root scope; has_pending_work and its five _has_pending_*_work helpers, the four code claims and six code predicates in imas_codex/discovery/code/graph_ops.py, and the one ingestion claim in imas_codex/discovery/code/workers.py all call that one helper at the 22 sites the node names — none resolves the exclusions itself. The name-based families (basename directories, patterns, archive extensions, dotfiles, scratch names) stay seed-time and scan-time rules, because they judge an entry as the scanner meets it.

Gate uv run --no-sync pytest tests/discovery tests/graph/test_path_prefix_filter.py exits 0 (1218 passed) on the fleet node, against a baseline of 1188 passed. The new tests/discovery/test_claims_honour_exclusions.py seeds one claimable row under an excluded prefix and one outside for each of the 22 claims and predicates and asserts only the outside row is claimed or counted; a stub GraphClient evaluates the seeded rows against the prefix predicates the query itself carries, read from the named parameters the caller bound. A separate assertion binds a scoped claim and confirms it carries both scope_prefixes and excluded_prefixes, and another seeds a sample of paths and asserts the claim's exclusion matches exactly the paths ExclusionConfig.should_exclude marks with a path_prefix: reason. Because Cypher binds AND tighter than OR, an exclusion clause appended after a disjunction governs only the last branch: has_pending_work rendered its five state tests as disc OR scn OR exp OR enr OR (rsc AND none(...)), so rows under an excluded prefix that were discovered, scanned, expand-eligible or enrich-eligible still counted as pending — and a has-work predicate true while every claim returns nothing drives the phase reset loop. The state disjunction is now parenthesised so the exclusion binds the whole predicate, and the other sites were audited: each appends the clause to an AND-chain, or to a disjunction already parenthesised, so none needed the same change. A remaining test renders each claim's and each has-work predicate's Cypher and asserts no top-level OR precedes the exclusion clause, which the row-filtering stub cannot see.
