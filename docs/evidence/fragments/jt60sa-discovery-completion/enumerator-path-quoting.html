The directory enumerator quotes its path

_enumerate_files_find in imas_codex/remote/scripts/discover_files.py built a find command as a string and handed it to sh -c with the scanned path interpolated unquoted, so a path holding a space, a # or a shell metacharacter was mangled before find ran. The command is now built by a _build_find_command helper that passes the path through shlex.quote. It is the only site in the script that builds a shell command from a path: _enumerate_files_fd, _count_lines and _rg_count already pass argv lists to subprocess.run with no shell.

Reproduction before the fix: the path /analysis/a b#c reached the shell as find /analysis/a b#c … and shlex.split produced ['find', '/analysis/a', 'b#c', …] — the path split at the space.
