SELENE sensor order — EDDB channels joined to geometry-input positions

Goal: give the ambix machine map a receipt joining each raw EDDB magnetics channel to its geometry-input sensor position through the shared sensor index. Read-only, from /analysis/src/getseldata_v4.2 and /analysis/src/SAselene_v2.0_forPSRC on the jt-60sa host, the node writes docs/evidence/receipts/jt60sa-selene-sensor-order.json with three ordered lists — 27 flux loops, 17 tangential probes and 17 normal probes. Each entry carries its sensor index, EDDB channel name, geometry-input position and the source file and line range that establishes it. No discover run, no graph write, and no file written on the host. The receipt's parsed lengths are asserted against ILOOP=27 and IPROB=17; the assertion fails closed on a mismatch.

Counts and the shared index

A raw channel joins its position only through the shared sensor index: the EDDB channel icnt+1 fills measured-array slot icnt, and inpgeo.c fills the position-array slot icnt from the geo.in row at the same ordinal. So flux loop k is EDDB “1626 S007” channel k ↔ geo.in line 502+k; tangential probe i is EDDB “1626 S006” channel i ↔ geo.in line 484+i.

Count conflict, recorded not resolved by guess. SELENE's standalone default mgset0.f:135–136 sets IPROB=17, ILOOP=15. The geometry input and the getseldata namelist use ILOOP=27 (FXMAX), and eqinpu96.f:221–222 overrides the default from the namelist. The receipt's flux list uses the geometry-input count 27; the mgset0.f 15 is carried in the receipt under count_conflict.

Normal probes: order not established

The source does not establish an EDDB channel for the normal probes, and the receipt says so rather than guessing. geteddb.c reads only one probe PID (“1626 S006”) and outeddb.c writes no RPOSN/ZPOSN field, so normal-probe positions are not written by the pipeline at all. The receipt records the normal-probe list with eddb_name: null, order from the mgset0.f sensor index only, and its position from the cold branch mgset0.f:127–128 (RPOSN=RPSNM(I,1), data 19–22/28–30) — selected because outeddb.c:224 writes TMPW=0.0. Those hardcoded normal positions are numerically identical to the tangential ones in mgset0.f, so no independent normal-probe geometry is available.

Gate and negative control

Gate: the generator parses the emitted JSON and asserts len(flux_loops)==ILOOP, len(tangential_probes)==IPROB, len(normal_probes)==IPROB, ordered channels, and that every normal entry is flagged unestablished — all pass. The declared mutation sets ILOOP=15; the flux-length and channel-order checks then fail and the run exits non-zero, so the guard fires rather than passing by silence.
