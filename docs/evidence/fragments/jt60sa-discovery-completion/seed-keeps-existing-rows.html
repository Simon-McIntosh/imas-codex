Root seeding is create-only, so an existing root keeps its state

seed_facility_roots built every root as a fresh discovered depth-0 row and wrote it through GraphClient.create_nodes, whose MERGE ... SET upsert reset the status, scores and timestamps of a root already scored by an earlier run. When a scoped --root run named the three equilibrium tree roots, they went from scored (0.45, 0.60, 0.75) back to discovered, and no later run would claim them again.

create_nodes gains a create_only option, off by default, that scopes the property write to the creation event via ON CREATE SET; relationship creation is unchanged. seed_facility_roots writes its canonical and alias rows with it, so every caller of the seed — the --root seed in imas_codex/cli/discover/paths.py, the empty-graph startup seed and imas_codex/discovery/paths/parallel.py — is additive. seed_missing_roots, whose pre-query of existing paths only worked around the overwrite, is retired with its exports in imas_codex/discovery/__init__.py and imas_codex/discovery/paths/__init__.py; --add-roots now calls seed_facility_roots(facility). create_child_paths, which carried the same overwriting write with no live caller, is deleted. Reprocessing an existing root is left to --reset-to.
