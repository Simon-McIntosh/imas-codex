imas_codex/discovery/base/services.py gains decisions_health_check(service="facility-discovery"), a cheap reachability probe of the OpenRouter decisions route. It resolves the credential with get_api_key_for_service(service) and sends a single authenticated GET to https://openrouter.ai/api/v1/key — the key-info endpoint on the origin parsed from DECISIONS_ENDPOINT, so the probe follows the route if the host moves. The request carries no model, state or questions, so the decisions endpoint is never asked to judge anything and no decision is billed; a 200 is healthy, a refused connection or timeout is endpoint refused/endpoint timeout, and 401/403 is auth refused. A second function, llm_health_check_with_decisions(section, service), runs the existing llm_health_check(section) first and returns score (...) when that seat is down, otherwise probes the decisions route and returns decisions (...) when it is down — so the row names which of the two endpoints is unreachable.

The row therefore stays down when either the local score seat or the decisions route is unreachable; the other discovery CLIs are unchanged.
