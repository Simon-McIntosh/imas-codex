Chunk source resolves through the owning HAS_CHUNK edge

A new slot annotation, inverse_of, names the multivalued slot on a target class that owns an edge. GraphSchema.relationships in imas_codex/graph/schema.py derives no Relationship for such a slot and fails closed at schema load when the named owner is absent on the target class or does not range back to the annotating class. It is applied to CodeChunk.code_example_id, WikiChunk.wiki_page_id and WikiChunk.document_id in imas_codex/schemas/facility.yaml; their owning has_chunks slots still derive HAS_CHUNK. The generated context (imas_codex/graph/schema_context_data.py) now carries none of CODE_EXAMPLE_ID, WIKI_PAGE_ID or DOCUMENT_ID after build-models --force.

render_chunk_source(alias, output) in imas_codex/graph/query_builder.py renders the one resolution — the OPTIONAL MATCH (ce:CodeExample)-[:HAS_CHUNK]->(chunk) over the writer's edge plus the coalesce(ce.source_file, chunk.source_file). find_code in imas_codex/graph/domain_queries.py and the shipped code example in imas_codex/graph/schema_context.py embed it, retiring the dead reversed CODE_EXAMPLE_ID join and the undeclared CodeFile-[:HAS_CHUNK] join. Both rendered queries EXPLAIN cleanly on the live graph.
