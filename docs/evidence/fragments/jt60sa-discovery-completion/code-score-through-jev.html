Every code score number is a Jev judgement, and the LLM scorer is retired

The code score stage no longer asks a local model for numbers. The model that once produced eleven relevance dimensions is gone: CodeFile loses its nine score fields and file_category, and a file's relevance now comes from the same decisions model the triage stage calls. Both arms write score_composite — the largest of the four scope nouls the names arm already judged — so the stored relevance and the ingest gate can never drift; CODE_RELEVANCE_EXPR and its Cypher max() retire, and its nine readers compare against score_composite directly. The content arm additionally asks a graded relevance_grade (0–4) and four facet Scores — data access, signal processing, machine description and IMAS mapping — from the file's preview and its pattern evidence, and stores each facet divided by its own top level, every judgement's distribution and confidence beside its value, and the eight-role distribution in the enum's fixed order. imas_codex/discovery/base/scoring.py is untouched and the code package stops importing CODE_SCORE_DIMENSIONS; SCORE_DIMENSION_NAMES becomes the four facets.

Every answer shape the decisions seam admits is now validated. _validate_decisions_answers refuses a score outside [0, top level], a distribution whose probabilities do not sum to one over the levels the question offered, and a confidence outside [0, 1]; the choice and score distribution tolerances are both 0.005 per nonzero probability plus 1e-9. The guard fires before any retry: a malformed score answer is a contract violation, not a transport fault. The score-stage prompt code/scorer.md is reduced to a description-only response — the local model writes a one-sentence summary and nothing else — and score_worker calls it only for a file whose content relevance reaches code-ingest-threshold, after the content decision has been made. Routine progress (idle polls, claimed files, batch summaries, start and stop) logs at INFO or DEBUG rather than WARNING, and per-file decision failures are reported once per batch as a count with the first reason, so a healthy run is no longer painted red.
