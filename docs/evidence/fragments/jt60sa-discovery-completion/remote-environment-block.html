Facility remote_environment block

One facility-level remote_environment block now declares the interpreter and shell setup a host's remote scripts need, resolved in a single place and handed to the executor as parameters. The executor stays facility-agnostic: it receives python_command and setup_commands and performs no facility lookup of its own.

What landed

  • Schema. RemoteEnvironmentConfig and RemoteEnvironmentModule classes in imas_codex/schemas/facility_config.yaml, with a remote_environment slot on FacilityConfig. The loose data_access_patterns.setup_commands slot is removed.
  • Resolver. resolve_remote_environment() in imas_codex/remote/environment.py is the one function. The facility block supplies the default; a data system's own python_command / setup_commands override it for that system's scripts; an explicit caller argument wins over both.
  • Pass-down. The facility-aware imas_codex/remote/tools.py wrapper and the signal-discovery scanner config builder (imas_codex/discovery/signals/parallel.py) resolve the block and hand the result to the executor. The executor and the SSH worker pool document that their environment arrives as parameters.
  • Adoption. jt-60sa.yaml, iter.yaml and tcv.yaml each carry the block; data_access_patterns.setup_commands is absent from facility_config.yaml and tcv.yaml.

The block also carries min_python_version and required_modules (name and optional path), so a tool probe can read the environment floor the host expects.
