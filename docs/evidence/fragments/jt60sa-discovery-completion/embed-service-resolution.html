One owner for SLURM service-node discovery

resolve_service_url in imas_codex/remote/locations.py is now the single owner of SLURM service-node discovery. It decides by discovery rather than by whether the caller's hostname counts as local: squeue answers only from inside the cluster, which is exactly the reachability test, so a compute node is served the service node's address directly instead of falling through to a loopback URL behind a tunnel it cannot open. The three other discovery copies — the settings helpers, the readiness loopback rewrite, and the graph client's branch — are routed through it or removed.

What landed

  • Owner decides by discovery. _resolve_service_url_uncached no longer gates its SLURM branch on if local and info.scheduler == "slurm"; the branch runs for any SLURM location and collapses to the loopback only when the caller is the discovered node. Discovery lives in the shared _discover_slurm_compute_node (squeue, then the recorded host), and _service_url_for_slurm returns None to mean "undiscoverable here — fall through to the remote branch", so the graph client can keep its tunnel.
  • Graph client delegates. profiles.py's _resolve_uri_uncached calls _service_url_for_slurm for the SLURM branch and keeps its remote auto-tunnel branch (IMAS_CODEX_TUNNEL_BOLT_<HOST>, ensure_tunnel, tunnel-port URL) untouched; its docstring is now true.
  • Settings helpers routed. get_embed_host reads the host from the resolved URL, so it carries no discovery of its own; _embed_host_from_facility is retired.
  • Readiness rewrite removed. _resolve_url_for_compute and its call site are deleted — the URL now arrives resolved, so no post-hoc loopback rewrite remains.
