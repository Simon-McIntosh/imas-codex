Remote interpreter floor in the tool probe

The existing facility probe now reports the facility's declared remote interpreter and the importability of each required module, and discover signals / discover code refuse before a remote scan when the declared floor is unmet. No new CLI command: the environment is a section of imas-codex tools status.

What landed

  • Interpreter floor. get_python_status (imas_codex/remote/python.py) runs the remote_environment block's interpreter under its setup commands through run_python_script, records it as active_python, and judges it with PythonVersion.meets_minimum against the block's min_python_version. No second comparison is introduced.
  • Module importability. check_all_tools gains an environment entry carrying per-module importable verdicts (with import error text) and the block's fix setup commands, produced by one stdlib-only remote script imas_codex/remote/scripts/probe_environment.py (Python 3.5-safe; the failing case is the old interpreter it reports). probe_remote_environment() in imas_codex/remote/tools.py is the one prober.
  • CLI override and exit. tools status renders the environment section and exits non-zero when the floor is unmet (or a required module unimportable), with --python-command / --no-setup to show the unconfigured path without editing committed config. Tool failures keep their existing exit behaviour.
  • Scan gate. ensure_remote_environment in imas_codex/cli/discover/common.py raises click.ClickException naming the floor and the fix; called by discover signals and discover code before their pipelines when the facility has an ssh_host and a block. Paths and wiki are untouched (follow-on).
