JT-60SA source conventions for mapping

Read-only study on 2026-10-08. The proposed conventions block holds eight source entries and seven explicit unknowns. A single facility COCOS would be wrong: three hashed G-EQDSK examples declare indices 2, 7 and 17. The local SELENE writer fits 2; FAME and generic EQDB records have no demonstrated universal index. Raw EDDB signals have signs and sensor geometry, not an equilibrium COCOS.

Machine orientation and reference frame

The JT-60SA Research Plan, Appendix G specifies clockwise plasma current and clockwise toroidal field from above for reference operation, with both reversible. This is high confidence for the standard operating direction, not a promise about every discharge. EDAS's edas_cdcalc_api.py:156 describes its beam geometry PHI from the horizontal X axis as anti-clockwise. We propose that counterclockwise φ as the mapping reference (medium confidence, because this one API does not define every writer's native φ). In that reference frame, standard Ip and Bt are negative. R points outward and Z upward.

The COCOS definition, Table I and equations 12–13 distinguishes φ direction, the sign of the poloidal field equation, ψ/2π versus full ψ, and q orientation. Indices 2 and 7 use ψ/2π; 17 uses full ψ. A positive Ip or Bt in a file is defined relative to that file's φ, so it cannot by itself identify the machine direction.

Each FLEDD row came from a successful eqdata_get_ (IRET=0), followed by successful eqdbl_get_ calls for BTV, TTCU, SAXIS, SIV and QQV (five IRET=0 returns per record). The FAME time list and ψ grid had already been positively read in the FLEDD receipt. /analysis/src/safledd/eqitem_get.f:188–208 defines the five field meanings. G-EQDSK numbers are the first 20 numeric header fields and q array of the three hash-pinned examples. The CHEASE header says COCOS=17; the other two file names declare 02 and 07. All five reads returned data rather than an empty instrument response. FAME 45218 is a legacy numbered shot, so its signs describe that record's storage rather than a JT-60SA E-shot.

SELENE's SAselene_v2.0_forPSRC/mgfild.f:4–41 computes internal BR=(1/R)∂ψ/∂Z and BZ=−(1/R)∂ψ/∂R, then negates them into the measured-field projections; efitout.f:19–30 says its ψ is Wb/rad, and eqdbput.f:219–231 writes ψ, BTV, TTCU and q without a sign conversion. The projected field signs, clockwise φ, increasing ψ, positive q and ψ/2π fit COCOS 2 (medium confidence for EQ31 because its binary record has no COCOS tag). The SA G-EQDSK writer explicitly carries the same signs and COCOS02 label (high). DBSEL invokes getseldata and SAselene.ex 0 1 -2 mgt; eqdbput.f:23–29 routes −2 to the local EQ31 writer, so its output inherits the SELENE convention (medium). FAME's successful BTV/TTCU/SIV/QQV signs support the same candidate but do not establish its φ or BR/BZ equation; keep its COCOS null. Generic FLEDD EQDB also stays null because the interface returns no COCOS tag and other database IDs may have other writers.

The LIUQE/MEQ and CHEASE examples have positive current and Bcentr in COCOS 7 and 17 files, whose φ is counterclockwise under Table I. The machine reference is clockwise. The same E101011 shot even has a positive-current COCOS02 SA file. These file-native signs must not be copied into a physical-direction assertion without resolving the writers' sign transformation. Their COCOS labels and ψ trends are established; that transformation is not.

EDDB measurements and sensor normals

eddb_pwrapper.eddbreadTime opened EDDB and returned IRC=0 and 41 samples per channel for E101163, 5.000–5.010 s: PSRC/Ip +994088.375 A, calIp +986436.375 A and comIp +1000000 A at the first sample. Positive stored Ip is thus observed for a standard-direction shot; preserve it as clockwise-positive in the raw source. The same call returned magFluxLp1 −0.624938 Wb, magFluxLp7 +1.085777 Wb and magPbTC1 +0.108064 T. Opposite loop signs make a common normal an unsafe inference. getseldata_v4.2/eddbaccess.h:49–54 names the raw PID channels. Its outeddb.c:170–176 derives BTV from PID 1625 O293 with the positive scale 2.25×2.96/25.7; the PID's actual sign was not read, so raw EDDB Bt polarity remains open.

The sensor-order receipt joins 27 loop channels to R,Z positions and 17 pickup channels to R,Z,angle rows in getseldata_v4.2/UTL/getseldata/geo.in:484–529. inpgeo.c:108–124 reads the third probe column into omeg; outeddb.c:254–288 passes it as DMPT0; mgprc.f:13–24 converts degrees to radians; and mgfild.f:19–41 forms the model's signed radial/vertical projection with cos and sin. This establishes the modeled probe axis in the R–Z plane. It does not establish the cable winding polarity of the measured channel. The loop input has R,Z only: its positive surface normal is not recorded there. The getseldata namelist also omits the normal-probe angles and channels, so they cannot be inferred from its tangential probe list.

There is a live 2π discrepancy in the two getseldata source paths: geteddb.c:598 divides each raw flux-loop sample by 2π as Wb → Wb/rad; the outeddb.c:91–92 path passes that array unchanged while labelling it Wb/2π. The direct PSRC loop reads above report Wb. Determine which conversion DBSEL actually runs before mapping loop measurements into SELENE ψ.
