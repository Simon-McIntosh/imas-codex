Signal, wiki-chunk and code-example vector searches pre-filter by facility

The three remaining imas_codex/llm/search_tools.py vector searches now select candidates inside their index rather than discarding them afterwards. A vector_index_filters: facility_id annotation on the FacilitySignal.embedding, WikiChunk.embedding and CodeExample.embedding slots (imas_codex/schemas/facility.yaml) registers facility_id on the facility_signal_desc_embedding, wiki_chunk_embedding and code_example_desc_embedding indexes. Each search passes its facility predicate as prefilter_clauses to build_vector_search, which renders it as a WHERE inside SEARCH, so the ANN cut is taken over the facility's own rows. _vector_search_code_examples now catches only (ClientError, DatabaseError), so a programming error surfaces instead of reading as an empty result. Commits: 3072c2f07.

The over-fetch the in-index filter made unnecessary is retired. _vector_search_signals and _vector_search_wiki_chunks passed k = max(k * 2, 50) as the ANN limit behind a post-filter facility predicate; both now pass the requested k. The diagnostic and physics_domain signal predicates, and the wiki site/domain/score predicates, stay as post-filters over the returned rows, since their properties are not on the index.

The three live indexes were rebuilt through the owner's option-mismatch path (GraphClient.ensure_vector_indexes, which drops an index whose live dimension or property set differs from the schema). SHOW INDEXES after the rebuild:

Against the rebuilt indexes at the default k = 10: _search_signals(query="divertor IR camera", facility="jt-60sa") returns 10 jt-60sa signals (jt-60sa:general/cam_divirmp15r0, …r2, …r4, …), and _search_docs(query="JT-60SA data analysis server software", facility="jt-60sa") returns 10 jt-60sa handbook chunks from three JT-60SA Data Analysis Server pages. Both are the facility's own rows; before the filter moved inside the index a small facility's rows could not survive the global top-k cut.

find_code in imas_codex/graph/domain_queries.py filtered facility through a CodeFile join on the CodeExample's source_file after the ANN cut — a predicate the code_chunk_embedding index cannot evaluate inside SEARCH. It now pre-filters on cc.facility_id (registered on that index by the CodeChunk.embedding annotation) via prefilter_clauses. The join existed only to carry the filter, so it is removed; the CodeExample OPTIONAL MATCH remains and the RETURN coalesces its source_file with the CodeChunk's denormalized copy. That copy is load-bearing for jt-60sa: none of its 201 CodeChunks carries a CODE_EXAMPLE_ID link, so the old join matched nothing and facility-scoped code search returned no rows; it now returns the facility's own chunks with usable file paths.
