Follow-ons from the scan

  • DATA_ACCESS edges are dropped on a first scan. In seed_worker the signals are ingested before the DataAccess node is created, so the ingest's Phase-2 MATCH (da:DataAccess {id: sig.data_access}) finds nothing and the MERGE edge is dropped; a second scan (node now present) creates all 6240. The cause is the ordering in imas_codex/discovery/signals/parallel.py, outside this node's write scope; the fix is to create the DataAccess node before ingesting the signals. Every facility's first scan is affected.
  • Fenced-worker SSH. The executor calls bare ssh; the fenced worker's nobody-owned system include makes ssh abort its config parse. Reported as a sandbox/fence issue, not an executor fix here.
  • Unit normalisation. Units are free text (KA, deg. C, T.m, V.S) and will need a normalisation table before any DD binding.
