DataAccess written before signal ingest

A facility's first signal scan now writes its DATA_ACCESS edges. In seed_worker (imas_codex/discovery/signals/parallel.py) the scanner's DataAccess node is now MERGEd before the scanned signals are ingested, so the ingest's edge phase — MATCH (da:DataAccess {id: sig.data_access}) MERGE (s)-[:DATA_ACCESS]->(da) — finds the node on the first pass instead of silently matching nothing.

Previously the signals were ingested first and the DataAccess written afterwards, so the edge phase ran against an absent node and dropped every edge; a second scan (node then present) created them all. This reproduces the first live EDAS scan of run r-20261005T061226180725, where 6,240 FacilitySignals landed with zero edges and a re-run produced all 6,240. The cause is the ordering, and it held for every scanner returning a ScanResult.data_access (TDI, PPF, JPF, EDAS) through seed_worker. The fix is the ordering alone — no re-link repair pass. The MDSplus branch seeds via seed_versions and creates its mdsplus:tree_tdi DataAccess in a separate block; it was not touched.
