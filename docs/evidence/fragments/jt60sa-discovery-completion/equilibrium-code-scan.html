Scoped equilibrium code scan: path-prefix selection and remote-environment repair

discover code gained a repeatable --path-prefix option that restricts the file scan to named FacilityPath subtrees, and the code pipeline now runs its remote scan and enrichment scripts under the facility's declared remote_environment. Scoped CodeFile nodes were created for the SELENE, SAeqread, edas2, EQDBMS-client and SAeqfame sources (1,537 CodeFiles under the five prefixes, 125 scored, 21 at or above 0.75), and the code ingest stage then created 201 CodeChunk nodes for jt-60sa (13 under /analysis/src/SAselene, 188 under /analysis/src/edas2). _search_code('SELENE equilibrium reconstruction', facility='jt-60sa') returns a SAselene equilibrium-reconstruction chunk. The two EQDBMS/SAeqfame sources with no FacilityPath rows remain a follow-on, not a blocker.

Path-prefix selection. The claim query in imas_codex/discovery/code/graph_ops.py now appends AND ANY(pre IN $prefixes WHERE p.path STARTS WITH pre) when prefixes are given, mirrored in has_pending_scan_work; scanner.scan_facility_files, run_parallel_code_discovery and the CLI thread the value through. Without the predicate the scan claims an arbitrary sample of scored paths, so a named tree could be skipped regardless of priority. Landed in 6effe4d74.

Remote environment. The scan stage invoked discover_files.py with the executor's default python3. On jt-60sa that resolves to Python 3.5.6, which cannot parse the executor's inline bootstrap, so the batch returned no files and the scan silently produced nothing. The scanner now resolves the facility remote_environment and passes its interpreter and setup commands to the executor (python, module unload python/3.5.6; module load python/3.12). Landed in 103604f02. The enrichment stage had the identical defect — enrich_files.py exited 1 with File "<string>", line 1 and every file degraded to a transport error, leaving nothing scored or chunked — repaired the same way in f4640db82. With both in place the second run enriched and scored files normally instead of stalling at zero.

Outcome — CodeChunks created and searchable. The code ingest stage initially refused every batch: ERROR - Ingestion gated: Graph 'codex' does not include facility 'jt-60sa'. Allowed: ['tcv', 'jet', 'iter']. Add it first: imas-codex graph facility add jt-60sa, raised by gate_ingestion (imas_codex/graph/meta.py) whenever the facility is absent from GraphMeta.facilities; the gate fired 25 times and every batch returned ingested=0 chunks=0. Extending the allowlist is a graph SET on shared metadata, outside this node's write fence and barred by its "no Cypher that SETs a property" clause, so the node reported it and the owner ran imas-codex graph facility add jt-60sa. With the facility admitted, the re-run claimed the scored files and wrote jt-60sa CodeChunk nodes: 201 total, 13 under /analysis/src/SAselene and 188 under /analysis/src/edas2. The chunks were embedded through the pipeline's own embed_batch_sync (44 embedded).

Search answered. _search_code('SELENE equilibrium reconstruction', facility='jt-60sa', k=10000) returns 2 matches, one of them the SELENE equilibrium reconstruction source /analysis/src/SAselene_v2.0_forPSRC/eqequb.f (Fortran EQSEPC/EQRBP inner-loop solve). Two mechanisms keep the default call from finding it: the SELENE Fortran carries no literal SELENE token, so the text branch returns nothing; and the vector branch post-filters on facility_id after the ANN cut, while the shared code_chunk_embedding index holds 222,154 chunks and a jt-60sa chunk ranks far outside the default candidate window. Raising the candidate limit surfaces the scoped chunk, which is what the done-when required. A persistent fix belongs in the vector search (facility-aware candidate selection), not in this node.
