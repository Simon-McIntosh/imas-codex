Scoped equilibrium code scan: path-prefix selection and remote-environment repair

discover code gained a repeatable --path-prefix option that restricts the file scan to named FacilityPath subtrees, and the code pipeline now runs its remote scan and enrichment scripts under the facility's declared remote_environment. Scoped CodeFile nodes were created for the SELENE, SAeqread, edas2, EQDBMS-client and SAeqfame sources (1,537 CodeFiles under the five prefixes, 125 scored, 21 at or above 0.75). The CodeChunk half of the deliverable is blocked: ingestion is refused by the graph's facility allowlist, which does not list jt-60sa.

Path-prefix selection. The claim query in imas_codex/discovery/code/graph_ops.py now appends AND ANY(pre IN $prefixes WHERE p.path STARTS WITH pre) when prefixes are given, mirrored in has_pending_scan_work; scanner.scan_facility_files, run_parallel_code_discovery and the CLI thread the value through. Without the predicate the scan claims an arbitrary sample of scored paths, so a named tree could be skipped regardless of priority. Landed in 6effe4d74.

Remote environment. The scan stage invoked discover_files.py with the executor's default python3. On jt-60sa that resolves to Python 3.5.6, which cannot parse the executor's inline bootstrap, so the batch returned no files and the scan silently produced nothing. The scanner now resolves the facility remote_environment and passes its interpreter and setup commands to the executor (python, module unload python/3.5.6; module load python/3.12). Landed in 103604f02. The enrichment stage had the identical defect — enrich_files.py exited 1 with File "<string>", line 1 and every file degraded to a transport error, leaving nothing scored or chunked — repaired the same way in f4640db82. With both in place the second run enriched and scored files normally instead of stalling at zero.

Blocker — ingestion gated by the graph facility allowlist. The code ingest worker claims scored files correctly (for example eqdb_get.f, score 0.78) and then: ERROR - Ingestion gated: Graph 'codex' does not include facility 'jt-60sa'. Allowed: ['tcv', 'jet', 'iter']. Add it first: imas-codex graph facility add jt-60sa. gate_ingestion (imas_codex/graph/meta.py) raises whenever the facility is absent from GraphMeta.facilities; the live value is ['tcv', 'jet', 'iter']. The gate fired 25 times during the scoped run, every ingest batch returned ingested=0 chunks=0, and the scoped CodeChunk count is 0. Because ingestion/search.py::search_code_chunks queries CodeChunk only, the SELENE / EQDBMS search_code done-when cannot be met either. Extending the allowlist is a graph SET on shared graph metadata, outside this node's write fence and barred by its "no Cypher that SETs a property" clause, so the node reports it rather than applying it. Remediation for the owner: imas-codex graph facility add jt-60sa, then a second discover code jt-60sa --path-prefix … run to ingest the 21 already-scored ready files.

Gate: uv run pytest tests/discovery/test_code_pipeline.py exits 0 (89 passed) before and after, base green at 192c3a462.
