Fortran include files (.bf, .inc) now reach the code scanner

The code scanner enumerates remote files by extension: it lists only the extensions that are keys of EXTENSION_TO_LANGUAGE (imas_codex/ingestion/readers/remote.py), read through _get_extensions_list in imas_codex/discovery/code/scanner.py. That map had neither .bf nor .inc, so no Fortran include file at any facility could be listed and none could get a CodeFile row. The change adds .bf and .inc, both mapped to fortran, to that map, and adds the same two to the fortran entry of imas_codex/config/patterns/file_types.yaml, so both extension lists name them. The scanner therefore returns bf and inc in its extension list, and detect_language maps both to fortran.

A JT-60SA include name begins with #, which opens a comment in a shell. Both fetch builders already pass each path through shlex.quote; the new tests pin that. The remote listing in imas_codex/remote/scripts/scan_files.py interpolated the scanned path unquoted into a find command; it now quotes it with shlex.quote. The same unquoted interpolation remains at imas_codex/remote/scripts/discover_files.py:150, which is outside this node's write scope and is recorded as a follow-on.
