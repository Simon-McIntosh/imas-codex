EDAS census-category enrichment and access check

The five EDAS census categories (MAG, MDAC, PSRC, FAME, MMSYS — 741 signals) were enriched and access-checked against reference shot E101173 under a USD 8 cap. Enrichment and the check both scope by category through a new --category claim filter on discover signals, backed by build_category_predicate in imas_codex/discovery/signals/parallel.py. The predicate reads the leading path segment of the signal's data_source_path, not its name, because enrichment rewrites the name.

Outcome: 731 of 741 in-scope signals were enriched — each carries an English description, a physics_domain, and an enriched_at timestamp (07:34–07:53Z). Total recorded llm_cost across them is USD 1.24, under the USD 8 cap. Every one of the 731 also has checked = true, but every CHECKED_WITH edge is success = false with error_type = 'no_data' (EDDB irc=1031). The four named signals — PSRC/magFluxLp1, PSRC/magPbTC1, MMSYS/curCS1LKAT, PSRC/calIp — are checked and described but their CHECKED_WITH edges are not success, so the four-signal pass criterion is unmet.

First cause: the EDAS scanner's check() (imas_codex/discovery/signals/scanners/edas.py) parses each signal's category and data name from check()'s s.name via s.name.split("/"). Enrichment rewrites name to an English label (PSRC/calIp becomes Plasma Current (Ip)), so after enrichment the split never yields two parts, the category sent to the remote script is empty, and every read returns irc=1031. The repair belongs in edas.py — read data_source_path there, as the claim predicate already does — which is outside this node's declared write scope.

Second cause, measured directly against the host with category and data name supplied correctly: at shot E101173 only MMSYS/curCS1LKAT reads successfully (eddbreadTime returns a time series). PSRC/calIp, PSRC/magFluxLp1 and PSRC/magPbTC1 return irc=1015 (no data for the name) over both a short and a wide window and for every data class. Shots E080000–E100000 return irc=1013 (shot does not exist). The four-signal pass criterion therefore cannot be met at the stated reference shot even after the category repair.

Gate: uv run pytest tests/discovery/test_signals_pipeline.py exits 0, 36 passed. Negative control — dropping the category predicate from the three claim sites — fails the three TestCategoryScope claim tests and exits 1, confirming the tests bind the filter.
