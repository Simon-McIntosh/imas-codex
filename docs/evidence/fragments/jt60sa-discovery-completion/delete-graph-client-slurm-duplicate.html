Delete the graph client's SLURM duplicate

The graph client carries no SLURM resolution of its own. In imas_codex/graph/client.py the private helper _slurm_service_uri and the SLURM_JOB_ID branch of _resolve_graph_uri are deleted, and _resolve_graph_uri is reduced to get_graph_uri(). The bolt address a default GraphClient() connects to is now resolved by the profile layer alone (profiles.py Mode 2), which obtains the SLURM service address from the shared owner in remote/locations.py.

Before this change the client held a second discovery path: it called the shared owner itself and preferred its answer over the profile URI whenever SLURM_JOB_ID was set. That copy existed only because tests/graph/test_client_address_resolution.py imported and pinned _slurm_service_uri; the same delegation was also pinned by two cases in tests/remote/test_locations_resolution.py added alongside it. The test module is reworked to assert the client's address through the shared owner via the profile layer instead of importing the deleted symbol. The raise-on-unreadable-location behaviour is kept: an unreadable location raises out of resolve_neo4j and propagates through _resolve_graph_uri rather than being swallowed into a fallback address.
