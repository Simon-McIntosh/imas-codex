Operational node, no source change. Rows that failed to embed while the fleet node addressed a loopback tunnel were reclaimed and re-embedded through the pipeline's own writer against the server made reachable by §8.

Reclaim path

The pipeline's fetch predicate excludes failed rows — _fetch_unembedded in imas_codex/discovery/base/embed_worker.py requires embed_failed_at IS NULL — and no reset command clears that flag: SIGNAL_RESET_SPECS["discovered"] omits it and would also clear the enrichment (description, physics_domain), destroying the USD 1.32 of enrichment already carried. The module's own remedy is "To retry, clear the property manually", so the reclaim is a scoped REMOVE n.embed_failed_at — it writes no embedding. Embeddings themselves were written only by the pipeline's embed_batch_sync → _persist_embeddings. 

MATCH (n:FacilitySignal {facility_id:'jt-60sa'}) WHERE n.embed_failed_at IS NOT NULL REMOVE n.embed_failed_at
MATCH (n:CodeChunk     {facility_id:'jt-60sa'}) WHERE n.embed_failed_at IS NOT NULL REMOVE n.embed_failed_at
