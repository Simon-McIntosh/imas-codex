The MCP search tools follow the handbook DOCUMENTS edges in both directions

fetch_content of a fronts_database page now lists the catalogue the page fronts — signals grouped by data class with counts and a bounded sample (name, unit, pid) and the read call — instead of the empty stub alone. search_signals cites the page that fronts a signal it returns (Documented in: "Category Information" (jt-60sa:CategoryInformation)). search_docs names the signal family a query reaches beside the prose that documents it, so search_docs("flux loop", "jt-60sa") returns the PSRC flux-loop signals next to the EDDB manual chunks. A stub chunk's DOCUMENTS collection is capped in the enrichment query (bounded sample plus the true count) so a page fronting a whole catalogue cannot swamp a report.

The signal-side text search's fulltext branch never ran: it bound its query text to a Cypher parameter named query, which collides with Session.run()'s own query argument, so every fulltext call raised and fell back to a CONTAINS scan. The parameter is now search_query in the signal, wiki-chunk and code-chunk text searches.
