Code files are judged for diagnostic relevance by a decisions model, in two arms

The code discovery triage stage no longer scores eleven dimensions from a structured completion. imas_codex/llm/prompts/code/triage.md is rewritten in place as the decisions template whose six questions — reads measured data, processes measured signals, describes the machine or its diagnostics, maps to IMAS, is a simulation, and role — carry the wording validated for code relevance. triage_worker renders that template into a questions mapping through build_triage_questions(), builds each discovered file's decision state (build_triage_state, carrying the facility's data_access_patterns — primary method, key tools, import patterns, tree organisation, signal naming — plus the file's path, language, directory, directory description and sibling names), and calls acall_decisions on the discovery-relevance seat with service=facility-discovery at bounded concurrency 8. A file's relevance is the largest of the four scope probabilities (triage_relevance); it passes when that reaches code-triage-threshold (default 0.40) and is otherwise skipped with a reason naming its role and its two highest role probabilities. A decisions failure leaves the file at its status and unclaimed, so a later pass retries it (fail closed).

The score stage keeps its LLM description call but no longer decides skip. Before a file is marked scored, a content arm asks the same six questions of its preview text — the state adds the first 1500 characters as content_head — and the description scores and the content-arm relevance fields are written to scored in one step (apply_file_scores). A file whose content decision fails is written nowhere: it stays at its prior status, carries no content relevance, and has its claim released, so the next score pass reclaims and retries it rather than stranding it. The ingest claim admits only a file whose relevance came from the content arm (relevance_stage = 'content') and reaches code-ingest-threshold (default 0.50), claiming the highest relevance first; a name-arm relevance can never carry a file into ingestion. The content-stage requirement is applied in every pending-ingest count and has-work predicate — the ingest claim, has_pending_code_work and the pending_ingest and embedding counts in get_code_discovery_stats — so a run never counts or waits on a name-only file as ingestable. Both thresholds live under [tool.imas-codex.discovery] with accessors beside get_triage_threshold in imas_codex/settings.py. CodeFile loses its eleven triage_* fields and gains eight relevance fields (relevance_loads, relevance_processes, relevance_describes, relevance_imas, relevance_simulation, relevance_role, relevance_stage, relevance_model); the reset spec, claim predicates, has-work predicates, progress display and CLI model section are migrated to the new fields. build-models --force regenerates the derived models with exit 0, so the schema edit is valid.
