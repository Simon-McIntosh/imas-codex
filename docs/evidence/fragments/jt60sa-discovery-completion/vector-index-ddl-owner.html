Vector index DDL has one owner

GraphClient.ensure_vector_indexes (imas_codex/graph/client.py) is now the only Python source that composes a CREATE VECTOR INDEX statement. The five statements that repeated the owner's option block by hand were each replaced by a call to that owner: build_dd.py (one statement for the two cluster indexes), dd_identifier_enrichment.py (two — identifier_schema_embedding and imas_node_embedding), dd_ids_enrichment.py (one), and discovery/wiki/pipeline.py (one). The option block (dimensions, similarity function, quantization, and the filter properties §12 added) therefore has a single definition, so the copies can no longer drift from it.

No schema change was needed: all five indexes are already schema-derived. Enumerating GraphSchema().vector_indexes returns every one of them — cluster_description_embedding (IMASSemanticCluster description_embedding), identifier_schema_embedding (IdentifierSchema embedding), imas_node_embedding (IMASNode embedding), ids_embedding (IDS embedding) and wiki_chunk_embedding (WikiChunk embedding) — so the owner derives each one and the calls above reconcile the live index shape rather than inventing a parallel one. The only registered filter is code_chunk_embedding: facility_id, contributed by the schema-section work; none of the five carry a filter.

A source-scan test (tests/graph/test_vector_index_ddl_owner.py) pins the property: it walks every .py under the package and requires the only file carrying a CREATE VECTOR INDEX string literal to be graph/client.py, and it asserts each former site calls ensure_vector_indexes. The scan is written over the parsed module, so it matches a statement of any shape — a hand-written copy that omits the IF NOT EXISTS clause, or the options block, is caught just the same. The one exclusion is a docstring, identified by being the first statement of a module, class or function, never by its wording: prose that names the grammar is documentation, a string built for the database is a composition of the DDL. That structural exclusion is what the plan applies to imas_codex/graph/AGENTS.md. The docstrings in graph/schema.py and graph/vector_search.py still name the phrase in prose; they are documentation of the grammar, not a copy of the DDL, and they remain outside this node's write scope. Under the plan's literal form rg 'CREATE VECTOR INDEX' those two prose hits remain, so the binding measure is the parsed-statement scan the test performs.

Against the live graph, SHOW INDEXES lists all five indexes ONLINE as VECTOR with vector.dimensions = 256 unchanged: cluster_description_embedding, identifier_schema_embedding, imas_node_embedding, ids_embedding and wiki_chunk_embedding.
