The wiki-chunk fulltext search binds its parameter correctly

_text_search_wiki_chunks in imas_codex/llm/search_tools.py bound its query text to a Cypher parameter named query, colliding with GraphClient.query(query, **params); the raised TypeError was swallowed by a bare except Exception, so every documentation prose search ran on the CONTAINS fallback at score 0.5. The fulltext parameter is now $search_query, the swallow is narrowed to (ClientError, DatabaseError) as in the signal and code-chunk branches, and a regression test drives the branch through a stub with the real signature.

Measure

  • Reproduction (base). Driving the branch through a stub whose query(self, query, **params) mirrors Session.run recorded only the CONTAINS fallback call and returned [], while the fulltext stub would have returned its hit.
  • Negative control. Rebinding the wiki-chunk fulltext query back to $query fails two of the new tests (EXIT=1); the head arm passes them.
  • Gate. pytest -p no:cacheprovider tests/search tests/llm → 634 passed, 10 skipped, EXIT=0.
  • Live proof. _search_docs("flux loop", "jt-60sa") returns the wiki documentation via BM25 (Wiki Documentation (10 chunks from 3 pages), scores 5.65–6.05) instead of the base arm's single fallback page, beside the PSRC flux-loop signals jt-60sa:general/psrc_dispfl and jt-60sa:general/psrc_maxabnormp.
