The decisions endpoint gets a call layer that validates every answer before returning it

imas_codex/discovery/base/llm.py gains call_decisions(model, state, questions, *, service) and acall_decisions with the same signature. Both take the model as a parameter, as call_llm_structured does, and post {model, state, questions} to https://openrouter.ai/api/alpha/decisions — an endpoint whose request and response shapes differ from chat completions, so it cannot route through call_llm_structured. The API key comes from get_api_key_for_service(service) and the dashboard headers from a new _service_headers(service) helper extracted out of _build_kwargs, which now calls the same helper, so the chat and decisions paths share one definition. A retryable response — 429 or any 5xx, reaching the retry test through _is_retryable and DEFAULT_RETRY_BASE_DELAY — is retried with the existing backoff. Every answer is validated against its question type before it is returned: a noul must lie in [0, 1]; a choice must name one of the offered criteria, carry a probability for each offered criterion and no other, sum those probabilities to 1 within 0.01, and hold any confidence in [0, 1]. A violation raises DecisionsValidationError without a retry, so a malformed judgement fails fast rather than repeating; a response that carries no usable usage.cost is refused the same way rather than read as zero. The call returns the answers together with that cost.

A new [tool.imas-codex.discovery-relevance] seat is registered in pyproject.toml with model = "typesafe/jev-1.13", and "discovery-relevance" joins MODEL_SECTIONS and _MODEL_DEFAULTS in imas_codex/settings.py so get_model('discovery-relevance') resolves it. The seat is deliberately not added to _MODEL_ENV_VARS: the decisions model is called directly, not through the litellm proxy that prefixes openrouter/, and the test_openrouter_prefix_present guard parametrizes over exactly that mapping.
