A retry path for embed-failed rows

The shared embed worker now admits a row whose embed_failed_at is older than a retry cutoff, so a transient failure is fetched again on a later pass while a fresh failure is left alone. The pending predicate is one rendered fragment, pending_embed_predicate(alias) in imas_codex/discovery/base/embed_worker.py, embedded by _fetch_unembedded, _count_unembedded and the code phase's three-aggregate progress query in imas_codex/discovery/code/parallel.py; the cutoff is bound as embed_retry_cutoff (embed_retry_cutoff_time(), DEFAULT_EMBED_RETRY_HOURS = 24). SIGNAL_RESET_SPECS["discovered"].clear_fields in reset.py now also clears embed_failed_at, and no new --reset-to value appears. The manual-clear instruction in the _mark_embed_failed docstring is retired. Evidence: a new tests/discovery/test_embed_worker.py fetches a stale-failed row and excludes a fresh one; the gate pytest tests/discovery/test_embed_worker.py tests/discovery/test_reset.py tests/discovery/test_code_pipeline.py tests/discovery/test_signals_pipeline.py exits 0 (154 passed). Negative control — dropping the cutoff from the rendered fragment — fails the stale-row test, exit 1.
