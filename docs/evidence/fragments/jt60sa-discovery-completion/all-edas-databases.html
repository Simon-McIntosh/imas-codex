The configured scanner reads EDDB, UDDB, PMDB, LCDB, MBDB and EQDB. It found 6,298 EDDB signals in 73 categories, 188 UDDB raw channels and 8,469 distinct LCDB fields. The graph holds those same counts; only the new UDDB and LCDB rows were written, preserving the existing EDDB rows and ids. Signal enrichment spend was USD 0.00.

Before the change, a scanner test requesting EDDB and UDDB failed with KeyError: 'databases'. A separate failure probe found that eddbOpen() returning false produced an empty success record; the scanner now receives an error for that case. The focused test file passed 18 tests. A mutation returning zero UDDB rows produced one failing test, TestConfiguredDatabases::test_uddb_table_rows_are_emitted (exit 1).

The LCDB wrapper found shots in seven of 217 owner roots under /analysis_DB/EDASDB: 23 shots in all. Its library category list returned 298 category observations, each retaining the revision suffix required by lcdb_dname; those wrapper calls returned 8,469 distinct owner/category/field identities with zero failed catalogue calls. A graph check found jt-60sa:general/lcdb_a042181_ate.s001_device with source path a042181/ate.s001/DEVICE. The live checker accepted that field and refused a missing field in the same category.

The UDDB table method accepts pid and active, but no shot. It returned 188 rows with active=0 and the same 188 with active=1, both at irc 0; an individual lookup for 2111UA001 returned one row. Thus 188 is the registered global raw-channel catalogue visible through this wrapper, rather than a count for E101173 alone. Before the check repair, that registered PID failed a reference-shot header read with irc 1301. The live check now accepts its catalogue membership and refuses NO_SUCH_PID with irc 1022, so absence of data in one shot does not erase a registered channel.

The PMDB wrapper and its shared library expose only keyed plantdread and planthread reads. Both wildcard probes returned 301 and zero rows. No wrapper method lists categories or data names, so this result does not establish that PMDB is empty; an authoritative inventory is still needed.

The MBDB owner tree contains two candidate case files, both under d240034: case 12345 data.t001 and case 23345 dav.t001. mbdbSetDirectory('mbdb') succeeded, but mbdbROpen returned 1012 for each case, so mbdbDatanmCount/List could not run. The MBDB wrapper route is implemented for a readable case, but this root supplied none to land.
