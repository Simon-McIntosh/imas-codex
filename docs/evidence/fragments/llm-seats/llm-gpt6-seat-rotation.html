GPT seat rotation: every live seat on its ruled GPT-6 model

The seat bench (llm-gpt6-seat-bench.html) was ruled on 2026-10-18: GPT seats use the latest GPT models; gpt-6-luna takes the seats the bench shows it capable for, gpt-6.1-sol the seats it does not, and seats with no bench move generation for generation. GPT-6 pricing and family handling were already on main; this change is seat configuration only, in pyproject.toml.

  • [sn-benchmark] measurement panels: compose-models, candidate-models, reviewer-model and reviewer-models are the measurement slate, not production seats.
  • Switch-back comments: the [sn-compose] switch-back comment naming gpt-5.5, and the commented [sn-fanout] proposer alternative naming gpt-5.5. Neither is a live seat.

No live seat names a gpt-5.x model.

Test evidence

tests/core/test_gpt6_seat_rotation.py resolves all eight rotated seats through the project's own accessors — settings.get_model for the five scalar seats, and get_sn_review_docs_models, get_sn_review_profile_models("default") and get_model_source_models("sn-review:names") for the three chain seats — and asserts each resolves to its new model. Run against the base pyproject.toml it fails 8 of 8 at EXIT=1; against the rotated tree it passes 8 of 8 at EXIT=0.

The model-settings suites (tests/core/test_settings.py, test_gpt6_model_support.py, test_model_seat_names.py, tests/discovery/test_llm_*) run 240 passed at base and 239 passed with 1 failed at head. The one added failure is test_settings.py::TestDiscoveryFunctionSeats::test_cluster_labels_keeps_openrouter_seat, which pins cluster-labels to the pre-rotation gpt-5.4 and now fails because that seat moved to gpt-6.1-sol. test_settings.py is outside this node's write scope, so per the node's evidence fence the stale pin is left for a follow-up node rather than edited here; the fix is to update the expected id to openrouter/openai/gpt-6.1-sol, keeping the assertion's intent that the seat stays on OpenRouter.
