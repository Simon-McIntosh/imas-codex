GPT seat rotation: every live seat on its ruled GPT-6 model

The seat bench (llm-gpt6-seat-bench.html) was ruled on 2026-10-18: GPT seats use the latest GPT models; gpt-6-luna takes the seats the bench shows it capable for, gpt-6.1-sol the seats it does not, and seats with no bench move generation for generation. GPT-6 pricing and family handling were already on main; this change is seat configuration only, in pyproject.toml.

Fallbacks rotated with the seats

_MODEL_DEFAULTS in imas_codex/settings.py is what a seat resolves to when its pyproject.toml entry is absent. Every seat currently sets its key, so a stale default is invisible — and then silently returns the pipeline to a superseded model the moment a key is removed or a section is not present. The lead ruled on 2026-10-18 that fallbacks name the latest models too, so each gpt-5.x default was rotated generation for generation by the same rule as the seats: a luna-generation default takes gpt-6-luna, a full model takes gpt-6.1-sol.

Assertion the rotation broke, repaired

tests/core/test_settings.py::TestDiscoveryFunctionSeats::test_cluster_labels_keeps_openrouter_seat pinned cluster-labels to the pre-rotation gpt-5.4, so the seat move turned it red. The expected id is updated to openrouter/openai/gpt-6.1-sol, keeping the assertion's intent that the seat stays on an OpenRouter model whose endpoint is unresolved rather than moving to the local lane — a local seat would miss the whole label cache on the next DD build.

Seats and settings left alone

  • Non-production reviewer profiles: quality-cost-balanced (pins gpt-5.4), opus-only, local-only. These are opt-in alternatives, not the active production profile.
  • [sn-benchmark] measurement panels: compose-models, candidate-models, reviewer-model and reviewer-models are the measurement slate, not production seats.
  • Switch-back comments: the [sn-compose] switch-back comment naming gpt-5.5, and the commented [sn-fanout] proposer alternative naming gpt-5.5. Neither is a live seat.

No live seat names a gpt-5.x model.

The same grep over imas_codex/settings.py returns 8 hits, all of them inside _SN_BENCHMARK_DEFAULTS (lines 1956–1961, 1975, 1983) — the measurement panels, the same exclusion the [sn-benchmark] list gets. No _MODEL_DEFAULTS entry names a gpt-5 model.

Test evidence

tests/core/test_gpt6_seat_rotation.py resolves all eight rotated seats through the project's own accessors — settings.get_model for the five scalar seats, and get_sn_review_docs_models, get_sn_review_profile_models("default") and get_model_source_models("sn-review:names") for the three chain seats — and asserts each resolves to its new model. A ninth assertion walks _MODEL_DEFAULTS and requires no entry to name a gpt-5 model, holding the fallback path to the same rotation. Run against the base sources it fails 9 of 9 at EXIT=1; against the rotated tree it passes 9 of 9 at EXIT=0.

The model-settings gate (tests/core/test_settings.py, test_gpt6_model_support.py, test_model_seat_names.py, tests/discovery/test_llm_*.py) now runs 218 passed, 0 failed at both arms (EXIT=0 each). Against the base sources it is 218 passed; the merged tree adds no failure, the added test_cluster_labels_keeps_openrouter_seat failure having been repaired in this change.
