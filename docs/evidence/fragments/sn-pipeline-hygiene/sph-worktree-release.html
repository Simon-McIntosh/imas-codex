§5 — A release can run from a detached worktree

Both on-main pre-flight guards read git branch --show-current, which prints nothing on a detached head, so every release cut from a worker's worktree was refused before any other check ran. Measured on the pre-change tree: a detached worktree whose head is the tip of main was refused by both guards with "current: " in the message.

Each guard now admits a detached head only when git merge-base --is-ancestor HEAD main succeeds, the same ancestry test the release-branch preparation already uses. A named branch other than main is still refused, and a detached head carrying a commit main has never seen is refused before the version is computed, so the tag cannot land on an unreviewed revision. The clean-tree and synced checks are unchanged.

A release cut run from a real detached worktree against a local bare stand-in remote rehearses the tag it would cut (v1.0.0rc1) and then creates it: the tag exists in the worktree and on the stand-in remote. The same cut from an unmerged detached head is refused with one error and no tag. Evidence: docs/evidence/fragments/sn-pipeline-hygiene/sph-worktree-release.json, produced by sph-worktree-release-run.py.

The cut delivers its own commit. A non-dry-run candidate cut that publishes a change commits on the checked-out HEAD, and the push then sent the literal main ref — which on a detached worktree is the shared local branch, so the release commit never reached the remote and the tag named a commit the remote's main lacked. The push now sends HEAD to the remote's main, the same ref the main checkout pushes. A test publishes a real commit from the cut and checks the stand-in remote's main and the tag both resolve to it.

Gate: 78 tests pass across tests/standard_names/test_catalog_release.py and tests/standard_names/test_cli_release.py, including seven new tests, run on an all_debug node. Three arms were run red, each reverting one part of the change alone: the catalog guard to its branch-name check (3 tests fail), the CLI guard likewise (2 fail), and the push ref back to main (the delivery test fails). Evidence: negative-control.log.
