Three statements of the ISN version agree at 0.11.1, and each comparison refuses a planted mismatch

The pin was compared with itself and with nothing else. It is now compared, in a default-tier test, with the installed distribution's version, and in a graph-tier test with the version of the ISNGrammarVersion node marked active. At the head revision all three read 0.11.1. Planting a mismatch in either comparison turns the corresponding test red and names the two versions, so neither comparison can pass by doing nothing.

The snapshot query returned exactly one row, and it carried a version — the check that the instrument sees something known present before any comparison is reported. The writer of that node is imas_codex.standard_names.grammar_sync, which rotates active across synced versions; the test imports that module so the coupling to its owner is stated rather than assumed.

The installed-side mismatch is planted at the metadata lookup rather than by installing a different package, because the environment is the shared project .venv that every peer session on this workstation uses. The metadata value is the only thing the test reads to learn the installed version, so planting it produces exactly the state a pin bump without a package bump leaves behind, and the test refuses it. The planted value 0.11.2 is a version the distribution does not hold at head, so the passing arm cannot be the planted one.

What changed

  • tests/core/test_isn_pin_agreement.py — the pin extraction moved into pinned_isn_version(), and test_isn_pin_matches_the_installed_package compares it with importlib.metadata.version. The original agreement test is unchanged in what it asserts.
  • tests/graph/test_isn_grammar_snapshot_pin.py — new, graph-marked: compares the active snapshot version with the same pin, importing the extraction from the default-tier file so one extraction serves both tiers.
