Retiring a name in the step that returns its source to the pool — blocked on write scope

Outcome: blocked. The step is identified and both halves of its defect are reproduced on a disposable graph, but the step lives in imas_codex/standard_names/graph_store/graph_audits.py, which is not among this node's declared write paths (the declaration names imas_codex/standard_names/graph_ops.py, the graph store's façade). The step is reconcile_source_status_liveness — the pass run_sn_pools logs as source-status reconcile — N aligned to a live target, M returned to extracted and the one sn sourceless's population follows: its orphan branch treats superseded, exhausted and contested targets as terminal, deletes each bound source's PRODUCED_NAME edge, clears the source's produced_sn_id/composed_at/attempt budget and drops the source id from the name's source_paths cache — while leaving the name itself in the graph, live, with no producer.

The defect reproduces in both directions

Two planted cases on a disposable Neo4j, run at revision 81026a662b6c (log: negative_control_head_reproduction.log, EXIT=1):

plantthe step's result at headrequired by the ruling
StandardName{name_stage:'exhausted'} + StandardNameSource{status:'composed'} via PRODUCED_NAME orphaned_reset=1; source extracted; edge deleted; name still present at exhausted; the enumeration now lists it with no producer (SOURCELESS ['probe_recycled_exhausted']) the exhausted name is retired in the same step, so the step leaves no live name without a source
StandardName{name_stage:'contested'} + a bound composed source source extracted — the source of a name that is not exhausted was taken the source stays bound; only an exhausted name's source is recycled

The step writes no StandardNameChange row, so the recycling is not recorded against the name it empties. That is why the 24 sources the 2026-11-17 maintenance pass returned cannot be attributed back to their names from the graph.

The population the step has already left without a source

imas-codex sn sourceless --json at 2026-11-17 reads 23 live names with no producer, against the 10 recorded in docs/evidence/fragments/sn-catalog-consistency/scc-live-names-without-a-source.json. The 13 names that appeared since (all exhausted, none accepted, none a derived parent) are listed with their stage and origin in recycled-source-names.json. Their former sources are not recoverable from the graph: the step deleted the edge, cleared the source's mirror and erased the source id from the name's source_paths, and a query over StandardNameChange for those 13 names returns no 2026-11-17 event. The JSON records that as the reason rather than naming a source it cannot name.

The change the step needs

In the orphan branch of reconcile_source_status_liveness, partition the terminal targets of each orphan source: when every target is an exhausted non-derived name, retire those names and release the source in the same transaction (recording one change row per retired name); when any target is a live non-exhausted name (contested, or a name still carrying an open hint), leave the source bound and the edge intact. The retirement mechanism is a decision the plan does not settle — deleting the node through provenance_lifecycle.retire_unrecoverable_provenance_orphans, or flipping name_stage='superseded' with a ledger row — and both also live outside the declared write paths.

The 13 backlog names are not retired here. Retiring them is a live-graph write of its own, made under a single-writer window and through the same write path the fix installs; doing it ahead of the fix would retire 13 names with no code able to do it again.
