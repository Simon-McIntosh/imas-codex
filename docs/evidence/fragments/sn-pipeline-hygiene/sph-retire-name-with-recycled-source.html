Retiring a name in the step that returns its source to the pool — blocked on write scope

Outcome: blocked on write scope. The step is identified, both halves of its defect are reproduced on a disposable graph, and a patch that fixes it is implemented and measured in a scratch tree — but the step lives in imas_codex/standard_names/graph_store/graph_audits.py, which is not among this node's declared write paths (the declaration names imas_codex/standard_names/graph_ops.py, the graph store's façade, and graph_ops.py holds no step). The scratch patch and its logs are in the run directory; nothing of the product change is committed.

The step

reconcile_source_status_liveness — the pass run_sn_pools logs as source-status reconcile — N aligned to a live target, M returned to extracted. Its orphan branch treats superseded, exhausted and contested targets as terminal, deletes each bound source's PRODUCED_NAME edge, clears the source's produced_sn_id/composed_at/ attempt budget and drops the source id from the name's source_paths cache — while leaving the name itself in the graph, live, with no producer. No StandardNameChange row is written, which is why the 24 sources the 2026-11-17 maintenance pass returned cannot be attributed back to their names from the graph.

The patch, measured in a scratch tree

Patch graph_audits-retire-recycled-source.patch (in the run directory) changes the orphan branch in three ways: a source whose targets include a contested name is no longer taken at all; the query carries the names it emptied; and, in the same statement — so no interruption between releasing a source and retiring its name can strand the pair — each emptied target that is exhausted, non-derived, carries no catalog approval and has no remaining producer is retired: name_stage and status become 'superseded', its claims are cleared, and a StandardNameChange row with operation retire_recycled_source_name and a deterministic sn-change:recycled-source:<name> id is attached through HAS_INTERNAL_CHANGE. Superseded history still releases its source as before. The patch adds names_retired to the pass's result and log line, which required the two expectations in tests/standard_names/test_pipeline_recovery_mechanics.py to carry the new key (tests-result-key-update.patch).

The population the step has already left without a source

imas-codex sn sourceless --json on 2026-11-17 reads 23 live names with no producer against the 10 recorded in docs/evidence/fragments/sn-catalog-consistency/scc-live-names-without-a-source.json. The 13 that appeared since are all exhausted, none accepted, none a derived parent; each is listed in recycled-source-names.json with its stage, origin, the candidate former source ids the source audit can still recover, and each candidate's present status.

Two facts about that backlog decide how it can be closed:

  • The repo's own source audit classifies all 13 as population dropped_edge, not orphan_awaiting_retirement, because the step erased the provenance the classification reads. A read-only preview of supersede_exhausted_standard_name_orphans over the 13 refuses every one of them (requested 13, admitted 0, refused 13, manifest a0a12e70…): the signed retirement path cannot retire the population this step creates. That is a second reason the retirement has to happen in the step itself.
  • Eleven of the 13 still have candidate former source ids whose nodes are now extracted with attempt_count 0 and no produced mirror; one name carries six candidate paths, four of which still produce other live names and are aliases rather than former producers; two names carry no candidate at all. The retired-source status is recorded per name in the JSON rather than summarised here.

The 13 are not retired here. Retiring them is a live-graph write; the signed path refuses them, the deletion path (provenance_lifecycle.retire_unrecoverable_provenance_orphans) would remove 13 names with no code able to reuse the rule, and the choice between superseding and deleting this cohort is a decision the plan does not settle. With the patch applied the step retires future cases; this cohort needs one signed action by the lead, listed by name in the JSON.
