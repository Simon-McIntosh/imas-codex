Stopping the graph and embed services selects pids, not names

Both stop paths used a command-line pattern as their selector. On a shared login node one uid carries every project's fleet, and a shell whose own argv contains the service name matches the same pattern, so a stop could signal a process it never inspected. Each selection now comes from a fact attributable to this service only:

  • a scheduler job id, read from the process cgroup (/job_<id>/) or from the job the scheduler lists for the service;
  • a pid the service's own launcher recorded (the login embed writes codex-embed.pid at start);
  • a working directory or an open file inside this service's graph store path.

The scan prints every holder with its age and command line before any signal, signals exactly those pids, sends SIGTERM first, and escalates to SIGKILL only for a listed pid still alive after the stated wait. A process that names the service but holds neither the store nor the job is printed as left alone with the reason and is never signalled.

A stop returns success only after the job has left the scheduler and no listed process still holds the store; otherwise it raises, so lock cleanup cannot run while Neo4j is still flushing its shutdown checkpoint.
