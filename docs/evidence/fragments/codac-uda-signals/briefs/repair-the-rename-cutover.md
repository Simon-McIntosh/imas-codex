# Repair the rename and its cutover sequence after the peer check

## Goal

Correct the rename tool's kept list and the cutover sequence for the defects
the session coordinating standard names found when it read them, and answer
one open question about the rehearsal's own evidence.

## Why

The rehearsed rename is on the primary branch in `scripts/rename/`. The peer
session read `cutover.json` and `kept_names.json` on 2026-11-20 and found
three defects. The lead wants the rename correct before others are invited,
so each is repaired and re-proven before a date is proposed.

## What is wrong

1. **Evidence scripts are kept byte-for-byte but are live code.** The kept
   paths hold all of `docs/evidence`. Many Python files there import the
   package by its old name and are loaded by tests and by plan gates. After
   the rename they would fail at import. Python under `docs/evidence` must be
   renamed like any other code; only the `.html`, `.json` and `.md` bytes stay
   kept, the same split already made for `docs/figures`.
2. **The freeze step does not cover queued work.** A queued or
   awaiting-upstream reckon request stores the old project key, a base
   revision before the rename, and write paths under the old package name. One
   admitted after the tracked rename would build a pre-rename tree. The freeze
   step must list every session's queued and awaiting-upstream requests for
   the project, per owner, with the rule that each owner drops them before the
   tracked rename and re-dispatches after reckon serves the new project key.
   A retained worktree may be recorded as parked by its owner under a kept
   ref; it is then not carried across.
3. **The saved gate scripts are evidence.** `~/.cache/imas-codex-live-rewrite`
   is cited by absolute path in landed run records. It keeps its name and its
   bytes. The step records it as regenerated by its owner in a new directory,
   and nothing rewrites or moves it.

Also settle one inconsistency: one step speaks of "the renamed checkout" and
another says the checkout keeps its directory name. State one answer. The
intended answer is that the checkout directory does not move at cutover,
because the worktree root, every worktree's links and the editable install
resolve through it; if the sequence needs it to move, that is its own step
with its own check and undo.

And add a check to the reckon project-key step that plan slugs and run ids
are unchanged across it.

## The open question about the rehearsal

The rehearsal's renamed test arm showed no added failure. If tests load
evidence scripts that import the old package name, some should have failed.
Find out which is true and say it with test identifiers: the tests are
deselected by the default markers, skipped, among the failures already on the
base, or the arm did not run them. If the arm's result does not hold once
evidence scripts are handled correctly, say so; that is a finding.

## Done when

- The kept list holds `docs/evidence` data and prose bytes only; Python there
  is renamed. Applied to a scratch copy of the current primary branch head,
  the tool leaves no old-name import in any Python file outside a kept name,
  with the count before and after; a second application changes nothing.
- On that scratch copy, with an environment built for it alone, the tests
  that load or reference `docs/evidence` are run at the base and after the
  rename on `rigel`; none is added to the failures, with identifiers
  recorded, and the open question above is answered in the evidence.
- The default tier is run at the base and after the rename as before, with no
  failure added, both arms recorded in the manifest as single-line JSON
  objects.
- `cutover.json` carries the three corrections, one statement on the checkout
  directory, and the slug and run-id check; the cutover test compares against
  the inventory and fails if the queued-request rule or the evidence split is
  removed.
- Scratch copies and environment are removed, with removals printed.

Negative control: a Python file under `docs/evidence` left importing the old
name is reported by the closing search; with the queued-request rule deleted
from the sequence, the cutover test fails. Run each as a pytest run in a
scratch copy and cite a log that shows a non-zero exit and a failing test id.

## Rules

- Scratch copies only, made with `git worktree add` under node-local `/tmp`
  inside a compute job, with their own environment there. Never sync or
  repoint the shared environment. Rename, move or edit nothing under the home
  directory, no service, no repository setting, no graph content and no reckon
  state. Do not drop or touch anyone's queued requests: the sequence only
  describes that step.
- Heavy work as its own job:
  `env -u SLURM_JOB_ID -u SLURM_JOBID sbatch --partition=rigel`, logs on GPFS,
  each pytest log ending with pytest's summary and one EXIT line.
- The manifest's `tests` field is one literal command that parses.
- Commit locally with a conventional subject and a body, and give `commits`
  as a JSON list of full shas. Do not push or merge.

Write paths: `scripts/rename`, `tests/scripts`, and
