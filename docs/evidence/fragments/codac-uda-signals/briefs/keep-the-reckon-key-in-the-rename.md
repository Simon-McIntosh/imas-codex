# Keep reckon's project key out of the rename, and finish the cutover sequence

## Goal

Change the rename tool and its cutover sequence so that reckon's project key
and its state directory keep the old name, and close the last points the peer
session raised on the sequence.

## Why

The reckon coordinator reported on 2026-11-20 that reckon has no supported way
to rename a project key: stored reviews, the run ledger, the queue, live
pointers and the state directory `docs/state/<key>/` are all keyed on it, and a
key change would orphan them. The lead decided on 2026-11-21 that the rename
goes ahead with reckon's key and `docs/state/imas-codex` left as they are, and
that the checkout directory on this machine does not move at cutover. The
repositories, the package, the commands, the MCP key, the services and the
state roots carry the new name. Reckon's key moves later, when reckon has a
migration.

## What must change

1. **Reckon's key and state directory are kept.** The path
   `docs/state/imas-codex` and its contents keep their name and bytes. Wherever
   a tracked file names the reckon project key as a key (a `--project`
   argument, a project-qualified plan reference, a figure or page URL that
   starts with the key, the SPA mount name), that occurrence is kept, with the
   reason recorded in the kept-name list. Occurrences of the same spelling that
   mean the package, the distribution, the command or the repository are still
   renamed. Say in the evidence how the tool tells the two apart, and give the
   count of each.
2. **The reckon step of the cutover becomes a check, not a move.** It states
   that reckon's project key, mounts entry, state directory, stored reviews,
   ledger rows and worktree root are unchanged, and its check is that reckon
   lists the project under the old key with its run-history count unchanged,
   opens one stored plan review and one stored run review by id, and resolves
   one plan by slug. Its undo is nothing, since it changes nothing. A later
   migration of the key is named as out of scope.
3. **Evidence files are kept by default.** Under `docs/evidence` everything
   keeps its bytes except `*.py` and `*.sh`, which are renamed. New evidence
   file types are then kept without a list change.
4. **The freeze step tells the operator what to do.** Its step text, not only
   its check, lists every session's queued and awaiting-upstream requests for
   the project and has each owner drop them before the tracked rename and
   re-dispatch afterwards. Since reckon's key does not change, say when
   re-dispatch is safe: after the shared environment is rebuilt and verified.
5. **One stale title.** The gate-script step's title says "rewrite or
   regenerate"; its body says the directory is evidence and is regenerated by
   its owner. Make the title match the body.
6. **The checkout directory does not move.** One statement, no step that
   assumes otherwise.

## Done when

- Applied to a scratch copy of the current primary branch head, the tool
  leaves `docs/state/imas-codex` byte-identical and every reckon-key
  occurrence unchanged, renames the package, distribution, command and
  repository occurrences, and the closing search reconciles as kept plus
  protected plus zero leftover, with the counts of kept reckon-key occurrences
  and of renamed occurrences in the evidence. A second application changes
  nothing.
- On that copy, with an environment built for it alone and reckon run against
  the copy's own docs through a scratch mount that uses the old key, reckon
  resolves one plan by slug and reads one stored plan review. If a scratch
  mount cannot be made without touching the user's reckon configuration, do
  not make one: state that, and show instead that every path and key reckon
  reads from the repository is byte-identical before and after.
- The default tier and the tests that reference `docs/evidence` add no failure
  after the rename, both arms recorded in the manifest as single-line JSON
  objects with whole test ids.
- `cutover.json` carries the six changes above; the cutover test fails if the
  reckon step turns back into a move, if the evidence default is narrowed to a
  list, or if the freeze step loses its operator instruction.
- Scratch copies and environment are removed, with removals printed.

Negative control: a reckon-key occurrence renamed by hand in the scratch copy
is reported by the kept-name check; a file under `docs/state/imas-codex`
altered by hand is reported by the kept-path check. Run each as a pytest run in
a scratch copy and cite a log with a non-zero exit and a failing test id.

## Rules

- Scratch copies only, made with `git worktree add` under node-local `/tmp`
  inside a compute job, with their own environment there. Never sync or
  repoint the shared environment. Change nothing under the home directory:
  not reckon's configuration, mounts, state or queue, no service, no
  repository setting, no graph content.
- Heavy work as its own job:
  `env -u SLURM_JOB_ID -u SLURM_JOBID sbatch --partition=rigel`, logs on GPFS,
  each pytest log ending with pytest's summary and one EXIT line.
- The manifest's `tests` field is one literal command that parses; failure ids
  are whole (everything between `FAILED ` and ` - `).
- Run `ruff check --fix` and `ruff format` on exactly the files you change and
  add no lint finding against the base.
- Commit locally with a conventional subject and a body, and give `commits`
  as a JSON list of full shas. Do not push or merge.

## Scope

Write paths: `scripts/rename`, `tests/scripts`, and
`docs/evidence/fragments/codac-uda-signals/keep-the-reckon-key-in-the-rename.html`.
