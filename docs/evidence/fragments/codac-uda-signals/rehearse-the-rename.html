The whole rename is proven on a scratch copy

Authority: plan codac-uda-signals §21, read at base revision c8a99be9645f2bd7a8a7ca99642d906ba04c5dc4. One repeatable rename was applied to scratch copies only: no shared checkout, shared environment, graph, service, repository setting or reckon state was touched. Copies live on node-local scratch of the compute allocation's jobs and were removed at the end of each job.

What the rename reaches and what it leaves alone

The tool is scripts/rename, committed at 53c95aaac, 32e073d16 and 51636462b. python -m scripts.rename apply rewrites every tracked text file, moves every path whose basename carries the project name, and reads the kept-name list at scripts/rename/kept_names.json. The kept list is committed beside it; python -m scripts.rename check is the closing search, python -m scripts.rename cutover the inventory accounting, and python -m scripts.rename digest the idempotence measure.

A kept path is not merely counted: apply digests every kept path before it writes and after it finishes, fails if any changed, and records the digests in its report; check --receipt re-reads them against that record. A hit floor alone is blind to an insertion that carries no old name, which is what the negative control proves.

What was removed

Every job removed its own scratch at the end and printed the paths. A renamed copy is dirty by definition, so `git worktree remove` refuses it and the brief forbids force: the job copies were therefore removed with the scratch directory that held them, after the evidence above was captured, and each removal is printed in the run directory (`logs/removals.txt`, and `slurm-<job>.out` beside the manifest). The base arm's copy was clean because its rename was never applied, so it was removed with `git worktree remove` without force. On the login-node scratch the two probe copies were committed in place (scratch commits `05d11ad3` and `aef3e416`, never pushed) and then removed with `git worktree remove` without force, followed by the 295 MB store clone, the dependency symlink and a stale uv lock.

Boundary

No shared checkout, shared environment, graph, service, timer, repository setting or reckon run was changed. The rehearsal's own writes are the scratch copies, each copy's environment, the run directory and this record. The dependency source imas-standard-names is installed editable by [tool.uv.sources], and its build hook writes into its own checkout, so each job built against a writable copy of that source rather than the shared one; the first two jobs failed at uv sync on the read-only shared checkout, which is a scaffolding fault, not a rename failure.
