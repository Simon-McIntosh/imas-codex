Server tools survive the REPL's module reload

A tool call no longer fails with a missing-module error when the server's REPL reinitializes while the server's own modules are being imported. The REPL reload was kept, and its module-cache deletion was removed.

Why the reload existed

The REPL carries a reload() utility so a long-lived server process can rebuild the utilities it holds — the graph client, the encoder and the globals — against current settings without being restarted. Its documented purpose was wider: it cleared source edits made in a developer session. That wider promise was never delivered coherently. Tool handlers are closures registered at server startup, so deleting the module entries never rebound them; it only caused the next call-time import to load a second copy of a module whose siblings were still referenced by the running closures.

The failure mechanism

The reload deleted every module whose name began with iter_codex from sys.modules. Each tool body imports its support modules at call time, and CPython's importlib installs the module under its name, runs its loader, then pops that name to hand it back. A reload that removed the entry between the install and the pop made the underlying lookup raise KeyError for the module name. The tool call surfaced as an arbitrary KeyError: 'iter_codex.…' that a fresh process could not reproduce.

What changed

_reload_repl() now resets only the REPL's own state (_repl_globals, _imas_tools_instance, _graph_client) and reinitializes the utilities. It no longer touches sys.modules. Source edits require a server restart, which is the only operation that replaces every module and every reference to it together; the docstring states that boundary rather than promising a hot reload it cannot provide.

Reproduction and measure

The reproduction runs the server's reload from inside the tool's own call-time import — the worst interleaving two threads can produce, made deterministic — and then calls the signal and pulse searches in both orders, and every plant tool across four orders, in one process.
