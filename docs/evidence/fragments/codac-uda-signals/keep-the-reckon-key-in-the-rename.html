Why a spelling is not the product

The old name is four things: the import package and distribution, the command, the repository, and reckon's project key. The first three are renamed; the key is not. Reckon has no supported way to rename a project key, and the key is what its mounts entry, its stored reviews, its ledger rows and the same key in every plan-qualified resource identifier resolve through. Serving the project under a new key would re-register its retained history under identities that no stored record names.

The tool therefore decides by position and syntax, never by a list of exceptions to a global substitution. An occurrence is claimed before the rename runs, by two mechanisms:

MechanismSyntax it claimsWhy that syntax
Kept pathAny file under docs/state, docs/.reckon and the kept evidence and record treesA path is kept as a whole. Inside it every occurrence counts as kept, so no rule has to classify the text.
Kept context, reckon-spa-mount(?<![\w.~/-])/imas-codex/A URL or page path starting with the key is where reckon mounts the project. The lookbehind excludes a filesystem path: ~/.local/share/imas-codex/... and /home/<user>/Code/imas-codex/... name the product and are renamed.
Kept context, reckon-plan-referenceimas-codex:[a-z][a-z0-9-]+, scoped to docs/evidenceA project-qualified plan or resource identifier is a record the plan system resolves by key. The scope matters: outside the evidence tree the same spelling is a container tag (ghcr.io/.../imas-codex:latest) or an application title, and both are the product and are renamed.
Kept context, reckon-project-argument--project[= ]+['"]?imas-codex\bA project key passed to a reckon command names the project. --project passed to uv names a directory, and that is the product and is renamed.

Claimed spans are marked first and survive both the text rewrite and the path moves; identifiers already on the kept-name list (the independent standard-names distributions, imas-python, the data-dictionary spellings and the DD graph label) are claimed in a separate pass, so the two sets cannot overwrite each other. The counts below show the split: 85 protected occurrences of independent names sit inside renamed files, and the reckon key contributes 45 kept occurrences in covered files plus every hit inside the kept bytes.

Reckon still serves the project, measured through a scratch mount

A scratch reckon home was created under /tmp and copied from the checkout's stored records, so the user's configuration, mounts entry and state were never read as a target and never written. Through that mount, before and after the rename, the same four reads were taken: a plan resolved by slug, the mounts entry, one stored plan review and one stored run review opened by their ids, and the state directory listed. Every digest was identical in both passes, both parsed, and both exited 0. The stored review inventory read 2 plan reviews and 1 run review from the committed tree, with their fields intact.

The check on the committed tree is therefore a check, not a move. cutover.json records the step as kept: the project key, the mounts entry, docs/state/imas-codex, its stored reviews, its ledger rows and the worktree root all keep their names and bytes. A value that differs from the freeze listing is reported, never repaired by moving the key or the directory. Its check requires the project to be listed under the old key with the check's run count equal to the freeze listing, one plan review and one run review opened by id, one plan resolved by slug, and the rename check still exiting 0 with docs/state and docs/.reckon reported kept. Its undo is "Nothing changed", and a later key migration is recorded as out of scope.

The checks fire, and the suite does not move

Four mutations of the tool each produced a failing test with a whole id, against an unmutated control of 39 passed: hand-renaming ten kept page URLs (test_apply_keeps_a_mounted_url_and_renames_the_code_beside_it), altering one kept state file (test_check_reports_a_kept_file_altered_without_losing_a_hit and test_apply_leaves_reckon_state_bytes_and_check_reports_an_alteration), and dropping the reckon or freeze blocks from the sequence (test_cutover_accounts_for_every_inventory_surface, test_cutover_keeps_the_reckon_key_and_its_state_directory). At the data level, a hand-renamed ten kept URLs drove reckon-spa-mount to 31 against its floor of 40 and the check reported kept-name-missing; an altered state file produced kept-path-altered against the pre-rename digest.

Both arms of the suite were run on their own scratch clones, built with their own environment, the after arm with the rename applied to the copy. The tests that reference docs/evidence passed equally in both: 325 passed, 3 skipped, 35 deselected, exit 0 each.
