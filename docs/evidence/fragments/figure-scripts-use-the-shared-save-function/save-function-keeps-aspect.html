The shared save function keeps the drawn aspect at any canvas size, and the signal legend fits one row

Defect

The SVG post-processing in imas_codex/plotting’s save_figure declared a fixed width of 31.1cm and derived the height from the default canvas height (16 * figheight / 7.2). Any figure drawn at another width was exported with a wrong declared size: a 28×7.2 in canvas was declared 31.1×16 cm, a ratio of 1.944 instead of the drawn 3.889.

The signal plot asked for ncol=min(3, len(lines)), so a four-trace and a six-trace legend both wrapped onto two rows.

Fix

The declared height now follows the figure's own ratio under the fixed slide width: SLIDE_WIDTH_CM * figheight / figwidth, formatted with three significant digits. The default 14×7.2 in canvas still declares width="31.1cm" height="16cm", because its ratio matches the slide ratio within the formatting precision.

The legend fits up to six lines into one row (ncol=min(len(lines), 6); wider legends still wrap by column count), the top margin is derived from that column count, and plot() reports the measured legend_rows in its receipt so the rendered layout, not the request, is checkable.

Negative control

Restoring the pre-fix height formula makes the non-default arms fail while the default arm still passes: [wide] and [narrow] fail with AssertionError (measured ratios 1.945 vs drawn 3.889, and 0.7772 vs 0.7778 at one-part-per-thousand), [default] passes, run ends with EXIT=1. Log: logs/negative-control-width-pin.log in the run directory.

Outside scope

The shared text check counts a tick label the axis never renders (an AutoLocator tick just past the view limit) as clipped figure text, so a plain figure without pruned locators is refused with clipped figure text: 1.2. The signal plot avoids it with MaxNLocator(prune="both"); the aspect test does the same. Not changed here because the section forbids new refusals and this is a pre-existing false refusal, reported for triage.
