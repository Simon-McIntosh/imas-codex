The mutation kind, and the change it writes

The kind is supersede. It is the only kind in _SIGNED_MANIFEST_MUTATION_KINDS whose write the orphan lifecycle's own retirement (supersede_exhausted_orphan in imas_codex/standard_names/graph_ops.py) also uses, so the recorded retirement carries the same shape as a lifecycle orphan retirement. The mutation is written without a signed successor — no arguments.successor_id — so no HAS_SUCCESSOR edge is minted, which is what keeps the 183 in the census: they still point to nothing. Its Cypher is the signed-manifest supersede branch, which sets superseded_from_stage = coalesce(superseded_from_stage, name_stage), leaves name_stage = 'superseded' and status = 'superseded', clears the claim fields, and writes no review. The guard set a supersede mutation must carry is structural-legitimacy and out-of-allowlist-immutability; both are attached to each row, the second over the target alone.

The receipt change is one StandardNameChange per admitted row, written by _write_receipts with: operation = 'supersede_exhausted_orphan' (taken from the authority's receipt_policy.operation); from_name = to_name = <name id> (a retirement has no replacement, so _receipt_names returns the name itself for both); origin = 'signed_manifest'; internal = true; run_id; manifest_sha256; authority_file_sha256; authority_payload_sha256; row_id; mutation_kinds. It is linked to the name by HAS_INTERNAL_CHANGE. The reason on every change states that the supersession census found no supersession event on a source-less superseded identity, and that the retirement it lacks is recorded and the name left terminal at superseded.
