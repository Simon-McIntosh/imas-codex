Draining review, refine, documentation and parent enrichment for names already in the pipeline

A sn run --flush drains work already seeded — review_name, refine_name, generate_docs, review_docs, refine_docs and parent enrichment — while skipping auto-seeding and the compose pool, so it never mints a new source name. This fragment records the live census before and after two flush passes, read with the unaccepted-census instrument's own query and the export gate's own report.

Both phases are measured by sib-flush-unaccepted-run.py, which loads sib-unaccepted-census-run.py and calls its source_rows and classify_source, so the classes reconcile to the census's published totals rather than a re-derived query. The export gate is the gate's own ExportReport. The approved and contested rows are hashed over their full property maps in ID order. The guarded cohorts and their positive control

A fresh graph holds no approved or contested StandardName rows, so an equal digest over that population is vacuous. The runner therefore also hashes a non-empty accepted cohort and a copy with one property perturbed: the baseline digest differs from the empty-string digest and the mutated copy changes the digest, which shows the instrument sees content and would notice a mutation. ID absorbed_power_due_to_neutral_beam_injection was perturbed in that control; it ran with the after measurement and both checks hold.
