Cause

Not the stranded-identity admission change. generate_docs admission still requires docs_stage = 'pending' (imas_codex/standard_names/pools.py:551-554), and claim_generate_docs_batch verifies eligible_stage="pending" (imas_codex/standard_names/graph_store/graph_docs_persistence.py:34-68). A docs-accepted name is unreachable by that pool on any path the change touched.

Not the startup grammar reconcile. reconcile_vocab_gaps deleted one false gap and reclassified one (log 18:25:21), and retry_vocab_gap_sources_on_grammar_change returned four parked sources to extracted under vocabulary 01f3670d941bdb6f. Neither writes docs_stage.

The startup DD-source drift refresh did it, called unconditionally from run_sn_pools (imas_codex/standard_names/loop.py:2149-2189) with include_accepted=True (source_refresh.py:391-505). It logged 1065 name(s) drifted (0 renamed) at 18:28:08 and steered 508 of them through apply_edit(axis="docs"), which calls reset_standard_name_docs (edit.py:4434) and sets docs_stage='pending' (graph_docs_persistence.py:360-425).

Why 1065 names read as drifted with zero renames: the comparison (_source_deltas, source_refresh.py:168-242) tests the stored snapshot's source_path against the resolved terminal DD node, and source_path is one of the three steering fields (source_refresh.py:325-328). A DD version whose RENAMED_TO lineage moved the terminal path therefore makes every stamped name a steering candidate. A probe of the 508 reset names' 600 DD source bindings finds 468 with a path delta (324 path only, 138 path + documentation, 6 path + units + documentation) and 132 unchanged; no reset name in the sample had a unit-only or documentation-only delta. The rename counter stayed at 0 because renamed compares the source's anchor to the terminal, not the snapshot path to the terminal — so the run reported "0 renamed" while resetting 508 names.
