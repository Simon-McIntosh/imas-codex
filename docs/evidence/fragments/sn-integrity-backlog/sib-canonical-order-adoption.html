sib-canonical-order-adoption — a segment-order refusal is adopted under the parser's spelling when the expression is unchanged

A composition whose segments are merely out of the strict grammar's canonical order was retired as a source failure. The parser rejects such a flat spelling in compose_standard_name — inside the composer, before any normalization in codex can run — with _NonCanonicalParseError: name is not canonical: flat segment order renders as '…'. The pre-validation gate caught that ValueError at worker_compose_batches.py and marked the source failed, even though the parser was reporting a reordering rather than a malformed name. The refusal is reproduced offline against the recorded candidates; for example parse_canonical_name("radiated_energy_accumulated_due_to_impurity_radiation") raises name is not canonical: flat segment order renders as 'accumulated_radiated_energy_due_to_impurity_radiation'.

The repair adds adopt_canonical_segment_order to the grammar adapter. It asks the strict parser for the canonical spelling through normalize_canonical_name, then requires that the spelling denote the same expression, comparing the non-strict parse of the refused name with the canonical parse through _require_semantic_ir. Only then does the candidate proceed, under the canonical name. A reorder that moves a token between semantic roles is refused, and any grammar failure that carries no canonical spelling is re-raised unchanged. The pre-validation gate adopts the refused spelling carried on the parser's error, logs both spellings, and otherwise keeps its existing refusal path. The candidate's operator chain is not re-composed, so a candidate carrying operators keeps its refusal: only the base composition's spelling is recoverable from the parser's error.

The rule run offline over every recorded segment-order refusal that carries both spellings — the strict-grammar rejections in the full run's log (sn-run-1308077.log). 8 of 9 adopt; the one refusal is a reorder that changes the expression, so the same-IR check fires on recorded data.
