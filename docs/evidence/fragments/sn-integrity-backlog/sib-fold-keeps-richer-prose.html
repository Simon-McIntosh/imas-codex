A fold onto an occupied identity keeps the richer documentation

The defect, reproduced

Folding one spelling into an identity that already exists merges two prose bodies under one surviving spelling. Before this node, supersede_into never wrote the target's documentation at all — the fold carried source_paths, name_stage and updated_at, nothing else. A rich source folded onto a sparse canonical target therefore lost its prose, the regression recorded on coolant_absorbed_energy_accumulated_of_plasma_facing_component whose live description carried an exclusion clause and real documentation while its canonical target was docs_stage='pending' with null documentation. The reproduction is the second integration test below: with the documentation choice reverted, the sparse-onto-rich case fails (see the negative-control log).

The rule stated

The surviving identity holds whichever side's documentation is richer, never whichever spelling happened to be the target. Documentation is prose carried whole — never averaged or merged. _fold_carries_source_documentation decides by:

  1. A documented side beats an undocumented or placeholder one. Whitespace-only prose is a placeholder, not documentation.
  2. When both sides carry documentation, the accepted docs stage beats a lower one (accepted > reviewed > drafted > pending > exhausted).
  3. The incumbent target wins every tie: a fold never silently prefers the source's prose unless it is demonstrably richer.

On a carry the target takes the source's documentation and docs_stage together; otherwise it keeps its own. A None value removes the slot, matching SET x = null, so an undocumented side leaves none behind and the postflight exact-state proof still holds.
