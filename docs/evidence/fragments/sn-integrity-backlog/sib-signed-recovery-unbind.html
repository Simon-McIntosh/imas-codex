Removing a recorded recovery binding from an exhausted name

The signed-repair envelope now carries one closed program, recovery-binding-unbind, that removes a recorded PRODUCED_NAME edge from a standard name whose name_stage is exhausted. A row is admitted only when the edge exists, its StandardNameSource is not stale, and the target name's stage is exhausted; any failing row refuses the whole authority and writes nothing. The name, its stage, its other edges and the source node are left exactly as they were, and the removal is recorded as a StandardNameChange naming the removed source, the operation and the authorized manifest digest. The source invariant keeps refusing a sourceless live name from every other writer; this program passes its own signed exhausted rows as a narrow exemption, and the exemption is honoured only while the row's own stage still reads exhausted.

Design: one closed program inside the existing envelope

The program is a self-contained adapter in imas_codex/standard_names/signed_manifest.py, dispatched from apply_signed_manifest ahead of the generic registry rather than beside it, so a signed recovery unbind is previewable and applies through the same entry point as every other signed repair. Its Cypher is marker-tagged and re-derives its closure inside the applying transaction:

  • RECOVERY_UNBIND_CLOSURE reads, per signed row, the existence of the name, the source and the binding, and the properties each decision reads.
  • RECOVERY_UNBIND_MUTATION deletes the edge only when its element id, its source's element id and its name's element id all still match the closure the manifest authorized — a compare-and-set, so a concurrent re-hardening of the binding cannot be silently removed.
  • RECOVERY_UNBIND_RECEIPT writes one StandardNameChange, linked by HAS_INTERNAL_CHANGE, carrying the removed source in from_name, the target in to_name, the operation, and the manifest digest in manifest_sha256.
  • RECOVERY_UNBIND_POSTCONDITION proves the edge is gone, the stage still reads exhausted, and then re-runs the source invariant over the admitted names with its narrow exemption.
  • RECOVERY_UNBIND_REPLAY answers a re-apply whose change nodes already exist with already_applied and no writes.

The invariant exemption is narrow and self-guarding

find_sourceless_live_names and require_producing_sources in source_invariant.py gained an optional exhausted_exempt_ids keyword, defaulting to empty. The predicate excuses an id only when both the id is in the caller's signed set and the node's own name_stage still reads exhausted in the live graph, so an exemption cannot survive the name being moved on. No existing caller changes: the keyword is optional and every other writer keeps refusing exactly as before, which test_source_invariant_still_refuses_a_sourceless_live_name and test_exemption_is_confined_to_its_own_exhausted_rows pin.

Negative control

Applied and logged (negative_control.log, EXIT=1): the program's dispatch in apply_signed_manifest disabled, the exhausted-stage refusal removed from _recovery_unbind_refusal, and the exhausted-name clause removed from the invariant predicate. Under that mutation 7 of the 11 tests fail, including test_exhausted_row_loses_its_binding_and_records_a_change (nothing is unbound) and test_live_name_is_refused_and_nothing_is_written (the live-row refusal no longer fires). The tree was restored from a byte copy taken before the mutation; the restored tree reports zero traces of the neutering and re-passes the gate.

Caveats

  • No live graph write and no LLM call were made. The program has not been run against a real database by this node; the graph-marked contract suites skip without a disposable Neo4j.
  • The change node carries the removed source in from_name, because StandardNameChange declares no source-id slot; the Cypher property check enforces that only declared slots are set.
