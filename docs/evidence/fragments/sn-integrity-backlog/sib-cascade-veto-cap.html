A vetoed documentation decision never reads as acceptable, and the calibration rebuilds

Three independent causes kept test_matched_policy_rebuilds_from_frozen_scores_and_receipts red. The contradiction veto chose the refine route but left decision_score at the unvetoed mapping, so poloidal_mode_number read 0.9121 against an accept_threshold of 0.3883 — a score any consumer comparing against its own threshold would accept. The veto now caps the mapped score at the float immediately below min_score, which is what the artifact's own policy.veto_score states. The frozen documentation logistic column was written against the scorer as it stood before the claim-settlement retunes, so 12 of its 386 paired rows no longer reproduce, nine of them sitting at exactly 0.0 — the retired veto's denial. The column is re-derived from the stored receipts with no judge call, and the cutoffs refit through the existing build. The calibration replay ORed every per-binding claim answer into a veto; it now reads the fold the live path uses, where a claim contradicts only when no binding supports it.

The cap

cascade._route raises claim_contradicts_source for a contradicted documentation claim and routes the item to refine. The mapped score was computed before that happened and was returned unchanged, so the route and the score disagreed. The cap is applied at the veto: mapped = min(mapped, math.nextafter(min_score, 0.0)). A vetoed item below the threshold already keeps its lower value, and the hold still records which check failed, so a triager sees the finding as well as the score. Without the cap the new test reads 0.985 on the same judgment; with it the score is the float below 0.85.

The replay folds by support

The replay computed its contradiction feature as any(claim_contradicts(answer) for key … if key.startswith("check:claim_contradicts_source:")), which reintroduces the per-source OR the live path retired: one narrow binding ruling a claim out vetoed a name another binding supports. Binding labels
