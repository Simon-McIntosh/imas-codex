Landing record: the retired-successor row reaches the caller named, and compose withholds it without a retry

A source bound to the live predecessor and a successor that has itself been retired — one live claim beside a settled one — no longer falls through to the anonymous RuntimeError that callers retry. In imas_codex/standard_names/provenance_lifecycle.py that preflight row is now classified by its own branch and raised as the sibling named type SourceRetiredSuccessorConflictError, whose record names the source, the live holder with its stage, and the retired holder with its stage. One source bound to the live predecessor and a live successor still raises the dual-live SourceBindingConflictError; the retired row never reports two live identities. The two remaining refusals — the dual-live conflict and this one — keep raising RuntimeError-derived types, so existing callers are unaffected.

The compose persist boundary consumes it through the same consumer as the dual-live conflict: _persist_description_checked_candidates in imas_codex/standard_names/workers.py catches both named types and routes them to _withhold_binding_conflicted_sources, which leaves the source claimed, releases no claim, returns no winner id, and warns with the live holder and (where present) the retired holder. No retry attempt is spent.

The dd: source-node-id rule is now defined once: _candidate_source_node_id in workers.py is the single definition, and the release path that previously inlined the same expression now delegates to it.
