What the build still leaves unlabelled

The cause record predicted 617 labels restored from the 623 fields 3.42.2 declares. The build set 495 of those 623 and left 128 null, with zero disagreements and zero missing nodes; the remaining labelled nodes come from the inferred sources (109 forward, 61 sign flip), which take the total to 574. The 128 nulls are paths the latest DD version no longer carries, such as equilibrium/time_slice/profiles_1d/j_tor, .../b_tor and .../bpol_probe/measured: the forward-port backfill writes onto the latest version's path set, so a path renamed or dropped in 4.x is skipped even though its node is still in the graph. Every holdout path survives that boundary, so the authority test is unaffected, but the restoration is 128 labels short of the DD's own declaration for older-version nodes.

The paid work the CLI could not skip

Preflight found no enrichment work (0 IMASNode, 0 identifier schema and 0 IDS nodes needed enrichment; 0 Tier-1 domain-classification candidates), and the build confirmed it: 0 paths enriched, 0 embeddings updated. But restoring the labels changes the clustering input text, so the cluster input hash no longer matched and the cluster worker recomputed 3,025 clusters and began labelling the 350 unlabelled ones with openrouter/anthropic/claude-sonnet-4.6. Three batches billed $0.1599, $0.1258 and $0.1343 ($0.42 total, three batches of 50 of 350 clusters) before the build was sent SIGTERM at 150/350; a fourth batch was in flight when it stopped. One Tier-1 domain classification also ran (1 path, cost not itemised in the log). The process printed its full summary and then hung joining executor threads, so it was sent SIGKILL after the summary; the wrapper recorded exit 137.
