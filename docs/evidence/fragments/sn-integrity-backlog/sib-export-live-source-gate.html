The export source gate counts live names only

The release export no longer fails on an exhausted name whose recorded Data Dictionary source is missing. The gate in imas_codex/standard_names/export.py partitions the classifier's dropped-edge and never-bound rows: an exhausted row is recorded on the report as dormant with its count and left out of the gate, and any other stage still blocks the export. Six live names whose quantity no Data Dictionary path measures are added to _RELEASE_IDENTITY_HOLDS with the reason release_hold_no_dd_source; they leave through the existing release-hold path and the gate does not count them. No live graph write and no LLM call were made.

What changed in the source gate

Before the change the gate failed the whole export on any row whose population was dropped_edge or never_bound, whatever the name's stage. The classifier returns exhausted, accepted and other-stage names in the same two populations.

Before:

source_losses = [
    row
    for row in source_audit
    if row["population"] in {"dropped_edge", "never_bound"}
]
if source_losses:   # blocks on exhausted names too

After:

sourceless = [row for row in source_audit
              if row["population"] in {"dropped_edge", "never_bound"}]
dormant_sourceless = [row for row in sourceless
                      if row["name_stage"] == "exhausted"]
source_losses = [row for row in sourceless
                 if row["name_stage"] != "exhausted"
                 and row["id"] not in _RELEASE_IDENTITY_HOLDS]
report.dormant_sourceless_names = [ ... ]   # visible on the report

The dormant rows are emitted in the export report under dormant_sourceless as a count and a list of {name, name_stage, population}, so the exclusion stays visible after the gate passes.

The six release holds

Each of the six held names is a live, non-derived name with no Data Dictionary source. This node adds the holds and touches no graph row; a sibling node applies the graph changes. The reason key is release_hold_no_dd_source and the detail reads no Data Dictionary path measures the quantity, so a reviewer sees the measure is absent from the DD rather than the name being unreviewed. The existing neutron_flux_due_to_fusion hold is untouched.

Measure

Three behavioural tests are added. Each drives run_export against a stubbed source audit, so the gate is exercised without a live graph:

  • test_exhausted_sourceless_row_is_dormant_not_blocking — an exhausted dropped-edge row no longer fails the export, the population is fetched, and the row appears under dormant_sourceless with count 1.
  • test_live_sourceless_row_blocks_the_export — an accepted dropped-edge row still fails the export and the population is never fetched.
  • test_held_sourceless_identity_is_not_counted_and_not_exported — a held sourceless identity does not fail the gate, is not exported, and is excluded with reason release_hold_no_dd_source at stage release_authority.

Negative control

Reverting the live-only filter and the six holds (base-revision export.py with the head tests) fails the two behavioural tests that depend on the change plus the three hold tests in test_export_release_holds.py: 5 failed, 4 passed, EXIT=1. That is the set of tests the change exists to make pass, so each is shown able to fail.

A second, boundary mutation — the gate blocks nothing (source_losses forced empty) — fails test_live_sourceless_row_blocks_the_export alone, showing that test fails when the live-name refusal is removed as well. Both logs are named in the manifest.

Covering gate

The gate is every tests/standard_names/test_export_*.py file together with tests/standard_names/test_source_audit_gate.py, run at the base revision in a scratch extraction and at the head in this worktree. Its delta is recorded in the manifest as baseline_suite and after_suite.
