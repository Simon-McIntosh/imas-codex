D2 — the pending count dropped the open docs veto

Reproduced before the change: test_refine_docs_pending_matches_canonical_claim_predicate failed because the emitted refine_docs clause carried sn.reviewer_score_docs < $min_score where claim_refine_docs_batch builds (sn.reviewer_score_docs < $min_score OR EXISTS { MATCH (sn)-[:HAS_HOLD]->(hold:ReviewHold) WHERE hold.axis = 'docs' AND hold.status = 'open' }).

The claim is right and the pending count was wrong. A name above the threshold that carries an open documentation veto is claimable work, and the watchdog counted only low scores, so it reported an empty pool while the claim query still returned items — the premature exit the test's own docstring names. imas_codex/cli/sn.py now builds that disjunction once and renders it into the pending clause.

D3 — an exception attribute nothing declared

Reproduced before the change: the guard reported two reads of an undeclared defaulted attribute, imas_codex/cli/discover/sequence.py:686 (now the raise site) and :906 (now the stage loop), both getattr(exc, "discovery_receipts", []).

The attribute was real only at runtime: three sites assigned it to whatever exception a stage raised. A StageFailure now declares discovery_receipts and carries the receipts, and both readers check the type before reading the declared field. The wrapper keeps the original exception as its cause, so the stage summary still reports the original type name and the host-unreachable test still sees the original error; the existing budget test that charges a failed stage's receipt to the next stage's limit still passes.

D1 — the frozen docs logistic column predates the scorer

Reproduced before the change, and the cause confirmed directly: cascade_calibration.build() raises ValueError: landed logistic mismatch: extent_of_soft_xray_detector after 120.6 s. The item's landed docs score is 0.18538907974010682; the frozen value in srtj-jev-vs-panel-operating-point.json is 0.48696524039224126.

The disagreement is not one item. Against the current scorer, 374 of the 386 paired docs items reproduce to 1e-10 and 12 do not. Nine of the twelve are frozen at exactly 0.0, which is the score the contradiction veto returns — commit 040e16a16 deliberately stopped that veto reading an undecided answer as a denial. The remaining disagreements follow the documentation gate learning which name it documents (e4752d43c) and the claim-settlement retunes. The frozen column was written with the scorer as it stood at bd658567d, the commit that also froze cascade_thresholds.json.

Relaxing only that cross-check exposes a second, independent defect in the same rebuild. With the equality bypassed, build() trips _matched_report's own invariant on 8 docs calibration rows (the name axis is clean on both folds). Each is a contradiction-vetoed row that _route routes to refine while decision_score stays at the unvetoed mapping — for example poloidal_mode_number at decision_score 0.9121 with accept_threshold 0.3883. The artifact's own policy.veto_score says the veto caps the mapped score at the float immediately below the consumer threshold, and cascade.py:213 raises the veto without applying that cap.

Both repairs need files this node may not write: imas_codex/standard_names/review/cascade.py for the missing cap, and a re-frozen docs/evidence/fragments/sn-review-through-jev/srtj-jev-vs-panel-operating-point.json (or a regenerated cascade_thresholds.json) for the stale column. No change to cascade_calibration.py makes the id pass on its own, so this node reverted its two exploratory edits there rather than land a partial change that moves calibration output without a green measure. The defect is a real one: a vetoed name whose decision_score reads above the consumer threshold is a name a score-reading consumer would accept.

At head the id still fails with the same error after 104.8 s in the gate arm, ValueError: landed logistic mismatch: extent_of_soft_xray_detector, so nothing this node landed touched the calibration path.
