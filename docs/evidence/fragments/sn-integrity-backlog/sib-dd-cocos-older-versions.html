The 128 older-version-only DD nodes carry their declaring version's COCOS label

The forward-port backfill walked only the newest DD version's path set, so a field deleted or renamed after 3.42.2 kept its IMASNode but never received the label its own DD version declares. Read-only measurement on the live graph finds 623 fields labelled by DD 3.42.2, of which 148 are absent from 4.1.1's path set and all 148 still have an IMASNode. 128 of them carry no label; 20 already carry the same label with zero disagreements. Every one of the 128 declares its label at 3.42.2, the newest version that carries the path, so the declaring version is unambiguous. The build now writes those labels tagged cocos_label_source='inferred_older_version'.

How the 128 were measured

Three facts, each asserted rather than assumed: DD 3.42.2 declares 623 labelled fields (XML cocos_label_transformation); the newest version 4.1.1 extracts 44,150 paths; the difference is 148 paths, and a bounded UNWIND … MATCH (p:IMASNode {id: id}) over them returns 148 rows — every node exists. 4.1.1 declares 384 labels of its own, so the 4.x line is not silent about COCOS; the 148 are simply paths it no longer carries, and neither 4.0.0 nor 4.1.0 carries any of them either (checked, 0 both). That is why each one's newest declaring version is 3.42.2 and why the label is the DD's own statement rather than an inference.

The build change

_backfill_cocos_labels gains a fourth source after the forward-port, expression-parse and sign-flip passes. For every path present in a version that declares labels but absent from the newest version's path set, the newest such version that contains the path decides: it labels the node if it declares a label there, and leaves it unlabelled if it carries the path without one. A version that declares no label anywhere cannot settle the question, so a build scoped to a version line with no declarations never invents or removes an older label. The resulting paths join the set the scoped stale-label clear already protects, and inferred_older_version joins the sources the clear refuses to strip when no label-declaring version is in scope.

Tests and gate

Four tests in tests/graph/test_dd_cocos_label_preservation.py run the real phase_build on the disposable graph: a 3.x-only path takes its declaring version's label; a shard build over another IDS leaves it intact; a build covering a later version that carries the path unlabelled removes it; and a scoped rebuild over an IDS whose scope holds only 4.x versions keeps a label it has no authority to withdraw. Against main's build_dd.py all four fail (4 failed, 3 passed, EXIT=1); at head all seven pass (EXIT=0).

The fourth test exists because the clear's source list is otherwise unexercised: every other fixture carries a 3.x version, so the authority clause short-circuits. Removing inferred_older_version from authority_sources makes exactly that test fail (1 failed, EXIT=1), which is the shape that stripped every shard's labels when the clear was global.
