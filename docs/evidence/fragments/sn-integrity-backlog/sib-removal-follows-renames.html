A removed DD path moves its name to the successor, or supersedes it

A DD rebuild stamps every path it dropped lifecycle_status='removed'. reconcile_standard_name_sources marks the sources on such a path stale; before this change it never read the name those sources produced, so the last-producing-source invariant — which runs only inside a writer's transaction — never fired and a live name was left with no producer.

The name is now resolved in the same statement that marks the source stale, by the removed path's unheld successor:

BranchConditionEffect
movea RENAMED_TO successor no live name holds, units agreethe successor's source becomes the name's sole producer; the name stays live
supersede_holderanother live name holds the successorthe name is superseded, (holder)-[:REFINED_FROM]->(name), receipt removed_path_successor_holder
retireno successor, or the successor's unit disagreessuperseded with a removed_path_retirement receipt and no successor edge

Every branch fires only when the source was the name's last non-stale producer, so one removed path never retires a name another source still produces. The resolution is also scoped to DD sources: a removed DD path has a RENAMED_TO successor to follow, while a signals source names a facility signal that is not an IMASNode at all, so a signals source is marked stale and its name is left to the signal-side lifecycle. The dead-end revival guard also read the batch's source_type, which worker outcomes omit; it now reads the source node's own type.

Evidence, on the disposable graph: tests/standard_names/test_removal_follows_renames.py has four tests that drive the real reconcile_standard_name_sources('dd') — one per branch plus the unit-mismatch case — one that drives reconcile_standard_name_sources('signals') and proves the drained name stays live with no receipt, and one that checks the revival guard. Negative controls: restoring the stale-mark-only body fails all four reconciliation tests (EXIT=1), and removing the DD scoping supersedes the signal-backed name (EXIT=1).
