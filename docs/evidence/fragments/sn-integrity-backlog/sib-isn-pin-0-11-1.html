imas-codex pinned to ISN 0.11.1 and the graph's grammar snapshot synced to it

Both imas-standard-names pins in pyproject.toml moved from ==0.11.0 to ==0.11.1 (line 18, the build-system requires list, and line 186, the catalog-preview extra). The editable sibling override in [tool.uv.sources] is unchanged, so the lock continues to resolve the package from ../imas-standard-names. The graph's grammar snapshot was then moved to 0.11.1 through the repository's own grammar-sync path, sync_isn_grammar_to_graph() in imas_codex/standard_names/grammar_sync.py — the helper that sn run's startup auto-sync, sn clear's re-seed and the hatch build hook call. No Cypher was written by hand.

Lock

uv lock re-resolves at the new pins and exits 0 with no change to uv.lock. That is the correct result, not a missed refresh: an editable path source records neither the requirement specifier nor a resolved version, so the lock's only imas-standard-names entries are the three references already present — the root dependency list, the source record, and the package block whose source = { editable = "../imas-standard-names" } is untouched. The resolution was re-run from a scratch copy of the bumped pyproject.toml placed beside a symlink to the sibling checkout, because this worktree has no ../imas-standard-names of its own; the resulting lock is byte-identical to the committed one.

Grammar sync, before and after

The sync takes its version label from the installed imas_standard_names.__version__. The shared project environment's editable install carries 0.11.1.dev1+gef1bc401e in its dist metadata — a build made before the release tag existed — so a sync driven from that environment would have labelled the same content 0.11.1.dev1+gef1bc401e rather than 0.11.1. The sync was therefore driven with the released 0.11.1 wheel built from tag v0.11.1 (85ed43e) on PYTHONPATH first and the worktree second, and the run asserts imas_standard_names.__version__ == "0.11.1" before writing anything. Both module paths are printed by the run, so the reader can confirm the released artifact supplied the grammar and the worktree supplied the sync code.

Controls

  • Positive control. The same read-back query that returns the five target tokens returns power_convertor with two rows at 0.11.1 (segments device and object) and two at 0.11.0, so the instrument is shown to see what is present before any absence is reported.
  • Negative control. The made-up spelling halo_current_flow returns no GrammarToken row at any version after the sync, and the same query reports the five real tokens present — so a reader cannot mistake a broken query for an absent token.

What the thirteen ids are

The thirteen were characterised by re-running exactly those ids in the worktree at the head commit, which splits them into two groups.

  • Five are an artefact of the re-check's trees. They pass in the worktree at the head commit and fail in an archived tree, because they read catalog data this checkout generates outside git: test_cascade_calibration.py, test_catalog_layout_hierarchy.py::TestOrderingCycleDetection, and all three test_manifest_generability.py tests. The focused run passes those five (8 failed, 5 passed).
  • Eight reproduce in the worktree at the head commit, so they are pre-existing in this environment and outside this node's scope: six in test_gap_rule_verdicts.py (one DD-field-name, two ordinal-sample, two settled-fold and one stored-gap-replay id), one in test_geometry_enumeration_collapse.py, and one in test_compose_prompt_examples_round_trip.py.
