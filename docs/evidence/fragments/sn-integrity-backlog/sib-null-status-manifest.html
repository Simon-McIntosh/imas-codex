Why the predicate was wrong

In Cypher, x.status <> 'stale' evaluates to null when x.status is null, and a null filter drops the row. A StandardNameSource that carries no status therefore vanished from every count that asked whether a source was live: the query answered "no producer here" about a source the rest of the module treats as a producer. The module already evaluates this test in Python in the disposition preview (status != "stale" → a null status is live), so the Cypher filter disagreed with the preview it was verifying.

The three sites, and what a null status means

SitePredicateDecisionReason
signed_manifest.py:4113 — stale-source detach postcondition (_verify_postconditions) coalesce(live.status, '') <> 'stale' Null means not the excluded value: a live producer. This is the postcondition that asserts a detached target kept producing authority. A status-less producer is exactly the authority the detach was told to preserve; dropping it from the count makes a sound detach refuse as "stale-source target authority was stripped".
signed_manifest.py:4611 — ordinary source migration compare-and-set (_apply_ordinary_source_migration) coalesce(source.status, '') <> 'stale' Null means not the excluded value: the signed source may be rewritten. The guard's purpose is to refuse a source that was retired from authority; the row's identity is already pinned by element id, scalar, single binding and an unclaimed lease. stale is a retirement marker, not a "do not touch" marker for unclassified rows, so a null status must not silently block a signed migration.
signed_manifest.py:5844 — removed-target live-authority postcondition (_apply_catalog_source_dispositions) coalesce(remaining.status, '') <> 'stale' Null means not the excluded value: a live incoming binding. The same preview evaluates this in Python, where a null status counts as live; the Cypher postcondition counted it as absent and raised "removed target lost its final live authority" on a graph the preview had just admitted. Coalescing makes the postcondition agree with the admission it verifies.

Tests, and the refusal they cover

  • test_stale_detach_postcondition_counts_a_status_less_producer drives _verify_postconditions over a target whose only producer has no status, and asserts live_producers == 1.
  • test_ordinary_source_migration_admits_a_status_less_source drives _apply_ordinary_source_migration and asserts the binding, scalar and projection all moved to the new target.
  • test_catalog_source_disposition_keeps_status_less_authority drives the public apply_adjudicated_source_dispositions over a removed target kept alive only by a status-less producer, and asserts the apply completes.
  • test_lifecycleless_stub_cohort_change_refuses_before_deletion reaches the previously untested LifecyclelessStubConflict("stub placeholder cohort changed before deletion") by mutating a stub inside the apply transaction, after the manifest hash is checked and before the placeholder stamp. It asserts the refusal and that the transaction rolled back, so nothing was half-deleted.
