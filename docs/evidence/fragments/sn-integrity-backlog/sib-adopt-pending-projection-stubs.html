sib-adopt-pending-projection-stubs — composition adopts an unowned projection stub

Outcome: landed. A compose claim now adopts a pending projection stub that its own DD source projects onto, instead of colliding with it until the source is parked at the claim cap. Seven such stubs were the export source gate's whole blocking set; six sources were already parked against them.

Census, read-only on the live graph

Counted before the change: a live StandardName at name_stage='pending' with no PRODUCED_NAME edge into it, no reservation fields, and a HAS_STANDARD_NAME projection from a DD node; and the StandardNameSource rows parked failed at the cap whose DD path projects onto one of them.

The seven stubs are line_averaged_neon_density, radial_coordinate_of_reflector, radius_of_soft_xray_detector, ratio_of_diamagnetic_vorticity_to_major_radius, toroidal_coordinate_of_spectrometer, toroidal_tritium_velocity and vertical_coordinate_of_reflector. Every parked row carried only compose claim-attempt cap reached: the collision that caused the attempts was gone, which is the second defect this node closes.

The rule, as narrow as the case

_lock_claimed_name_bindings already had two lifecycle exceptions: reuse of a stable stage, and revival of a superseded or exhausted spelling with no live successor. A third joins them, and it is granted only to the composition claim paths. sn attach keeps both exceptions off — it calls the lock with each one false — so the same stub is still a collision on that path:

  • the candidate target is at pending;
  • no PRODUCED_NAME edge reaches it and it carries no reservation, so no claim owns it;
  • the claimed source is a DD source and its own DD node projects onto that target through HAS_STANDARD_NAME;
  • the unit and attachment guards still pass for the pairing.

Adoption moves the stub to drafted with pending validation and a linked StandardNameChange (adopt_pending_projection, carrying the adopting source and its path) in the same transaction as the binding. The batch path reserves the source and the rich write binds PRODUCED_NAME; the focused path writes that edge in the same transaction. A pending identity owned by another live claim matches none of the conditions and is refused exactly as before.

The writer that actually composes

An exception is worth nothing where composition refuses to grant it, and the first cut granted it in the wrong place: the enabling call sat on a staging helper no production path reaches, while persist_generated_name_winners — the writer the compose worker reaches through persist_generated_name_batch. The live writer now grants it, so the path that actually composes adopts the stub instead of colliding and parking.

A second defect sat behind the first: the winner split routed adoption to the stable finalize branch, and a projection stub carries a name and a provenance edge but no content. The stable statement binds the source and clears the claim, so the source finished composed while the name stayed drafted with no description, no unit and none of the composed grammar columns — the generated content was discarded at the last step. Adoption now takes the rich name write the reserved path uses, in the same transaction, so the stub enters drafted with the receipt and the candidate's description, unit and composed columns. Only stable_reuse remains in the no-rich-write split, where it is still correct: that target is a live name with its own content.

The cause survives parking

The orphan sweep's parking statement now appends the recorded refusal to the cap message (compose claim-attempt cap reached; last refusal: …) rather than overwriting it, and the undisposed-park reader matches that message by prefix. The tick also passes the wired services to the disposition write, which it previously called without them.
