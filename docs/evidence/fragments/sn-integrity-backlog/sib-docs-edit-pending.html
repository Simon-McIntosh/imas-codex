A docs edit seeds documentation onto an un-started docs axis

apply_edit in docs mode refused any target whose docs_stage was not accepted or exhausted, so an accepted identity whose docs axis had never started (docs_stage='pending', no documentation) could not have documentation seeded: REFUSED: target docs_stage='pending' — docs edits require the docs axis to have settled (docs_stage in accepted/exhausted). The race protection is not the stage test but the edit path's own compare-and-set, which moves docs_stage to refining under a fresh claim_token and so excludes any docs-pool writer. pending is the un-started state and races nothing that claim does not already exclude.

The precondition now admits pending: the stage set is {pending, accepted, exhausted}. The claim and its compare-and-set, the name_stage='accepted' requirement, and the refusal of drafted and refining (stages a docs worker may hold) are unchanged. The comment now states the rule as the claim rather than as a settled-stage list.
