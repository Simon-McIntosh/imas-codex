The signed release can drop an edge to a superseded parent

The release still removes exactly one named HAS_PARENT edge and creates nothing. Its admission now classifies the child and the old parent separately (_structural_release_lifecycle). The exact relationship id and properties, the one-parent count, the closure digest, the receipt and the parentless postcondition are unchanged. This node changes admission only; the graph was not written, and whether a superseded child's other edges or successor change stays open.

The postcondition keeps every check it had: the child has no parent edge, and the child's properties and producing sources equal the signed state. It adds one: the child and the old parent must still be in the supersession class they were admitted in, so a release that leaves a revived parent or child behind is refused.

The new test file has 26 tests over a faked graph, in tests/standard_names/test_structural_release_superseded.py. With the admission reverted to accepted-only, 24 of the 26 fail (EXIT=1): each admission, each named refusal and each postcondition test. The gate went from 96 passed at base to 122 passed at head with zero added failures, and the Cypher property check passed in both arms. The graph-marked release tests were deselected in both arms because no disposable graph was configured.
