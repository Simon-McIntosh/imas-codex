sib-claim-outcome-receipts — every ended claim writes its outcome on the source

A composition claim could end without leaving any per-attempt record. The source carried a single last_error, overwritten by whichever writer touched it last, so a failure census could not tell five refusals from one, nor a batch that raised from a source that was genuinely refused. This node adds StandardNameSourceClaimAttempt, an append-only receipt reached from the source by HAS_CLAIM_ATTEMPT, and writes one entry inside each claim-ending statement.

Claim-ending writerOutcome writtenWhere
Produced-name attachment (candidate binds and the source attaches) produced graph_source_bindings.py, the winner attach statement
Pre-validation and persist refusal writer (_mark_source_prevalidation_failed routes here) refused graph_source_bindings.py, persist_claimed_source_outcomes
Binding and attachment refusal release released graph_source_bindings.py, the collision-release statement
Batch failure (the paid batch raised before any per-source verdict) batch_failed worker_compose_batches.py, compose_batch's except path
Attempt-cap parking sweep capped orphan_sweep.py, the compose_attempt_cap statement

Writers left out, and why

  • release_generate_name_claims / release_generate_name_failed_claims (graph_claim_release.py, called from worker_common.py) releases a claim for retry on the empty- description and worker-failure paths. It is outside this node's write scope, so it appends no receipt; a claim it releases reads as an attempt with no outcome entry until a later node or the sweep accounts for it.
  • graph_catalog.py's PRODUCED_NAME merge is claimed by the sibling node sib-persist-refusal-per-source, so this node leaves it untouched. The produced outcome is recorded at the attach statement in graph_source_bindings.py, which is the fenced writer that ends the claim.

Bounded, append-only, and fenced

The entry identity is claim-attempt:{source}:{claim_seq}:{outcome}. A source holds one claim per sequence number, so the MERGE is idempotent under a deadlock-retried write, and the record is bounded by the claim-attempt cap: a source that fails five times holds five entries and is then parked capped. The standalone writer fenced on claim_token/claim_seq, so a delayed duplicate worker cannot append a receipt to a claim it no longer holds.

Negative control

The declared mutation removes the append from the batch-failure release. Run against it, test_compose_batch_records_the_receipt_before_it_reraises fails and the run exits non-zero. The first version of the tests survived that mutation — they exercised the helper directly — which is why the guard now asserts the call sits inside compose_batch's except block ahead of its re-raise.
