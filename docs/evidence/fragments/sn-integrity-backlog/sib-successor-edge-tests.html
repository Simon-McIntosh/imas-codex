sib-successor-edge-tests — the signed supersede's edge check is isolated and executed

Three follow-ons from the review of the node that retired the successor scalar are closed: the successor_ids clause of the signed supersede postcondition is now isolated by its own unit test and shown to refuse; the graph-marked supersede test is executed against a disposable Neo4j rather than left deselected; and no plan-label test class remains in the graph edge-writer file.

1. The successor_ids clause has an isolating test

In imas_codex/standard_names/signed_manifest.py the signed supersede postcondition refuses unless three clauses hold: the successor edge count is exactly one, its receipt_ids equal the minting receipt, and its successor_ids equal the mutation's declared successor. The pre-existing unit test returned count=0, so its refusal came from the count clause whether or not the id was checked. test_supersede_postcondition_refuses_edge_to_a_different_successor returns exactly one edge whose receipt_ids are the minted receipt — satisfying count and receipt — but whose successor_ids point at a different name, so the refusal can only come from the id comparison.

  • head-new-test.log: 1 passed, EXIT=0.
  • negative-control-successor-ids.log: with the declared mutation — the successor_ids comparison removed and nothing else changed — the same test fails, 1 failed, EXIT=1. The production file was restored afterwards (git diff on it is empty).

2. The re-pointed assertion ran under -m graph

tests/standard_names/test_supersede_successor_scalar.py is marked graph, so the recorded gate of the prior node deselected it. It was run here under -m graph against a fresh disposable Neo4j (the apptainer image started on bolt://127.0.0.1:56001, auth disabled, empty store) rather than the project graph, which the fixture refuses. It passes: the signed supersede writes the receipt-stamped successor edge, the receipt binds predecessor to successor, collateral bytes are unchanged, and a replay is already_applied with zero persistent writes. No test change was needed.
