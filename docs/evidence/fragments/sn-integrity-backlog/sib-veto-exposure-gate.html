What the parent-admission probe now raising exposes

The superseded-parent veto closes a fail-open guard: _filter_admissible_parents used to log a failed topology probe and return every proposed parent edge; it now logs and re-raises, so a reconcile whose probe fails aborts. This measures whether any test in the standard-name suite was passing only because that guard switched itself off.

Answer: no. Running the whole tests/standard_names/ directory plus tests/graph/test_cypher_property_check.py at the veto's base (27a2b4299) and head (06e0451f2) adds exactly two failures, and neither reaches the probe, the veto, or the reconcile. Both are pytest-timeout (>30.0s) on a git subprocess in the release-notes path, and one of the two passes on a serial re-run. No test exercised a fake graph client that raises, so closing the guard exposed nothing that the green suite was resting on.
