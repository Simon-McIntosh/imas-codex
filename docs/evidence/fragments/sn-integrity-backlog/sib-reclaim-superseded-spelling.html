A reclaim is signed and receipted. In one transaction the tombstone is revived at the stage its own reviews earned (superseded_from_stage, capped so acceptance is a review outcome, never a side effect), its documentation, docs stage and ledger are untouched, and the renaming name is retired. A closing-lineage reclaim writes no new REFINED_FROM edge: the chain already runs tombstone → intermediates → renaming name, so an edge back would close a directed cycle and leave the lineage unreadable. A different-locus reclaim links the retired name onto the revived id. A postflight refuses any reclaim that leaves the revived id on a directed cycle. The receipt is a StandardNameChange with operation='reclaim_spelling' whose reason names the case, the two ids and the source cohort. The producing sources then move through retarget_standard_name_sources, the one sanctioned source-move mechanism, and a shortfall raises. A postflight read asserts the tombstone is no longer superseded and carries this reclaim's run_id. Every other tombstone target keeps the existing refusal, which now also names why the reclaim route did not apply.
