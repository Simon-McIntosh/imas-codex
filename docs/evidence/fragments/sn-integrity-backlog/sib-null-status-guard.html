What the guard refuses, and what it accepts

In Cypher, x.status <> 'v' evaluates to null — not true — when x.status is null, and a null filter drops the row. A guard written that way therefore excludes two classes of row and names only one of them. The eight sites repaired under this plan chose their reading deliberately; this test keeps a later edit from reintroducing the silent drop.

A comparison is refused unless it is explicit in one of two ways:

  • the property is read inside coalesce(...), which names the value a null status takes — coalesce(source.status, '') <> 'stale'; or
  • the same alias.property carries an IS NULL or IS NOT NULL test in the same statement, which names the null case beside the exclusion — n.status IS NULL OR n.status <> 'draft'.

The property filter covers status and every _status suffix (validation_status, lifecycle_status, edit_status): a validation or lifecycle status drops a row exactly as a plain status does.

The readers, and why literals are kept

Strings are selected by python_cypher_strings (imas_codex/graph/cypher_property_check.py) and blanked with CYPHER_LITERAL_OR_COMMENT (imas_codex/cli/sn.py), so a string the repository does not read as Cypher is not scanned and a commented-out exclusion is not a finding.

One deliberate difference from the readers' use of that pattern: a quoted run is blanked inside its delimiters rather than whole. The operator being checked sits between two literals, so emptying the delimiters too would delete the comparison along with the value — coalesce(x.status, '') <> 'stale' must survive as coalesce(x.status, '') <> ''. Comment spans still become whitespace, which is what makes the commented-copy arm pass.

What this check does not cover

Cypher accepts != as a synonym for <>. The brief named <>, so != is not detected; no Cypher string in the package uses it today (measured: zero occurrences). A status property compared with IN or = is outside the rule entirely — those select on a value rather than exclude one, so the null row is not silently dropped in the same way.
