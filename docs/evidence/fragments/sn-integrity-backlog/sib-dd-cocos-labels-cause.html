The loss is not in extraction: the labels come from the DD, and the 4.x line dropped the attribute while the 3.x line still declares it. The loss is a delete in phase_build. The stale-label pass nulls cocos_transformation_type on every IMASNode whose id is not in the current build's latest_labeled | backfilled_paths, with no scope filter at all. Reproduction on a disposable graph

Three tests drive the real phase_build against an empty Neo4j (disposable_graph), each with a 3.x version that declares the label and a 4.x version that does not. At base (058c6a1e1, log negative-control-base.log) all three fail:

  • test_full_sharded_build_keeps_every_shards_labels — the equilibrium shard's forward-ported label was cleared; the only label left was the second shard's.
  • test_scoped_build_leaves_out_of_scope_labels_intact — a scoped build cleared a label outside its scope (assert None == 'psi_like').
  • test_full_rebuild_is_idempotent_on_labels — a 3.x-declared label was cleared although a version in the build declares it.

At head (45eb2442d, log head-arm.log) the same three tests pass, EXIT=0.

The fix

phase_build now scopes the clear to what the build examined: it matches only nodes whose IDS unit is in the build's version_data, excludes paths the newest in-scope 3.x version declares a label for (_reference_cocos_labels, shared with the forward-port backfill), and refuses to clear xml or inferred_forward labels at all when no label-declaring version is in scope (an incremental --from-version run starting after the 3.x line). A label can now leave the graph only when a build covering its path, and a version that could declare it, shows the DD no longer declares it.
