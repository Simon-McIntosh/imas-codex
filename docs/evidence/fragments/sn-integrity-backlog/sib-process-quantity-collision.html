A published quantity spelled like a process token is no longer a collision

The export identity-token collision gate now admits a published quantity whose spelling is also a process token. halo_current is a process token and also the halo current, a quantity with physical base current. The gate refused it as an identity standing in for a grammar token. Under the lead's 2026-11-11 ruling that "due to X" names the quantity X as its cause, the process segment is exempt when the grammar parses the identity with a physical base; every other segment, and every process token the grammar cannot parse, still collides.

The refusal, reproduced

At base 06ac2d0c2 the gate refuses the identity with one issue:

gate passed: False issue count: 1
identity_token_collision halo_current process

Run at head the same gate call passes with no issue. Over the live published population (1,975 emitted identities in the day's export report) the base predicate reports exactly one issue, ('halo_current', 'process'), and the head predicate reports none, exempting that one identity with base current.

The live dry run

uv run imas-codex sn release --dry-run over the live graph reads 2,865 candidates and 1,975 emitted identities, and reports identity_token_collision passed=True issues=0 advisories=0. halo_current is among the emitted identities, so the pass is not an absence of the case the gate exists for. Every other gate in that report passes as well, with all_gates_passed true. The dry run then stops at the publisher's lock file, which is a read-only ISNC checkout in this sandbox rather than a gate failure; the export leg and its report are complete before that point.
