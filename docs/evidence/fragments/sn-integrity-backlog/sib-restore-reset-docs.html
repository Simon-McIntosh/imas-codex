Restore through the signed repair manifest

The reset has no inverse: promote.py records the design position that a wording revert is a new sn edit, and the generic signed path's set_properties mutation is refused by the structural-legitimacy guard on every name that owns a live structural child — 179 of these 391 do. A first pass through set_properties therefore restored 212 of 391 names, and the remaining 179 needed a writer the guard admits. The write site is now signed_manifest.py's purpose-built docs-revision-restore adapter, whose single mutation restore-documentation-from-revision writes the documentation fields the named DocsRevision snapshot carries (documentation, description, review score, docs model, chain length) plus docs_stage='accepted', and nothing else. It can name neither a structural property nor a relationship, so the guard admits it where set_properties is refused; every other mutation kind keeps the guard unchanged. A payload naming any non-documentation property is refused with the field named, and every write is checked against the target's id, name, unit, kind, physical base, lifecycle stage and full relationship closure before and after it, so a restore that would change structure fails instead of writing. Each receipt records the snapshot id on the change (docs_revision_id). Raw Cypher is never used for a write.

Restore result: all 391 partition-(c) names are docs_stage=accepted again, and every one reads back its own snapshot's documentation. 212 were restored through set_properties in the first pass; the remaining 179 went through restore-documentation-from-revision in two signed cohorts of 90 and 89 rows, both of which previewed would_apply with no refusal and applied in full. The controlled field is docs_stage and the documentation text.

The first pass stopped short because set_properties is refused by the structural-legitimacy guard with target has a live structural child on 179 of these names; the docs-revision-restore mutation is what completed them. Both passes share one other constraint: a cohort preview re-read a few minutes later produces a fresh closure digest that no longer matches the authorized manifest_sha256, so each cohort is previewed immediately before its apply. Applied cohorts are replay-detectable (already_applied), which is how the second pass resumed from the 212 already restored without re-writing any of them.
