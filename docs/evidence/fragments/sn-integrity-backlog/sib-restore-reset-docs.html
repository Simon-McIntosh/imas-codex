Restore through the signed repair manifest

No purpose-built writer restores documentation from a DocsRevision: the reset's inverse does not exist, and promote.py records the design position that a wording revert is a new sn edit. The restore therefore goes through the repository's signed repair path — build_repair_authority schema imas-codex.repair-authority.v1 applied by apply_signed_manifest — with one set_properties row per name carrying its snapshot text and a row id restore:<name>:<DocsRevision id>, so every admitted row's receipt names the snapshot it restored from. Raw Cypher is never used.

Restore result: __RESTORE_RESULT__. The controlled field is docs_stage and the documentation text; the read-back below compares each restored name's live documentation to its snapshot text and its docs_stage to accepted.
