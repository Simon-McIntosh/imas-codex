The path driven

A compose pass that recomposes a name for a DD source writes the successor's PRODUCED_NAME binding, then calls graph_ops.supersede_prior_source_names to retire the predecessor and restore the invariant one source → at most one live pipeline name. That helper runs a preflight to enumerate the judged source set, admits the pairings via guard_source_pairings, then delegates the move to provenance_lifecycle.retarget_standard_name_sources. The fixture drives that whole chain over one DD source whose only binding evidence is two live PRODUCED_NAME edges: the predecessor it is meant to retire and the successor this pass just wrote.

Reproduction

The migration's compare-and-set distinguishes two refusals: SourceBindingConflictError, a named, adjudicable conflict whose docstring states a caller should withhold a retry budget because repeating the migration changes nothing; and an anonymous RuntimeError for every other ineligible state, which callers treat as a transient fault and spend a retry budget on. A source bound to two live identities takes the second branch.

Verbatim, forced past the xfail with --runxfail:

raise RuntimeError(f"source migration compare-and-set failed: {details}")
E   RuntimeError: source migration compare-and-set failed: dd:example/predicted_path(exists=True, status='composed', claimed=False, bindings=['example_new_name', 'example_old_name'], scalar='example_new_name')
FAILED tests/standard_names/test_compose_supersede_dual_bound.py::test_compose_supersede_over_dual_bound_source_is_not_an_anonymous_fault

Both handlers sit inside retarget_standard_name_sources. The pending branch admits a source only when its live bindings are exactly [old_name]; the dual-bound source carries [new_name, old_name]. The completed branch admits exactly [new_name]. The named-conflict branch is reached only when _live_foreign_bindings finds a live holder outside the migration's own name pair — but here both holders (old_name and the just-written new_name) are inside that pair, so the holder set is empty and the guard falls through to the anonymous branch. The failure is therefore hard: the RuntimeError escapes supersede_prior_source_names and rolls the caller's transaction back, and its type reports a transient fault where the condition is a decision.

Caveats

  • The fixture drives the real supersede_prior_source_names and the real retarget_standard_name_sources; only guard_source_pairings is stubbed to admit the source, so the reproduction isolates the compare-and-set routing and is independent of whether the attachment guard would separately reject a dual-bound source. A live-graph run could reach the guard first; if it did, its refusal is a ValueError raised before the failure recorded here.
  • The transaction runs against a fixture handle, so the rollback is read from graph_ops.persist_generated_name_winners (the except BaseException around tx.commit() at the call site), not observed live.
