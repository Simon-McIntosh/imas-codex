Ten public graph entrypoints were bound through a split string, and no check could read them

The standard-name composition root re-exposed ten public callables, and provenance_lifecycle.py one more, by assigning through globals()[ with a key built from two string literals, as in globals()["reconcile_" + "error_siblings"] = _error_sibling_reconcile_apply. The AST of that statement carries a Subscript target, so every audit that collects assignment targets skips it while getattr() resolves the name normally. Measured against _collect_def_names in tests/standard_names/test_public_api_naming.py, the audit that governs every public name in this module: at base 0 of 10 of these names are visible, and after the change 10 of 10 are. The bindings now stand as plain module-level assignments, so the audit reads the same name the interpreter does. A new guard refuses the pattern itself, and no non-literal globals() lookup remains anywhere under imas_codex/: the last one, in worker_tasks' composition root, now reads a declared collaborator map. The same change widened the facade-closure audit so it sees the functools.partial entrypoints it had been dropping. The split was not contrived to defeat a specific assertion — see "Why the pattern existed" below, where spelling the names whole is measured against every candidate guard and none fires.

Every one of these names is imported from the composition root by test modules; one is imported by product code. The implementation of each lives in a graph_store module as a functools.partial over apply_signed_manifest, which is why the public name had to be carried somewhere.

Why the pattern existed, measured

The pattern enters at bd34e9631, whose body records its intent: "preserving the existing public callable and behavior" while the body moved to signed_manifest.py and then graph_store. A def forwarder is refused outright by test_facade_closure.py::test_facades_define_no_delegating_forwarder, so the natural spelling was unavailable and the name was bound at runtime instead.

The obvious hypothesis — that the split was written to get past a guard — does not survive measurement. With the names spelled whole, every candidate guard passes:

  • tests/standard_names/test_facade_closure.py — 6 passed (EXIT=0, logs/facade_after.log);
  • tests/standard_names/test_public_api_naming.py — 33 passed.

Two structural reasons, both measured: the owner map lists the private functools.partial implementations, and _moved_callables() filters them out because a partial's __module__ is "functools" rather than the owning module, so test_entrypoint_refuses_moved_symbols never examines them; and the public names are absent from the owner map altogether, so nothing resolves them. What the split actually bought was invisibility, not permission: a name no audit and no grep can read. That is the defect the plan records, and it is what this change removes.

What replaced it

Each binding is now a plain module-level assignment in the module that carries it, so the same name is visible to grep, to ast, and to the composing audit — the interpreter and the reader now agree. The service bridge fallback in graph_ops._GraphServices.__getattr__, which read globals()[name] for any wired collaborator the owner map did not resolve, is replaced by a declared mapping. Measurement of what that fallback actually served: of the 186 wired names, 185 resolve through the owner map and 1 (__file__) resolved locally, so the declared mapping holds exactly that entry and an unwired name is now refused with the closure message rather than raising KeyError.

The worker composition root carried the same shape one level down: worker_tasks asks workers._worker_dependency(name) for the thirteen collaborators it does not take from the owner map, and that function read globals()[name]. It now indexes a declared map whose values read the module attribute when the name is requested, not when the module is imported. Holding the imported object itself is what a frozen map would do, and it is measurably wrong here: the suite replaces these collaborators by dotted path — monkeypatch on "imas_codex.standard_names.workers.model_provider_exposure" — and a frozen map bypassed every such replacement, turning stubbed pricing into a live ProviderPricingUnbounded lookup. Measured on the head tree, that cost 65 added failure ids, all of which clear once each value is read at request time. The declared name set stays static and greppable, which is what the guard exists for; only the read is deferred.

The guard

tests/standard_names/test_no_split_name_bindings.py parses every .py under imas_codex/ and refuses two shapes, with no exemption list:

  • a globals()[ subscript that is an assignment target whose key is not a string literal (test_no_dynamic_name_binding);
  • a globals()[ subscript used as a lookup whose key is not a string literal (test_no_dynamic_name_lookup).

Negative control, declared mutation plant globals()['a' + 'b'] = f in a scratch module; the guard must fail — a scratch module carrying that statement was planted under imas_codex/, the guard run, and the file removed in the same command. Result: 2 failed, log ending EXIT=1 (logs/negative_control.log), with test_no_dynamic_name_binding failing — an id the head arm does not fail.

No site remains: grep -rn "globals()\[" imas_codex | wc -l returns 0 on the head tree, against 12 at base: eleven split-string bindings and one dynamic lookup. The same guard was extended to the facade-closure audit, whose moved-symbol set dropped every functools.partial because a partial reports "functools" as its __module__. Counting a partial as owned when its owner module's namespace carries the name brings the ten manifest appliers back into both the entrypoint scan and the forwarder scan. That widening has its own negative control: with reconcile_error_siblings() re-planted in graph_ops.py as a one-line forwarder, test_facades_define_no_delegating_forwarder fails with EXIT=1 (logs/negative_control_forwarder.log), and the plant was removed in the same session.
