Which sanctioned path can reverse a signed retirement

There is no command that un-supersedes a tombstone on its own. The two adjacent paths were read and neither reaches this state:

  • sn restore (imas_codex/cli/sn.py:8890, 8932, 8982) reconstructs an absent identity from an archived extraction. It composes an authority that creates the node and its edges; it is the adapter §8 used to rebuild deleted identities, and it does not restore a present tombstone's stage.
  • sn supersede --into (imas_codex/cli/sn.py:7469) revives a tombstoned target only as the destination of a fold that carries a live source onto it. A revival writes what the repository's own revival rule restores: name_stage from superseded_from_stage capped by _FOLD_REVIVAL_STAGE_CAP, and status='draft' (imas_codex/standard_names/edit.py:2214-2235, 2935-2949). This name carries no source to fold, so no fold can reach it.

The write therefore used the repository's generic signed path, set_properties under apply_signed_manifest (imas_codex/standard_names/signed_manifest.py:4850-4893), writing exactly the two properties the revival rule writes: name_stage='exhausted' and status='draft'.
