Landing record: the signed supersede mutation mints its receipt-stamped successor edge

A signed supersede now MERGEs (predecessor:StandardName)-[:HAS_SUCCESSOR {receipt_id, signed_at}]->(successor:StandardName) inside the same apply, in imas_codex/standard_names/signed_manifest.py. The edge carries the minting receipt's id in receipt_id, so a signed edge is distinguishable from one a scalar-derived rebuild creates, which carries no such property. superseded_by still writes. A missing successor leaves the edge unwritten through an OPTIONAL MATCH … FOREACH guard.

The mutation's postcondition now requires that edge: it reads the HAS_SUCCESSOR relationship, requires exactly one row, and requires its receipt_id to equal the receipt the apply minted for that row. A supersede whose edge is absent or unstamped raises SignedManifestConflict.

Pinned by tests/standard_names/test_signed_supersede_edge.py: one test applies a signed supersede on a disposable graph and asserts the edge reads back with the minting receipt's id; one asserts the postcondition refuses the supersede when the edge write is stubbed out. Gate: base 166 passed, EXIT=0; after 168 passed, EXIT=0 — the two new tests, zero added failures.
