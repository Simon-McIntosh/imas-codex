The gap this closes

source_invariant.require_producing_sources already refuses a write that leaves a live name without a producer, but every writer passed it only the names it was writing, never the name losing the source. A writer that moved a name's last source therefore reported success while the former holder stayed live, non-derived and sourceless — the shape that produced 122 of the 156 lost catalog sources.

Mechanism

One builder, supersede_drained_name_cypher in source_invariant.py, writes the whole supersession: it filters the names a write touched down to those the graph agrees are live, non-derived, have no successor path to the new holder and have no non-stale PRODUCED_NAME source left; then it retires them (name_stage and status = superseded, claim fence cleared), merges (new)-[:REFINED_FROM]->(old) and creates the StandardNameChange receipt linked by HAS_INTERNAL_CHANGE — the successor edge that carries its own receipt. It never refuses the write: the ruling is that the write happens and the drained name is superseded.

The builder is embedded where each writer already runs, so the supersession commits or rolls back with the write that caused it and no writer gains a second statement. Where it is embedded it evaluates the guard into a flag and applies the update through a FOREACH, because a filtering clause inside a CALL subquery also removes the pair from the enclosing statement, and the write would then report that it moved nothing at all:

WriterWhere the clause runs
retarget_standard_name_sourcesfused into the compare-and-set migration statement, after it has moved the admitted cohort
mark_sources_composed / mark_sources_attachedfused into the source-move statement, which also drops the predecessor's stale PRODUCED_NAME edge so the move is a move
_lock_claimed_name_bindings callers (persist_claimed_attachments, stage_claimed_generated_candidates)the provisional-edge cleanup now reports the drained source ids, and the same transaction supersedes each former holder
bind_recovery_sourcesinside the write transaction: prior holders are captured, the stale edge is deleted, then each is superseded
persist_refined_namereaches it through the retarget above; the refine statement already retires its predecessor, so the clause is a no-op there rather than a second retirement

Derived parents stay exempt, for the same reason the invariant exempts them: a structural parent has children, not sources.

Negative control

Declared control: each per-writer test must fail on main because the losing name stays live with no source. A git archive tree of the base revision runs the same test file with the same fixture; the per-writer cases fail there and the keep-another-source control passes on both arms, which is what separates "the write is wrong" from "the test is wrong".
