The catalog approval tests timed out on a PATH git wrapper, not on their fixtures

Integration note (2026-10-13): the diagnosis below is kept; the test change it describes was not merged. That change pinned the real git ahead of the worker wrapper inside the test modules, which bypasses a sandbox component for every worker that runs them. On main the approval tests are unchanged: they pass outside a worker sandbox and time out inside one until the wrapper's per-call startup cost is fixed in reckon. Where this record says the files now pass, it refers to the unmerged change.

A gate on 2026-10-12 reported tests/standard_names/test_sn_approve_tag.py with 23 setup errors and 2 failures, and tests/standard_names/test_sn_approve.py with 3 setup errors, tracebacks suppressed. Reproduced here with tracebacks, the cause is the worker sandbox's git wrapper on PATH: it pays a full interpreter start for every invocation, and these git-heavy tests cross the 30 s per-test timeout. No product defect. The two files now pass (61 passed, 15.18 s, EXIT=0) and the change is module-local.

The gate's 26 setup errors are the same cause at its heavier load: a test item's setup is charged against the same timeout = 30, and a fixture that builds a repo with a dozen git calls (≈15 s idle here, more under load) crosses it during setup — reported by pytest as a setup error, not a failure. It did not reproduce here because this node's load kept setup under 30 s.

Cause: the PATH git wrapper

The fixtures are already self-contained: a local bare repo (git init --bare) as origin, and git config user.email/user.name set per repo — no network, no dependence on a global identity. The environment fact each failure depends on is which git a PATH lookup resolves. Inside this worker run, shutil.which("git") returns the crew worker shim /home/ITER/mcintos/Code/reckon/reckon/worker_shims/git — a /bin/sh wrapper that starts a Python interpreter to import reckon — ahead of /usr/bin/git.

Measured per-call cost of an ordinary local git operation, spawned exactly as a test's _git does (subprocess.run(["git", ...])):

InvocationWall time
git init -b main0.91 s
git config user.email t@t1.01 s
git add f1.04 s
git commit -qm x1.02 s
git rev-parse HEAD (read-only)1.04 s
/usr/bin/git --version0.11 s

Every wrapped call costs about one second regardless of the verb. A test that makes thirty git calls therefore spends thirty seconds in process startup alone, against a 30 s bound. Bypassing the wrapper for the same tests collapses the cost: 

PATH=/usr/bin:$PATH UV_PROJECT_ENVIRONMENT=... uv run pytest ... \
  tests/standard_names/test_sn_approve_tag.py::TestApprovedCatalogMaterialization \
  tests/standard_names/test_sn_approve_tag.py::TestApprovalCliTag::test_undo_restores_the_exact_rc_tag

Result: 4 passed in 9.15 s; the same fixtures' setup fell from 15–16 s to 0.15–0.49 s (log bypass-shim-3tests.log). The failure depends only on the sandbox, so the fix makes the tests independent of it.

Repair

Each file resolves the compiled git binary (skipping any PATH entry whose git begins with a #! shebang, i.e. a wrapper script) and pins it ahead of PATH in an autouse fixture, so both the tests' _git helper and the product code that shells out to git resolve the real binary. Files changed: tests/standard_names/test_sn_approve_tag.py, tests/standard_names/test_sn_approve.py.
