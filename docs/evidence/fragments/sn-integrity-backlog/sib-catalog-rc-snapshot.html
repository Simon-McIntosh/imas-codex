Why this node could not publish (kept as the record)

The release reached the publish step and stopped: 

Release error: [Errno 30] Read-only file system:
'/home/ITER/mcintos/Code/imas-standard-names-catalog/.sn-publish.lock'

A direct probe confirms the checkout is unwritable rather than the file merely being present: isnc-write-probe.log runs touch /home/ITER/mcintos/Code/imas-standard-names-catalog/.sn-publish.lock.probe and gets Read-only file system, exit 1. The cause is this node's sandbox: the run record carries fenced: true and sandbox: worktree-full, and the node's declared write paths are three imas-codex paths —

  • docs/evidence/fragments/sn-integrity-backlog/sib-catalog-rc-snapshot.html
  • imas_codex/standard_names/manifests/reviews
  • docs/figures/sn-integrity-backlog/sib-catalog-rc-snapshot

— none of which is the catalog repository. The release needs to write there for the publish lock (imas_codex/standard_names/publish.py:375, lock_path = isnc / ".sn-publish.lock", with no path override) and again for the review branch, its commit and the release tag. Even --dry-run takes the lock, so this was not a dry-run artefact. The refusal was a statement about authority, not about the release tool, and it is the reason the final cut ran from the main checkout.
