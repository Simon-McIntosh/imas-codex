The gate, and the identity behind it

The gate rejects a published identity that is also a grammar token belonging to a non-quantity segment, because publishing it would make the catalog name indistinguishable from a structural vocabulary token. Its own issue record:

 "registry_entry": "runtime ISN vocabulary:line unavailable",
 "detail": "published identity 'halo_current' equals grammar token
            'halo_current' in non-quantity segment 'process'"}

The identity is not a documentation casualty and not an unfinished row. Read from the live graph (halo-current-identity.log) it is name_stage='accepted', docs_stage='accepted', validation_status='valid', kind='scalar', physics_domain='magnetohydrodynamics', with one producer (derived:halo_current) and two children, poloidal_halo_current and toroidal_halo_current. So it is a derived parent whose documentation was reviewed and accepted, and the block is vocabulary rather than lifecycle: the name it publishes is a token the grammar already spends on a process.

Pin equivalence, and why the version string is not the pinned literal

imas-standard-names is an editable dependency resolved to the sibling checkout ../imas-standard-names. That checkout's head ef1bc401e8 is one commit past the v0.11.0 tag 9c9443370d, so hatch-vcs stamps the distribution 0.11.1.dev1+gef1bc401e while the imported code is the pinned release plus a documentation commit: git diff v0.11.0..HEAD -- imas_standard_names/ prints nothing, zero lines. The version string is a sync artifact; the code is the pin.

The dry run sees this refusal, and that is a difference from the batch path

For this whole-catalog attempt the dry run propagated the gate and exited 2, naming it. That is worth recording beside the earlier WEST batch attempt, where the same dry run measured the export leg in a scratch tree and still exited 0 without printing any gate verdict, so that node reached the cut believing its preflight was complete. The visibility therefore differs by path: a whole-catalog cut is visible at the dry run, a --batch cut is not.

What unblocks the cut

  1. Resolve the collision. halo_current must stop being the published identity, either by a rename through the sanctioned sn edit path, which runs the generate, review and score pipeline, or by a grammar-side decision that the token may also name a quantity. Both are graph or vocabulary decisions this node may not make, and --skip-export is the one route the tool offers for crossing this gate, so it is not a route.
  2. Re-run the same command unchanged: the whole-catalog dry run and cut need no batch identity, and everything else is already established by the logs above.
  3. Then run recipe step 6's tag gate on the pushed tag and the preview check, which this node has not been able to reach.
