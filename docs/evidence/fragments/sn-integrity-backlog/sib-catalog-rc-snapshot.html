What the pin mismatch is, and what it is not

imas-standard-names is an editable dependency of this repository: [tool.uv.sources] resolves it to the sibling checkout ../imas-standard-names, and the installed _editable_impl_imas_standard_names.pth points at /home/ITER/mcintos/Code/imas-standard-names. The imported code is therefore the live sibling tree, which sits at ef1bc40, git describe --tags = v0.11.0-1-gef1bc40 — the pinned release plus one documentation commit. The 0.10.1 figure is the distribution metadata written at the last environment sync, not the release the pipeline is executing, so the kind derivation above already runs on the 0.11.0 bases.

That distinction does not clear the gate as the recipe states it, and it cannot be cleared from inside this node: a rebuild of the editable distribution at ef1bc40 yields a 0.11.1.dev1 development version rather than 0.11.0, because the tag is one commit behind the checkout head, and reaching a literal 0.11.0 would mean moving the shared grammar checkout onto its tag. The substance the gate protects — reconciling against the pinned bases — is instead proven by the editable path and shallow history above.
