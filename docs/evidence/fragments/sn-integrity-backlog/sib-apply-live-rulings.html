The separatrix temperature swap, unapplied

The swap has two halves: move electron_temperature_at_separatrix off the flux-surface-averaged DD path onto the local one, then bind bulk_electron_temperature_flux_surface_averaged_at_last_closed_flux_surface to the averaged path that leaves free. The holder migration is previewed as the envelope's single closed ordinary-source migration, with the local path's source as the migrating source and the ruled receiving name as its target. That name reads accepted with validation valid, as the ruling required. The row is refused: signed ordinary source lifecycle does not match migration authority. The refusal is about the migrating source, not the receiving name. The program retargets one source between two names and holds that source's own DD path invariant, so the source it moves must be the one already holding the binding the row removes. The swap needs the opposite: the name keeps its identity and the DD path behind it changes. The pair's only other row the program can shape, which reinstates the averaged source at the name it already holds, is refused as well, with target would lose its last producing source: the guard reads the removed edge as leaving the name unproduced. Neither shape therefore performs any part of the swap.

The averaged-path binding is not run. Its precondition is that the averaged path holds no name, and it still holds electron_temperature_at_separatrix; bind_recovery_sources is add-only, so running it first would MERGE a second PRODUCED_NAME edge onto a source that is still attached, leaving the source's scalar disagreeing with the edge that remains.
