How each plant was applied

The four plants whose subject is in this node's write paths were applied in the worktree and reverted with git diff --stat confirming an empty diff afterwards. The fifth subject is the finalize statement in graph_catalog.py, which a concurrent node owns, so that plant was applied to a copy of the tree under $TMPDIR and run there with PYTHONPATH pointing at the copy; the copy was removed afterwards. Its two runs are the plant 5 and plant 5b sections of the log, whose header lines record the scratch tree's path.

The first attempt at plant 5 inserted into the reserved-name finalize block and the guard passed: that block is not the one a stable successor binds through. The plant was moved to the stable block, where the guard reddened. That failed attempt is recorded because a plant that never reaches the statement under test is indistinguishable from a guard that does not bite — the guard's own positive control (the bound sn_id is the successor) is what showed the statement had run at all.

The guards run through one shared scaffold

Review scored reuse below its floor: the added guards each rebuilt a collaborator scaffold the suite already owns. Three duplications were removed, with no assertion changed. The compose tests now share one _run_batch helper that patches the structured call and drives the batch, instead of five tests each writing that block. The pending-count double and the equality assertion answer through one _restrictions helper, so a count and a selection cannot disagree about what a clause restricts. The successor-binding guard reads the shared TransactionDouble's own calls log — the double records every statement (cypher, params) it is sent — rather than wrapping the side effect a second time.

Measured at the repair commit: patch sites for the structured call 5 → 1, claimability computations 3 → 2 (the helper and its one caller), statement-log implementations unchanged at 1 with the local wrapper deleted.
