Is the generator still open?

Yes. A DD rebuild stamps the path absent from the current DD with lifecycle_status='removed'; the next reconcile run marks every source still pointing at it stale.

  • stale query: imas_codex/standard_names/graph_store/graph_audits.py:600
  • stale write: imas_codex/standard_names/graph_store/graph_source_bindings.py:2468
  • lifecycle stamp: imas_codex/graph/dd_lifecycle.py:110
  • name handling: Nothing. reconcile_standard_name_sources returns stale_marked, revived and relinked counts; it never reads the name that PRODUCED_NAME pointed at and never writes a supersession.

The supersession helper exists but reconcile never calls it: imas_codex/standard_names/source_invariant.py:58, imas_codex/standard_names/source_invariant.py:27. The invariant runs inside a writer's transaction. Reconcile marks the source stale by setting a property; no writer runs, so the name is never tested for having lost its last producer.

What the rename records miss

dd_path_index walks only <field> elements and reads change_nbc_previous_name from them; the renamed <IDS> element's own change_nbc_previous_name is never read, so an IDS rename has no RENAMED_TO edge and no renamed_to property.

An array-of-structures rename is not carried by the DD 4.1.1 XML's change_nbc_previous_name either; it surfaces only by structural inference over the current DD's own paths.

Successor discovery methods across the 65 distinct stale paths: ids_rename_dd_xml 7, none 39, renamed_to_edge 15, structural_inference 5.

Repair node

Goal. Supersede a standard name in the same transaction that marks its last live source stale, so a DD removal can no longer leave a live name sourceless.

Guard test. tests/standard_names/test_source_invariants.py::test_removal_marks_last_source_stale_and_supersedes_its_name -- seeds a live accepted name with one source pointing at a removed DD path, runs reconcile_standard_name_sources, and asserts the name carries a successor edge and no non-stale producer. It fails on main: the fixture section below runs that exact scenario against today's code and the name keeps accepted/draft with zero non-stale producers.

Where the source has no recorded successor, the name is retired without a successor link rather than rebound to a guess; where another live name already holds the successor path, the edge points at that holder.
