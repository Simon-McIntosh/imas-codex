Dual-bound source compose refuses without spending an attempt

A compose pass that meets a source already bound to two live identities is an adjudicable conflict, not a transient fault, so it must not spend a retry attempt. Three defects in the compare-and-set refusal are repaired.

  • The named refusal now has a consumer. _persist_description_checked_candidates in imas_codex/standard_names/workers.py catches SourceBindingConflictError at the persist boundary, records the holding identity and stage, and withholds the source — no claim is released to retry, so no attempt is spent; the source is left for adjudication.
  • A retired holder no longer counts as live. The dual-bound classification in retarget_standard_name_sources counts only identities at a non-retired stage, so a source bound to a live predecessor and a retired successor is not reported as a conflict.
  • The holder is named correctly. For a dual-bound source the refusal names the live successor holding the binding rather than the predecessor being retired.
