The startup drift refresh compares each source against its own snapshot

The startup DD-source drift refresh compared every producing source of a name against the name's single source_path snapshot. A name with more than one DD source therefore read as drifted whenever a sibling source resolved to a different path — not because anything had changed, but because the comparison was between two different sources. Every such row steered a documentation refine and reset the name's docs. This node compares each binding against the snapshot that belongs to that source, and keeps a RENAMED_TO path move classified as a rename rather than a steering delta.

Mechanism

  • _RESOLVE_SOURCE_TERMINAL binds recorded_binding: true when the source's anchor is the identity the name's snapshot was taken from, or is connected to it by a RENAMED_TO move in either direction.
  • The snapshot fields that reach the comparison are per source: old_path, old_unit and old_doc take the source's own captured dd_path, dd_unit and dd_documentation, and fall back to the name's snapshot only for the recorded binding. A sibling source is never compared against another source's snapshot.
  • _source_deltas compares a field only when the source carries it, so a binding with no snapshot of its own produces no delta at all rather than a spurious path difference.
  • The provenance fields — raw unit, raw documentation, resolution identities, digest, typed marker — describe the name, so they are compared only for the recorded binding.
  • A source_path difference the RENAMED_TO lineage fully explains — the per-source snapshot path is a direct or transitive ancestor of the resolved terminal — is carried as a delta flagged "rename": true. It is reported, counted in the renamed counter, and excluded from requires_steering, so it re-stamps the snapshot without resetting documentation.
  • Units and documentation deltas steer exactly as before, and a path change no lineage explains still steers.

Measure: read-only live dry run

Both arms are refresh_drifted_sources(dry_run=True) against the live graph from a git archive of the pre-node revision 55af2a7ff with the main checkout's .venv; the after arm carries this node's working tree.

The drift population falls from 1061 names to 84, and 13 of the remaining rows are lineage-explained renames that now re-stamp instead of steering: 977 of the previous reports were sibling sources compared against another source's snapshot.

A census over the after arm resolves the 84 that remain: 72 carry a units delta, 13 a lineage-explained source_path rename, and 1 a documentation delta (one name carries two of these). All 72 unit deltas compare a source's own captured DD unit against the live node's unit, for example co_passing_thermal_particle_source_rate (s^-1.m^-3) and diamagnetic_conductivity (ohm^-1.m^-1); they are real per-source unit changes and keep steering, as they should.

Tests

  • Seven tests in tests/standard_names/test_source_refresh_rename_lineage.py: a lineage-only move steers nothing, counts one rename and re-stamps the terminal path; its delta carries "rename": true; a lineage move plus a unit change still steers; a path change with no lineage still steers; a two-source name whose second source is unchanged does not steer (the sibling is never compared against the name's snapshot); a single-source name whose own path or unit genuinely changed still steers; and the detect query still asks the graph for the rename flag.
  • Gate: tests/standard_names default tier, both arms from a git archive of revision 55af2a7ff with the main checkout's .venv. Base 22 failed / 8626 passed; head 22 failed / 8633 passed (the seven new tests). The failing-id sets are identical, so this node adds no failure.
  • Negative control: with the three lines that implement the lineage rename reverted, 4 of the 7 fixtures fail, including test_lineage_only_move_steers_no_docs_reset_and_counts_one_rename, which then steers a docs reset again.

Limits and notes

  • The shared .venv does not carry pytest-xdist, which the gate command needs. A uv sync --extra test against the main checkout is refused as a read-only file system under the worker fence, and duplicating the environment is not permitted, so the gate runs with an ephemeral overlay (uv run --no-sync --with pytest-xdist), which installs nothing into the shared environment.
  • The 72 residual unit deltas are genuine per-source changes, not sibling artifacts; whether their documentation refine is the right response is the existing drift policy and is not changed here. A source that carries no captured unit and is not the recorded binding is not compared on units at all, so its unit drift is not reported.
