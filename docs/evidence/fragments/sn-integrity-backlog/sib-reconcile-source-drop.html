Why the writer invariant did not refuse it

The source invariant is consulted by writers around a move or a bind: find_sourceless_live_names and require_producing_sources in source_invariant.py answer whether a live name still has a producer, and supersede_names_losing_last_source is the writer that acts on the answer. This reconcile is neither. It performs a bare edge deletion plus a stage change in one statement, consults no invariant, and has no branch that could refuse. The invariant is correct and was never asked.

The repair

grammar_adapter.parse_canonical_name(name) is the predicate: it is the strict writer's own parse, returning the canonical IR and raising when the spelling is not exactly canonical. The reconcile treats a refusal as not reusable, so a name compose cannot mint keeps its producer. The parse diagnostics cannot stand in for this: _parse_grammar reports [] for a rejection and for a valid name carrying warnings alike, so it cannot distinguish accept from reject. An unavailable grammar package also answers not accepted, because compose cannot mint a name without the parser either.

reconcile_descriptionless_composed_names now reads its candidates, partitions them by that predicate, and re-opens only the names compose can mint again. A name the strict writer rejects keeps its composed producer, stays live and claimable, and is logged by id: its only correct destination is a signed retirement with a named successor, which is a separate authority. Everything else about the re-open is unchanged, including the active-claim exclusion and the idempotence rule.
