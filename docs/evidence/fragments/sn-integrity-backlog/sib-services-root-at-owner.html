Landing record: the storage layer installs the services it reads

Nineteen lines across two product files, plus one new test. The graph store reaches its collaborators through a composition root that was installed only as a side effect of importing imas_codex.standard_names.graph_ops. Every storage-module reader calls foundation.get_services(), so a reader imported by an entrypoint that never imported the facade — a CLI command, a worker task, a test — refused with Graph services are not wired; import graph_ops first. sib-red-export-accounting worked around that at one call site; this node moves the install into the module that owns it, so every entrypoint into the storage layer gets it, and removes that call site.

Reproduction before any change

A fresh interpreter that imports a storage reader and nothing else, calling classify_sourceless_standard_names with a client that is never meant to answer, at the assigned base abb08fa730: 

graph_ops imported: False
services initialized: False
RuntimeError: Graph services are not wired; import graph_ops first

The same probe at head prints wired: reader read the services before touching the client and exits 0: the reader installs the root on its own first read and then reaches the client, which is the whole of the change.

The fix

get_services() imports the composition root when the module-level services are still uninitialized, and services_for_call() becomes a delegation to it — one install path, in the module that owns the services, and no new public name. None keeps its distinct meaning: an explicitly removed root still raises, which is what tests/standard_names/test_package_import_boundaries.py::test_unwired_graph_services_refuse measures by setting the module attribute to None. That guard passes unchanged.
