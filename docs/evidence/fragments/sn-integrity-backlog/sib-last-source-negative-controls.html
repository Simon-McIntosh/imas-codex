Two properties no test guarded

The hardening that made the last-source supersede atomic (graph_store/graph_source_bindings.py) and made the drained receipt unconditional (provenance_lifecycle.py) landed with neither property guarded. Its review found that reverting either left every test green: the move primitive had no test that makes the receipt write fail, and retarget_standard_name_sources was only ever driven with record_change=True while all four production callers pass False, so reinstating the removed guard reddened nothing.

The three tests added

  1. Atomicity. test_failed_receipt_rolls_back_the_move_and_the_supersession patches source_invariant.record_supersede_receipts to raise, drives mark_sources_composed, and asserts the exception propagated while the source still produces the former holder (status still extracted), the holder is still drafted with no successor, and no composed_source_moved receipt exists.
  2. The receipt under record_change=False. test_retarget_writes_the_drained_receipt_when_no_change_is_recorded drives the retarget primitive exactly as the four production callers do and asserts the drained holder is superseded and carries its last_source_supersede receipt, while the operation receipt is absent — which is what the flag suppresses.
  3. The non-GraphClient branch. test_duck_typed_client_leaves_the_move_committed_when_the_receipt_fails passes a client offering only query. It documents that this branch has no transaction to enlist in, so a refusing receipt writer leaves the source moved and the holder superseded with no receipt. Recorded under outside_scope; no product change was made.
