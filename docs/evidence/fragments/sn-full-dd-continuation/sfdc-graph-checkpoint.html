The export

The command was uv run --directory /home/ITER/mcintos/Code/imas-codex --no-sync imas-codex graph export, run with no --no-restart so that stop and restart are one step. It ran from the main checkout from 08:15:38Z to 08:32:07Z. It stopped the service (codex-neo4j, job 1310901), dumped 2,615.7 MB, wrote the archive and then restarted — and the restart is the one step that failed. Its own sbatch was refused by the nested-launch guard with exit 97, because the export ran inside SLURM job 1291586, so the command exited 1. The graph was down for about forty seconds and was then restarted by submitting the service's own generated script with its partition named: sbatch --partition=titan ~/.local/share/imas-codex/services/codex-neo4j.sh, giving job 1313403, RUNNING on 98dci4-gpu-0002. Bolt answered before the counts below were taken.

The archive is unaffected by that exit status: it was written and closed before the restart step began. The status is recorded rather than smoothed over, because a reader restoring this checkpoint should know the command that produced it exited 1 at a step after the archive.
