A name's sources are read from one place, and the count that reads them agrees with the edges

Three readers answered "what are this name's sources" from the source_paths list copied onto the name rather than from the PRODUCED_NAME edges that every writer maintains: name search, the benchmark corpus loaders, and the judgment goldens. The copy drifts, so the readers disagreed with the graph and with each other. There is now one module, imas_codex/standard_names/source_reads.py, and every reader asks it — those three, the review pipeline's catalog load, and eleven further sites that answered from the copy inside a claim query, a review batch, a promotion loader or a documentation fetch. Fifteen readers in all. The guard that keeps them honest walks the package rather than a list of modules, so a reader added in a module no review named fails it.

One place, and what each reader now asks

source_paths_projection() renders the Cypher pattern comprehension [(producer:StandardNameSource)-[:PRODUCED_NAME]->(sn) | producer.id], which is a drop-in for sn.source_paths in a RETURN: it returns an empty list rather than null and declares no variable the enclosing query needs. normalize_source_ids() fixes the order by calling merge_source_paths() in imas_codex/standard_names/source_paths.py — the union the writers already merge with — so a list a reader hands out and a list a writer merges cannot order or deduplicate differently, and read_source_paths() answers for one name or a list of names.

Name search projects the edges in fetch_standard_names and now carries source_paths into the hydrated search rows, which previously omitted sources altogether. The benchmark corpus loaders (load_refine_corpus, load_breaker_corpus, load_docs_sample, the advisory paired corpus, the discrimination corpus) project the edges, and the refine loader falls back to the ancestor's edges rather than the ancestor's copy. The judgment goldens project the edges for the quarantined-name census and for the documentation sheet.

The frozen corruption corpus beside the tests is a different thing from a reader: it records the extraction that produced its committed rows. That record is kept verbatim, so the artifact stays checkable, and the corpus is not claimed to have been regenerated under the new projection; the query that runs is the one that reads the edges.

A guard test refuses a reader that spells sn.source_paths AS into its own projection and requires each reader to name the projection function, so the defect is refused at the source rather than caught downstream. The review pipeline's _load_catalog in imas_codex/cli/sn.py was the fourth reader: its catalog load returned the copied list and the --ids filter then read that list, so a name whose copy is empty was invisible to a review run aimed at its path. It now projects the edges and normalises the rows, and a guard test reads that function out of the module by name and applies the same rule to it. At the revision this work started from that test's rule fails on the function — names_the_one_place=False and reads_the_copied_list=sn.source_paths — and passes on the landed one.

The guard's one exemption is the frozen extraction records, and it is an explicit list of names (FROZEN_EXTRACTION_RECORDS), not a suffix rule: a constant that merely ends _EXTRACTION_RECORD is a live reader and is still refused. A test plants such a constant beside the allow-listed one and shows the allow-listed record removed while the unlisted one is still found reading sn.source_paths.

Every touch of the copy, enumerated

The guard does not check a list of modules a review happened to name. It walks imas_codex/, parses every module, and treats four kinds of syntax as a touch of a name's copied list: an attribute X.source_paths, a keyword argument named source_paths, a subscript with that key (row["source_paths"]), and a string constant that either is source_paths or contains a property-qualified reference such as sn.source_paths. Each touch is attributed to the innermost function or class that carries it — a module-level assignment target when there is none — and any site not listed with a role fails the test, as does a listed site the scan no longer finds.

The roles, and what each licenses: owner (3) encodes, parses or unions the property's value — source_paths.py and the two projection and read functions in source_reads.py; writer (27) sets or maintains the list on a name; repair (7) reads it as an input to a repair or migration write; recovery (5) reads it to rebuild provenance an edge lost; inspection (8) has the list disagreeing with the edges as its subject, including the sourceless count, which sizes the copy on purpose; guard (2) compares the list with the bindings as a precondition to a write; published (1) is the export's provenance field list, which exists so the property is left out of a publication; record (1) is the frozen extraction record a committed corpus is pinned to; runtime (44) is an in-memory item dict whose value came from a routed read: the query already projected the edges, so the key is a value passed along, not an answer taken from the graph; other_label (12) touches a same-named property on another label — DDGap, a configuration object — and not a standard name's copy at all.

The count, as §9 exposes it

imas-codex sn sourceless prints "how many live names does no source produce, and which". The predicates are the source invariant's own, imported from imas_codex/standard_names/source_invariant.py rather than restated here: a name is live when neither its status nor its name_stage reads superseded, and a producer is a PRODUCED_NAME source that is not stale — the rule the write guard and the export gate's find_sourceless_live_names already apply. The export gate now composes the same two builders, so the command and the gate report one population by construction rather than by agreement.
