A name's sources are read from one place, and the count that reads them agrees with the edges

Three readers answered "what are this name's sources" from the source_paths list copied onto the name rather than from the PRODUCED_NAME edges that every writer maintains: name search, the benchmark corpus loaders, and the judgment goldens. The copy drifts, so the readers disagreed with the graph and with each other. There is now one module, imas_codex/standard_names/source_reads.py, and each of those readers asks it.

One place, and what each reader now asks

source_paths_projection() renders the Cypher pattern comprehension [(producer:StandardNameSource)-[:PRODUCED_NAME]->(sn) | producer.id], which is a drop-in for sn.source_paths in a RETURN: it returns an empty list rather than null and declares no variable the enclosing query needs. normalize_source_ids() fixes the order, and read_source_paths() answers for one name or a list of names.

Name search projects the edges in fetch_standard_names and now carries source_paths into the hydrated search rows, which previously omitted sources altogether. The benchmark corpus loaders (load_refine_corpus, load_breaker_corpus, load_docs_sample, the advisory paired corpus, the discrimination corpus) project the edges, and the refine loader falls back to the ancestor's edges rather than the ancestor's copy. The judgment goldens project the edges for the quarantined-name census and for the documentation sheet.

The frozen corruption corpus beside the tests is a different thing from a reader: it records the extraction that produced its committed rows. That record is kept verbatim, so the artifact stays checkable, and the corpus is not claimed to have been regenerated under the new projection; the query that runs is the one that reads the edges.

A guard test refuses a reader that spells sn.source_paths AS into its own projection and requires each reader to name the projection function, so the defect is refused at the source rather than caught downstream. The review pipeline's _load_catalog in imas_codex/cli/sn.py was the fourth reader: its catalog load returned the copied list and the --ids filter then read that list, so a name whose copy is empty was invisible to a review run aimed at its path. It now projects the edges and normalises the rows, and a guard test reads that function out of the module by name and applies the same rule to it. At the revision this work started from that test's rule fails on the function — names_the_one_place=False and reads_the_copied_list=sn.source_paths — and passes on the landed one.

The guard's one exemption is the frozen extraction records, and it is an explicit list of names (FROZEN_EXTRACTION_RECORDS), not a suffix rule: a constant that merely ends _EXTRACTION_RECORD is a live reader and is still refused. A test plants such a constant beside the allow-listed one and shows the allow-listed record removed while the unlisted one is still found reading sn.source_paths.

The count, as §9 exposes it

imas-codex sn sourceless prints "how many live names does no source produce, and which". The predicates are the source invariant's own, imported from imas_codex/standard_names/source_invariant.py rather than restated here: a name is live when neither its status nor its name_stage reads superseded, and a producer is a PRODUCED_NAME source that is not stale — the rule the write guard and the export gate's find_sourceless_live_names already apply. The export gate now composes the same two builders, so the command and the gate report one population by construction rather than by agreement.

The command also reports the bare population — live names with no PRODUCED_NAME edge of any kind — and names every name on which the two differ, which is exactly the names whose only producers are stale. A name of derived origin with live children is listed apart from the count, because a derived parent's producer is its children by design and counting it would report every such parent as a loss.

On the live graph the two populations coincide: 9 names under the owner's rule and 9 with no edge at all, so no live name is currently held only by stale producers. Checked on 2026-11-15 by calling find_sourceless_live_names over all 3,266 live name ids: it returned the identical 9 ids, and beta is excluded by both as a derived parent.
