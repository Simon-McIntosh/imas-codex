One enumeration of the names no source produces

Three statements answered "which live names have no source", under two different rules. On 2026-11-15, in one job on the live graph, the source audit's own query named 27 names, the count the sn sourceless command printed 9, and a direct read of the PRODUCED_NAME edges 10. The package now holds one enumeration, in imas_codex/standard_names/source_invariant.py: find_sourceless_live_name_rows applies the live-name rule and the no-live-producer rule in a single statement and returns each name with its origin, name stage, live-child count and derived-parent attribute. find_sourceless_live_names returns the ids of those rows, so the command reports what the invariant finds by construction. count_live_names_without_source in imas_codex/standard_names/source_reads.py deletes its own query and its restated live-children expression and presents the owner's rows; classify_sourceless_standard_names in imas_codex/standard_names/graph_store/graph_supersession.py deletes its own population query and classifies exactly the names that enumeration names. Both the count and the audit read the population with no exemption: a derived parent is listed with derived_parent set rather than subtracted, which is what §7 needs in order to apply its own exemption.

One statement, and the reader's one rule

find_sourceless_live_name_rows(query, name_ids=None, …) takes name_ids=None for the whole graph and a list for the writer's touched set, so the same statement answers both. The writer's two exemptions — superseded names and derived parents — are parameters of that statement, and the population read sets derived_parents_exempt=False: the count and the audit report every live name with no live producer, so the two can no longer differ by an exemption. The live-child rule is stated once, in _live_child_condition, which feeds the existence test, the count and the derived-parent attribute, so no statement restates it.

The shared projection had one disagreement of its own: source_paths_projection() listed every producer edge, so a name whose only producer is stale answered read_source_paths and name search with that retired path while the count treated it as no source. The projection now filters coalesce(producer.status, '') <> 'stale', so search, read_source_paths and the count answer the same way for the same name. A planted graph shows it by value: stales_only, whose only producer carries status: 'stale', reads with no source from all three and is the count's single entry, while its control stales_control answers ['dd:stales/live'] and is not counted.

A disposable graph planted with the seven names the section names reports three: reads_empty_list, reads_full_list and reads_derived_parent. The two superseded names are not counted, the name produced by a derived record is not counted, and the data-dictionary producer with an empty copy is not counted. reads_derived_parent is listed with derived_parent: true and one live child, and reads_full_list — a live name with no edge whose copied list names a path — answers name search with no source.
