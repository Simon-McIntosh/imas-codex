Credential-forward repair and regression evidence

A socket appearing after five seconds reproduced the defect against the starting revision: the forward returned False and logged D-Bus forward socket did not appear in time after three seconds. The baseline also delayed an SSH exit diagnostic until three seconds and treated an unavailable keyring as an empty credential store. Four regression checks failed before the repair.

The forward now polls for up to fifteen seconds, reports an early SSH exit immediately with its stderr, and uses a late socket for the session bus. Strict stored-credential reads raise an explicit store-unavailable error when the keyring cannot be read. A readable store with no saved credentials still returns the distinct empty-store outcome. The ICP client preserves this distinction through its authentication error boundary.

The focused gate passed 158 tests. A test-process mutation shortened the socket deadline to three seconds and returned an empty result for an unavailable store: four tests failed and 154 passed. The mutation did not change source files. The repair is committed at aeafd8f40184977cdabfac319586fc0e774dc1fa.
