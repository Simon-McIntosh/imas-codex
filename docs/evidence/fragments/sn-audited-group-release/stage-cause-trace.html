The stages that produce the shared catalog defects

The blind adjudication of the equilibrium group judged 208 members against their complete source packets. Reading its judgments gives 14 causes shared by three or more defective members, 89 defect instances in all; that census reproduces the plan's figures exactly. The three largest are traced here to the stage that produces them, with 12 traced members quoted from the record, and the remaining 11 are traced to their stage with whether the same repair reaches them. Nothing on this page changed product source or wrote the graph.

The three largest causes, traced member by member

physical_scope_qualifier_lost — 18 members

Stage: compose_name, imas_codex/standard_names/worker_tasks/worker_compose_and_validate.py::_compose_batch_body.

Given. DD path, enriched leaf description, unit, data type, keywords, sibling fields, hybrid and related neighbours, identifier enums and reviewer history, plus an item['ancestor_context'] list of enclosing-structure statements attached by worker_extraction_and_enrichment.py::_enrich_batch_items

Drops. In names batching mode _compose_batch_body renders sn/generate_name_dd_names, whose per-item block emits item.path, item.description, item.unit and the neighbour blocks but no item.ancestor_context and no item.documentation; the full-mode template sn/generate_name_dd does render the lineage block, so the enclosing text the extraction stage attached never reaches the composer that writes the identity.

Smallest repair. Render the enclosing-structure lineage that the extraction stage already attaches: add the item.ancestor_context block from sn/generate_name_dd.md to the per-item block of sn/generate_name_dd_names.md, so the composer sees the clause that states the component, geometric reference or locus and can emit the token or a vocab_gap for it.

Files it would touch: imas_codex/llm/prompts/sn/generate_name_dd_names.md

The prompt already forbids silently generalising a source-stated axis; the defect survives because the text stating the axis is never rendered in names mode.

source_bindings_conflate_distinct_definitions — 13 members

Stage: attach_guard, imas_codex/standard_names/worker_tasks/worker_extraction_and_enrichment.py::_is_attachment_consistent.

Given. The candidate DD path's spelling, the DD unit and the name's unit, the name's spelling (tense, state, shape surface, vector-field axis, geometry representation, hardware device tokens) and the paths already bound to the name

Drops. The sources' stated descriptions and operations: the guard has no text parameter, so two sources whose stated operations differ are admitted to one name and the definition stage must then write a single definition from them.

Smallest repair. Give the pairing guard the text it is missing: pass the candidate's dd_description and the already-bound sources' descriptions into _is_attachment_consistent and reject a second binding whose stated operation contradicts the first's (the pairing-guard query and attachment_audit._attachment_consistency already select dd_documentation).

Files it would touch: imas_codex/standard_names/worker_tasks/worker_extraction_and_enrichment.py, imas_codex/standard_names/attachment_audit.py

boundary_forced_to_lcfs — 11 members

Stage: locus_binding, imas_codex/standard_names/context.py::locus_context_for.

Given. The source's boundary-selection clause as recorded in the packet (psi_norm = 99.x% of the separatrix, near-separatrix, or LCFS-or-99.x% for a fixed-boundary code) and, at documentation time, the ISN locus registry definition for the name's locus token

Drops. The selection. generate_name_system.md binds every plasma-shape parameter to _of_plasma_boundary for the LCFS contour, and locus_context_for injects the registry definition of plasma_boundary, which is categorical: 'the outermost flux surface on which field lines close on themselves'. The documentation stage then states the boundary as that surface.

Smallest repair. Bind the locus to the selection the source states: in the naming rules, reserve _of_/_at_plasma_boundary for a source that names the LCFS, and require a qualifier for a selected boundary (psi_norm = 0.99 or near-separatrix) or a vocab_gap when the grammar has no such qualifier; the documentation stage then inherits the selection instead of the registry's categorical LCFS.

Files it would touch: imas_codex/llm/prompts/sn/generate_name_system.md, imas_codex/llm/prompts/sn/generate_name_dd_names.md

The registry definition of plasma_boundary lives in imas_standard_names and is not edited here; the repair is the codex-side rule that decides when that token is the right identity.

Why this is not a naming-style complaint

Each stage above is fed the text that states the missing qualifier and then writes an artifact without it, so the loss repeats for every group the stage processes — the defects are properties of the pipeline, not of the 208 names. The check that accompanies this page re-reads both the record and the product source: it fails if the recorded stage of any traced member moves, if a quoted line leaves the packet, if the names-mode prompt starts rendering the lineage, if the binding guard starts reading source text, or if the locus registry redefines plasma_boundary.
