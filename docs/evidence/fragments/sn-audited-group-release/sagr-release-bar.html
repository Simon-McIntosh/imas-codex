Where the ruling and the audit records are read from

The bar is a document, not a constant: IMAS_CODEX_SN_GROUP_RELEASE_BAR or [tool.imas-codex.sn].group-release-bar, with no default path, because a bar nobody ruled must refuse rather than pick a threshold. It carries max_defect_rate (required, numeric), class_maxima (per defect class), sourceless_exceptions (member ids), family_exceptions (family ids) and groups_cut_together (group pairs). A document missing the rate is reported as a problem, never read as a looser bar. The group's audit record is IMAS_CODEX_SN_GROUP_AUDIT_DIR or [tool.imas-codex.sn].group-audit-dir, one <group>.json holding one row per member with text_sha256 (the digest the shipped cut recomputes from the strings they stand for, so a record and a patched stored text are comparable without either side changing). The defect classes are the fixed list the plan names: name_contradicts_source, name_omits_source, definition_contradicts_source, name_definition_disagree, unit_wrong, wrong_physics_domain, duplicate_of_live_name; a record carrying a class outside it is refused as incompletely measured.

What the ruling must state before a group is cut

  • max_defect_rate: the largest share of a group's live members an audit may read as defective, with the audit's measured rates beside each option the lead weighed.
  • class_maxima: the maximum rule for any class whose consequence differs from the rest.
  • sourceless_exceptions and family_exceptions: the member ids and family ids a ruling lets stand; section 2's ruling already lists every spanning family as an exception for the first cut, and the family id the gate reports is the id that list can carry.
  • groups_cut_together: any pair released as one cut.
