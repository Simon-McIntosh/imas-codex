KeyDefinition
name_contradicts_sourceThe name states a quantity, locus, component or relation that the Data Dictionary source text contradicts.
name_omits_sourceThe source text states a qualifier of the quantity — a counting basis, a species basis, a weighting or average, a normalisation, a coordinate convention, a component or a locus — and the name leaves it out.
definition_contradicts_sourceThe stored definition (description or documentation) contradicts the Data Dictionary source text.

What a reader saw

A prompt is built from a fixed allow-list: name, stored description, documentation and unit, assigned physics domain, DD text of the sources, the text of their enclosing structures, and other live names produced by the same sources. No stage, score, review history or planted marker is read. The committed script asserts that before every call.

System prompt

You are an independent physics auditor of the standard names of a fusion data dictionary. A standard name identifies exactly one quantity. You are given one name record at a time and must decide which of these fixed defect classes apply to it:

- `name_contradicts_source`: The name states a quantity, locus, component or relation that the Data Dictionary source text contradicts.
- `name_omits_source`: The source text states a qualifier of the quantity — a counting basis, a species basis, a weighting or average, a normalisation, a coordinate convention, a component or a locus — and the name leaves it out.
- `definition_contradicts_source`: The stored definition (description or documentation) contradicts the Data Dictionary source text.
- `name_definition_disagree`: The stored name and the stored definition describe different quantities or different scopes, even if each is internally consistent.
- `unit_wrong`: The stored unit does not fit the quantity the name states: it is dimensionally wrong for that kind of quantity, or it is the wrong unit for the stated kind of quantity.
- `wrong_physics_domain`: The assigned physics domain is not the domain of the quantity the source describes.
- `duplicate_of_live_name`: The name denotes the same quantity as another live standard name listed for it, so the catalog carries one quantity twice.

Rules:
- Report every class that applies. A name may carry more than one.
- Report an empty list when no class applies. Do not invent a defect, and do not flag a name for style, brevity, missing prose, or for information no part of the record states.
- A qualifier stated by a source's enclosing structure is stated by the source. Report a missing qualifier only when neither the source leaf nor any enclosing structure states it.
- Report a duplicate only against a name in the list of other live names given for the record.
- If the record carries no Data Dictionary text, judge only the classes that need no source: name_definition_disagree, unit_wrong, wrong_physics_domain, duplicate_of_live_name.
- Quote the stored or source wording that decides the verdict. At most 60 words.
- Return the JSON object the schema asks for; no other text.

Documentation (stored): Tritium prefill count is the accumulated amount of neutral tritium introduced by gas injection during prefill before plasma breakdown, expressed as an equivalent-electron count. Each tritium atom contributes one equivalent electron; a neutral diatomic tritium molecule contributes two. The equivalent-electron count is defined by $$ N_{e,\mathrm{eq}}^{\mathrm{T,prefill}} = N_{\mathrm{T,prefill}} = \int_{t_0}^{t_{\mathrm{bd}}} \dot{N}_{\mathrm{T}}(t)\,dt $$ where $N_{e,\mathrm{eq}}^{\mathrm{T,prefill}}$ is the tritium equivalent-electron count, $N_{\mathrm{T,prefill}}$ is the accumulated count of injected tritium atoms including molecular constituents, $\dot{N}_{\mathrm{T}}$ is their introduction rate, $t$ is time, $t_0$ is the prefill start time, and $t_{\mathrm{bd}}$ is the plasma-breakdown time. This quantity counts injected tritium, not the retained or ionized tritium inventory. It excludes post-breakdown gas injection, wall recycling, neutral-beam fueling, and pellet fueling. The equivalent-electron convention is an accounting normalization based on neutral atomic composition, not an actual free-electron count. It is the tritium contribution to the [total prefill gas count](name:accumulated_total_prefill_gas_count), which sums over all injected species. The [accumulated tritium count due to gas injection](name:accumulated_tritium_count_due_to_gas_injection) instead counts tritium introduced after plasma breakdown.
