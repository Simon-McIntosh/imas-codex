The remaining pass runs as chained jobs, not as a turn

Four hundred and seventy-three names are queued in six SLURM jobs on the unbounded partition, one per class in the ruled order and each dependent on the last, so the work continues after the session ends. Every job re-reads the progress file and skips what is settled, so a resumed chain never re-spends on a name already carrying the wording. Documentation edits run four at a time; renames and any signed apply stay strictly one at a time and are held out of the automated path.

Each edit is bounded at 600 s, and its settled state is read back from the graph rather than taken from the wrapper's exit status. Four stop rules write their reason to the progress file: the USD 60 ceiling summed from cost rows, a class stopped after twenty names averaging over USD 0.20, an immediate stop on a review error or an apply refused for drift, and a stop if the count of sourceless live names rises above the baseline each job records at its start.
