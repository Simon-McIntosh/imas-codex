Why a live rewrite edit cost USD 0.39 and did not settle

The reported rate is not the edit's spend. The bulk report reads StandardName.llm_cost into its spend_usd field. That property is the name's cumulative lifetime cost, so USD 0.391 a name is the whole history of five names, not the cost of these five edits. Measured from the pipeline's own LLMCost records, the five edits spent USD 1.2267 in total, USD 0.2453 a name. Of that, two escalation-seat refine calls are USD 0.7055, or 57 percent.

The 280 seconds is the batch wrapper's own timeout 280, not a pipeline limit. Two of the five edits had in fact reached the acceptance threshold when the wrapper signalled them. One edit is refused for the right reason and needs a rename rather than a rewrite. The pipeline defect that makes an edit expensive is a documentation refinement that was never shown the settled shared wording it is forbidden to paraphrase.

Why the writer counts neutral atoms under a bare species name

It was fed text that says so, and that text is right about the source. The oxygen_density node the writer links to reads "Total number density of oxygen atoms and ions across all charge states, from neutral to fully stripped", and its documentation sums Z = 0..8. boron_density reads "summed over neutral atoms and all ionic charge states through fully stripped B5+". The writer reproduced its source accurately, and the population gate then correctly refused the only text that source supports.

So the refusal is the right outcome for these names, and the ruling for them is a rename, not a docs edit. A name whose DD source is an elemental atom density cannot be given an ion-only definition without contradicting its own source. Regenerating them under the settled sentence would publish a definition the source does not support.

The related error in the bulk pass is the blanket application of the species hint to volume_averaged_neutral_species_density, a name whose subject is an aggregate the population rule deliberately excludes. The pipeline generated text that was right for the name and spent three rotations and one escalation call trying to make it say the opposite.

The repair

generate_docs gives the model every settled shared part verbatim through shared_parts. The refine path built neither that context key nor a template block, while the renderer still installs the stored sentence and the persistence gate refuses a paraphrase of it. Each rotation therefore re-guessed wording it could not land, was refused, and spent a rotation until the escalation seat happened to reproduce the sentence. That is why the expensive call is the one that settles.

The refine prompt now carries the same settled-wording block as generate (6b94875). The template test fails at the base revision with two cases and passes with seventeen after the change.
