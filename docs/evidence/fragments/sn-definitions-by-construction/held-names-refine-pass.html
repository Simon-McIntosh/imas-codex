The equivalent_electron word, and why three renames still landed. The word is a registered grammar qualifier, not a vocabulary gap: `Qualifier.EQUIVALENT_ELECTRON = "equivalent_electron"` in the shared library's `grammar/model_types.py`, added by commit `135c42e` ("feat(grammar): add equivalent-electron counting qualifier", 2026-11-13) and first tagged `v0.12.0rc1` in the `imas-standard-names` checkout the pipeline imports. The strict parser reads the token in the `normalized` qualifier category, so a name carrying it parses as `<qualifiers> + <base>`. The 56 names live in `live-rewrite-bulk.json` under `waiting_equivalent_electron` (as of 2026-11-14T21:49Z); that slice listed them with a stated counting basis and left their names unchanged, so the list records an expectation, not a refusal. This pass parsed every planned rename with `parse_canonical_name` before submitting it, so a spelling that composes to itself reached the name reviewer as a canonical name; three of the 56 — ammonia, argon and neon — landed accepted, and the review chose the word in each. They are accumulated_ammonia_equivalent_electron_count, accumulated_argon_equivalent_electron_count_due_to_gas_injection, accumulated_neon_equivalent_electron_count each accepted on both axes.
