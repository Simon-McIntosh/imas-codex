Shared definition parts rendered from one stored wording

A definition has parts that belong to a concept shared with other names — the operator applied, the population counted, the locus — and parts that belong to this name alone. The writer now emits only the latter. Every shared part is substituted from one stored wording, and a definition that departs from it after rendering is refused before it is stored.

The mechanism

PartStored wordingWhere it is rendered
Operatoroperator_definition_sentence: the grammar library's operator entry, sentence and equation, unchanged for every name that applies itdocs_gates.shared_part_sentences, installed by _documentation_with_registry_form
PopulationSPECIES_POPULATION_SENTENCE: The density counts ions summed over all charge states; neutral atoms are excluded. — the catalog decision of 2026-11-12same renderer, on every bare species density
Locuslocus_definition_sentence: the locus registry's definition with its equation and symbolssame renderer, unchanged by this section

The renderer removes a written sentence that states a shared part in other words and installs the stored sentence, so a definition carries one wording per part rather than two. shared_part_findings reports a definition that still carries a paraphrase or omits the part, as a further class of the documentation conformance findings (shared_part_altered), and _refuse_altered_shared_parts refuses such a definition in the writer before persist_generated_docs runs.

Stated limits

  • The review ran on a disposable graph carrying only the fifteen names, so it had none of the graph-derived context a live review receives: no Data Dictionary source context, no scored review examples and no catalog neighbours. The nine refinement decisions are therefore a lower bound under degraded context, not a measure of the documentation.
  • The two regimes differ in kind: the written scores are Jev-deciding decisions, the earlier scores are quorum means from the reviewer chain. Only the six graded written scores are compared, and even those were decided by one judgment rather than a quorum.
  • The writer run reported twelve of the fifteen names present in the published catalog; the other three were seeded from the name alone, so their descriptions are not the catalog's.

What that does and does not settle. A numeric dimension score neither names the shared sentence nor clears it. The six shortfalls are exactly the six species densities, and the population sentence is the only text this change added to them, so the shortfall is consistent with that sentence being judged a physics inaccuracy — but that is an inference from which names moved, not something the review said. The remaining three refined names (flux_surface_averaged_electron_density, flux_surface_averaged_electron_temperature, helium_density) are refined in both arms or have no published row, so they are not shortfalls against the control.

Context still missing, in both arms. None of the fifteen rows carries source_paths, so no IMASNode was copied and the Data Dictionary path context is absent; the DD resolution manifest is absent, which is what produced the two DD source text unavailable holds; and a disposable instance has no vector index, so vector neighbours were empty. Same-base and same-path neighbours and the scored review examples were served from the copied catalog. Both arms review the same names under the same missing context, so the comparison between them holds even though neither matches a fully provisioned live review.

Settled parts, written around rather than appended

The two arms above measured a renderer that appended the shared sentences after the model had written freely, and the six species densities it refined were exactly the names whose own prose and equations counted neutral atoms while the appended sentence excluded them. Appending is not rendering, so the shared parts are now settled text the model is shown before it writes, and a written text that contradicts them is refused before persistence.

Wording proposed to the grammar library

The species population rule has no sentence in the grammar library's concepts.yml. It is stored in this repository as docs_gates.SPECIES_POPULATION_SENTENCE and proposed upstream as a population entry so that one stored wording serves every species name.
