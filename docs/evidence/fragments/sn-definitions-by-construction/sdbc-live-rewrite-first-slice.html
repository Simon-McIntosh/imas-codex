The live rewrite: first slice and the costed manifest of the rest

The catalog checkpoint this node required was present and verified (sfdc-graph-checkpoint.json, archive sha256 beginning 389e1fffa380, four checks passed, counts equal before and after), so the write path was opened. The live rewrite did not proceed: every documentation edit is refused before review by a defect in the review worker's dependency registry. The slice's before-state, the two wording censuses and the costed manifest of the whole remaining pass are recorded here; no graph text was changed.

Why no live name could be brought to accepted text

imas_codex/standard_names/worker_tasks/worker_review_docs.py:891 resolves _name_definition_note through _worker_dependency(), whose registry in imas_codex/standard_names/workers.py carries no such entry. The function is defined locally at worker_review_docs.py:699 and takes the resolver as its first positional, so the lookup raises KeyError: '_name_definition_note' on the first item and the pool retries the same item forever: 31,430+ identical error lines in one 17-second window, with no model call made in the loop. The call was introduced by a42c54b8d.

Reproduction, run once from the worktree:

The slice, run: what the pipeline now does with a flagged name

Main's repair merged into the worktree at 7caff689c (from a003422a5) registers name_definition in HOLD_KINDS, so documentation review runs. The acceptance test was the same carbon_density edit that had failed on every retry: it now generates, reviews and scores — 0.99, exhausted — and the definition it stored states the settled population (carbon ions summed over all positive charge states, counting each ion once and excluding neutral carbon). A second documentation name was then run and its reviewer went further: it refused the generated text in writing.

reviewer_comments_docs = [docs_generate_refusal] population:species: the written
text includes neutral atoms ('The local population entering the average is related
to the neutral-inclusive elemental density b') where the stored wording reads
'The density counts ions summed over all charge states; neutral atoms are excluded.'

That refusal is the review working as designed, and it is the first measured evidence of what the flagged set's rewrites cost and produce. Two things follow, both recorded in the evidence and the manifest:

  • A documentation rewrite can be refused on its own wording. A bare hint asking for the settled population does not override the DD source the candidate is generated from: the generator wrote including every boron charge state for a name whose source path is summary/volume_average/n_i/boron/value, and the reviewer caught the contradiction. The class therefore needs a spelling-level steer, not a population hint alone, before it converges.
  • The two families this node was asked to unify are mostly outside the flagged population. The population rule admits only label-carried mismatched names; of the fifteen <X>_density members censused, only carbon_density is flagged, and the rest reconcile as agreeing (argon, beryllium) or disputed (neon, oxygen) — not this node's to touch. Of the eight flux-surface-average names censused, two are flagged. The families can be measured; only their flagged members can be rewritten in this pass. Both facts are carried in live-rewrite-manifest.json under family_scope.

Three names are listed in the manifest as waiting on the grammar rather than attempted, each with the word it needs: the two equivalent-electron counts need equivalent_electron, and electron_number_density needs an areal abundance base (column_density) so that electron_column_density parses.
