Repairing the rendered shared wording: terminal states, a tested description, a dead branch

The shared-wording machinery landed with four gaps: a refusal that never reached a terminal state, a reported class that held nothing, a refine repair with no test of its own, and an unreachable clause in the renderer's removal filter. Each is repaired here; nothing else is added.

1. A contradiction now ends the attempt

A definition whose shared part contradicted the settled population was refused before storage — and then both writers released the claim. The refine path reverted the name to reviewed, and the generate path cleared the token and left the name at pending, so a model that contradicted the stored wording on every pass was re-claimed and re-charged on every pass. Both writers now move the name to the terminal docs_stage = 'exhausted' the refine path already uses for a deterministic failure. No second counter is introduced: the terminal state is the existing one, and the bound is one refused answer per name, which is inside the rotation cap the refine pool admits on.

The same contradicting answer fed through three passes reaches the terminal state on the first, costing 1 model call against an attempt bound of 3.

2. The class does not hold a name at review — the pre-storage refusal is the guard

shared_part_altered and contradicted_shared_part are raised by conformance_findings and acted on by _refuse_altered_shared_parts before persist_* runs. The set of classes that hold a name at a documentation review is the barring set inside _documentation_conformance_note (worker_tasks/worker_review_docs.py), which carries template_opening, forbidden_equation_variant, forbidden_locus_gloss, locus_definition and non_canonical_equation; the two shared-part classes are not in it, so nothing in the review barring set presents them as a hold.

This node takes the second branch the brief allows and says why: the class does not hold a name at review, and the report does not present it as one. Two reasons. The refusal is pre-storage on this repository's only documentation-writing paths, so text that contradicts a shared part is never stored and cannot arrive at review from them; a review hold would only fire for text another writer produced, and would then hold a name whose stored text this change did not write. And the hold set lives in worker_review_docs.py, outside this node's granted write paths — recorded under outside_scope for the coordinator rather than reached into.

3. The refine description repair is tested

The refine test planted documentation that contradicts the population whatever the description says, so the description repair could be deleted and the test stayed green. A refinement is now driven through process_refine_docs_batch with a description that omits the population and documentation that conforms, and the test reads back what was stored:

4. The unreachable clause is removed, and its behaviour pinned

replace_altered_shared_parts skipped a part the text already carried, then filtered each sentence with _collapsed(candidate) == stored or overlap < _COMPETING_OVERLAP. A candidate equal to the stored sentence implies the stored sentence is present in its line, which the skip above has already handled, so the first disjunct can never decide anything. It is removed.

Removal is measured rather than asserted: restoring the clause and re-running the two renderer tests leaves both green (gap4-clause-restored-unchanged.log, EXIT=0), which is what an unreachable branch looks like. The behaviour the clause claimed — a part already stated in its stored wording is left alone rather than re-appended or dropped, and a paraphrase beside it is removed — is pinned by test_a_definition_already_carries_the_stored_wording_is_unchanged and test_a_definition_already_in_the_stored_wording_is_left_untouched.
