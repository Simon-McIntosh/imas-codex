§2 — First answer in under ten seconds

The command group now resolves each command module when that command is invoked, so imas-codex serve imports serve and nothing else. On the debug-partition node the median of five cold starts fell from 8.32 s to 3.80 s to first answer, and serve --help from 6.79 s to 0.17 s. On the fleet node, at a load average of 27–34, the five starts answered in 10.72–13.10 s (median 11.98 s) against a base-revision pair of 23.95 s and 22.17 s.

What changed

register_commands() imported all fifteen command modules at package import, so every command — including the MCP server entry point — paid for every other command's imports. It is replaced by a table of (module, attribute, help) entries and a DeferredCommandGroup that imports a module in get_command only. list_commands and format_commands answer from the table, so --help never imports a command module; the help strings moved into the table for that reason.

The control, failing at the base revision

Two tests were added. test_help_imports_no_command_module asserts that imas-codex --help exits with no command module in sys.modules. test_initialize_path_imports_only_the_serve_command resolves serve through the group, builds the object that answers initialize, and asserts that no other command module and not litellm was imported. Both pass in this tree (21 passed across the two touched test files, 64 passed across tests/test_cli.py and tests/core/test_cli.py). Run against the base tree they fail, and their own output names the cause:

AssertionError: ['imas_codex.cli.compute', 'imas_codex.cli.config_cli', … 'imas_codex.cli.tunnel'] and AssertionError: litellm imported — 2 failed.

The tool list is unchanged in each of the three serve modes: 38 tools by default, 31 read-only, 15 DD-only, identical by name to the base revision.
