Cause 1: the drift clause read an absolute stage

measure_batch (imas_codex/standard_names/campaign.py) walked the batch's member ids and appended a name to BatchOutcome.name_drift whenever the refreshed row was missing, or whenever its name_stage was anything other than accepted. That is a test of absolute post-drain state. A docs-only campaign never writes the name axis (the invariant on the run lists the family's five names with their stage fields untouched), so a member that was already outside accepted when the family was planned could only ever be reported as drift. Both names the halt named — electrostatic_potential_at_outboard_midplane and electrostatic_potential_at_wall — were at reviewed before the drain and at reviewed after it. Neither is in touched_names: the campaign wrote no documentation for either, because neither could be claimed.

The clause now asks whether the name's stage moved. The runner reads the batch's member rows once before anything in the batch touches them and passes that read to measure_batch as prior_rows; a name is drift when its post-drain stage differs from the inherited one and the new stage is not accepted. A name with no inherited row, or absent from the post-drain read, is still drift, because the gate cannot otherwise distinguish an unreadable name from an untouched one. A name the batch itself moves out of accepted still halts.

Planning also stops offering such members to a docs-only batch. plan_family_applies now reads the members' name stages, through the campaign's own member read rather than a second query that could drift from it, and splits them: only accepted members enter the batch list, and the rest are carried in the plan under skipped with their stage. Nothing the campaign measures can name a skipped member, because it never enters a batch, so the plan is the only place the name survives — and a plan nobody prints reaches no reader. apply_families therefore logs one line per skipped member, naming it and its stage, and skipped_members flattens each plan's entries into the returned summary under skipped. A stage the read cannot answer for is treated as eligible — an absent answer is not evidence that the member is excluded, and dropping it silently would be the same defect in the other direction. Such a member then enters a batch with no inherited row, so a non-accepted stage after the drain counts as drift rather than as an inherited state nobody read.

The gate's reading. A held document is not accepted. The veto did not promote the document; counting a held review as accepted because of a score would let the gate pass a document the cascade refused, which in effect lowers the acceptance bar below the one the cascade applies. So measure_batch reads docs_stage == "accepted" exactly, and the member batch's 1 of 2 is a true halt for as long as the hold stands. If the hold is wrong, the repair belongs to the veto and the document, not to the convergence gate.
