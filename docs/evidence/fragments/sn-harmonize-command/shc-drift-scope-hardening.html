Guarding the loop half of the scoped drift refresh

The scope fix that stopped a family apply steering names outside its family was never tested from the side that decides the scope. _scope_name_ids resolves a scoped run's own names and run_sn_pools hands that set to the drift refresh; deleting the hand-off would have passed the whole suite. The selector also caught every exception and returned an empty list, so an unreachable graph read as "this run owns nothing" and the default-tier live-graph guard's own refusal was swallowed, surfacing as a passing test. Four findings are repaired here: no test reached the selector or the hand-off, the handler swallowed the conftest guard, one test's docstring claimed a guard its double cannot provide, and one string replace was a no-op.

Plan authority: imas-codex:sn-harmonize-command §4, from the four follow-on findings on docs/evidence/fragments/sn-harmonize-command/shc-drift-refresh-scope-fix.html.

1. No test reached the scope selector or its call site

Before. _scope_name_ids and the sn_ids=_refresh_ids argument at the refresh call had no test. Nothing asserted which names a scoped run owns, and nothing noticed if the resolved set was never passed.

After. tests/standard_names/test_scoped_drift_loop.py drives run_sn_pools and asserts the refresh receives the resolved set, that an unscoped run still passes None, and that a scope owning no names passes an empty list rather than falling open. A separate test pins the selector's Cypher to both ways a run binds a name — sn.run_id and a StandardNameSource of that run through PRODUCED_NAME — because one arm alone returns a silently smaller scope.

2. The handler swallowed the live-graph guard

Before. except Exception returned []. Reproduced first: restoring that handler against the new guard test fails with test_scope_selector_lets_the_default_tier_live_graph_guard_raise — the RuntimeError raised by conftest.py when a default-tier test opens a live GraphClient was converted into an empty scope, so the guard reported nothing and the test passed on nothing.

After. The handler catches only the connection errors production can meet (ServiceUnavailable, OSError, TimeoutError) and returns None, which is distinct from an empty list. run_sn_pools reads None as "skip the refresh" and logs the scope id and the reason, so an unreadable scope neither sweeps the graph nor claims to own nothing. A response carrying no name ids is treated the same way, which keeps a selector defect from failing the whole drain while still skipping the refresh and saying why.

3. A docstring claimed a guard its double cannot give

Before. test_scoped_refresh_never_steers_a_name_outside_its_scope said it exercised the sn.id IN $sn_ids clause, but its double filters on the ids it is handed, so it would pass with the clause deleted.

After. The docstring now states that it guards the forwarding, names the two graph-marked tests that do guard the clause — test_scoped_drift_scan_touches_only_the_runs_names and test_scoped_refresh_leaves_an_out_of_scope_name_unsteered — and says why the double cannot see the clause.

4. A no-op replace in the test helper

Before. _attach_source in test_source_refresh.py ended its Cypher with .replace("{id: $name_id)", "{id: $name_id}"), which replaces nothing and reads as though the template were parametrised.

After. Deleted; the query string stands as written.
