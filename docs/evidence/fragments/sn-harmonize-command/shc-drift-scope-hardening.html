Guarding the loop half of the scoped drift refresh

The scope fix that stopped a family apply steering names outside its family was never tested from the side that decides the scope. _scope_name_ids resolves a scoped run's own names and run_sn_pools hands that set to the drift refresh; deleting the hand-off would have passed the whole suite. The selector also caught every exception and returned an empty list, so an unreachable graph read as "this run owns nothing" and the default-tier live-graph guard's own refusal was swallowed, surfacing as a passing test. Four findings are repaired here: no test reached the selector or the hand-off, the handler swallowed the conftest guard, one test's docstring claimed a guard its double cannot provide, and one string replace was a no-op. A review of that repair added five findings, all answered below: the handler was still incomplete for two connection failures a concurrent drain meets, its other two outcomes had no test, the new test file duplicated the orchestrator patch set instead of importing the file that owns it, one evidence claim named no log that could be opened, and one edited path sat outside the fence. A final pass removed the handler's hand-written exception list: the repository already classifies a connection failure, and asking it picks up the cases a local list misses.

Plan authority: imas-codex:sn-harmonize-command §4, from the four follow-on findings on docs/evidence/fragments/sn-harmonize-command/shc-drift-refresh-scope-fix.html.

1. No test reached the scope selector or its call site

Before. _scope_name_ids and the sn_ids=_refresh_ids argument at the refresh call had no test. Nothing asserted which names a scoped run owns, and nothing noticed if the resolved set was never passed.

After. tests/standard_names/test_scoped_drift_loop.py drives run_sn_pools and asserts the refresh receives the resolved set, that an unscoped run still passes None, and that a scope owning no names passes an empty list rather than falling open. A separate test pins the selector's Cypher to both ways a run binds a name — sn.run_id and a StandardNameSource of that run through PRODUCED_NAME — because one arm alone returns a silently smaller scope.

2. The handler swallowed the live-graph guard

Before. except Exception returned [], so the RuntimeError raised by conftest.py when a default-tier test opens a live GraphClient was converted into an empty scope: the guard reported nothing and the test passed on nothing. Restoring that handler against the new guard test fails test_scope_selector_lets_the_default_tier_live_graph_guard_raise — one failure, EXIT=1, in negative-control-broad-except.log in the run directory, which also carries the revision, tree and command it was produced from.

After. The handler returns None only when the repository's own classifier says the failure was a connection failure, and re-raises otherwise — see the last section before the gate. run_sn_pools reads None as "skip the refresh" and logs the scope id and the reason, so an unreadable scope neither sweeps the graph nor claims to own nothing. A response carrying no name ids is treated the same way, which keeps a selector defect from failing the whole drain while still skipping the refresh and saying why.

3. A docstring claimed a guard its double cannot give

Before. test_scoped_refresh_never_steers_a_name_outside_its_scope said it exercised the sn.id IN $sn_ids clause, but its double filters on the ids it is handed, so it would pass with the clause deleted.

After. The docstring now states that it guards the forwarding, names the two graph-marked tests that do guard the clause — test_scoped_drift_scan_touches_only_the_runs_names and test_scoped_refresh_leaves_an_out_of_scope_name_unsteered — and says why the double cannot see the clause.

4. A no-op replace in the test helper

Before. _attach_source in test_source_refresh.py ended its Cypher with .replace("{id: $name_id)", "{id: $name_id}"), which replaces nothing and reads as though the template were parametrised.

After. Deleted; the query string stands as written.

5. Two outcomes of the handler had no test

Before. The selector can answer three ways — a set, an empty set, and "unreadable" — and it reaches "unreadable" by two routes: an answer carrying no name ids, and a raised connection error. Only the raised-error route was exercised, and only through the members added in this node's first pass. The rows-without-id branch and the OSError/TimeoutError alternatives could have been deleted with every test still green.

After. The graph double answers the scope query from its call arguments, so one harness drives every case: an id row is a readable scope, no rows is an empty one, a row with no id is an unusable answer, and a raised error is an unreadable one. The failure test is parametrised over all five connection classes. Removing the rows-without-id guard fails test_a_scope_answer_without_name_ids_skips_the_refresh, and the base arm fails every parametrised case including OSError and TimeoutError.

6. The new test file copied the orchestrator patch set

Before. test_scoped_drift_loop.py carried its own copy of the 23-entry graph-wide maintenance patch set and of the graph double, both already owned by test_scoped_global_maintenance.py. A maintenance pass added to run_sn_pools would have had to be patched twice, and a copy that fell behind would fail these tests on an unpatched writer rather than on the behaviour under test.

After. It imports the orchestrator driver and the double from the file that owns them, the way the bypass test already did, and that file's double and driver take the scope answer as a parameter. Patch calls in the loop test fall from 23 to one — the selector's own client double, which is local to the selector and owned by no one else. Recorded in negative-control-dedupe.log.

7. The handler hand-listed the exception list instead of asking the repository

Before. The handler named five exception types. That is a second, independent answer to a question imas_codex/discovery/base/supervision.py already answers for the whole pipeline: is_infrastructure_error recognises the three Neo4j connection failures, a DatabaseError whose message says the database needs a restart, and connection failures carried by other exception types through their message. The local list matched the first three by name and missed the rest, so a server reporting a restart — how a transaction log corrupted on shared storage presents — failed the drain instead of skipping the refresh.

After. The handler catches Exception and asks that classifier. A connection failure skips the refresh with the same logged reason as before; anything else re-raises, which is what keeps the default-tier live-graph guard's RuntimeError propagating. The list and the comment about driver class hierarchy are gone: one owner decides, and the selector follows it.

Evidence. The parametrised failures now carry messages the classifier recognises rather than relying on their class, and test_a_graph_that_needs_a_restart_skips_the_refresh covers the DatabaseError case. Restoring a local isinstance list in place of the classifier fails that test, and only that one — negative-control-restart-error.log, 1 failed, EXIT=1.

Gate

Default markers, separate git archive trees each with its own --basetemp, over tests/standard_names/test_source_refresh.py, tests/standard_names/test_scoped_global_maintenance.py and the new tests/standard_names/test_scoped_drift_loop.py: base f657a98dc 8 failed, 40 passed (EXIT=1), head 0a39e40fb 48 passed (EXIT=0). Every base failure is one of the new discrimination tests — the guard, the rows-without-id case, the restart case and all five parametrised connection classes — so the delta is zero added failures and the new tests do discriminate. Both trees run the head's copies of the three test files, so the delta measures product code alone.

-m graph against the shared disposable_neo4j_uri fixture, same trees and separate basetemps: base 6 passed (EXIT=0) and head 6 passed (EXIT=0); identical test ids, zero added failures. The fixture needs a writable scratch directory and the worker's /tmp root is not one, so both arms run with TMPDIR inside the run scratch tree; without that, all five graph tests error at fixture setup in both arms and the arm measures nothing.

Scope note

Narrowing the handler surfaced a stale test double in tests/standard_names/test_scoped_global_maintenance.py: its GraphClient answered every query with a count row, which the old catch-all had been converting into an empty scope. The repair answers the scope query with a name id and leaves every other query as it was. That file is now inside this node's write fence: it owns the orchestrator harness the loop tests import, so a test that changes what the scope read answers belongs in the owner rather than in a copy.
