The sanctioned route and the defect

sn rescore reverts a name to drafted through stage_name_for_rescore and then runs an inline review quorum. Its first action is a compare-and-set query at imas_codex/standard_names/graph_ops.py:24506 whose predicate uses the infix form coalesce(sn.status, '') NOT IN ['deprecated', 'superseded']. The server rejects that form; the codebase's own convention is the prefix form NOT coalesce(sn.status, '') IN [...] (used at the same file's lines 1853, 1854, 8288, 8373, 8568 and elsewhere). The failure is deterministic and independent of the name, so it blocks every sn rescore invocation, not only these three.

The fix is one line: replace coalesce(sn.status, '') NOT IN ['deprecated', 'superseded'] with NOT coalesce(sn.status, '') IN ['deprecated', 'superseded'] at graph_ops.py:24506. Product code is outside this node's write fence, so it is reported rather than applied.

Control (log ~/.config/reckon/crew/runs/r-20261016T100729750893-shc-exhausted-rescore/cypher-not-in-control.log): the invalid form is REJECTED: CypherSyntaxError ("Invalid input 'NOT'"), while the valid form is ACCEPTED: [{'c': 2936}]. The accepting arm is the positive control — it proves the connection and the label resolve, so the rejection is the predicate's syntax and not the query's reachability.
