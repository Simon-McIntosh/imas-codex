Attachment reconcile holds a stranding detach instead of aborting the pass

Defect

reconcile_attachment_consistency (imas_codex/standard_names/attachment_audit.py) detached every attachment the consistency guard rejected, then called require_producing_sources over the touched names inside one transaction. A rejected attachment that was its name's sole producer left the name sourceless, so the invariant raised MissingStandardNameSource inside the transaction and rolled the attach → every attachment was restored and the pass aborted, taking the family apply that runs after it with it. The halt was self-sustaining: the next pass computed the same detach set and raised again, so one name the pass could never repair blocked sn harmonize --apply indefinitely.

Reproduced live (read-only, dry_run). The name vertical_coordinate_of_coil_conductor (stage exhausted, status draft, documentation accepted) has one producer, dd:ic_antennas/antenna/module/strap/geometry/arcs_of_circle/z (status extracted). The guard rejects the pair — hardware locus coil_conductor shares no device token with the DD path: 

locus/source device mismatch: SN 'vertical_coordinate_of_coil_conductor' has hardware
locus 'coil_conductor' but path 'ic_antennas/antenna/module/strap/geometry/arcs_of_circle/z'
shares no device token with it

Change

In reconcile_attachment_consistency, before any detach: an actionable verdict whose removal would leave its name with no non-stale producer is not detached. It is counted in a new skipped_stranding bucket beside skipped_protected and skipped_misnamed, kept in held_stranding, and logged loudly by name and path as an operator worklist the way names_misnamed is. The attachment is left exactly as found — no binding written, none removed. The remaining verdicts are detached as before and require_producing_sources still runs after the detach, so a stranding the hold did not anticipate is still refused.

The would-strand test is the invariant's own rule, not a second definition, and Python performs no part of it. The audit's single attachments read also returns, per name, the set of its non-stale producers (live_producers, collected from the name side so a producer without a FROM_DD_PATH edge is still counted) and the invariant's own derived-parent exemption (sn_stranding_exempt, composed from source_invariant._derived_parent_cypher() over sn.origin and the live-child block, its braces doubled because the read is a str.format template). The hold then does only the arithmetic the read cannot — subtract the strings the detach set would remove from a name's producer set and see whether any survives — so the hold and the require_producing_sources backstop cannot drift. The template's call contract is unchanged: scope remains its only placeholder, so the .format(scope=…) calls at tests/standard_names/test_attachment_audit.py:690,707,1017,1018 still work, and no query is added to the pass.

Tests

tests/standard_names/test_attachment_stranding_hold.py runs the reconcile's own Cypher against an empty disposable Neo4j (started by imas_codex.graph.temp_neo4j helpers, no export dump loaded) that the test plants its own fixtures in.

  • test_sole_producer_rejected_attachment_is_held — a sole-producer rejected attachment is held and counted, and its edge, DD projection and mirror are untouched.
  • test_other_rejected_attachments_are_detached_in_the_same_pass — a rejected attachment on a name with another producer is detached in the same pass, with the accepted one and the surviving producer left intact.
  • test_invariant_refuses_a_detach_forced_past_the_hold — forcing the held detach past the hold leaves the name sourceless and require_producing_sources raises, so the backstop still holds.

Negative control: disabling the hold so the stranding detach is attempted makes test_sole_producer_rejected_attachment_is_held fail (1 failed, 2 passed, exit 1), while the unmodified head passes all three.
