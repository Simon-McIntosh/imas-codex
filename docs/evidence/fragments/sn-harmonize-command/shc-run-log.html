Every spending sn command writes a run log

A command that can spend places model calls whose record is the run log under ~/.local/share/imas-codex/logs/. A command that calls no logging helper leaves nothing behind, so its evidence can cite only the command line and its exit status. Every qualifying command now starts with a setup_logging call. Write paths: imas_codex/cli/sn.py, tests/standard_names/test_sn_command_logging.py.

The spending set, established structurally

The set is derived from what each command is, not from a hard-coded roster, so a newly added spending command is caught before it runs unlogged. A command qualifies when it takes a cost-limit option (cost_limit) or when its callback reaches a compose / review / documentation / inline-review entry point through this module's call graph. The walk over the sn click group, recursing into sub-groups, found eight:

  • run — takes a cost-limit option.
  • bench — reaches rescore_descriptions_report, run_benchmark, run_calibration_gate.
  • release — reaches run_review_release (LLM notes under --llm-notes).
  • approve — reaches tag_fold_back, which composes notes when --llm-notes is set.
  • harmonize — takes a cost-limit option.
  • review — takes a cost-limit option.
  • edit — takes a cost-limit option; spends through run_inline_review.
  • rescore — takes a cost-limit option; spends through rescore_name.

run and review already logged and were left as they are, as were the helper calls inside _run_sn_cmd. The six remaining commands each received one added call.

Each call sits at the top of its command body, after the docstring, before any work. The setup_logging import is function-local in each command, matching how these command bodies import their other helpers.

use_rich=True: why

These six commands print through the module-level rich console (console = Console() at the top of sn.py). With use_rich=True, setup_logging configures the log file and returns a rich Console without touching logging.basicConfig, so console output is exactly as it was and no stderr handler is added. use_rich=False would attach a basicConfig handler and change what the command prints — the choice is made to leave output unchanged, not for a logging preference.

Negative control

Declared mutation: remove each setup_logging call and its tests fail. Removing every setup_logging("sn" line from sn.py and re-running the file gave 4 failed, 1 passed (EXIT=1): the structural test names the commands left unlogged, and the three behavioural tests find no call reached. The source was then restored byte-identical from the pre-mutation copy (diff reported no difference; the call count returned to the expected figure). The guard is live rather than vacuous.
