A dry run reports the apply's refusals

sn harmonize --apply --dry-run returned before apply_families ran, so the recommended-name guard never saw the scope and the dry run printed decision=apply with the full call total for a scope the real apply refuses. The dry run now runs the same guard, over the same targets, and reports the refusal instead of hiding it. Write paths: imas_codex/standard_names/harmonize.py, imas_codex/cli/sn.py, tests/standard_names/test_harmonize_apply.py.

One target computation, one evidence read

apply_guard_targets is extracted in harmonize.py and now feeds both the real apply and the dry run, so the guard operates on exactly the members of every apply-decision family in either path. preview_recommended_refusals reads the evidence through protection.recommended_name_protections — the same call the guard reads — in a single query, and writes nothing. With no --force a family holding a protected member prints decision=refused, names each protected member with its evidence, and its calls are excluded from the planned-call total and cost estimate; with --force REASON it prints decision=forced and keeps its calls. The override reason is never stamped by a dry run.
