Refusing an apply over names already recommended

Builds the recommended-name guard of sn harmonize --apply (§3 of this plan). A reset rewrites text a physicist has been asked to review, or has already reviewed, so the apply refuses the family before the first member is marked. The guard reuses imas_codex/standard_names/protection.py — the module that already owns "this name is committed, do not move it" — rather than a second query. Write paths: imas_codex/standard_names/protection.py, imas_codex/standard_names/harmonize.py, imas_codex/cli/sn.py, tests/standard_names/test_harmonize_guard.py.

The three classes, exactly

recommended_name_protections returns per-identity evidence for the three classes the lead ruled on 2026-10-12, so a refusal can name each identity and the evidence that protected it:

member of an open frozen review roster a manifests/reviews/*.sn_names.yaml that recorded a candidate request (pr_number/pr_url) candidate_request=<url>
name at name_stage=approved StandardName.name_stage name_stage=approved
name at name_stage=contested StandardName.name_stage name_stage=contested

Refusal before the first reset

apply_families collects the members of every family whose decision is apply and calls refuse_recommended_members before the first mark_members_for_regen. Without --force a protected member raises RecommendedNameError naming every protected identity with its evidence; nothing is marked, snapshotted or reset. With --force REASON the apply proceeds and the reason — together with the evidence it overrode — is recorded once per protected name as a StandardNameChange under the apply's own scope run id, so the override is auditable against the run that made it.

Gates and the negative control

The gate suite is the harmonize, family-harmonization, campaign, pattern-family, protection and Cypher-property tests. Baseline at the orientation base revision: 577 passed. After the change: 582 passed (+5, the new guard tests). The negative control removes the guard call before the reset (SHC_NO_RECOMMENDED_GUARD replaces refuse_recommended_members with a no-op), and test_roster_and_approved_members_refused_without_force then fails — the apply proceeds instead of refusing. The log is negative_control.txt beside the run.
