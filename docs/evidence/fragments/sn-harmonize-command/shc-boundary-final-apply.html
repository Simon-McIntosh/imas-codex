Applying the boundary-averaged density family, unforced — where the run stops

The boundary-averaged density family (flux_surface_averaged_electron_density_at_plasma_boundary, 17 members) was to be applied unforced, at a dry-run estimate of USD 7.04, and then shown to converge. The dry run passes and the family is no longer protected, so the guard no longer stands in the way — but the apply itself does not finish: it needs far longer than any single command the harness allows, and than this node's window. Every figure below is read from the CLI's own output and its log; nothing was fabricated.

Step 1 — dry run: PASS

The report dry run lists the 17-member family and its anchor and is not refused. The --apply --dry-run (which is what prints the call plan and cost) reports decision=apply with no protected-member refusal, the same anchor, 17 planned calls, and an estimate of USD 7.04 at $0.41 per call — at or below the USD 8.50 ceiling. This is the state §14 promised: the family's one formerly-protected member is released.

Steps 2–4 — apply, convergence, idempotence: NOT met

The apply was attempted twice and both attempts were killed before the family composed. Attempt 1 was cut by the brief's timeout 540 at 563 s; the CLI had spent about eight minutes of that on fixed startup (graph resolve, family lint, derive_edges, pool start) before the scoped run began, so barely 90 s of work ran (names_composed=0, spend $0.009934). Attempt 2 was cut by the harness background cap (600 s foreground + 600 s background = 1200 s); at the kill only the anchor had been generated and reviewed, its review cycling at chain=1/3 and held from acceptance on a locus_definition finding, with names_composed=0 and spend ~$1.0069. Twenty minutes produced one member and no acceptance, so the 17-member family needs a long-lived runner — not a single bounded command. The report and the idempotence dry run below record the resulting state honestly.

  • Lint before (step 1 report): 29 — convention_violation=17, link_missing_reverse=12.
  • Lint after (step 3 report): 30 — convention_violation=17, link_missing_reverse=13. Not zero; one reverse link was lost.
  • Convergence (step 3): not met. The 17 convention_violation findings are unchanged; the family was not applied to completion, so the opening-template and canonical-equation checks are not reached family-wide.
  • Idempotence (step 4, second --apply --dry-run): 17 planned calls, not zero — the family remains pending.
  • Per-member documentation scores: only the anchor's were produced by the run — docs_stage=reviewed score=0.849 at chain=0/3, then docs_stage=reviewed score=0.849 at chain=1/3, both held from acceptance. No member reached acceptance, so there is no before/after acceptance pair to report.

Spend against the ceiling

Total spend ≈ USD 1.017 of the USD 8.50 ceiling (attempt 1 $0.009934 + attempt 2 ≈$1.0069). Roughly 12% of the authorized budget was used: the work stopped on the time cap, not on cost — the USD 7.04 estimate would have fitted the ceiling had the apply been allowed to run.

The apply is moved to a long-lived runner

The wall-time bound above is a property of the command, not of the family, so it is answered by giving the apply a runner that outlives a single command rather than by touching the family. On 2026-10-17 the apply was submitted as one batch job — slurm job 1287983, partition all, four hours, four CPUs, 16 GB — pinned to the same --cost-limit 8.5 ceiling and still without --force. It is submitted from inside the fleet allocation (job 1281970 on 98dci4-clu-2002); the fleet guard refuses an implicit nested sbatch by default, so the launch is explicit and bound to one task.

The dry run was re-taken against the main checkout's code before submitting, so the estimate reflects main rather than this worktree. It still lists the 17-member family and the same anchor, with decision=apply and no protected-member refusal, and an estimate of USD 7.20 — below the ceiling. Main's lint path reports 28 where the 2026-10-15 worktree run reported 29 (convention_violation 15 against 17); the family and its anchor are unchanged between the two.

Steps 3 and 4 are therefore reported here only once the job ends: the report's lint count and per-member documentation scores, and the second dry run's call count, will be added with the job's own log and its spend against the ceiling. Until then this section states the runner, and the sections above state the interrupted attempts it replaces.
