The dry-run cost estimate reads whole runs, and its tests assert independent figures

Three follow-ons from the independent review of the estimate landing (shc-dry-run-estimate): the cost read truncated runs, and two tests asserted the literals they had themselves injected. A fourth change gives the dead-reference prose rewrite one owner. Write paths: imas_codex/standard_names/harmonize.py, tests/standard_names/test_harmonize_estimate.py.

The cost read selects runs, then counts them whole

_DOC_COST_QUERY applied LIMIT $row_cap to the LLMCost row stream before it grouped by run_id. A run with more rows than the cap was cut mid-run, so its summed run_cost and the name list its calls covered were reported for only the rows the cap happened to keep. The read now names the recent run ids first, bounded by a run count, and aggregates every row of each selected run. A per-run bound is stated as a constant and checked on every returned run, so a run that outgrows it is reported rather than silently truncated. 

# before
MATCH (c:LLMCost)
WHERE c.phase IN $phases AND c.llm_at >= datetime($since)
WITH c ORDER BY c.llm_at DESC LIMIT $row_cap
WITH c.run_id AS run_id, sum(c.llm_cost) AS run_cost,
     collect(c.standard_name_ids) AS name_lists
RETURN run_id AS run_id, run_cost AS run_cost, name_lists AS name_lists
# after
MATCH (c:LLMCost)
WHERE c.phase IN $phases AND c.llm_at >= datetime($since)
  AND c.run_id IS NOT NULL
WITH c.run_id AS run_id, max(c.llm_at) AS newest
ORDER BY newest DESC
LIMIT $run_cap
WITH collect(run_id) AS run_ids
MATCH (c:LLMCost)
WHERE c.run_id IN run_ids AND c.phase IN $phases
  AND c.run_id IS NOT NULL AND c.llm_at >= datetime($since)
WITH c.run_id AS run_id, sum(c.llm_cost) AS run_cost,
     collect(c.standard_name_ids) AS name_lists, count(c) AS rows
RETURN run_id AS run_id, run_cost AS run_cost, name_lists AS name_lists,
       rows AS rows

measure_doc_call_cost takes run_cap in place of row_cap and reads each returned rows count against _DOC_COST_ROWS_PER_RUN; over the bound it raises with the run id and its row count rather than returning an understated spend.

Each assertion names a figure the code computes

Two assertions restated literals the test had itself handed the code, so they held whatever the code did. Each now reads a quantity the code derives from inputs the test does not echo back. 

# before
applied = outcome["applied"][0]["result"].total_cost
assert applied == pytest.approx(0.30 + 5.40)   # the test's own drain spends
# after
assert drain.calls[0][1] == pytest.approx(_FAMILY_CEILING)
assert drain.calls[1][1] == pytest.approx(_FAMILY_CEILING - drain.spends[0])
# before
assert result.total_cost == pytest.approx(3.0)   # the cost_fn the test injected
# after
anchor_charge = cost_fn(f"scope-{_ANCHOR}")
assert result.total_cost == pytest.approx(anchor_charge)

The family-span pair asserts the family-cap arithmetic — each batch offered the single ceiling less what the earlier batch charged — rather than the spends the drain was handed. The total-cost assertion reads the hook's own figure, so a stale literal in the test cannot keep it green.

One owner for dropping a dead reference

_drop_doc_reference removed a dead name: reference from documentation prose and restored the visible link text. Its two local regexes restated the syntax owners in doc_links.py, so they could drift from what the derivation actually reads. The markdown spelling is now found by doc_links.find_name_links — the owner of the label-and-target pairs — and the bare name: spelling by doc_links.find_name_references, the owner of the reference syntaxes. Both local regexes are deleted.

Signature gap. resolve_doc_links(gc=None) is named in the brief as the owner of the rewrite, but it does not fit this call. It is a graph-wide pass: it scans every accepted StandardName's documentation, decides which references are dead from the graph (a target that is superseded or exhausted, resolved through REFINED_FROM), rewrites them and writes the cleaned prose back to the graph. _drop_doc_reference is the opposite shape: a pure in-process rewrite of one prose string, given the one target it must drop, run while the reverse-link step is still composing a write batch that has not been written. resolve_doc_links takes no prose and no target, and would neither know which reference to drop nor be correct to call from inside that loop — it would scan and write mid-step. The brief's other owner, find_name_links, is the right one for the syntax half and is what the code now uses; the rewrite half has no fitting owner in doc_links.py beyond the reference parser used here.
