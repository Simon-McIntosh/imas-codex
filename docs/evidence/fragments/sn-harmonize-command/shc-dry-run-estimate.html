The dry run estimates from measured spend, and the family cap is airtight against an unmeasured batch

sn harmonize --apply --dry-run used to multiply the planned calls by a fixed constant (ESTIMATED_DOC_CALL_COST_USD = 0.05): 17 planned calls printed $0.85, while the apply then spent $6.26 — a guess three-quarters of the real cost low. The dry run now reads the recorded documentation-seat spend from the ledger and estimates each planned call from it, and it prints the basis so the figure can be judged. For the 17-member boundary-density family it printed $7.04 — measured from 7 recent runs covering 23 calls at $0.41 per call — against the $6.26 the second forced apply recorded (anchor $1.026 + members $5.233), 12% above the applied spend and inside the 30% band. A separate leak is closed too: a member batch whose drain cannot measure its own spend was charged the runner's fallback cost to the runner but not to the family, so the family could overrun its cap; that fallback is now charged to the family as well.

Where the estimate is measured

The measured estimate, after the change
SiteRole
imas_codex/standard_names/harmonize.py — measure_doc_call_cost(gc) The bounded reader. It reads the documentation-seat phases (generate_docs, refine_docs, review_docs) from LLMCost nodes in a fixed recent window, most-recent-first under a row cap, and returns the distinct-name count, the run count and the total spend. The mean cost per call is the aggregate spend over the distinct names those runs documented, so the self-inflating solo-run figure is not used and the review that follows each regeneration is included. It returns None when nothing was recorded — the dry run then says the estimate is unavailable rather than guessing.
imas_codex/cli/sn.py — the dry-run branch Multiplies the planned calls by the measured mean and prints the basis: the runs read, the calls, and the mean cost per call. The retired constant is gone — there is no second path.
imas_codex/standard_names/harmonize.py — _family_budget_drain(...) The family cap wrapper. A batch whose drain returns None — the same condition under which the runner falls back to cost_fn(run_id) — now charges cost_fn(run_id) to the family's spent and returns it, so the family's remaining budget reflects it and the family cannot exceed its ceiling by one unmeasurable batch.
