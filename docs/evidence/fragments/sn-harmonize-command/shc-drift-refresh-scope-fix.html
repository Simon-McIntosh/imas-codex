Binding the source-drift refresh to the run that asked for it

sn harmonize --family electrostatic_potential --apply spent all twelve of its model calls on two names outside the family because the docs-only flush carried the family's run id into run_sn_pools, which handed that id to a graph-wide drift refresh. The refresh found drifted sources anywhere in the graph, steered them, and attached each one to the active run id — after which the family drain, whose claim predicate is that same run id, regenerated them inside the family's cost ceiling. Four changes land here: the refresh is scoped to the run's own names, a path change is no longer reported as a rename, a source the detector cannot resolve is reported rather than dropped, and a name with several sources is compared against every one of them.

Plan authority: imas-codex:sn-harmonize-command §4, anchor c-s4-drift-scope-landed, and the diagnosis docs/evidence/fragments/sn-harmonize-command/shc-apply-drift-scope.html.

1. The scope now binds the refresh

Before. detect_source_drift had no target set at all; it scanned every (src:StandardNameSource)-[:PRODUCED_NAME]->(sn:StandardName) row in the graph. refresh_drifted_sources therefore steered whatever it found, and because the loop passed only scope_run_id=run_id, every steered name came away tagged with the active run — which is precisely the predicate the docs pool claims on. A scoped run could not avoid owning names it had never selected.

After. detect_source_drift takes sn_ids=None and adds AND sn.id IN $sn_ids to its scan when that set is supplied (imas_codex/standard_names/source_refresh.py:280); refresh_drifted_sources threads it through, and the loop resolves the set once per drain and passes it (imas_codex/standard_names/loop.py:2103–2111). 

_refresh_ids = (
    await asyncio.to_thread(_scope_name_ids, scope_run_id)
    if scope_run_id
    else None
)
sr = await _global_maintenance_call(
    refresh_drifted_sources,
    scope_run_id=run_id,
    sn_ids=_refresh_ids,
    default={},
)

_scope_name_ids(scope_run_id) (imas_codex/standard_names/loop.py:331) returns MATCH (sn:StandardName) WHERE sn.run_id = $rid OR exists { (:StandardNameSource {run_id: $rid})-[:PRODUCED_NAME]->(sn) } RETURN DISTINCT sn.id. Both halves are needed: a family apply marks its members by setting sn.run_id, while focus mode seeds sources carrying the run id and produces names through them. The helper returns an empty list on any query error, so a scope whose size cannot be read fails closed into a no-op refresh rather than open into a graph-wide sweep.

Unscoped runs did not change. With scope_run_id is None the loop passes sn_ids=None, the filter is absent from the query, and refresh_drifted_sources(gc=…) steers every drifted name in the graph exactly as before. The graph test asserts both directions: a scoped scan returns only the run's name, and the same graph unscoped returns both.

2. A path change is a path change, a rename only when lineage says so

Before. The reason string called every source_path delta a rename, whatever happened: a source re-pointed to an unrelated path read in the log as a rename, which is a claim about lineage the detector had never checked.

After. The scan resolves the source's anchor through RENAMED_TO*1..12 to its terminal node and returns both the anchor id and the resolved id, so renamed is true only when the two differ (source_refresh.py:336). _format_reason(…, renamed=…) then emits path renamed for a lineage move and path changed otherwise (source_refresh.py:366).

3. A source the detector cannot compare is reported, not dropped

Before. A source whose id does not resolve to an IMASNode produced no drift row and no mention. The refresh reported a smaller drift count with no way to tell a clean name from one it had never managed to look at — a name could be silently unmaintained indefinitely.

After. The scan reaches the source with an OPTIONAL MATCH (o:IMASNode {id: src.source_id}) and records {"sn_id", "source_id"} into the caller's unchecked list when the comparison yields no resolved path (source_refresh.py:316). The summary gains unchecked and unchecked_count (source_refresh.py:439–440) and a warning names the first few pairs (source_refresh.py:444–449); the loop's log line carries the count (loop.py:2117–2122).

4. Every source of a name is compared

Before. The scan emitted one row per (name, source) pair and the caller's grouping took what it got, so a name produced by several sources was not guaranteed to be judged against each of them — a second source that had drifted could be invisible behind a first that had not.

After. Rows are grouped per name, each source is compared, and the name is reported as drifted when any source has drifted, with the drifting source as the representative (source_refresh.py:245–340, ordered ORDER BY sn.id, src.id). The graph test seeds one clean and one drifted source on a single name and asserts exactly one drift row, naming the drifted source.

The negative control is the one that matters: the guard's whole point is that it stops steering, and a green suite never shows a guard firing. Dropping the AND sn.id IN $sn_ids filter left the scoped test red on the assertion that the out-of-scope name keeps its stale documentation and a null run_id, with the outsider steered instead. The filter was then restored and git diff --exit-code imas_codex/standard_names/source_refresh.py confirmed the tree matched the commit.

Left for a later node

Re-stamping source snapshots after documentation regeneration in imas_codex/standard_names/graph_ops.py is not addressed here and remains open. This node scopes the refresh and corrects what it reports; it does not change when a snapshot is written once a name's documentation has been regenerated, so a name regenerated but not re-stamped can still be reported as drifted on the next drain.
