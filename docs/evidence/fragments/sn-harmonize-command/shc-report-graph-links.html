A report link is dead only when the graph holds no such name

The §2 report built its dead-link lookup from the scoped members alone, so a family documentation linking to a valid name outside the family counted that link as dead — 19 such links on the 17-member boundary-density family. Deadness now resolves against every name the graph holds; the scoped set stays the scope of what is reported, and the missing-reverse test is unchanged.

run_link_integrity in imas_codex/standard_names/review/audits.py takes an optional known_ids set. The dead-link test uses it when given and the ids of the passed names otherwise, so a caller that hands the whole catalog keeps its previous behaviour. The reverse-link index and the missing-reverse test stay on the scoped ids: a target outside the scope is not reported on, so it cannot be reported as non-reciprocal. report_family_rows in imas_codex/standard_names/harmonize.py supplies the set from one bounded read of every StandardName.id (_known_name_ids).

The test and its negative control

tests/standard_names/test_report_graph_links.py drives report_family_rows with a two-member scope whose default member links to a third name outside the scope. With the third name in the graph set the report carries no link_dead_link finding; with the set holding only the two scoped ids it carries one. A direct call to run_link_integrity without known_ids still reports that link dead, pinning the fallback.

The declared negative control — ignore the graph set and the out-of-scope link is reported dead again — was applied by passing in_scope without known_ids in report_family_rows and kept as negative_control.log: EXIT=1, with test_target_in_graph_outside_scope_is_not_dead failing while the other three pass. Reverted, the gate runs 72 passed, 4 more than the 68-pass base with no added failures.
