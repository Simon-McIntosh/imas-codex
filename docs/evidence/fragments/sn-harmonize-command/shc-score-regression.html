Naming the members whose documentation score fell or dropped below acceptance

Builds the documentation-score report of sn harmonize (§4 of this plan): an apply that rewrites a family reports, by name, every member whose post-rewrite documentation score is below the acceptance threshold and every member whose score fell, each with its before and after value. Write paths: imas_codex/standard_names/harmonize.py, imas_codex/cli/sn.py, tests/standard_names/test_harmonize_apply.py.

Before, from the family rows already read; after, from the same query

The acceptance threshold is the pipeline's own DEFAULT_MIN_SCORE (0.85), not a new constant. plan_family_applies already reads each family through fetch_pattern_families, whose member rows carry reviewer_score_docs; the plan now keeps those as member_scores, captured before the reset replaces each member's docs to pending. After the family drains, apply_families re-reads the same family through the same query and docs_score_regressions compares the two maps. A member newer than the plan, or one with no measured score on either side, is skipped rather than reported as a fall. The report rides the snapshot-and-reset the campaign runner already takes — no second snapshot and no new query family.

What the comparison reports, per member
ClassConditionCarries
below_threshold After score is measured and below the acceptance threshold. id, before, after
fell Both scores measured and the after score is lower. id, before, after

The command prints each such member by name, per family and across the scope, with its two scores; the scope summary counts them, and an apply in which nothing fell prints docs scores: no member below threshold, none fell. A member can appear in both classes — a rewrite that drops a member from 0.90 to 0.60 both fell and lands below acceptance, and the report says so twice rather than collapsing the two readings.

Gates and the negative control

The gate is the harmonize, guard and campaign suite (test_harmonize.py, test_harmonize_apply.py, test_harmonize_command.py, test_harmonize_guard.py, test_campaign.py, test_campaign_pricing.py, test_campaign_manifest_schema.py, test_quarantine_instrument_roles.py). Baseline at the orientation base revision: 144 passed, exit 0. After the change: 148 passed (+4, the new score tests), exit 0 — no added failure. The fixture harness drains through a graph whose member scores the test supplies, so the comparison is exercised end to end rather than at the helper alone: test_apply_names_a_member_below_threshold rewrites base_at_boundary from 0.90 to 0.60 and asserts it is named in both classes with those two values, and test_apply_reports_no_fall_when_no_member_scores_worse asserts a family with no fall names none.

The negative control removes the score comparison (SHC_NO_SCORE_COMPARISON makes docs_score_regressions return two empty lists). test_apply_names_a_member_below_threshold then fails — the apply reports no member below threshold for a member that scored 0.60 — so the test is measuring the comparison and not the fixture. Log: negative_control.log beside the run.
