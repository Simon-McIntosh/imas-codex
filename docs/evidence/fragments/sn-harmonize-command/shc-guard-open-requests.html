shc-guard-open-requests — the recommended-name guard protects only open requests

The recommended-name guard protected every member of a frozen review roster that recorded a pull request, whatever the request's state. A name whose roster request had merged or closed was refused an apply even though nothing was outstanding to protect. _frozen_roster_requests in imas_codex/standard_names/protection.py now reads each roster's request state through the shared promote reader (parse_pull_request_url, _pull_request_call, _pull_request_state) once per roster and protects its members only while the request is open. A merged or closed request contributes nothing: a name a merged request approved is protected by name_stage=approved, which recommended_name_protections already reads from the graph, and a merged request whose fold-back never ran protects nothing. A state that cannot be read — a non-200 reply, a malformed URL, or a pr_number with no readable URL — protects, with evidence naming the request and stating that its state could not be read.
