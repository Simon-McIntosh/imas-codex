§3 — the pipeline was reporting gaps for vocabulary it already had (2026-07-28)

The RC was not cut. The lead asked whether the pipeline's vocab-error rate was a prompt-context defect — “it seems like the pipeline is throwing up lots of vocab errors when the vocab exists”. It is, but not in the prompts: the prompts are complete and the classifier is blind. 531 of 564 recorded vocab gaps say “this token does not exist”, and a large share name quantities that compose from operators the grammar already registers. Chasing that took precedence over the release, because composing the gm cluster before fixing it would only have minted more of them.

Two of this session's own confident diagnoses were falsified by later measurement, both before any code depended on them. That is recorded below as prominently as the findings, because the pattern — a plausible mechanism asserted from reading, then contradicted by one query — is the recurring failure mode in this plan's history.

The defect is one mechanism behind four call sites

Operators are a grammar mechanism that lives outside SEGMENT_TOKEN_MAP, so every consumer reaching for that map alone is silently operator-blind. Measured in the decomposition classifier: 0 of 51 operator tokens appear in its index.

Single operators are caught — ab826533 holds. Every multi-operator compound falls through, which is exactly the inverse ∘ square shape of gm1/gm4/gm5/gm9. The cost is not cosmetic: an absent actionable gap either strands a nameable source (the next drain pays to re-compose it) or raises a spurious request to extend ISN's closed vocabulary. Both look like real gaps in every report.

Tokens the model actually proposed, verbatim from the graph, every one of them expressible today: inverse_square_of_magnetic_field, magnetic_field_magnitude_squared, derivative_of_area_with_respect_to_poloidal_flux, line_integrated_density, gradient_rho_squared_over_B_squared (this one is gm6), logarithmic_gradient, path_length_variation, z_square_average, average_square, mean_square, pedestal_maximum_gradient_of_electron_temperature.

Compounding it: the reason field is empty on all 564. ISN's UnknownBaseTokenError carries the full legal token list, but codex has zero handlers for it and ISN's own message prints only the count. A model that fails is never told which token, which slot, or the alternatives, so it re-offers the same compound. The gap-report segment field is also unconstrained free text.

Two diagnoses of this session, falsified

assertedfalsified bythe truth
The operator_token → qualifier map in the rescue path was relabelling correct model output, producing the qualifier:inverse_square records. One graph query. That path writes a distinctive literal reason string; it occurs 0 times in 564 nodes. The map is not firing at all. The model proposes unregistered compounds; the classifier calls them absent.
A fold/detach costs ~2 min because of 43.6 s of ISN import plus 27.7 s of context build, per process. Interleaved re-measurement on an idle sun_debug node versus the login node at load 15–50. Only the build is intrinsic: 24.5–24.9 s against the production catalog on an idle node. The import is 1.7–2.5 s there; the 43.6 s figure was the BEST of five login-node samples (43.6–96.3 s), and the build read 156–221 s on the same node. So ~80% of the observed 2 minutes was contention and ~20% real, of which the build is ~95%. tests/grammar/ runs in 21 s on a compute node and did not finish in 20 min on the login node.

The second correction has a standing consequence: never take an ISN wall-clock measurement on the login node. The lever on import cost is the NUMBER of module files (936 for the grammar package), not CPU: under load each costs ~50 ms against ~0.6 ms idle, and -X importtime total self-time tracks the swing exactly (3.1 s quiet, 46.8 s loaded, same 936 modules). ~400 of them are pulled by pydantic entry-point plugin discovery, triggered by the first BaseModel class creation, dragging in the whole opentelemetry / rich / protobuf / requests tree. PYDANTIC_DISABLE_PLUGINS=1 cuts login-node import 2.0–2.6× (median ~66 s → ~25 s, interleaved A/B over 6 reps) while costing only 0.26 s of CPU idle — so it is a contention win, not a compute win. logfire is a dev-group dependency that no source file imports; removing it is a dependency decision for the lead, not an agent. Next-largest file-count reduction after it: imas_standard_names/__init__.py imports pint unconditionally, 154 modules a parse-only consumer never needs.

The honest ordering of the three levers, since it changes what to do rather than just what to believe: (1) run bulk sweeps on sun_debug — that removes the ~95 s contention term and is the single biggest factor in the observed 2 minutes; (2) the cache, which removes 24.5 of the ~26 genuinely-real seconds and is what makes a compute-node sweep effectively free; (3) logfire, which halves the residual import that dominates a warm-cache process anywhere contended. Stated plainly: a no-cache sweep on sun_debug would have cost ~26 s per fold, not 2 minutes — the login node was the blocker, not the missing cache.

The ambiguity is one path, and /phi is not it

Counted on the edge the export actually reads (HAS_STANDARD_NAME, both ends at an exported stage, excluding HAS_PARENT co-realization): 103 pairs corpus-wide, exactly 1 of them WEST — equilibrium/time_slice/constraints/b_field_pol_probe/measured realizing both poloidal_magnetic_field and poloidal_magnetic_field_at_constraint_position. The lead has authorised the detach-plus-rebind, which reaches three non-manifest paths, because it is the only fix that closes the ambiguity without orphaning a name.

/phi is resolved as a reasoned residual, and three of its recorded premises were wrong. First, toroidal_coordinate_of_line_of_sight is not grammar-invalid: it parses cleanly as coordinate + a toroidal projection, and toroidal_coordinate parses alone. Both spellings are legal, so this was never a validity problem. Second, the grammar-correct toroidal_angle_of_line_of_sight carries superseded_from_stage='refining', not accepted — it never earned quorum, so restoring it would be a hand-accept, which is banned. The restore-then-repoint capability that tombstone_supersede_into's docstring anticipates cannot be justified on “reinstate previously-earned acceptance” grounds here. Third, /phi is not release-blocking: the family splits 28 paths on toroidal_angle_of_measurement_position and 3 on toroidal_coordinate_of_line_of_sight, on disjoint paths, so no path realizes both and the export stays unambiguous. The cycle risk is real and confirmed (toroidal_angle_of_line_of_sight →REFINED_FROM→ toroidal_coordinate_of_line_of_sight, while toroidal_angle_of_measurement_position refines FROM the former), so a fold would close a 2-cycle. The remaining option — folding the 3 into the measurement-position name — is the one this plan already says to leave alone, since that name legitimately spans a broader concept.

Noted and deliberately untouched: toroidal_angle_of_measurement_position is origin='catalog_edit' and holds 116 sources — the unreviewed bulk-import name whose dedup exemption this plan already removed as a defect. Accepted, broad, and not WEST-blocking; it belongs to sn-graph-wide-integrity.
