§3 unit hygiene — one canonical unit authority, two upstream DD defects, ISN rc58 (2026-07-27)

Chasing the WEST hard tail turned into a units investigation. The tail was not blocked by naming ability but by unit metadata: a dimensionless quantity had no unit at all, one unit had two spellings in one graph, and the Data Dictionary declared one quantity with two different dimensionalities. All are now fixed, two are filed upstream, and the vocabulary the remaining tail needs is released.

Codex fixes

CommitDefect
3989bce6 Dimensionless is not "no unit". normalize_unit_symbol listed -, 1 and dimensionless as non-units and returned None, so every dimensionless quantity (beta, zeff, q, li, elongation, triangularity, magnetic_shear, fractions, h_98) lost its HAS_UNIT edge while its standard name carried the canonical 1 — and the SN↔DD reconcile then dropped each pair on a false disagreement. Split dimensionless (→ 1) from genuine non-units (→ None); healed 706 nodes.
2b95c2de DD count pseudo-units. The DD writes a count as a plural noun (electrons, atoms), which pint cannot parse — so the quantity lost its unit, and with it the correctly-resolved as_parent inheritance of the gas-injection value fields (whose inherited unit IS electrons). Mapped to 1; healed 63 nodes.
28b7fb63 Never guess an ambiguous spelling. The DD wrote Elementary Charge Unit on both charge numbers (genuinely a charge) and ionisation potentials (energies). Aliasing it to e typed 16 energy nodes as a charge — a dimensionality error. Resolves to None instead; retyped the 16 nodes to eV.
70e91cfc, 02cf907d Path-aware DD unit resolution. Where the DD contradicts itself on one quantity there is no single declaration to mirror, so the build now stores the dimensionally-correct unit — driven by the existing dd_unit_exceptions.yaml registry under a new correct_in_graph flag, rather than a second hardcoded list.
de249e5d Symbol order is convention, not cosmetics. A power density is W.m^-3, never m^-3.W. The custom pint formatter emitted factors in pint's internal order, so the DD side spelled units differently from the standard-name side (which canonicalises via imas_standard_names.canonical_unit): 30 Unit nodes carried non-canonical ids and the reconcile logged 168 false disagreements. Both sides now use the one authority; re-canonicalised 30 nodes, repointed 5274 HAS_UNIT edges, synced 348 scalars. (~F is not a substitute — it fixes ordering but emits W / m ** 3, not IMAS dot-exponential notation.)
5d5d9690 ISN pin → rc58; read-only tool assertion now names the suppressed write-tool set instead of a count that had gone stale (6→7 when edit_standard_name was added).

ISN rc58 — the vocabulary the tail needs

  • half_width (physical_base) — the distance from a peaked profile's maximum to its half-maximum on one side. Deliberately not geometric_base: that segment is mutually exclusive with physical_base, so placing it there would split the width family (width, angular_width) across segments that can never be reasoned about together.
  • confinement_enhancement_factor (physical_base) + ipb98y2 (qualifier, normalized category) — the H-factor, with the scaling law it is measured against carried by a qualifier, so each further scaling costs one token rather than a new base. Follows the safety_factor / peaking_factor precedent, and the greenwald / ejima / bohm named-model qualifier precedent.
