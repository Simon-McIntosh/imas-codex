§3 — three write paths that quietly un-named sources, and the real size of the double-name defect (2026-07-28)

The RC was not cut. Chasing the WEST residual as the lead asked turned up three structural defects in the repair machinery itself — two of which would have destroyed acceptance had the planned repair been applied as written. Those are fixed and pushed. But two of the section's own done-when criteria are genuinely unmet, and the honest report is that the release candidate is not ready, not that it is.

Acceptance moved 289 → 301 of 355. The line-of-sight /z family now reads under one name. The release-blocking ambiguity is 14 DD paths, not 48 — and the number was wrong in both directions for reasons worth recording.

Three write paths that removed a source's only live name

All three are the same shape: an operation whose purpose is to consolidate names silently left a source realizing nothing. A source with no live name is not merely cosmetic — the next drain rewinds it to extracted and pays to re-compose it, and in the meantime the manifest reports it as a gap.

The ambiguity was counted on the wrong edge

The plan carried “48 WEST-touching ledger rows, dominated by the line-of-sight /z and /phi splits.” Measured, the picture is different in both magnitude and composition:

  • Line-of-sight is 4 of them, not most. The dominant class is 34 unrelated near-duplicate pairs — one catalog-imported name and one pipeline name competing for a single source (atomic_mass vs neutral_species_atomic_mass, poloidal_magnetic_flux vs …_at_flux_surface, and so on). Each is a physics judgement, not a structural sweep.
  • Provenance edges over-report by 2.6×. Counting PRODUCED_NAME gives 37; the export reads the DD-side HAS_STANDARD_NAME realization. Of the 35 paths realizing more than one live name, 13 have only one end at an exported stage and 8 are HAS_PARENT parent/child co-realization — correct by construction, with the parent sitting at drafted so it never reaches the catalog. 14 are genuinely ambiguous in the export.
  • A realization can exist with no provenance behind it. 32 HAS_STANDARD_NAME edges corpus-wide have no StandardNameSource asserting them. The ledger's orphan and desync checks both run name→source and cannot see this class, yet it is precisely the class that reaches consumers.

A missing instrument, now built

The consistency guard rules on mechanical questions — dimensionality, locus and device, vector families. It is silent on a semantic mis-share: two names that are each valid, denote different quantities, and both attach to one DD path. Deciding which the path realizes is a physics judgement, and once made there was no way to record it — no CLI reached a single realization edge.

sn detach <dd-path> <name> --reason … (6fd9c365) closes that. It reuses the reconcile's own detach semantics so a targeted repair and the retroactive sweep leave the graph in the same shape, writes the reason into the change ledger, reaches projection-only pairings, and refuses to orphan a name — when every source rejects a name the NAME is wrong, which is sn edit --rename's job. That refusal fired twice in anger during this session, correctly stopping two detaches that would have orphaned triangularity_of_flux_surface and poloidal_magnetic_field.

What was applied

A read-only adjudication fleet ruled on all 31 non-coordinate pairs against DD documentation and the ISN grammar vocabularies. Applied from those verdicts:

  • The /z line-of-sight fold — 47 sources carried; the axis now reads under one name (vertical_coordinate_of_line_of_sight, 46 sources) plus two genuinely distinct loci. No source of the folded name was a beam-tracing DD path, so the name was wrong for its entire set.
  • 9 targeted detaches on release-blocking ambiguity, each with a DD-quoted reason: the two radiance_spectral paths (continuum vs impurity line emission), hard_x_rays/channel/etendue, grid/psi_boundary, faraday_angle/measured, flux_loop/reconstructed, r_outboard, j_phi.
  • Folds for normalized_beta, the darea_drho_tor derivative duplicate, and the decomposed magnetic-shear name (a mis-decomposition: magnetic_shear is a lexicalized registered base, and s = (r/q)dq/dr is not the bare derivative).
  • A review drain — 18 names reviewed, 5 regenerated, $4.06 of the $15 cap, accepting at 0.92–0.95 by quorum consensus. This is what moved 289 → 301, including the poloidal_magnetic_flux_at_measurement_position unit repair (W → Wb) landing on merit at 0.950.

The gm cluster needs no operator vocabulary — but it does need one base

The recorded gaps blamed qualifier:inverse_square and qualifier:square. That diagnosis was wrong twice over: inverse and square are already registered operators, so the composer was reaching for the wrong segment class — and, verified against the real parser, they cannot be used in _of_ chain form anyway. The flat model carries exactly one transformation slot, so inverse_of_square_of_major_radius raises; the working construction is one bare flux_surface_averaged prefix with inverse/square absorbed as base-compound glue.

Four of the nine are expressible today with no ISN change, all four round-tripped through parse_standard_name and clean under run_semantic_checks at their DD unit. The genuine gap is ∇ρ: toroidal_flux_radius is a geometric carrier and the model forbids transformation together with geometric_base, so gradient_of_toroidal_flux_radius is a hard error and |∇ρ| has no expression. It needs one vector base toroidal_flux_radius_gradient — which must not carry constant_on_flux_surface, since ρ is constant on a flux surface but |∇ρ| is not, and flagging it would trip the flux-surface-reduction gate against flux_surface_averaged.

Both collapsed names parse cleanly, so this is a semantic collapse rather than a parse defect — but one name serves two paths of different dimension (gm2 m^-2 vs gm6 T^-2) while recording unit 1, and its base is an ordinal-family placeholder that discriminates neither a power nor a divisor. Neither is recoverable by unit correction; both must be superseded.

Why the RC was not cut

Two done-when criteria are unmet, and cutting anyway would ship exactly the shoddiness the lead's direction was about:

  1. 54 of 355 sources still lack an accepted name — 23 of them with no name proposed at all. Roughly 8 of those only need a free compose drain; the rest are the gm cluster, the exhausted/superseded remainder, and a documented non-nameable set that has not yet been written into a form the PR body can state.
  2. The ambiguity is reduced, not closed. 9 detaches and 4 folds landed against 14 blocking paths, and several remaining verdicts are sequenced behind a review pass because the correct name is the drafted one and sn supersede requires an accepted target. Inverting those folds to satisfy the tool would enshrine the defective name.

Two further blockers are tooling, not judgement. /phi cannot be folded the way the plan directs: toroidal_coordinate is not a registered ISN carrier (toroidal_angle is), and toroidal_angle_of_line_of_sight — the grammar-correct id — was refined into a measurement-position name, so it sits tombstoned inside a REFINED_FROM chain that no sanctioned instrument reaches. Separately, the new gate makes each fold take about two minutes because the scoped audit reloads the guard's grammar context per call; acceptable for a handful of repairs, too slow for a bulk sweep.

Findings worth their own work

  • Six of eight engineering pairs were one bug, not six disputes — a derived structural parent holding its child's DD leaf. Parents otherwise hold zero DD sources, so a single sweep (“detach every derived name from any DD source also held by one of its HAS_PARENT children”) would clear a large share without per-case adjudication.
  • toroidal_plasma_beta is superseded yet still holds equilibrium/…/beta_tor, and the normalized name holds that path too — so an un-normalized quantity now resolves to a normalized name. The same dedup bug in a nastier form.
  • radiance_at_spectral_line is accepted on an energy basis (W.m^-2.sr^-1) while all three DD paths it came from store photon radiance — a unit contradiction across its whole historical set, and its child inherits it.
  • The ISN grammar carries two carriers for rho_tor (toroidal_flux_coordinate and toroidal_flux_radius), both flagged constant_on_flux_surface. That will keep minting near-duplicate derivative names — one of the pairs folded this session was exactly that.
  • Binary-operator operands are not vocabulary-validated: parse_standard_name("ratio_of_wibble_frobnicator_to_square_major_radius") succeeds. Any ratio_of_… construction would appear to parse while being meaningless.
