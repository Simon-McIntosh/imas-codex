§3 — the attachment heal, and the three guard rules it caught (2026-07-27)

The heal ran, and it would have damaged the graph had it run as written. The previous session left a retroactive attachment audit that was landed, tested, and — as it turned out — never called by anything. Pointing it at the live graph for the first time rejected 892 of 6027 attachments. Triage of those 892 found that a large fraction were the GUARD being wrong, not the data.

Acting on them unexamined would have detached correct attachments and stripped 127 standard names of every source they had. Three rule defects were root-caused and fixed first; only then was the heal run.

Defect 1 — the tense rule read a container and a species suffix as derivatives

Three independent faults, 24 false positives between them, every one on an accepted name:

  • _dt was taken to mean d/dt. The DD also uses it for deuterium–tritium, so neutron_diagnostic/reconstructed_emissivity/emissivity_dt read as a time derivative. The DD's real derivative form carries a leading d on the differentiated quantity (ddensity_dt_total, dphase_dt) — a shape, not a suffix.
  • /derivatives_1d/ marks a CONTAINER. A grid coordinate inside it is not a change, so transport_solver_numerics/derivatives_1d/grid/area was refused as a rate.
  • A name expresses rate-ness by suffix as well as prefix. Only leading prefixes were recognised, so runaway_electron_source_rate and rotation_frequency_of_neoclassical_tearing_mode read as base quantities and every genuine derivative attached to them was rejected — 21 attachments.

The one true positive was kept as the regression guard: bremsstrahlung_visible/channel/intensity → time_derivative_of_bremsstrahlung_count_at_detector_pixel. Rate bases are now derived from ISN's own physical_base vocabulary at runtime, not listed in codex. Commit 7f84d189.

Defect 2 — ordinality, which a locked decision says never enters a name

The distinct-vector rule exists for a real fault: a camera's direction/z and its image-up up/z are different vectors and must not share one scalar name. It was also firing on first_point / second_point / third_point — ordinal samples of ONE line of sight.

That directly contradicted a decision already locked on this plan: "name the line-of-sight endpoint quantity via the existing line_of_sight locus, WITHOUT the point index — ordinality never enters the name." The compose prompt had been corrected to obey it, so the guard was refusing exactly what the composer was instructed to produce. radial_coordinate_of_line_of_sight had 67 of its 70 attachments rejected on this basis.

So the answer to the plan's question is: over-reach, and against a locked decision. Ordinal samples no longer conflict; camera direction-vs-up and the geometry primitives (a rectangle's centre vs an oblique's reference corner) still do, pinned by tests.

Defect 3 — the same root pattern a third time

state_subjects was the literal tuple ("ion_state", "ion_charge_state", "neutral_state") — an ISN vocabulary set hardcoded in codex, which AGENTS.md names as a binding violation, and which had already drifted. ISN expresses state resolution through a dedicated state segment whose tokens are charge_state and internal_state; nothing in the tuple knew about internal_state. So neutral_internal_state_pressure read as species-level while its source edge_profiles/ggd/neutral/state/pressure/values is plainly state-resolved. About 40 names in that one family. Now read from the live grammar, with a drift test asserting every ISN state token is covered. Commit 59331ae6.

Two defects in the audit itself

  • An order-dependent rule applied order-independently. The distinct-vector rule is pairwise against existing_sources. At compose time sources arrive one at a time and only ACCEPTED ones accumulate, so of a conflicting group the first survives and the rest are refused. The audit passed every sibling to every row, so each member saw the others and all N were rejected — including the one compose would have kept. That is where the 127 would-be-orphaned names came from. Fixed to accumulate deterministically, compose-style. Commit 1cd51e0d.
  • A whole-name wipeout is a NAME defect, not an attachment defect. When every source of a name is refused by the same rule, the sources are consistently grouped and the NAME is wrong — atomic_count_of_ion_state has 76 sources, all at element/species level. Detaching all 76 would orphan an accepted name and rewind 76 sources to paid recomposition to fix what one sn edit --rename fixes. Such names are now reported for sn edit and withheld from the detach set.

The 10 name-level defects

Each needs sn edit --rename (or a hint) rather than a detach: atomic_count_of_ion_state (76 sources, all species-level), ion_upper_bound_charge_number (37), flux_surface_averaged_metric (4 — the gm collapse), radiance_at_spectral_line (3), frequency_of_diagnostic_antenna (3), poloidal_magnetic_flux_at_measurement_position (2), equilibrium_weight_of_interferometer_beam (2), extent_of_hard_xray_detector (2), normalized_count_at_detector_pixel (2), wavelength_of_detector_pixel (2).

The 6 orphaned names

Every attachment each had was inconsistent, so they now carry no source at all — surfaced for a decision rather than auto-superseded, as designed: count_at_detector_pixel, electron_particle_source_rate, ion_vibrational_level, launched_power_of_electron_cyclotron_launcher, radial_derivative_of_area_of_flux_surface, wave_power_of_beam_tracing_beam.

Two reconciles that were never wired, and a registry that never applied

  • The attachment re-validation was never called. Its commit message read "re-validate existing source-to-name attachments on every run", but no module referenced it, so every stored edge went on unexamined. Now wired into the startup reconcile, ordered so a freed source recomposes in the same run that detached it. Commit 1e4aef30.
  • A name could carry two units. The schema declares HAS_UNIT cardinality one, and the guard admits a source by comparing dimensionality — so a name holding both 1 and m^-2 accepts sources of either, which is one mechanism by which distinct quantities collapse. Both writers already self-heal, but a name whose unit predates that keeps the residue forever once it reaches a terminal stage, because nothing recomposes it. radial_flux_surface_averaged_metric was the one such node, now healed; a graph-quality test holds the invariant.
  • A registered unit correction never reached the graph. The DD declares one documented quantity with two dimensionalities: ece/channel/position/psi and ece/channel/beam_tracing/beam/position/psi both read "Poloidal flux" and declare W and Wb. That is precisely the correct_in_graph case, but the registry entry carried suppression only — and an accepted poloidal-flux name duly inherited total power. Flagging it was not enough either: the correction is applied by the DD build alone, so an entry added afterwards has no effect on stored paths, and nobody rebuilds the dictionary to land a unit fix. A registry whose entries only work on a rebuild silently does not work. Both facets now declare Wb, and an invariant test asserts no stored unit contradicts the registry. Commit 5d33ecea.

The unit detector

The SN↔DD unit-agreement axis is down from the 354 recorded previously to 6 rows (the earlier figure was counted over a different edge). Every one is explained:

  • 4 — flux_surface_averaged_metric against gm2/gm3/gm6/gm7. The gm collapse; dissolves when the staged repairs recompose.
  • 1 — poloidal_magnetic_flux_at_measurement_position declaring W. The DD self-contradiction above; now correctly surfaced as a name-level defect for sn edit.
  • 1 — edge_profiles/ggd/a_field/r (the magnetic vector potential, T.m) attached to radial_neutral_momentum_flux. A single interloper among 23 correct momentum-flux sources; the guard rejects it and the heal detached it.

One decision remains

198 inconsistent attachments sit on accepted names and were deliberately not detached: an accepted name is catalog-authoritative, so losing a source is a decision rather than hygiene, and the audit gates it behind an explicit opt-in exactly as sn run --reset-to and sn prune do. The release candidate exports accepted names, so leaving them means PR'ing known-wrong attachments to the stage-3 reviewer — the thing this sequencing was inverted to avoid. Detaching them reroutes about 190 sources to recomposition, which is free to compose and paid to review.
