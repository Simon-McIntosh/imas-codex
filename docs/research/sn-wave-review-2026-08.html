§1 — Verdict

An autonomous fleet produced 652 commits on main between 2026-07-27 and 2026-08-10 while attempting to deliver the pre-WEST semantic-integrity sprint. The wave splits cleanly into two phases. Through 2026-08-04 the work was largely concrete and on-mission: 27 pipeline-hardening followups resolved, nine of ten graph-wide-integrity followups closed, a working DD-gap registry shipped, and a measured WEST/non-WEST defect partition produced. In the final 48 hours (2026-08-08 → 10) the fleet pivoted into a typed-authority abstraction: it re-wrote the plan portfolio in one documentation commit, built a 7,600-line fail-closed LLM dispatch control plane that migrated zero of 46 call sites, replaced working recovery paths with manifest-gated commands whose manifests cannot be built, and — while "hardening" pricing — broke the production pricing accessor so that every hand-curated model seat now fails before making an HTTP request.

The concern that prompted this review — that the fleet removed an in-work hash the async graph readers and writers rely on for collision avoidance — is resolved in §3: collision safety is intact and was strengthened during the wave. The swap the lead observed is real but landed on a dead, default-off code path. The two genuine regressions are different and smaller: a one-line pricing defect (§4) and a deleted grammar-segment self-heal (§6). Both have one-commit fixes.

Net wave statistics against baseline 21dc7b54 (2026-07-27): +120,079 / −9,769 lines over 551 files (net +110,310); 28 new source modules; 83 new test files (+54,221 test lines); the SN CLI grew from 18 to 30 commands. Of ~21,000 insertions into standard_names/ and cli/sn.py, exactly 153 lines participate in the live seven-pool loop. Actual paid product output over the same window: roughly two dozen repaired names and $10.64 of an authorized $200 recovery budget.

§3 — The claim-token question: collision safety is intact

All three concurrency patterns required of claim functions survive the wave in the single claim primitive _claim_sn_atomic() (imas_codex/standard_names/graph_ops.py:12698) that backs all seven pools: ORDER BY rand() seed ordering (graph_ops.py:12714; 16 occurrences package-wide), the two-step claim_token read-back verify (graph_ops.py:12951), and @retry_on_deadlock() on 20+ write functions. The wave strengthened the fence: commits 04c60e22 and d0208d5f added monotonic claim_seq compare-and-set, so the pre-existing relaxed re-claim form (dating to 5af31972, 2026-05-08, a deliberate trade to avoid discarding paid work on lease expiry) now applies only when claim_seq is null.

The observed token-for-hash swap is real: 21f3287b and 8511338a (2026-08-09) removed claim_token threading from the docs-review admission loop and the rollback compare-and-set, substituting content-hash preconditions (expected_docs_hash, expected_review_input_hash) and admission-node identity guards. That path is inert: admit_docs_review_request has zero production callers (its only references are its own definition and two test call sites), and it is reachable only behind --require-docs-admission, a default-off flag that additionally refuses to run without --scope-run-id and --only review_docs. The default REVIEW_DOCS path still persists through persist_reviewed_docs (graph_ops.py:15596), which compares claim_token and claim_seq and carries no hash gate. Every hash gate that guards a write sits on a CLI one-shot or dead path; pooled workers compute no content hashes, so two concurrent workers cannot diverge on an expected hash. The "force" recovery primitive (force_rollback_docs_review_admission, graph_ops.py:16958) ignores only the admission's stored worker token (which may belong to a dead process) while still CAS-fencing on the StandardName's live claim_token/claim_seq pair.

§4 — Live production outage: the pricing null

Commit aba3a0c0 (2026-08-10, "harden typed dispatch authority") changed the legacy pricing accessor get_openrouter_pricing at imas_codex/settings.py:111 from raw.get("request", 0.0) to raw.get("request") (same pattern at line 102), documenting the new contract as "never converts absence into a numeric zero". The key is now always present with value None, so the consumer fallback selected.get("request", entry.get("request", 0.0)) at discovery/base/llm.py:399 never fires and float(price["request"]) at llm.py:418 raises TypeError, surfaced as BudgetExposureUnknown by budget.py:249-252 in all three REVIEW_NAME quorum seats before any HTTP request.

The failure is perfectly inverted: it poisons exactly the five models with hand-curated pricing rows in pyproject.toml (none declares a request rate) while catalog-fallback models still price. Affected seats: all three sn-review.names reviewers, both sn-review.docs reviewers, sn-docs, sn-escalation, sn-prose-adjudicator, and sn-parent-enrich. The reviewer chain collapses from three seats to one. sn run cannot score a name, generate docs, enrich a derived parent, or escalate. The fleet's own guard test (tests/standard_names/test_seat_exposure_calibration.py) is red on main, and six further commits landed on top of it. The last recorded SNRun (2026-08-09) spent $0.42, reviewed one name, composed zero, and exited no_eligible_work. The plan narrative said paid production was paused by authority policy; it was actually jammed by this defect. The fix is one line per site.

§8 — DAG assessment

The S8 gating fails three independent tests. Provenance: every dependency on the WEST critical path was created in one documentation commit on the wave's final day. Semantic necessity: the blocked plan's own §1 states "None of it is release-blocking for sn-west-review-rehearsal, and the split was made by measurement rather than by judgement" — the restructure inverted a measured de-blocking split into a blocking gate. Direction of information: the blockers produce nothing the blocked plans consume — zero migrated call sites, zero active policies, no benchmark run; 33-cli-harmonization would, if executed, break every command the WEST release runs (and the SN command surface grew 18 → 30 during the same wave that plans to shrink it to 8).
